01 · The Four Stages

What Happens Before Embedding

Ingestion is the offline phase — run once, or whenever documents change. Most teams rush this and pay for it with poor retrieval forever. Errors here are permanent: bad embeddings, missing metadata, and duplicate chunks all cascade downstream and cannot be fixed at query time.

Stage 1
Load Extract raw text from PDFs, Word, HTML, databases, Confluence, Slack
Stage 2
Clean Remove noise, fix OCR artifacts, normalize whitespace, strip boilerplate
Stage 3
Enrich Add metadata: source, date, section, department, language, doc type
Stage 4
Chunk + Embed Split, embed, store in vector DB (Modules 2, 3, 5)
⚠️

Why 60% of RAG projects fail at ingestion

Noisy text produces bad embeddings. Missing metadata makes filtering impossible. Poor deduplication stores redundant chunks that confuse retrieval. You cannot fix bad ingestion at query time — you must rebuild the entire index from scratch.

02 · Document Loaders

Loading From Any Source

LangChain provides 100+ document loaders. These are the ones that matter in production — with the quirks you need to know before deploying.

📄 PDF — the tricky one

PDFs are positioned text boxes, not documents. PyPDFLoader loses tables. Use pymupdf4llm for markdown-preserving extraction. Scanned PDFs need OCR first (see Track 3).

🌐 Web pages

RecursiveUrlLoader crawls sites. For JS-heavy pages, use PlaywrightURLLoader. Strip navigation and footer boilerplate with Unstructured.io — it detects repeated elements automatically.

📊 Tables and spreadsheets

Tables are the hardest to chunk well. UnstructuredExcelLoader with table-to-markdown preserves row relationships. Consider storing rows as individual documents with the table header in metadata.

💬 Databases and APIs

SQLDatabaseLoader, ConfluenceLoader, NotionDirectoryLoader, SlackDirectoryLoader all work. Always add sync timestamps to metadata so you know when to re-ingest stale content.

from pathlib import Path
from langchain_community.document_loaders import PyMuPDFLoader
import hashlib, re

def clean_text(text: str) -> str:
    text = re.sub(r'\n{3,}', '\n\n', text)
    text = re.sub(r' {2,}', ' ', text)
    text = re.sub(r'Page \d+ of \d+', '', text)
    text = re.sub(r'CONFIDENTIAL|DRAFT', '', text)
    return text.strip()

def enrich_metadata(doc, source_path: str) -> dict:
    path = Path(source_path)
    return {
        "source": str(path),
        "filename": path.name,
        "extension": path.suffix.lower(),
        "department": infer_department(path),
        "content_hash": hashlib.md5(doc.page_content.encode()).hexdigest(),
        "char_count": len(doc.page_content),
        "is_empty": len(doc.page_content.strip()) < 50,
    }

def infer_department(path: Path) -> str:
    parts = [p.lower() for p in path.parts]
    dept_map = {"legal": "legal", "hr": "hr",
                "finance": "finance", "product": "product"}
    for part in parts:
        for key, dept in dept_map.items():
            if key in part:
                return dept
    return "general"

def deduplicate(docs: list) -> list:
    seen, unique = set(), []
    for doc in docs:
        h = hashlib.md5(doc.page_content.encode()).hexdigest()
        if h not in seen:
            seen.add(h)
            unique.append(doc)
    return unique

def ingest_folder(folder: str) -> list:
    docs = []
    for pdf in Path(folder).glob("**/*.pdf"):
        loaded = PyMuPDFLoader(str(pdf)).load()
        for doc in loaded:
            doc.page_content = clean_text(doc.page_content)
            doc.metadata.update(enrich_metadata(doc, str(pdf)))
            if not doc.metadata["is_empty"]:
                docs.append(doc)
    docs = deduplicate(docs)
    print(f"Loaded {len(docs)} clean unique pages")
    return docs
03 · Metadata Design

Metadata: The Secret Weapon

Good metadata turns a vector database into a structured, filterable knowledge base. Design your metadata schema before you ingest — adding a new filter field later means re-ingesting your entire corpus.

FieldTypeUse at Query TimeExample
sourcestringCitation and attribution"refund_policy_v3.pdf"
departmentstringFilter: "only search HR docs""legal", "hr", "finance"
doc_typestringFilter: "only policies, not meeting notes""policy", "contract", "report"
created_attimestampTime filter, freshness weighting"2024-11-15"
sectionstringStructured citation in answers"Introduction", "§4.2"
languagestringRoute queries to matching language docs"en", "hi", "ta"
