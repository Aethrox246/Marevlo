Post-training quantization starts from a frozen model. But what if the model could learn to be quantization-friendly during training itself? Quantization-Aware Training (QAT) simulates quantization in every forward pass, letting weights and scales co-adapt through the Straight-Through Estimator — the elegant mathematical trick that bypasses the zero-gradient problem of rounding functions. Meanwhile, on H100 GPUs, FP8 has moved quantization from deployment-time to training-time: the forward pass runs in E4M3 for precision, the backward in E5M2 for range, and optimizer states stay in FP32 for stability — achieving 2× BF16 throughput at the same effective model quality. This module covers the full training-side quantization stack, from the STE derivation through adaptive per-layer precision, SpQR sparse-quantized weights, and the frontier of token-level KV compression.

01 · Quantization-Aware Training — The STE Trick

Making round() Differentiable:
The Straight-Through Estimator

The fundamental obstacle to training quantized networks is mathematical: ∂round(x)/∂x = 0 almost everywhere. This zero gradient kills backpropagation entirely — no gradient means no learning. The Straight-Through Estimator (Bengio 2013, Hinton 2012) resolves this with a deliberate mathematical lie: in the backward pass, pretend the quantization never happened and pass the upstream gradient straight through. This single trick enables training neural networks that are quantized in their forward computation while remaining differentiable for optimisation.

import torch
import torch.nn as nn
import torch.nn.functional as F

# ── 1. STRAIGHT-THROUGH ESTIMATOR (STE) ────────────────────────────────────
class STEQuantize(torch.autograd.Function):
    """
    Straight-Through Estimator: the core trick that makes QAT trainable.

    The fundamental problem: round() and clamp() have zero gradients almost
    everywhere — backpropagating through them kills all weight updates.

    STE solution: in the FORWARD pass, do the real quantization (round + clamp).
    In the BACKWARD pass, pretend the quantization didn't happen — pass the
    upstream gradient straight through as if the operation were the identity.

    This is mathematically wrong (we're approximating the true gradient) but
    empirically works because:
    1. Quantization error is small — the true gradient is close to the STE gradient
    2. The model learns to place weights in regions where rounding is stable
    3. The scale s adapts to minimise rounding error during training

    The STE is used in every major QAT framework: PyTorch fake_quantize,
    TensorFlow QAT, NVIDIA TensorRT calibration, and Apple CoreML optimization.
    """
    @staticmethod
    def forward(ctx, x: torch.Tensor, scale: float, n_bits: int, clip: bool = True):
        n   = 2 ** (n_bits - 1) - 1    # 127 for INT8, 7 for INT4
        q   = (x / scale).round()
        if clip: q = q.clamp(-n, n)
        ctx.save_for_backward(x)
        ctx.clip_val = n * scale         # save for backward masking
        return scale * q                 # dequantize — still float!

    @staticmethod
    def backward(ctx, grad_output):
        x, = ctx.saved_tensors
        # STE: pass gradient through only for in-range values
        # Clipped values get zero gradient (weights outside range learn nothing)
        mask = (x.abs() <= ctx.clip_val).float()
        grad_input = grad_output * mask
        return grad_input, None, None, None


# ── 2. LSQ — LEARNED STEP SIZE QUANTIZATION (Esser et al. 2020) ────────────
class LSQQuantize(nn.Module):
    """
    LSQ: jointly optimise scale s with network weights via backpropagation.

    Standard QAT: scale s is set from calibration data and held fixed.
    Problem: fixed s doesn't adapt as weights change during training.

    LSQ: make s a learnable parameter. Backprop through the quantizer:
        ∂ℒ/∂s  =  Σᵢ ∂ℒ/∂q_hat_i × ∂q_hat_i/∂s

    For q_hat = s × clamp(round(x/s), -n, n):
      ∂q_hat/∂s = clamp(round(x/s), -n, n)  if |x| < clip
               = ±n                            if x at boundary

    This means s learns to minimise the total quantization distortion.
    LSQ typically recovers 0.3-0.8% accuracy vs FP32 on ResNet/Transformers
    at INT4, outperforming fixed-scale QAT by ~0.5%.

    Gradient scaling: divide ∂ℒ/∂s by √(N × n) for training stability
    (N = number of quantized weights, n = quant levels).
    """
    def __init__(self, n_bits: int = 4, per_channel: bool = False,
                 n_channels: int = 1):
        super().__init__()
        self.n_bits = n_bits
        self.n = 2 ** (n_bits - 1) - 1
        size = (n_channels, 1) if per_channel else (1,)
        # Initialise scale to sensible value (overridden by calibration)
        self.scale = nn.Parameter(torch.ones(size) * 0.1)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        s = self.scale.abs()                # ensure positive scale
        # LSQ gradient scaling factor for stability
        grad_factor = 1.0 / (x.numel() * self.n) ** 0.5
        s_scaled = s * grad_factor           # rescaled for gradient flow
        x_hat = STEQuantize.apply(x, s.item(), self.n_bits)
        # ∂ℒ/∂s gradient: computed implicitly via autograd on s_scaled
        return x_hat


# ── 3. PACT — PARAMETERIZED CLIPPING (Choi et al. 2018) ────────────────────
class PACTActivation(nn.Module):
    """
    PACT: learn the clipping bound α for activations.

    Problem: ReLU activations have unbounded positive range — outliers
    waste INT8 precision by forcing a large scale s.

    PACT: introduce learnable clip parameter α ≥ 0:
        act = clamp(x, 0, α)   — soft clipping
        quantize(act, scale=α/n)

    The network learns to clip at exactly the right point: too low and
    important activations are clipped; too high and precision is wasted
    on outliers. Regularise with L2 penalty λ‖α‖ to encourage small α.

    PACT reduces INT4 activation quantization error by ~20-30% vs fixed clipping.
    Used in NVIDIA's QAT workflow for INT8 inference on Tensor Cores.
    """
    def __init__(self, n_bits: int = 4, init_clip: float = 6.0):
        super().__init__()
        self.n_bits = n_bits
        self.n = 2 ** n_bits - 1                  # unsigned: 0..15 for INT4
        self.alpha = nn.Parameter(torch.tensor(init_clip))

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        alpha = F.softplus(self.alpha)             # keep positive via softplus
        x_clipped = torch.clamp(x, 0, alpha)     # ReLU + soft upper clip
        scale = alpha.detach() / self.n            # scale from learned clip
        return STEQuantize.apply(x_clipped, scale.item(), self.n_bits, False)


# ── 4. FULL QAT TRAINING LOOP ───────────────────────────────────────────────
def run_qat(model: nn.Module, train_loader, val_loader,
            n_bits: int = 4, epochs: int = 5) -> nn.Module:
    """
    Full QAT recipe for transformer models.

    Phase 1 (warm-up, 1 epoch): train FP32 model normally to stabilise
    Phase 2 (QAT, remaining epochs): insert FakeQuantize into all Linear layers

    Strategy: quantize weights only first (activations are harder).
    Add PACT activation quantizers after weight QAT stabilises.
    Use lower LR than FP32 training (typically 1e-5 to 1e-4).
    """
    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-5)
    scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=epochs)

    for epoch in range(epochs):
        model.train()
        for batch_idx, (X, y) in enumerate(train_loader):
            optimizer.zero_grad()
            # Insert fake-quantization into linear weight before forward
            for name, module in model.named_modules():
                if isinstance(module, nn.Linear):
                    # Fake-quantize weights in-place during forward
                    scale = module.weight.data.abs().max() / (2**(n_bits-1)-1)
                    module.weight.data = STEQuantize.apply(
                        module.weight.data, scale.item(), n_bits)
            loss = model(X).loss_fn(y)
            loss.backward()    # STE gradient flows through FakeQuantize
            optimizer.step()
            if batch_idx % 100 == 0:
                print(f"Epoch {epoch} step {batch_idx}: loss={loss.item():.4f}")
        scheduler.step()
    return model
Standard QAT

Fixed Scale STE

Scale s set from calibration data, held fixed throughout training. Simple but suboptimal — the scale may not be right for the learned weight distribution.

LSQ (2020)

Learned Step Size

Scale s is a learnable parameter updated by backprop: ∂ℒ/∂s = Σᵢ⌊wᵢ/s⌉_clipped · (∂ℒ/∂q̂ᵢ) · (1/√N·n). Best INT4 accuracy on ResNets and transformers.

PACT (2018)

Learned Clipping

Clip bound α is a learnable parameter for activations. Replaces fixed clipping at max(|x|) with data-driven α that minimises total quantization error. Essential for aggressive INT4 activation quantization.

🔑

QAT recipe: the two-phase training strategy

Phase 1 — Warm-up (1-2 epochs): Train with fixed scale s = amax(W)/(2^(b-1)-1) and STE. Scale adapts slowly. This ensures the model starts from a PTQ-equivalent state — you always know it's at least as good as PTQ. Phase 2 — LSQ+PACT (remaining epochs): Enable learned scales and clip bounds. Use LR 10× smaller than original training. Add L2 regularisation λ‖α‖ on PACT clip bounds to encourage tight clipping. This two-phase approach consistently achieves within 0.3% of FP32 accuracy at INT4 for models up to ~3B parameters.

02 · FP8 Training on H100 — Quantization at Training Time

1979 TFLOPS at FP8:
2× BF16, 30× FP32

The NVIDIA H100 introduces FP8 Tensor Cores that execute matrix multiplications at twice the throughput of BF16. Unlike post-training quantization, FP8 training applies quantization during every training step — the model never sees FP32 activations during the forward or backward pass. Two complementary formats handle the different numerical requirements: E4M3 (high precision, limited range) for forward pass tensors where values are well-scaled, and E5M2 (wide range, limited precision) for backward pass gradients where spikes must not overflow.

FP8 training pipeline — H100 Transformer Engine with delayed scaling and E4M3/E5M2 hybrid

fp8_training.py — H100 Transformer Engine FP8 training + adaptive precision + SpQR

import torch
import torch.nn as nn

# ── 1. FP8 TRAINING WITH TRANSFORMER ENGINE ─────────────────────────────────
# Requires: pip install transformer-engine
# Hardware: NVIDIA H100 (Hopper architecture — FP8 Tensor Cores)
try:
    import transformer_engine.pytorch as te
    import transformer_engine.common.recipe as recipe
    TE_AVAILABLE = True
except ImportError:
    TE_AVAILABLE = False


def build_fp8_transformer_block(d_model: int = 4096, n_heads: int = 32):
    """
    Build a transformer block using NVIDIA's Transformer Engine for FP8.

    Architecture:
      te.TransformerLayer wraps attention + FFN with automatic FP8 casting.
      Only GEMMs (matrix multiplications) run in FP8; everything else (LayerNorm,
      softmax, residual additions) remains in BF16 for numerical stability.

    FP8 formats used:
      E4M3 (4 exponent, 3 mantissa bits): forward pass weights and activations.
               Range: ±448. Higher precision, compact mantissa.
               Max representable: 448. Suitable for well-scaled forward tensors.
      E5M2 (5 exponent, 2 mantissa bits): backward pass gradients.
               Range: ±57344. Wider range needed for gradient spikes during training.

    Delayed scaling:
      Computing amax(tensor) per step requires a synchronisation barrier across
      the entire tensor — expensive for large activations. Delayed scaling uses
      the amax from the PREVIOUS step (or a rolling average of recent steps).
      This eliminates the synchronisation cost with negligible accuracy loss since
      tensor ranges don't change dramatically between consecutive steps.
    """
    if not TE_AVAILABLE:
        return nn.TransformerEncoderLayer(d_model, n_heads, batch_first=True)

    fp8_recipe = recipe.DelayedScaling(
        margin=0,                             # no extra scaling margin
        interval=1,                            # update scale every step
        fp8_format=recipe.Format.HYBRID,       # E4M3 fwd + E5M2 bwd
        amax_history_len=16,                  # rolling window for scale
        amax_compute_algo='max',              # use max not mean
    )
    return te.TransformerLayer(
        hidden_size=d_model,
        ffn_hidden_size=d_model * 4,
        num_attention_heads=n_heads,
        layer_type='encoder',
    ), fp8_recipe


def fp8_training_step(model, batch, optimizer, fp8_recipe,
                       loss_scaler: torch.cuda.amp.GradScaler):
    """
    Single FP8 training step on H100.

    Note on loss scaling: even in FP8, gradient underflow can occur for very
    small gradient values in early training. Loss scaling multiplies the loss
    by a large constant (e.g. 2^15) before backward, scaling gradients up to
    avoid FP8 underflow, then divides by the same constant before the optimizer
    step. GradScaler handles this automatically and adapts the scale factor.
    """
    optimizer.zero_grad()
    with te.fp8_autocast(enabled=True, fp8_recipe=fp8_recipe):
        output = model(batch['input_ids'])   # FP8 GEMMs run here
        loss   = output.loss                    # accumulated in BF16
    loss_scaler.scale(loss).backward()          # FP8 E5M2 backward
    loss_scaler.unscale_(optimizer)             # remove loss scale from grads
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    loss_scaler.step(optimizer)                 # update BF16 master weights
    loss_scaler.update()                        # adjust scale for next step
    return loss.item()


# ── 2. ADAPTIVE PRECISION — LAYER SENSITIVITY ANALYSIS ─────────────────────
def compute_layer_sensitivity(model: nn.Module, val_loader,
                               base_metric: float) -> dict[str, float]:
    """
    Measure how much each layer hurts accuracy when quantized to INT4.

    Algorithm:
    For each Linear layer L:
      1. Quantize L to INT4 (leave all others in FP32)
      2. Evaluate on val_loader → metric_L
      3. Sensitivity(L) = base_metric - metric_L

    High sensitivity → this layer needs higher precision.
    Low sensitivity → safe to quantize aggressively.

    Result: a per-layer precision assignment (INT4/INT8/BF16).
    Example findings: first and last embedding layers are most sensitive;
    middle FFN layers are most robust; attention Q/K projections are more
    sensitive than V/O projections.
    """
    model.eval()
    sensitivity = {}
    for name, module in model.named_modules():
        if not isinstance(module, nn.Linear): continue
        W_backup = module.weight.data.clone()   # save original
        # Quantize this layer to INT4
        n = 7  # INT4 range [-7, 7]
        s = W_backup.abs().max() / n
        module.weight.data = (W_backup / s).round().clamp(-n, n) * s
        # Evaluate
        metric_L = _evaluate(model, val_loader)
        sensitivity[name] = base_metric - metric_L
        module.weight.data = W_backup           # restore
    return sensitivity


def assign_mixed_precision(sensitivity: dict, high_thresh: float = 0.02,
                            mid_thresh: float = 0.005) -> dict[str, str]:
    """Assign INT4/INT8/BF16 per layer based on sensitivity thresholds."""
    assignment = {}
    for name, sens in sensitivity.items():
        if sens >= high_thresh:   assignment[name] = 'BF16'   # critical
        elif sens >= mid_thresh:  assignment[name] = 'INT8'   # moderate
        else:                     assignment[name] = 'INT4'   # robust
    return assignment


# ── 3. SpQR — SPARSE + QUANTIZED (Dettmers et al. 2023) ────────────────────
def spqr_compress(W: torch.Tensor, base_bits: int = 4,
                  outlier_fraction: float = 0.01) -> dict:
    """
    SpQR: Sparse + Quantized Representation — best of both worlds.

    Observation: most weight matrices have 1-5% of elements that are
    significantly larger than average (outliers). These outliers cause
    disproportionate quantization error when the scale must accommodate them.

    SpQR strategy:
      1. Identify top-p% outliers by magnitude.
      2. Store outliers in full FP16 (sparse format — very few of them).
      3. Quantize the remaining 99% to 3-4 bits.

    Result: effectively 3.1-4.1 bits/weight (99% at 4-bit, 1% at 16-bit),
    but with quantization error comparable to 8-bit for all weights.

    Mathematical intuition: if 1% of weights are outliers, the quantization
    scale is set by the outlier magnitude → 99% of weights use only a small
    fraction of the representable range. By treating outliers separately,
    the scale for the 99% is set optimally → 6-10× better error for those.

    SpQR achieves better perplexity than GPTQ at 4-bit on LLaMA-2 models
    because it handles the outlier problem directly rather than via Hessian
    compensation.
    """
    n_total  = W.numel()
    n_outliers = int(n_total * outlier_fraction)
    # Find outlier positions
    flat     = W.abs().flatten()
    threshold = torch.topk(flat, n_outliers).values.min().item()
    outlier_mask = W.abs() >= threshold
    # Store outliers in FP16
    outliers_fp16 = W[outlier_mask].half()          # sparse: (n_outliers,)
    outlier_indices = outlier_mask.nonzero(as_tuple=True)
    # Quantize remaining weights to base_bits
    W_inlier = W.clone()
    W_inlier[outlier_mask] = 0                    # zero out outliers
    n = 2 ** (base_bits - 1) - 1
    s = W_inlier.abs().max() / n
    W_q = (W_inlier / s).round().clamp(-n, n).to(torch.int8)
    effective_bpw = (n_total * base_bits + n_outliers * 16) / n_total
    print(f"SpQR: {outlier_fraction*100:.1f}% outliers in FP16")
    print(f"  Effective bits/weight: {effective_bpw:.2f}")
    return dict(W_q=W_q, scale=s, outliers=outliers_fp16, idx=outlier_indices)

⚠️

What stays in high precision — the FP8 non-negotiables

Optimizer states (m₁, m₂) stay FP32: Adam's moment estimates accumulate over hundreds of steps — quantization error compounds, destroying convergence. A single FP32 copy of optimizer states costs 2× model size but is mandatory. Residual connections stay BF16: residuals sum across 96+ layers — accumulated rounding error in FP8 would degrade final layer outputs. LayerNorm + softmax stay BF16: these operations involve log, exp, and normalisation that are numerically sensitive to range. Only GEMMs (Linear layers) run in FP8 — where the 2× throughput gain actually matters.

FP8 vs BF16 training: LLaMA-3-70B on 256 H100s

BF16 baseline: 989 TFLOPS × 256 GPUs = 253 PFLOPs. Model FLOPs Utilisation (MFU) ~40% → effective 101 PFLOPs. Training tokens per second: ~130K. FP8 with TE: 1979 TFLOPS × 256 = 507 PFLOPs theoretical. MFU ~35% (FP8 casting overhead) → effective 177 PFLOPs. Training tokens per second: ~200K. Speedup: ~1.5× tokens/sec. Memory: FP8 activations = half BF16 → larger effective batch size → further amortises data loading overhead. Cost savings on a $10M training run: ~35% reduction in H100 node-hours.

03 · Adaptive Precision, SpQR and Frontier Research

Layer Sensitivity · SpQR · Token-Level KV:
The Next Quantization Frontier

💡

Adaptive Precision: not all layers are equal

Sensitivity analysis (quantize one layer at a time, measure accuracy drop) consistently reveals: embedding and LM head are 10× more sensitive than middle FFN layers. Q/K projections are 2-3× more sensitive than V/O projections. Early transformer blocks are more sensitive than later ones. Production strategy: BF16 for embedding/LM-head (adds ~2GB to a 70B model), INT8 for attention Q/K, INT4 for FFN and V/O — total ~37GB vs 35GB pure INT4, but recovers 0.5-2.0 perplexity points. bitsandbytes and GGUF implement this automatically.

💡

SpQR: when outliers refuse to be quantized

Some weight matrices have 1-5% of elements that are 5-20× the typical magnitude. Standard quantization sets scale = max(|W|)/(2^b-1) — the scale accommodates the outlier but wastes 80-90% of precision levels on inliers. SpQR stores outliers exactly (FP16 sparse) and quantizes the 99% inliers to 3-bit with a scale set by their actual max. Effective bits: 0.99×3 + 0.01×16 = 3.13 bits/weight. Perplexity improvement over GPTQ 3-bit: 0.5-1.5 points on LLaMA-2 70B. Used in QMoE (quantized mixture-of-experts) for trillion-parameter models.

Question 1 of 8

You implement QAT for a ViT-B/16 model targeting INT4 deployment. After 3 epochs of QAT training, you observe the validation accuracy is LOWER than vanilla PTQ INT4. What is the most likely cause and fix?

Scale initialisation is the #1 QAT failure mode. If s is too small, most weights map to q=0 after rounding — the forward pass produces near-zero outputs (dead network). The STE backward pass passes gradients through but they update weights that then re-quantize to 0 again — a training loop that never converges. Fix: always initialise s = amax(W) / (2^(b-1) - 1) from the pre-trained weights. This ensures the initial FakeQuantize represents the weights faithfully, so training starts from a good point. Freeze s for epoch 1 (PTQ-equivalent) then enable LSQ learning from epoch 2 — this two-phase strategy consistently outperforms end-to-end LSQ from random init.
Question 2 of 8

The STE approximation sets ∂(round)/∂x = 1 for |x| ≤ clip and 0 otherwise. This is mathematically incorrect — why does it still work for neural network training, and what goes wrong when it doesn't?

STE convergence theory (Yin et al. 2019): The key insight is that STE is an unbiased gradient estimator in a specific sense — averaging over training batches, the STE gradient has the same sign as the true gradient with high probability. This is sufficient for SGD convergence. The practical failure modes are well-documented: clipping too aggressively kills gradient flow, and very coarse quantization (2-bit) often fails because the STE error term dominates. Adaptive methods like LSQ (learned scale) and PACT (learned clip) reduce these failure modes by letting the quantiser parameters adapt to the distribution.
Question 3 of 8

LSQ learns the step size s jointly with model weights via backpropagation. Write the gradient ∂ℒ/∂s for symmetric quantization with n levels, and explain why the gradient scaling factor 1/√(N·n) is needed.

LSQ gradient derivation: The chain rule gives ∂ℒ/∂s = Σᵢ (∂ℒ/∂q̂ᵢ)(∂q̂ᵢ/∂s). For in-range weights: ∂q̂/∂s = round(w/s) (the quantized integer value). For clipped weights: ∂q̂/∂s = ±n. The gradient scaling 1/√(N·n) is the key contribution of the LSQ paper — it makes the gradient magnitude comparable to ∂ℒ/∂w regardless of layer size, enabling a single shared learning rate for both weights and scale. Without this, a layer with N=1M weights produces ∂ℒ/∂s that is 1000× larger than ∂ℒ/∂w — the scale converges in 1 step while weights need 1000 steps, causing instability.
Question 4 of 8

FP8 training uses E4M3 for the forward pass and E5M2 for the backward pass. Why does the backward pass need more dynamic range rather than more precision, and what specific numerical event makes E5M2 necessary?

The overflow catastrophe: E4M3 can represent values up to ±448. During training on a bad batch, gradient norms can easily exceed 1000 — this would saturate E4M3 to ±448 for all gradient values, completely destroying the gradient signal and making the weight update garbage. E5M2 extends the range to ±57344 (57344/448 = 128× wider) at the cost of precision (2 vs 3 mantissa bits). The precision loss in E5M2 is acceptable for gradients because gradient noise already dominates — you're training with noisy mini-batch gradients anyway, so losing 1 bit of gradient precision matters far less than overflow prevention.
Question 5 of 8

SpQR stores 1% of weight elements as FP16 outliers and quantizes the rest to 3-bit. For a LLaMA-2-7B FFN weight W ∈ ℝ¹¹⁰⁰⁸ˣ⁴⁰⁹⁶: calculate (A) total storage and (B) effective bits/weight. Why does this beat GPTQ at 3-bit?

The outlier contamination effect: In a matrix W where 1% of elements are 10× larger than the rest, a single global scale s = max(|W|) / n means 99% of weights occupy only 1/10th of the quantization levels — 90% of the precision is wasted covering the outlier range that only 1% of weights use. SpQR eliminates this completely: the 99% get a scale set by their actual max (not the outliers'), using the full INT3 range. The 1% outliers get exact FP16 representation. The 3.13 bits/weight overhead is tiny compared to the accuracy recovery.
Question 6 of 8

Token-level KV cache compression assigns different precision to different sequence positions — recent tokens stay FP16 while older tokens get INT2. On a 128K context: model GPT4-class (L=96, d=12288), what is the memory saving if the most recent 2K tokens stay FP16 and the remaining 126K tokens use INT2?

Token-level precision arithmetic: The memory formula per section is 2 (K+V) × L × T × d × bytes_per_value. INT2 = 0.25 bytes vs FP16 = 2 bytes → 8× compression. The 86% saving enables dramatically longer contexts. The recency-biased precision assignment is justified by attention pattern analysis: in most transformer tasks, tokens attend most strongly to recent context and specific key positions — the bulk of the sequence gets low attention weights anyway, so quantising those KV vectors coarsely has minimal impact on attention output. This is validated empirically in H2O, SnapKV, and StreamingLLM papers.
Question 7 of 8

Layer sensitivity analysis finds that the first embedding layer and last LM head of a 70B LLM have 10× higher quantization sensitivity than the middle FFN layers. If you use mixed precision (sensitive layers at BF16, others at INT4), how much additional memory does this cost vs pure INT4, and is it worth it?

Mixed precision accounting: The total parameter count in embedding + LM head for typical LLMs is ~2-4% of total parameters (2×vocab×d / total_params ≈ 2×128K×8K / 70B ≈ 3%). But their quantization sensitivity is 10× higher — they directly map between discrete tokens and continuous representations. The extra 2GB for BF16 precision on these layers is unambiguously worth paying. In practice: use INT4 for all transformer blocks, INT8 for attention projections (slightly sensitive), BF16 for embedding/LM-head. This hybrid achieves accuracy within 0.3 perplexity of full BF16 at 35-37GB total.
Question 8 of 8

A research team reports that QAT at INT4 matches FP32 training accuracy on a BERT-base model (110M parameters) for classification. However, when they apply the same QAT recipe to GPT-4-scale models (1T parameters), accuracy degrades severely. What fundamental difference causes QAT to fail to scale, and what alternatives exist?

The QAT scalability wall: QAT training cost ≈ FP32 training cost × (QAT_epochs / pretrain_epochs). For BERT-base (110M), 5 QAT epochs on a V100 takes ~2 hours — trivial. For LLaMA-3-70B, 1 QAT epoch on 256 H100s takes ~40 hours and costs ~$50K. For GPT-4-class (1T), even 0.1 epochs is economically infeasible. PTQ methods (GPTQ, AWQ) run in minutes to hours and require only calibration data — no training. This is why the field has largely moved to PTQ for frontier models. QAT's remaining sweet spot: small models (BERT, T5-base, ViT-B) where a few fine-tuning epochs are cheap and INT4 accuracy is critical.
