Scalar quantization treats every dimension of a vector independently — a fundamental limitation when dimensions are correlated. Product Quantization splits the vector into subvectors and builds a separate codebook for each, enabling compression ratios of 100×+ while preserving approximate distances via a precomputed lookup table. Residual Quantization takes a different axis: iteratively encode the error, building hierarchical codes that enable progressive quality levels. This module builds both methods from mathematical foundations through production-grade FAISS and ScaNN systems — with complete implementations, interactive exploration, and deep scenario-based assessment designed for engineers who will actually deploy these systems.

01 · Product Quantization — The ADC Breakthrough

1024 Multiplications Reduced
to 4 Table Lookups

Product Quantization (Jégou et al. 2011) is the workhorse of production vector search. Given a d-dimensional vector, PQ splits it into m non-overlapping subvectors and quantizes each to one of k centroids in a separate sub-codebook. The storage cost drops from d × 4 bytes to m × ⌈log₂(k)⌉ bits. More importantly, approximate distances can be computed by precomputing a query-specific m × k distance table once, then each database vector lookup costs only m additions — reducing per-vector distance computation from O(d) to O(m) regardless of dimension.

product_quantization.py — PQ codebook training, encoding, ADC distance computation

import numpy as np
from sklearn.cluster import MiniBatchKMeans
from dataclasses import dataclass, field

@dataclass
class PQCodebook:
    """Trained Product Quantization codebook — everything needed for encode/decode."""
    centroids: np.ndarray      # shape (m, k, d_sub) — m books, k centroids, d/m dims
    m:         int             # number of subvectors
    k:         int             # codebook size per subspace (usually 256)
    d:         int             # original vector dimension

    @property
    def d_sub(self) -> int: return self.d // self.m
    @property
    def bits_per_dim(self) -> float: return self.m * np.log2(self.k) / self.d
    @property
    def compression_ratio(self) -> float: return (self.d * 32) / (self.m * np.log2(self.k))


def train_pq(X: np.ndarray, m: int = 32, k: int = 256,
             max_iter: int = 300) -> PQCodebook:
    """
    Train Product Quantization codebook on dataset X.

    Algorithm (Lloyd's / k-means per subspace):
    1. Split each vector into m non-overlapping subvectors of size d/m.
    2. For each subspace j: run k-means on the j-th subvectors of all training
       vectors to produce k centroids (the j-th sub-codebook C⁽ʲ⁾).
    3. Training is INDEPENDENT per subspace — the m k-means problems are
       solved in parallel. This is what makes PQ training O(m × N × k × d/m)
       = O(N × k × d) — the same as single-codebook VQ but with m-times
       better accuracy due to the product structure.

    Why k=256? Each subvector index fits in 1 byte (uint8), and 256 centroids
    give a good accuracy/storage trade-off. The ADC table is k × m = 256 × m
    float32 values — at m=64 this is 64KB, fitting comfortably in L1 cache.

    Args:
        X: (N, d) training vectors — needs N >> k for good codebook (N > 40k recommended)
        m: number of subvectors (must divide d evenly)
        k: codebook size per subspace
    """
    N, d = X.shape
    assert d % m == 0, f"d={d} must be divisible by m={m}"
    d_sub = d // m
    centroids = np.zeros((m, k, d_sub), dtype=np.float32)
    for j in range(m):
        sub = X[:, j*d_sub:(j+1)*d_sub]  # (N, d_sub)
        kmeans = MiniBatchKMeans(n_clusters=k, max_iter=max_iter,
                                 batch_size=min(10000, N), random_state=j)
        kmeans.fit(sub)
        centroids[j] = kmeans.cluster_centers_.astype(np.float32)
    return PQCodebook(centroids=centroids, m=m, k=k, d=d)


def pq_encode(X: np.ndarray, cb: PQCodebook) -> np.ndarray:
    """
    Encode vectors to PQ codes.
    Returns: (N, m) uint8 array of codebook indices.
    """
    N, d = X.shape
    codes = np.zeros((N, cb.m), dtype=np.uint8)
    for j in range(cb.m):
        sub = X[:, j*cb.d_sub:(j+1)*cb.d_sub]  # (N, d_sub)
        C   = cb.centroids[j]                      # (k, d_sub)
        # Batch L2 via broadcasting: ||sub - C||²
        dists = (np.sum(sub**2, axis=1, keepdims=True)  # (N,1)
                 - 2 * sub @ C.T                          # (N,k)
                 + np.sum(C**2, axis=1))                 # (k,)
        codes[:, j] = np.argmin(dists, axis=1)
    return codes


def adc_build_table(q: np.ndarray, cb: PQCodebook) -> np.ndarray:
    """
    Asymmetric Distance Computation (ADC) — precompute distance table for query q.
    Returns: (m, k) float32 table. table[j, i] = ||q_j - C⁽ʲ⁾[i]||²

    This is the key to PQ search speed. Given query q:
    1. Build table: m × k = 32 × 256 = 8192 distances (done ONCE per query).
    2. For each database vector with code [i₁,...,iₘ]:
       approx_dist = Σⱼ table[j, iⱼ]   — only m additions, no multiplications!

    For 1B vectors with m=32: 1B × 32 table lookups vs 1B × 1024 multiplies.
    Speedup: 1024/32 = 32× for the distance computation step.
    Plus memory: codes are uint8 → 4× smaller than FP32 → better cache hit rate.
    """
    table = np.zeros((cb.m, cb.k), dtype=np.float32)
    for j in range(cb.m):
        q_sub = q[j*cb.d_sub:(j+1)*cb.d_sub]  # (d_sub,)
        C     = cb.centroids[j]                   # (k, d_sub)
        table[j] = np.sum((C - q_sub)**2, axis=1)
    return table


def adc_search(q: np.ndarray, codes: np.ndarray, cb: PQCodebook,
               top_k: int = 10) -> tuple:
    """
    Approximate nearest-neighbour search using ADC.
    Returns (indices, distances) of top_k nearest neighbours.
    """
    table  = adc_build_table(q, cb)              # (m, k)
    # Lookup: for each vector n, sum distances across m subvectors
    scores = np.sum(table[np.arange(cb.m), codes], axis=1)  # (N,)
    idx    = np.argpartition(scores, top_k)[:top_k]
    idx    = idx[np.argsort(scores[idx])]
    return idx, scores[idx]
🔑

Why ADC is faster than SDC (Symmetric Distance Computation)

Two options for PQ distance: SDC (both query and DB are PQ-coded) precomputes a k²×m distance table between all centroid pairs — query lookup costs m reads but the table costs k²×m floats ≈ 250KB at k=256,m=4. ADC (asymmetric — only DB is coded) computes exact query subvectors vs PQ centroids per query: m×k = 4×256 = 1024 distances to build a 4KB table. Query lookup: m reads. ADC always outperforms SDC because the DB coding error is avoided on the query side. FAISS defaults to ADC. The critical insight: the 4KB ADC table fits in L1 cache (32-64KB typical), making the 50M × 4 lookups purely cache-bound — extremely fast.

02 · Residual Quantization and OPQ

Iterative Error Correction
vs Spatial Decomposition

Where PQ decomposes a vector spatially (each subvector is a different slice of dimensions), Residual Quantization decomposes it temporally — each level encodes the remaining error from all previous levels. The result is a hierarchical code where truncating at any level gives a valid approximation. This progressive property makes RQ ideal for audio neural codecs (EnCodec, SoundStream) and extreme-compression LLM weights (AQLM). OPQ bridges the gap: it applies a learned orthogonal rotation before PQ encoding to equalise variance across subspaces, recovering 3–5% additional recall at no storage cost.

RQ vs PQ vs OPQ+IVFPQ — three strategies, different accuracy-speed trade-offs

residual_quantization.py — RQ + OPQ rotation + IVFPQ full production pipeline

import numpy as np
from sklearn.cluster import MiniBatchKMeans

# ── RESIDUAL QUANTIZATION ───────────────────────────────────────────────────
def train_rq(X: np.ndarray, R: int = 4, k: int = 256) -> list[np.ndarray]:
    """
    Train Residual Quantization with R levels, k centroids per level.

    Algorithm: each level quantizes the residual from all previous levels.
    Level 1: standard VQ. Level 2: VQ of (X - reconstruction from level 1). Etc.

    Key difference from PQ:
    - PQ splits the vector SPATIALLY (each subvector is a different slice of dims)
    - RQ refines the vector TEMPORALLY (each level corrects the previous error)
    - PQ approximation: x̂ = concat(c₁⁽¹⁾, c₂⁽²⁾, ..., cₘ⁽ᵐ⁾)
    - RQ approximation: x̂ = c₁ + c₂ + ... + cᴿ  (full-dimension sum)

    RQ advantage: cross-dimension correlations are captured at every level,
    since each codebook operates on the full d-dimensional residual.
    PQ codes each subspace independently — cross-subspace structure is lost.
    """
    codebooks = []
    residuals = X.copy().astype(np.float32)
    for r in range(R):
        km = MiniBatchKMeans(n_clusters=k, random_state=r, batch_size=10000)
        km.fit(residuals)
        C     = km.cluster_centers_.astype(np.float32)  # (k, d)
        idx   = km.predict(residuals)
        residuals -= C[idx]                               # subtract nearest centroid
        codebooks.append(C)
        print(f"  RQ level {r+1}: residual norm = {np.linalg.norm(residuals, axis=1).mean():.4f}")
    return codebooks


def rq_encode(x: np.ndarray, codebooks: list) -> np.ndarray:
    """Encode single vector x using RQ codebooks. Returns (R,) index array."""
    residual = x.copy().astype(np.float32)
    codes    = np.zeros(len(codebooks), dtype=np.uint16)
    for r, C in enumerate(codebooks):
        dists    = np.sum((C - residual)**2, axis=1)
        codes[r] = np.argmin(dists)
        residual -= C[codes[r]]
    return codes


def rq_decode(codes: np.ndarray, codebooks: list) -> np.ndarray:
    """Reconstruct vector from RQ codes. x̂ = Σᵣ C⁽ʳ⁾[iᵣ]."""
    return sum(C[codes[r]] for r, C in enumerate(codebooks))


# ── OPTIMIZED PQ (OPQ) ───────────────────────────────────────────────────────
def train_opq(X: np.ndarray, m: int = 32, k: int = 256,
              n_iter: int = 10) -> tuple:
    """
    OPQ: Optimized Product Quantization (Ge et al. 2013).

    Problem with PQ: if variance is unevenly distributed across dimensions,
    subvectors have different amounts of information — some subspaces have
    huge variance (lots to quantize) while others are nearly constant.
    PQ allocates the same number of bits (log₂k) to each subspace regardless.

    OPQ Fix: Learn an orthogonal rotation matrix A such that after rotating
    y = Ax, the variance is distributed as evenly as possible across subvectors.
    This balances the quantization load across subspaces.

    Algorithm (alternating optimisation):
    E-step: fix A, train PQ codebook on AX
    M-step: fix PQ, update A via SVD of (XCᵀ) where C is reconstructed matrix

    Converges in 5-10 iterations. Typical improvement: +3-5% recall@10 vs PQ.
    """
    N, d = X.shape
    # Initialise rotation as identity
    A = np.eye(d, dtype=np.float32)
    from product_quantization import train_pq, pq_encode, PQCodebook
    for it in range(n_iter):
        Xr = X @ A.T                              # apply current rotation
        cb = train_pq(Xr, m=m, k=k)              # E-step: train PQ on rotated X
        codes = pq_encode(Xr, cb)
        # Reconstruct from PQ codes
        X_hat = np.zeros_like(X)
        for j in range(m):
            X_hat[:, j*cb.d_sub:(j+1)*cb.d_sub] = cb.centroids[j][codes[:,j]]
        # M-step: update A via SVD of correlation matrix
        U, _, Vt = np.linalg.svd(X_hat.T @ X)   # SVD of (d×d) matrix
        A = (U @ Vt).T                            # new orthogonal rotation
        err = np.mean(np.sum((Xr - X_hat)**2, axis=1))
        print(f"  OPQ iter {it+1}: recon error = {err:.4f}")
    return A, cb


# ── IVFPQ INDEX (production-scale search) ───────────────────────────────────
class IVFPQIndex:
    """
    Inverted File + PQ index — the workhorse of production vector search.

    Structure:
      Coarse quantizer: k-means with nlist centroids partitions space into cells.
      Each database vector is assigned to its nearest coarse centroid.
      PQ encodes the residual (vector minus coarse centroid) in that cell.

    Search:
      1. Find nprobe nearest coarse centroids to query q.
      2. Only scan vectors in those nprobe cells (vs all N in flat PQ).
      3. ADC distance on PQ residuals within each cell.

    Speed example: N=100M, nlist=4096, nprobe=64
      Scan fraction: 64/4096 = 1.6% of database = 1.6M vectors
      vs 100M for flat PQ.
      Speedup: ~60× over flat PQ at ~5% recall degradation.
    """
    def __init__(self, nlist: int = 4096, m: int = 32, k: int = 256):
        self.nlist = nlist; self.m = m; self.k = k
        self.coarse_centroids = None
        self.cells: dict = {}            # cell_id → list of (global_id, pq_code)
        self.pq_cb = None

    def build(self, X: np.ndarray, ids: np.ndarray | None = None):
        """Build the IVFPQ index from a database of vectors."""
        from product_quantization import train_pq, pq_encode
        N, d = X.shape
        if ids is None: ids = np.arange(N)
        # Step 1: Coarse quantizer (IVF)
        coarse = MiniBatchKMeans(n_clusters=self.nlist, batch_size=50000)
        coarse.fit(X)
        self.coarse_centroids = coarse.cluster_centers_.astype(np.float32)
        cell_assign = coarse.predict(X)            # (N,) cell assignment
        # Step 2: PQ on residuals
        residuals = X - self.coarse_centroids[cell_assign]
        self.pq_cb = train_pq(residuals, m=self.m, k=self.k)
        pq_codes = pq_encode(residuals, self.pq_cb)
        # Step 3: Build inverted lists
        for n in range(N):
            cell = cell_assign[n]
            self.cells.setdefault(cell, []).append((ids[n], pq_codes[n]))
        print(f"IVFPQ built: {N:,} vectors → {self.nlist} cells")
        print(f"  Avg cell size: {N/self.nlist:.0f} · Codebook: {self.m}×{self.k}")

    def search(self, q: np.ndarray, top_k: int = 10, nprobe: int = 64) -> tuple:
        """Search for top_k nearest neighbours using nprobe cells."""
        from product_quantization import adc_build_table
        # Coarse assignment: find nprobe nearest centroids
        coarse_dists = np.sum((self.coarse_centroids - q)**2, axis=1)
        probe_cells  = np.argpartition(coarse_dists, nprobe)[:nprobe]
        candidates   = []
        for cell in probe_cells:
            q_residual = q - self.coarse_centroids[cell]
            table = adc_build_table(q_residual, self.pq_cb)
            for gid, code in self.cells.get(cell, []):
                d = np.sum(table[np.arange(self.m), code])
                candidates.append((d, gid))
        candidates.sort(key=lambda x: x[0])
        return [gid for _, gid in candidates[:top_k]]
💡

AQLM — RQ applied to LLM weights (2024)

AQLM (Additive Quantization for Language Models) groups 8 adjacent weights into a 512-dim vector and encodes each group with R=2 RQ levels (k=256 per level). Result: 2 bytes per 8 weights = 2 bits/weight. Why better than scalar INT2: scalar 2-bit assigns each weight independently to (-3, -1, 1, 3) — 4 levels. Vector RQ-2bit with group 8 and R=2 represents 256² = 65536 possible group patterns, capturing inter-weight correlations scalar methods miss. LLaMA-2-7B: 256MB FP16 → 33MB AQLM. Perplexity: AQLM 2-bit beats GPTQ 3-bit on WikiText-2.

💡

ScaNN — Anisotropic Quantization (Google 2020)

Standard PQ minimises ‖x − x̂‖² uniformly in all directions. ScaNN observes: for retrieval via inner product, only the error component parallel to likely query directions matters. ScaNN minimises E_q[⟨q, x−x̂⟩²] = (x−x̂)ᵀΣ_q(x−x̂) where Σ_q is the query covariance matrix. The resulting codebook concentrates precision in high-traffic query directions, accepting larger errors orthogonal to queries. Result: +3–8% Recall@10 vs IVFPQ at identical latency on ANN benchmarks. ScaNN also uses asymmetric hashing (AH) for a fast scoring pre-filter before exact ADC reranking.

03 · Production Vector Search Architecture

100M Vectors, 10ms P99:
The Full System Design

Production RAG pipeline: 200M document chunks, d=1536

Indexing: IVFPQ with nlist=16384 (avg 12K vectors/cell), m=96 (each 16-dim subspace), k=256 → 96 bytes/vector. Total index: 200M × 96B = 18.7GB + codebook ≈ 20GB. Fits on 1× A100-80GB. Training: Sample 10M vectors, train coarse k-means (nlist centroids) then PQ on residuals. Total: ~2 GPU-hours. Query: Embed query (OpenAI/Cohere API, ~20ms) → IVFPQ search nprobe=256 cells (~12ms on GPU) → rerank top-100 with exact L2 on stored FP16 vectors (~3ms) → return top-10. Total: ~35ms p99. Recall@10: 91% vs exact L2 (FAISS benchmark). Scale: 2× A100 for redundancy, handles 800 QPS at <50ms p99.

⚠️

The reranking pattern — critical for production

Never serve PQ-approximate distances directly to users. Always: (1) ANN search returns top-K candidates (K=100-500), (2) rerank with exact distances using stored full-precision vectors, (3) return final top-k. This two-stage pattern recovers 3-5% recall at minimal latency cost. Store FP16 vectors separately from PQ codes — 200M × 1536 × 2B = 576GB for full-precision reranking. In practice: store top-10 candidates' full vectors in a fast secondary cache (Redis, DynamoDB) and rerank inline.

🔑

Choosing m and k — the two key hyperparameters

m (subvectors): Controls recall and storage. Rule of thumb: m = d/16 gives good balance (d=1536 → m=96). Each subvector covers 16 dims. Increasing m: +recall, +storage, +ADC table size. k (centroids): Almost always k=256 (uint8 codes, 8KB ADC table fits in L1). Going to k=65536 (uint16) doubles ADC table to 16MB — L2 miss penalty hurts latency. Training data: Need N_train ≥ 40k per subcodebook (N_train ≥ 40k × m). For m=96: need 3.84M training vectors minimum. nlist: Target nlist ≈ sqrt(N) for balanced cells. N=200M → nlist=14142, round to 16384. nprobe: Start at nprobe = nlist / 64, tune for recall target.

Question 1 of 8

You are building a PQ index for 50M sentence embeddings of dimension d=768 with m=48 subvectors and k=256 centroids. Calculate: (A) compressed storage per vector, (B) ADC table size per query, and (C) recall trade-off if you reduce m to 12.

PQ storage arithmetic: Bytes/vector = m × ⌈log₂(k)⌉ / 8 = 48 × 8 / 8 = 48. The ADC table is rebuilt each query: m × k floats = 48 × 256 × 4B = 49KB. The m-vs-recall trade-off exists because smaller m means each subspace covers more dimensions with the same k centroids — the quantization error per subspace increases. The key insight: m and k are independent levers. Increasing k (256→512) adds 1 bit/subvector but costs 2× more codebook training and memory. Increasing m improves recall but increases stored codes linearly.
Question 2 of 8

In k-means codebook training for PQ, why does Lloyd's algorithm converge and what is the computational bottleneck when training on N=10M vectors with d=768, m=32, k=256?

Lloyd's convergence proof: Let D_t = Σᵢ min_j ‖xᵢ − cⱼ‖² be distortion at iteration t. Assignment step: for each x, choose nearest c → D_t+₁(assignment) ≤ D_t. Update step: replace c with mean of cluster → D_t+₁(update) ≤ D_t+₁(assignment). Therefore D decreases monotonically → converges. Not to global optimum (NP-hard problem), but k-means++ initialisation (choose initial centroids proportional to squared distance from existing ones) dramatically reduces final distortion.
Question 3 of 8

You run IVFPQ with nlist=8192 cells and nprobe=128 on a 500M vector dataset. Recall@10 is 82%. Your latency target is 10ms but current p99 is 35ms. Propose two independent changes and predict their effect on recall.

IVFPQ latency decomposition: total_time = coarse_lookup(O(nlist×d)) + ADC_per_cell × nprobe × avg_cell_size. With nlist=8192 and nprobe=128: scanning 128/8192 ≈ 1.6% × 500M = 8M vectors per query. Each takes m=32 lookups → 256M table reads. This is the bottleneck. Reducing nprobe halves it but reduces recall. GPU parallelises the ADC across all 8M candidates simultaneously. Option D is wrong: increasing nlist with fixed nprobe means probing proportionally more of the database, not less — worse recall/latency.
Question 4 of 8

Residual Quantization (RQ) is used in audio neural codecs (EnCodec, SoundStream). Why is RQ preferred over PQ for continuous audio waveform reconstruction, and what is the progressive compression property?

Progressive compression in RQ: This is why EnCodec (Meta) and SoundStream (Google) both use RQ. The key property: sending only code i₁ gives a rough approximation; each additional code iᵣ halves the residual error. This maps directly to variable-bitrate audio codecs where bandwidth determines how many RQ levels can be transmitted. AQLM (2024) applies this to LLM weights: residual quantize weight matrices to ~2 bits/param with R=2-4 levels, achieving better accuracy than GPTQ at the same bit rate by capturing cross-dimension structure PQ misses.
Question 5 of 8

OPQ learns rotation A via SVD of the matrix XCᵀ (data × reconstructed data). What does this SVD compute and why does it give the optimal rotation?

Orthogonal Procrustes: The problem 'find orthogonal A to maximise tr(AXĈᵀ)' has a clean closed-form solution via SVD. This is not PCA (which finds the rotation that aligns with maximum variance directions) but the Procrustes alignment (which finds the rotation that best aligns X with the target Ĉ). The key difference: PCA minimises reconstruction error for a given rank-k approximation; OPQ minimises quantization error for given m and k, which means making the variance distribution across subspaces as uniform as possible.
Question 6 of 8

ScaNN (Google, 2020) achieves better recall@10 than FAISS-IVFPQ at the same latency on the GloVe-100 benchmark. What algorithmic innovation enables this, and how does it relate to anisotropic quantization?

Anisotropic VQ: The standard PQ objective is ‖x − x̂‖² (isotropic — equal penalty in all directions). For MIPS retrieval, what matters is ⟨q,x⟩ for likely queries q. ScaNN's insight: the quantization error component in the query direction affects retrieval accuracy; the component orthogonal to all queries is harmless. So the objective becomes: minimise E_q[⟨q, x−x̂⟩²] = minimise (x−x̂)ᵀ Σ_q (x−x̂) where Σ_q is the query covariance. This gives directionally biased codebooks that concentrate precision in high-traffic query directions.
Question 7 of 8

AQLM (2024) applies Residual Quantization to LLM weight matrices at 2 bits/parameter. A LLaMA-2-7B layer has weight matrix W ∈ ℝ³²⁰⁰⁰ˣ⁴⁰⁹⁶. Calculate the storage for the 2-bit RQ codes (R=2, k=256) vs FP16, and explain why RQ outperforms GPTQ at 2 bits.

AQLM vector grouping: The key trick is treating groups of weights as vectors and encoding jointly. Scalar 2-bit (like GPTQ at extreme compression) gives 4 levels: [-3,-1,+1,+3] for each weight independently. Vector RQ-2bit with group size 8 and R=2, k=256 gives 256² = 65536 possible group representations — vastly more expressive than 4⁸ = 65536 scalar combinations, but with better geometric coverage. The improvement over GPTQ is not algorithmic complexity but representational power: RQ can represent inter-weight correlations that scalar codes cannot.
