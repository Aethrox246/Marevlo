01 · What the LLM Does With Retrieved Context

From Retrieval to Answer:
Four Generation Behaviors

Most RAG tutorials treat generation as trivial: pass documents, ask question, done. In practice, generation is where RAG systems most frequently fail. The LLM can ignore context, blend it with parametric knowledge, refuse to answer, or fabricate when context is silent. These four behaviors are predictable — and each has a targeted fix.

How LLMs process a RAG prompt — four behaviors

✓ Grounded generation (target)

LLM reads context, identifies relevant passage, paraphrases accurately, acknowledges incomplete context. Every claim traceable to a specific retrieved chunk.

⚠ Parametric bleed (common)

LLM mixes context with pretrained knowledge. Context says "30 days", LLM adds "which is standard SaaS practice" from training. Plausible-sounding but not grounded in your documents.

✗ Context ignorance (severe)

LLM ignores retrieved context and answers from parametric memory. Occurs when the question is familiar enough the LLM does not need to look, or when relevant context is buried in the middle of a long window.

✎ Fabrication (critical)

Context does not contain the answer but LLM generates one via pattern completion. "Since context mentions subscriptions, I assume there is a 14-day grace period." Zero factual basis.

💡

Why LLMs default to fabrication

RLHF-trained models are rewarded for producing helpful-sounding responses. This bias directly conflicts with grounded RAG: the model generates a complete answer even when context does not support one. Your prompt must explicitly override this with hard boundary and refusal instructions.

02 · Prompt Architecture

Five Components, Each With
a Specific Job

A RAG generation prompt has five distinct components. Omitting any causes predictable quality failures. Understanding each component lets you debug generation by identifying which component is missing.

Full annotated RAG prompt — all 5 components labeled

COMPONENT 1: Role + Task
You are a customer support assistant for Marevlo.
Answer questions using ONLY the provided documents.
Do not use any knowledge outside these documents.

COMPONENT 2: Grounding constraints
Rules:
- Cite every claim as [Doc N].
- If the answer is absent, say "I don't have that information in the provided documents."
- If documents conflict, present both versions.
- Do not speculate.

COMPONENT 3: Retrieved context (best-first)
[Doc 1] Annual subscriptions are non-refundable after the 30-day trial. Refunds within 30 days via support@marevlo.com.

[Doc 2] Enterprise customers have custom contract terms. Contact your account manager.

[Doc 3] Monthly subscriptions may be cancelled any time. No prorated refunds for partial months.

COMPONENT 4: User question (after context)
Question: Can I get a refund on my annual subscription after 45 days?

COMPONENT 5: Output format
Answer in 2-3 sentences. Cite documents as [Doc N].
✓

Expected grounded output

Annual subscriptions are non-refundable after the 30-day trial period [Doc 1]. Since 45 days is past this window, a refund is not available under the standard policy. If you are an enterprise customer, custom terms may apply — please contact your account manager [Doc 2].

03 · Context Ordering and Lost-in-the-Middle

Where You Place Context
Changes Whether the LLM Uses It

Liu et al. (2023) demonstrated that LLMs perform significantly worse when relevant information is in the middle of a long context window vs the beginning or end. Context ordering is not cosmetic — it directly affects answer quality.

Answer accuracy vs document position (10-document context window)

✓

Best: highest-relevance chunks first

Reranker rank #1 goes to context position 1. LLMs attend most strongly to early context. Do this automatically after reranking.

✗

Worst: metadata ordering

Never order by date, ID, or file name. If the answer ends at position 5 of 10, accuracy drops ~15-20% vs position 1.

How many chunks to pack

Linear cost: chunks × chunk_size × price/token
More chunks = longer prefill = more latency
Rule: 3-5 for Q&A, 7-10 for synthesis

04 · Grounding Instructions

Forcing the LLM to Stay
Within Retrieved Evidence

The single most impactful prompt change in RAG is adding explicit grounding constraints. Without them, the LLM treats context as a suggestion. These instructions must cover all three main grounding failure modes.

Instruction TypeTemplate PhraseFailure Prevented
Hard boundary"Answer ONLY using the documents below. Do not use any outside knowledge."Parametric bleed from training data
Explicit refusal"If the answer is not in the documents, say 'I don't have that information.'"Fabrication when context lacks the answer
Citation requirement"Cite every claim as [Doc N]."Makes hallucination detectable via missing citations
Uncertainty acknowledgment"If documents partially answer, give what you can and note what is missing."False completeness on incomplete context
Scope constraint"Do not speculate about scenarios not described in the documents."Extrapolation beyond partial context
Conflict resolution"If documents conflict, present both and note the conflict."Silent arbitrary choice between contradictory chunks
Positive instruction"If the answer is present, provide it directly. Do not refuse when the answer is there."Over-hedging despite clear context

Without grounding (dangerous)

Context: "Annual subs non-refundable after 30 days."
Q: Can I get a refund after 45 days?
"While policy says 30 days, many platforms make exceptions for medical emergencies. Try requesting a goodwill refund."

✗ "Medical emergencies", "goodwill refund" not in context. Pure fabrication.

With grounding (safe)

Use ONLY documents. If absent, say "I don't have that information."
Context: "Annual subs non-refundable after 30 days."
Q: Can I get a refund after 45 days?
"Annual subscriptions are non-refundable after 30 days [Doc 1]. Since 45 days is past this window, a refund is not available. For exceptions, I don't have that information in the provided documents."

✓ Every claim cited. Uncertainty stated. No fabrication.

05 · Hallucination Taxonomy

Four Types, Four Targeted Fixes:
Diagnose Before You Treat

Hallucination in RAG is classifiable because you have a ground truth: the retrieved documents. Different types need different fixes. Generic prompt engineering wastes time; targeted diagnosis is faster.

Type 1: Extrinsic Hallucination (most dangerous)
Query: "What is Marevlo's cancellation period?"
Context has 30-day non-refundable policy. No mention of cancellation period.
LLM outputs: "Marevlo's cancellation period is 14 days." (invented from nowhere)
Fix: Explicit refusal instruction + citation requirement. "14 days" claim has no [Doc N] — that absence is detectable.
Type 2: Intrinsic Hallucination (context infidelity)
Context: "Annual subscriptions non-refundable after 30 days."
LLM outputs: "Annual subscriptions non-refundable after 60 days." (number mutated)
Fix: "For specific numbers, dates, or policy terms, quote them exactly from the document." Paraphrase failure on key figures is surprisingly common.
Type 3: Parametric Bleed
Context: "Marevlo offers a 30-day trial."
LLM: "Marevlo offers a 30-day trial, which is standard for SaaS and required by EU consumer protection." (second sentence from training data)
Fix: Hard boundary instruction. RAGAS FaithfulnessScore post-processing: auto-check each output sentence against retrieved docs.
Type 4: Refusal Failure (over-hedging)
Context: "Refund requests must be submitted via support@marevlo.com."
LLM: "I don't have enough information to answer." (despite clear answer present)
Fix: Positive instruction: "If the answer is present in documents, provide it directly. Do not refuse when the answer is clearly there."
06 · Faithfulness vs Relevance

Two Orthogonal Quality Axes:
Each Points to a Different Fix

Faithfulness measures whether the LLM's answer is supported by retrieved documents. Relevance measures whether the retrieved documents contain what is needed to answer the question. They fail independently. Diagnosing which is broken tells you exactly what to fix.

The 2x2 failure matrix

HIGH FAITH + HIGH RELEVANCE

Target state. Achievable with good retrieval + grounding prompts.

HIGH FAITH + LOW RELEVANCE

LLM accurately reflects context but context doesn't address the question. Fix: improve retrieval, not prompt.

LOW FAITH + HIGH RELEVANCE

Context has the answer but LLM ignores it. Fix: stronger grounding instructions or few-shot examples.

LOW FAITH + LOW RELEVANCE

Both broken. Most dangerous. Requires end-to-end pipeline fix.

💡

Measure both with RAGAS

RAGAS Faithfulness: fraction of answer claims supported by retrieved context (LLM-judged NLI). Answer Relevancy: does the answer address the question (embedding cosine). Context Precision/Recall: retrieval quality. Run on 50-100 production queries. The axis that fails tells you exactly where to focus: low faithfulness = fix prompt; low relevance = fix retrieval.

07 · Production Prompt Templates

Four Patterns for Four
Different Task Types

Different RAG use cases require different prompt structures. Direct Q&A, multi-document synthesis, multi-hop reasoning, and conversational RAG each need distinct designs.

Template 1: Direct Q&A (most common)

You are a support assistant for {company}. Answer ONLY from the provided documents. If absent: "I don't have that information in the provided documents." Cite every claim as [Doc N]. {context_block} Question: {question} Answer (2-3 sentences, cite sources):

Template 2: Multi-document synthesis

You are an analyst. Synthesize from ALL provided documents to answer the question. - Draw from all relevant docs, not just the first. - If documents conflict, present both with citations. - Note what is missing if synthesis is incomplete. Documents: {context_block} Question: {question} Synthesis (with [Doc N] citations):

Template 3: Multi-hop reasoning

Use documents to answer step by step. Step 1: List sub-questions to answer first. Step 2: Find each sub-answer in documents with [Doc N]. Step 3: Combine into final answer. If any step cannot be completed, stop and note what is missing. Documents: {context_block} Question: {question} Reasoning:

Template 4: Conversational with history

You are a helpful assistant with reference documents. Answer ONLY from these documents. The current documents are authoritative. If they conflict with conversation history, trust the current documents. Documents: {context_block} History: {history} User: {question} Assistant:
08 · Production Code

LangChain RAG Chain With
Citations and Streaming

generation_pipeline.py

from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough
from langchain_anthropic import ChatAnthropic
from langchain.schema import Document
import hashlib, re

# ── Context formatting with deduplication ────────────────────
def format_context(docs: list) -> str:
    seen, unique = set(), []
    for doc in docs:
        h = hashlib.md5(doc.page_content.encode()).hexdigest()
        if h not in seen:
            seen.add(h); unique.append(doc)
    return "\n\n".join(
        f"[Doc {i+1}] (source: {d.metadata.get('source','unknown')})
{d.page_content}"
        for i, d in enumerate(unique))

# ── Grounded RAG prompt ───────────────────────────────────────
RAG_PROMPT = ChatPromptTemplate.from_messages([
    ("system", "You are a customer support assistant.\nAnswer ONLY using provided documents.\nCite every claim [Doc N].\nIf absent: I don't have that information."),
    ("human", "Documents:\n{context}\n\nQuestion: {question}\n\nAnswer:")
])

llm = ChatAnthropic(model="claude-sonnet-4-20250514", temperature=0)

# ── RAG chain ────────────────────────────────────────────────
def build_rag_chain(retriever):
    return (
        {"context": retriever | format_context,
         "question": RunnablePassthrough()}
        | RAG_PROMPT | llm | StrOutputParser()
    )

# ── Streaming ─────────────────────────────────────────────────
async def stream_rag(question: str, retriever):
    docs = await retriever.ainvoke(question)
    context = format_context(docs)
    async for chunk in llm.astream(
        RAG_PROMPT.format_messages(context=context, question=question)
    ):
        yield chunk.content

# ── Citation extraction (hallucination signal) ────────────────
def extract_citations(answer: str, docs: list) -> dict:
    cited = re.findall(r'\[Doc (\d+)\]', answer)
    return {
        "answer": answer,
        "cited_docs": [docs[int(n)-1] for n in cited if int(n) <= len(docs)],
        "uncited_claim_count": answer.count(".") - len(cited)
        # Positive value = potential hallucination sentences without citation
    }
09 · Assessment

Module 9 Quiz

1. Context: "Annual subs non-refundable after 30 days." LLM says: "Policy says 30 days, but many platforms make exceptions for medical emergencies — try requesting a goodwill refund." What hallucination type?

Correct. Parametric bleed: the LLM correctly uses context AND injects training-data knowledge. Fix: "Answer ONLY using documents below" plus citation requirement. The uncited "medical emergencies" clause would have no [Doc N], making the hallucination detectable in post-processing.

2. 10 retrieved docs. Most relevant was ranked #5 by your reranker. How do you order the context block?

Correct. Reranker output is the correct ordering for context packing. Position 1 = highest reranker score. This is free quality: no extra compute, no extra latency, just reorder your list. A document at position 5 of 10 will be attended to less than the same document at position 1.

3. RAGAS: Faithfulness=0.93, Answer Relevancy=0.42. Which component needs fixing?

Correct. These two RAGAS metrics are orthogonal signals. High faithfulness = generation is working. Low relevancy = retrieval is failing. Improving the prompt has zero effect when the retrieved context doesn't contain the answer. Fix retrieval first: check what documents your retriever is returning for failed queries, then improve the embedding model, add hybrid search, or use query transformation.

4. Multi-turn RAG: Turn 1 context says "30-day refund window." Turn 3 retrieves fresh docs saying "14-day refund window" (policy changed). What prevents confusion?

Correct. Multi-turn RAG has a staleness problem: stale retrieved context persists in conversation history. When new retrieval contradicts earlier context (policy change, different topic), the LLM gets conflicting signals. The "current documents are authoritative" instruction establishes a clear priority rule. Without it, the LLM may try to reconcile 30-day and 14-day policies and produce confused or averaged answers.

5. Your answer has 6 sentences but only 3 [Doc N] citations. What does this signal?

Correct. Required citations are a hallucination detection mechanism, not just UX. An uncited claim means the LLM could not point to supporting evidence — it is either hallucinated, blended from training data, or inferred by extrapolation. Build post-processing: count citation-to-sentence ratio. A high proportion of uncited sentences in high-stakes responses should trigger human review or automatic filtering.
