01 · The Best of Both Worlds Problem

BM25 and Dense Both Have
Fundamental Weaknesses

After studying BM25 (6A) and dense retrieval (6B), we know their failure modes precisely. BM25 fails on vocabulary mismatch: zero tokens shared = zero score. Dense retrieval fails on exact identifiers: it generalizes "GET /api/v2 404" to similar-meaning text, returning the wrong documents. Can we get both in one model?

BM25 representation of "annual refund"

A 30,000-word vocabulary vector where almost every entry is zero. Only the exact tokens present get non-zero weights (from IDF):

the:0is:0my:0 annual:0.441subscription:0 refund:0.441policy:0 cancel:0monthly:0...

~30,000 dimensions, ~2 non-zero. BM25 has no weight for "subscription" even though it is semantically related.

Dense representation of "annual refund"

A 768 or 1024-dimensional vector where almost every entry is non-zero. Semantically meaningful but not interpretable:

dim1:0.23 dim2:-0.41 dim3:0.87 ... dim768:0.12

768 non-zero values. Captures semantics but cannot use inverted index. Requires ANN search infrastructure.

📚

What learned sparse models do

Instead of using token counts (BM25) or a dense vector (bi-encoder), learned sparse models use a transformer to output a vocabulary-sized sparse vector where each non-zero dimension corresponds to a vocabulary token. The key difference from BM25: the weights are learned by the neural network, not computed from simple statistics. The network can assign weight to "subscription" even when the text only contains "refund" — because it learned that these concepts co-occur in relevant documents.

02 · SPLADE Architecture and Formula

Sparse Lexical and Expansion Model:
The Formula Derived

SPLADE (Sparse Lexical and Expansion Model, Formal et al. 2021) uses BERT's Masked Language Model (MLM) head to produce a vocabulary-sized output, then applies log-saturation and max-pooling to create an interpretable sparse vector that can be stored in an inverted index.

SPLADE Forward Pass

Input: "annual refund requests"
↓
BERT encoder: 12 layers, contextual token representations
↓
MLM head: linear layer (hidden_dim → vocab_size) + GELU activation
↓
Output: logit matrix (seq_len × vocab_size) — each token's "affinity" for every vocabulary word
↓
wj(d) = maxi∈tokens(d) log(1 + ReLU(MLMj(hi)))
wj(d) = weight assigned to vocabulary token j for document d — this is the learned "importance" of term j
MLMj(hi) = the MLM head's logit for vocabulary token j at input position i (a learned affinity score)
ReLU(x) = max(0, x) — enforces sparsity by zeroing negative logits
log(1 + x) = log-saturation, same as BM25's TF insight: diminishing returns
maxi = take the maximum across all input positions — if any token suggests vocabulary term j, use the highest signal

What SPLADE "Expands" to — Worked Example

Input document: "annual subscriptions are non-refundable after thirty days"

SPLADE sparse vector (only non-zero terms shown). Note how it expands to related vocabulary terms the document never contains:

annual:2.14 subscriptions:1.87 non-refundable:1.93 thirty:1.22 days:1.45 refund:1.68 policy:1.21 billing:0.95 cancel:0.88 payment:0.74
✓

Term expansion: the key advantage

SPLADE assigned non-zero weights to "refund", "policy", "billing", "cancel", and "payment" — none of which appear in the original document. The transformer learned that documents about non-refundable subscriptions are relevant to queries about refunds, policies, and billing. Now a BM25-style inverted index lookup on "refund" will find this document, even though it does not contain the word "refund".

03 · SPLADE vs SPLADE++

Training Improvements in
the SPLADE++ Family

SPLADE (original, 2021)

Trained with a FLOPS regularization term to encourage sparsity, plus standard InfoNCE contrastive loss. A FLOPS regularization penalizes the model for having too many non-zero entries — forcing it to learn which vocabulary expansions are actually useful vs noise.

L_total = L_contrastive + lambda x L_FLOPS

Problem: slow training and inconsistent sparsity levels across different documents and query types.

SPLADE++ (2022) — production recommended

Two key improvements: (1) Replaces FLOPS regularization with a simpler L1 regularization on the sparse vectors, giving more stable and predictable sparsity. (2) Uses knowledge distillation from a cross-encoder teacher, significantly improving retrieval quality without increasing model size.

L_total = L_distillation + lambda x L1(sparse_vec)

Distillation: train SPLADE to match the scores of a slow-but-accurate cross-encoder, without the cross-encoder's inference cost.

04 · BEIR Benchmark Comparison

BEIR (Benchmarking IR, Thakur et al. 2021) is the standard benchmark for retrieval systems. It contains 18 datasets spanning diverse domains: news, biomedical, finance, legal, and code. NDCG@10 (Normalized Discounted Cumulative Gain at rank 10) is the primary metric — higher is better, max is 1.0.

Three insights from these numbers

1. DPR is often worse than BM25 out-of-domain. DPR was trained on open-domain QA (Wikipedia). On biomedical (TREC-COVID) and financial (FiQA) datasets, BM25 significantly outperforms DPR. Domain gap is real.

2. SPLADE consistently beats BM25 across domains. The semantic expansion helps everywhere, and SPLADE maintains inverted-index speed, unlike dense models requiring ANN infrastructure.

3. Hybrid search nearly always wins. BM25+BGE fusion beats both alone on almost every dataset. The two methods capture complementary signals. This is why Module 7 exists.

06 · Production Code

SPLADE with HuggingFace
and Sparse Vector Storage

splade_retrieval.py

from transformers import AutoTokenizer, AutoModelForMaskedLM
import torch, numpy as np

# ── SPLADE++ efficient model (recommended for production) ─────
model_name = "naver/splade-v3"  # or "naver/splade-cocondenser-ensembledistil"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForMaskedLM.from_pretrained(model_name)
model.eval()

def splade_encode(text: str, model, tokenizer, max_len: int = 256) -> dict:
    # Tokenize
    inputs = tokenizer(
        text, return_tensors="pt", max_length=max_len,
        truncation=True, padding=True
    )
    with torch.no_grad():
        output = model(**inputs)

    # SPLADE formula: max over positions of log(1 + ReLU(logits))
    logits = output.logits               # (batch, seq_len, vocab_size)
    activated = torch.log(1 + torch.relu(logits))
    sparse_vec, _ = torch.max(activated, dim=1)  # max over sequence
    sparse_vec = sparse_vec.squeeze(0).cpu().numpy()

    # Convert to sparse format: {token: weight} for non-zero entries
    nonzero_indices = np.where(sparse_vec > 0)[0]
    sparse_dict = {
        tokenizer.convert_ids_to_tokens(int(i)): float(sparse_vec[i])
        for i in nonzero_indices
        if not tokenizer.convert_ids_to_tokens(int(i)).startswith("##")
    }
    return sparse_dict

# Encode a document
doc = "Annual subscriptions are non-refundable after the 30-day trial."
doc_sparse = splade_encode(doc, model, tokenizer)
print("Top expansions:", sorted(doc_sparse.items(), key=lambda x: -x[1])[:10])

# ── Qdrant sparse vector storage ──────────────────────────────
from qdrant_client import QdrantClient
from qdrant_client.models import (
    Distance, SparseVectorParams, SparseIndexParams,
    PointStruct, SparseVector
)

client = QdrantClient(":memory:")

# Create collection with sparse vector support
client.create_collection(
    collection_name="policy_splade",
    vectors_config={},                   # no dense vectors
    sparse_vectors_config={
        "text": SparseVectorParams(
            index=SparseIndexParams(on_disk=False)
        )
    }
)

# Store SPLADE vectors
corpus = [
    "Annual subscriptions are non-refundable after the 30-day trial.",
    "Monthly subscriptions may be cancelled at any time.",
    "Enterprise support handles annual contract refund disputes.",
]
for i, text in enumerate(corpus):
    sparse = splade_encode(text, model, tokenizer)
    # Convert to Qdrant sparse format: {indices: [...], values: [...]}
    vocab_ids = [tokenizer.convert_tokens_to_ids(t) for t in sparse.keys()]
    weights = list(sparse.values())
    client.upsert(collection_name="policy_splade", points=[
        PointStruct(id=i, vector={"text": SparseVector(indices=vocab_ids, values=weights)},
                    payload={"text": text})
    ])

# Query with SPLADE
query_sparse = splade_encode("refund on annual plan", model, tokenizer)
vocab_ids = [tokenizer.convert_tokens_to_ids(t) for t in query_sparse.keys()]
weights = list(query_sparse.values())
results = client.search(
    collection_name="policy_splade",
    query_vector=("text", SparseVector(indices=vocab_ids, values=weights)),
    limit=3
)
07 · Assessment

Module 6C Quiz

Final assessment covering SPLADE, benchmarks, and retrieval method selection.

1. Document: "annual subscriptions are non-refundable". SPLADE assigns weight 1.68 to the vocabulary token "refund" even though "refund" does not appear in the document. What mechanism produces this?

Correct. BERT's transformer layers create contextual representations where "non-refundable" activates patterns associated with refunds, payments, and billing. The MLM head then projects these representations to logits over the full vocabulary. "refund" gets a high logit because the pretraining objective trained BERT to understand that non-refundable text co-occurs with refund-related queries.

2. From the BEIR benchmark table, DPR scores 0.332 on TREC-COVID (biomedical) but BM25 scores 0.656. DPR was trained on 58,000 Wikipedia/web questions. What explains this gap?

Correct. Domain shift is the key failure mode for dense retrieval. DPR trained on NQ (Wikipedia facts) produced an embedding space calibrated for that domain. TREC-COVID asks about COVID-19 research in papers with very different language patterns. BM25 has no training and simply matches exact tokens — which works fine for specialized medical terminology that appears literally in the documents.

3. A startup is building a RAG system for their internal HR policy documents. They have no GPUs, a small corpus (5,000 documents), and need a working system deployed by next week. Which approach?

Correct. BM25 is the right pragmatic choice here. The constraints (no GPU, tight timeline, small corpus) all favor BM25. HR policy queries tend to be keyword-heavy ("parental leave policy", "PTO carryover rules") which BM25 handles well. Hybrid search or dense retrieval can be added in a second iteration once you have user feedback showing where BM25 fails.

4. SPLADE's ReLU(logit) operation in the formula enforces sparsity. What happens if you replace ReLU with a sigmoid activation?

Correct. ReLU(x) = max(0,x) is the key sparsity mechanism. It zeroes out negative logits, leaving non-zero weights only for vocabulary terms the transformer thinks are genuinely relevant. Sigmoid maps everything to (0,1) with no exact zeros. A 30,000-word vocabulary with no zeros requires 30,000 entries per document — destroying the inverted index structure that makes SPLADE fast.

5. You are designing retrieval for a medical RAG system serving both "MI" queries (abbreviation, needs dense) and "metformin 500mg dosage" queries (exact drug name, needs BM25). Your budget allows one retrieval system. Which do you choose?

Correct. This is SPLADE's sweet spot: a domain where queries mix exact identifiers (drug names, dosages) with semantic concepts (abbreviations, disease names). SPLADE assigns high weights to both the exact tokens present AND semantically related expansion terms. It is not as strong as hybrid BM25+BGE on overall quality, but for a single-model constraint it is the best choice here.
