Handwritten Document Recognition
HTR vs OCR · CTC Decoding · TrOCR · Line Segmentation · Field Validation · Dual-Model Forms

Handwritten text recognition (HTR) is a fundamentally harder problem than printed OCR — stroke variability between writers, connected cursive letterforms, overlapping ascenders and descenders, and historical document degradation all break the assumptions that printed OCR relies on. This module covers CTC (Connectionist Temporal Classification) as the alignment-free training objective for HTR, TrOCR as the current state-of-the-art architecture, line segmentation algorithms for handwritten text, confidence scoring for ambiguous strokes, field-level validation as the primary error-catching mechanism, and the dual-model architecture pattern for forms containing both printed labels and handwritten values.

01 · HTR vs Printed OCR — Key Differences

Why Handwriting Breaks
Every Assumption Printed OCR Makes

Printed OCR assumes uniform character spacing, consistent font metrics, horizontal text baselines, and character boundaries that can be detected from whitespace. Handwriting violates all four. HTR must handle variable inter-character spacing within words, letters that touch or merge, baselines that drift, and overlapping ascenders and descenders between adjacent lines. The pipeline architecture must account for these differences at every stage — pre-processing, segmentation, model architecture, and post-processing.

02 · CTC Decoding and TrOCR

Alignment-Free Training and
Transformer-Based Handwriting Recognition

htr_pipeline.py — CTC decoding and TrOCR inference

from transformers import TrOCRProcessor, VisionEncoderDecoderModel
from PIL import Image
import torch

def ctc_decode(logits: list[list[float]],
               vocab: list[str],
               blank_idx: int = 0) -> str:
    """
    CTC greedy decode: collapse consecutive duplicates, then remove blank tokens.
    logits: (time_steps, vocab_size) — output from CTC model
    Rule 1: take argmax at each time step.
    Rule 2: collapse consecutive identical non-blank tokens (handles alignment).
    Rule 3: remove blank tokens (handles frames with no character emission).
    Blanks are necessary because HTR maps a variable-length image frame sequence
    to a variable-length character sequence without frame-to-character alignment.
    """
    import numpy as np
    indices = [np.argmax(frame) for frame in logits]
    # Rule 2: collapse consecutive duplicates
    collapsed = [indices[0]] + [indices[i] for i in range(1,len(indices))
                                  if indices[i] != indices[i-1]]
    # Rule 3: remove blank tokens
    chars = [vocab[i] for i in collapsed if i != blank_idx]
    return "".join(chars)

def load_trocr(model_name: str = "microsoft/trocr-base-handwritten"):
    """
    Load TrOCR for handwritten text recognition.
    Architecture: ViT encoder (image patches) + RoBERTa decoder (autoregressive).
    The ViT encoder processes the line image as patches — no explicit character
    segmentation required. The decoder generates characters autoregressively
    conditioned on encoder output, handling connected cursive naturally.
    Model variants:
    - trocr-base-handwritten:  IAM benchmark, modern handwriting
    - trocr-large-handwritten: higher accuracy, slower
    - trocr-base-printed:      printed text — do NOT use for handwriting
    """
    processor = TrOCRProcessor.from_pretrained(model_name)
    model = VisionEncoderDecoderModel.from_pretrained(model_name)
    model.eval()
    return processor, model

def transcribe_line(line_image: Image.Image,
                    processor, model) -> dict:
    """
    Transcribe a single handwritten text line.
    Returns transcription with per-token confidence scores.
    line_image: PIL Image of a single text line crop, RGB.
    """
    pixel_values = processor(line_image, return_tensors="pt").pixel_values
    with torch.no_grad():
        outputs = model.generate(
            pixel_values,
            output_scores=True,
            return_dict_in_generate=True,
            max_new_tokens=128)
    transcription = processor.batch_decode(
        outputs.sequences, skip_special_tokens=True)[0]
    # Per-token confidence: softmax of each generation step score
    token_confs = [float(torch.softmax(s, dim=-1).max())
                   for s in outputs.scores] if outputs.scores else []
    mean_conf = sum(token_confs)/len(token_confs) if token_confs else None
    return {"text": transcription, "mean_confidence": round(mean_conf, 3)
            if mean_conf else None,
            "token_confidences": [round(c, 3) for c in token_confs]}
03 · Line Segmentation for Handwritten Text

Path-Based Segmentation for
Overlapping Ascenders and Descenders

line_segmentation.py — projection profile and path-based segmentation

import numpy as np
import cv2

def projection_profile_segment(binary: np.ndarray,
                                 min_gap_px: int = 5) -> list[tuple[int,int]]:
    """
    Horizontal projection profile segmentation.
    Works for printed text and handwriting with clear inter-line gaps.
    Fails when ascenders/descenders fill the inter-line whitespace.
    """
    hp = binary.sum(axis=1)
    in_line, start, lines = False, 0, []
    for i, v in enumerate(hp):
        if v > 0 and not in_line: start = i; in_line = True
        elif v == 0 and in_line and i-start >= min_gap_px:
            lines.append((start, i)); in_line = False
    if in_line: lines.append((start, len(hp)))
    return lines

def path_based_segment(binary: np.ndarray,
                        n_lines_estimate: int,
                        smoothing: int = 5) -> list[tuple[int,int]]:
    """
    Path-based (seam) line segmentation for overlapping handwritten lines.
    Finds minimum-cost paths through the inter-line regions by treating
    the binary image as a cost map: foreground pixels have high cost,
    background pixels have zero cost.
    n_lines_estimate: approximate number of text lines (from projection profile
    or layout analysis). Used to seed path starting positions.
    Returns list of (y_start, y_end) tuples for each detected line.
    """
    h, w = binary.shape
    cost = binary.astype(np.float32)  # foreground = high cost
    cost = cv2.GaussianBlur(cost, (0,0), smoothing)

    hp = binary.sum(axis=1).astype(float)
    hp_smooth = np.convolve(hp, np.ones(smoothing)/5, mode="same")

    # Find valley positions between lines using smoothed profile
    from scipy.signal import find_peaks
    valleys, _ = find_peaks(-hp_smooth,
                             distance=h//(n_lines_estimate+1),
                             prominence=hp_smooth.max()*0.1)
    cuts = [0] + sorted(valleys.tolist()) + [h]
    return [(cuts[i], cuts[i+1]) for i in range(len(cuts)-1)]
04 · Field-Level Validation and Dual-Model Forms Pipeline

Catching HTR Errors With Format Rules
Before Routing to Human Review

htr_forms_pipeline.py — validation and dual-model routing

import re
from dataclasses import dataclass
from enum import Enum

class RegionType(Enum):
    PRINTED  = "printed"
    HANDWRITTEN = "handwritten"

def classify_region_type(region_image: np.ndarray) -> RegionType:
    """
    Distinguish printed from handwritten regions by ink density variance.
    Printed text: uniform ink density (low variance in horizontal runs).
    Handwritten text: variable ink density, irregular stroke width.
    Uses the ratio of horizontal run-length variance to mean as the signal.
    """
    grey = cv2.cvtColor(region_image, cv2.COLOR_BGR2GRAY)
    _, binary = cv2.threshold(grey, 0, 255, cv2.THRESH_BINARY_INV+cv2.THRESH_OTSU)
    row_sums = binary.sum(axis=1).astype(float)
    variance_ratio = row_sums.std() / (row_sums.mean() + 1e-6)
    return RegionType.HANDWRITTEN if variance_ratio > 0.6 else RegionType.PRINTED

FIELD_VALIDATORS = {
    "date":       re.compile(r"\d{1,2}[/\-\.]\d{1,2}[/\-\.]\d{2,4}"),
    "amount":     re.compile(r"\d{1,12}[\.,]\d{2}"),
    "invoice_no": re.compile(r"[A-Z0-9\-]{4,20}"),
}

def validate_field(field_name: str, value: str) -> dict:
    """Validate extracted field value against expected format."""
    validator = FIELD_VALIDATORS.get(field_name)
    if not validator: return {"valid":True, "reason":"No validator defined"}
    valid = bool(validator.search(value))
    return {"valid":valid, "value":value,
            "reason":"Format valid" if valid else f"Failed {field_name} format check"}

def process_form_region(region_image: np.ndarray,
                          field_name: str,
                          trocr_proc, trocr_model,
                          tesseract_lang: str = "eng") -> dict:
    """
    Dual-model routing: Tesseract for printed regions, TrOCR for handwritten.
    Apply format validation after extraction. Flag low-confidence or invalid
    fields for targeted human review (show only the field crop, not full document).
    """
    rtype = classify_region_type(region_image)
    if rtype == RegionType.PRINTED:
        import pytesseract
        value = pytesseract.image_to_string(
            region_image, lang=tesseract_lang, config="--psm 7").strip()
        conf = None; engine = "tesseract"
    else:
        pil = Image.fromarray(cv2.cvtColor(region_image, cv2.COLOR_BGR2RGB))
        result = transcribe_line(pil, trocr_proc, trocr_model)
        value = result["text"]; conf = result["mean_confidence"]; engine = "trocr"
    validation = validate_field(field_name, value)
    needs_review = not validation["valid"] or (conf is not None and conf < 0.6)
    return {"field":field_name, "value":value, "engine":engine,
            "confidence":conf, "valid":validation["valid"],
            "needs_review":needs_review, "region_type":rtype.value}
05 · Assessment

Module 10 Quiz

1. Your HTR model achieves CER=0.08 on the IAM handwriting test set but CER=0.31 on your historical medical records dataset from the 1920s. What are the two primary causes and the most cost-effective fix?

Correct. Historical writing style drift and document degradation are the two independent causes that compound to produce the large CER gap. Domain-specific fine-tuning on 200-500 transcribed lines addresses both simultaneously — it exposes the model to historical letterforms in the degraded image conditions it will encounter in production. Pre-processing improvements alone address only the second cause and are insufficient for a 23-point CER gap.

2. A CTC-based HTR model outputs the sequence "T-T--h-e--- --d-o-g-" (where - represents blank tokens). What is the decoded output, and why does CTC need blank tokens?

Correct. CTC decoding always applies both rules in order: collapse consecutive identical non-blank tokens, then remove all blank tokens. Blank tokens are essential for alignment — they absorb frames that do not correspond to character emissions, solving the fundamental problem that handwriting recognition must map a variable-length image sequence to a variable-length character sequence without explicit frame-to-character alignment supervision.

3. You are using TrOCR for handwritten form field recognition. A field containing "3/4/2024" is transcribed as "3/L/2024". The confidence score for the second token is 0.41. What should the pipeline do with this extraction?

Correct. Field-level validation (format and range checks) is the first line of defence against HTR errors, independent of confidence scores. Targeted field-level human review is more efficient than document-level review because it presents the annotator with only the ambiguous region, reducing review time from minutes per document to seconds per field.

4. Line segmentation for HTR fails on a handwritten letter where some lines have ascenders from one line overlapping descenders from the line above. What causes the segmentation failure, and what is the correct algorithm?

Correct. Projection profiles require zero-pixel-density valleys between lines. When ascenders and descenders overlap, these valleys disappear and projection profile segmentation merges adjacent lines. Path-based segmentation solves this by finding a minimum-cost path through the inter-line region rather than looking for a zero-density row.

5. You are building an HTR pipeline for handwritten medical forms. The forms contain both printed labels (field names) and handwritten values. Your TrOCR model trained on handwriting consistently hallucdinates on the printed labels. What is the correct architecture decision?

Correct. Separate specialised models for printed and handwritten regions is the correct architecture. Layout detection already provides the routing mechanism — extending the region taxonomy to distinguish print from handwriting adds one classification step that enables optimal OCR per region type. A single unified model always trades off accuracy for one type against the other.
