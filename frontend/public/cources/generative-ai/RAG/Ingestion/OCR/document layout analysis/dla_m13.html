Contract and Legal Document Analysis
Clause Segmentation · Obligation Extraction · Alias Resolution · Risk Classification · CUAD

Legal contracts are among the most structurally complex documents a pipeline must process — hierarchical clause numbering, defined terms that create aliases used throughout, obligation language that spans multiple grammatical forms, and risk classification that depends on who bears the obligation and under what conditions. This module covers legal document structure segmentation by numbered clause detection, obligation extraction with modal and passive patterns, party and defined-term alias resolution, contract risk classification beyond keyword matching, and the dataset shift patterns that cause NDA-trained extractors to fail on service agreements.

01 · Legal Document Structure

Numbered Clause Detection as
the Primary Structural Signal

Legal contracts have a predictable hierarchical structure: numbered clauses at multiple levels (1, 1.1, 1.1.1), defined terms introduced in parentheses, schedules and annexures appended after the main body, and signature blocks at the end. Unlike academic papers where font size signals heading level, legal documents use numbering patterns as the primary structural signal — and many legal contracts use bold at body font size for clause headings.

legal_structure.py — clause segmentation and defined-term extraction

import re
from dataclasses import dataclass, field

CLAUSE_PATTERN = re.compile(
    rr"^(\d+(?:\.\d+)*)\s+([A-Z][^
]{5,100})", re.MULTILINE)
DEFINITION_PATTERN = re.compile(
    rr"([A-Z][a-zA-Z\s]+?)\s*\(\s*["']?the\s+([A-Z][a-zA-Z\s]+?)["']?\s*\)")

@dataclass
class Clause:
    number: str; heading: str; text: str
    level: int = 1; children: list = field(default_factory=list)

def extract_clauses(text: str) -> list[Clause]:
    """
    Segment contract text into numbered clauses.
    Uses numbering pattern as primary signal — more reliable than font size
    for legal documents where headings often use bold at body font size.
    Clause level inferred from depth of numbering: "8" = level 1,
    "8.3" = level 2, "8.3.1" = level 3.
    """
    matches = list(CLAUSE_PATTERN.finditer(text))
    clauses = []
    for i, m in enumerate(matches):
        start = m.start()
        end   = matches[i+1].start() if i+1 < len(matches) else len(text)
        num   = m.group(1)
        clauses.append(Clause(
            number  = num,
            heading = m.group(2).strip(),
            text    = text[start:end].strip(),
            level   = num.count(".") + 1))
    return clauses

def extract_party_aliases(text: str) -> dict[str,str]:
    """
    Extract defined-term alias map from contract parties clause.
    Pattern: "ACME Ltd (the Supplier)" -> {"Supplier": "ACME Ltd"}
    Applied at extraction time (not source text modification) to
    preserve bounding box alignment with the original document.
    """
    aliases = {}
    for m in DEFINITION_PATTERN.finditer(text):
        canonical = m.group(1).strip()
        alias     = m.group(2).strip()
        aliases[alias] = canonical
    return aliases
02 · Obligation Extraction

Modal Verbs, Passive Constructions,
and Nominalisations

obligation_extractor.py

import spacy
from dataclasses import dataclass

OBLIGATION_PATTERNS = [
    r"shall", r"must", r"will",
    r"is required to", r"is obliged to",
    r"has an obligation to", r"undertakes to",
    r"agrees to", r"is required",
]

@dataclass
class Obligation:
    clause_number: str
    obligor: str         # who bears the obligation
    obligation: str      # the obligation text
    deadline: str        # temporal constraint if present
    alias_resolved: bool # was obligor resolved via alias map?

def extract_obligations(clause: object,
                          alias_map: dict[str,str],
                          nlp) -> list[Obligation]:
    """
    Extract obligation sentences from a clause.
    Covers modal verbs ("shall"), passive constructions ("is required"),
    and nominalisations ("undertakes to").
    Resolves obligor via alias_map (e.g. "Supplier" -> "ACME Ltd").
    """
    import re
    combined = "|".join(OBLIGATION_PATTERNS)
    obligation_re = re.compile(combined, re.IGNORECASE)
    doc = nlp(clause.text)
    obligations = []
    for sent in doc.sents:
        if not obligation_re.search(sent.text): continue
        # Extract obligor from dependency parse (nsubj of root verb)
        root = [t for t in sent if t.dep_ == "ROOT"]
        subj = [t for t in sent if t.dep_ in ("nsubj","nsubjpass")]
        obligor_raw = subj[0].text if subj else "Unknown"
        obligor_res = alias_map.get(obligor_raw, obligor_raw)
        # Extract temporal constraint (cardinal + time noun)
        deadline = ""
        for ent in sent.ents:
            if ent.label_ in ("DATE","TIME"): deadline = ent.text; break
        obligations.append(Obligation(
            clause_number  = clause.number,
            obligor        = obligor_res,
            obligation     = sent.text.strip(),
            deadline       = deadline,
            alias_resolved = obligor_res != obligor_raw))
    return obligations
03 · Contract Risk Classification

Structural Risk: Obligor, Scope, Cap —
Not Just Keyword Presence

risk_classifier.py

import re
from enum import Enum

class RiskLevel(Enum):
    LOW = "low"; MEDIUM = "medium"; HIGH = "high"

MUTUAL_MARKERS  = re.compile(rr"(each party|both parties|mutually|reciprocal)", re.I)
LIABILITY_CAP   = re.compile(rr"(capped?|limited? to|not exceed|maximum of)", re.I)
UNLIMITED_MARKER = re.compile(rr"(unlimited|without limit|no cap)", re.I)
INDEMNITY_VERBS = re.compile(rr"(indemnif|hold harmless|defend)", re.I)

def classify_indemnity_risk(clause_text: str, our_role: str) -> dict:
    """
    Classify indemnity clause risk by structural analysis:
    1. Is it mutual (each party indemnifies the other)?
    2. Is the obligation on our party or the counterparty?
    3. Is there a liability cap in or near the clause?
    keyword-only approach has 60%+ false positive rate on mutual indemnities.
    """
    if not INDEMNITY_VERBS.search(clause_text):
        return {"risk": RiskLevel.LOW, "reason": "No indemnity language"}
    is_mutual   = bool(MUTUAL_MARKERS.search(clause_text))
    has_cap     = bool(LIABILITY_CAP.search(clause_text))
    is_unlimited = bool(UNLIMITED_MARKER.search(clause_text))
    if is_mutual and has_cap:
        return {"risk": RiskLevel.LOW, "reason": "Mutual, capped"}
    if is_mutual:
        return {"risk": RiskLevel.MEDIUM, "reason": "Mutual, no cap"}
    if has_cap and not is_unlimited:
        return {"risk": RiskLevel.MEDIUM, "reason": "Unilateral, capped"}
    return {"risk": RiskLevel.HIGH,
            "reason": "Unilateral indemnity, no liability cap detected"}
04 · Assessment

Module 13 Quiz

1. extract_clauses() segments a 40-page contract into clauses using heading detection. It misses "8.3 Limitation of Liability" because the heading uses bold but no increase in font size. What is the root cause and fix?

Correct. Numbered clause patterns (8.3, 8.3.1) are the strongest heading signal in legal contracts — more reliable than font size because legal documents frequently use bold at body font size for section headings. The numbering regex plus length check catches virtually all legal clause headings regardless of font size variation.

2. extract_obligations() uses dependency parsing to find obligation sentences ("shall", "must", "will"). It extracts "The Supplier shall deliver the goods within 30 days of the Order Date" but misses "Delivery of goods is required within 30 days." What is wrong?

Correct. Modal verb matching ("shall", "must") captures the most explicit legal obligations but misses passive and nominalised forms that are equally binding in contract law. A comprehensive obligation detector must cover the full legal obligation vocabulary. Fine-tuning on CUAD or ContractNLI is the most robust approach for production legal extraction systems.

3. extract_parties() identifies parties from the contract header. It finds "ACME Ltd" and "Beta Corp" from "This agreement is between ACME Ltd (the Supplier) and Beta Corp (the Customer)." Later clauses use "Supplier" and "Customer" as pronouns. How should the pipeline resolve these references?

Correct. Parenthetical definition parsing is the correct approach for legal defined-term resolution — it is deterministic, interpretable, and does not require a coreference model. The alias map is extracted from a predictable pattern in contract header sections and applies throughout the document. Modifying source text is avoided to preserve bounding box alignment for audit rendering.

4. Your contract risk flagger marks every clause containing "indemnify" as HIGH risk. The legal team reports 60% of these are standard mutual indemnity clauses that are acceptable. What is wrong with the approach?

Correct. Legal risk classification requires structural analysis of who bears the obligation and what limits apply — not just keyword presence. A 60% false positive rate on a risk flag means the legal team ignores the flag entirely, defeating its purpose. Obligor/obligee extraction and mutual vs unilateral classification are the two structural features that most reduce false positives.

5. Your contract extraction pipeline is tested on 200 NDA agreements and achieves F1=0.91 for key date extraction. The team deploys it on service agreements and F1 drops to 0.63. What are the two root causes?

Correct. Date type distribution shift and clause structure mismatch are the two independent causes that compound to produce the large F1 gap. Both require domain-specific annotated examples — there is no hyperparameter tuning that compensates for training on the wrong document genre. Per-date-type F1 analysis is the diagnostic tool that confirms which categories drive the gap before investing in annotation.
