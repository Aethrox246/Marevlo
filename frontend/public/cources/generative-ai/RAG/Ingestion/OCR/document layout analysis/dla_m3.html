Reading Order and Document Hierarchy
Column-First vs Row-First · Full-Width Interleaving · Section Tree · Cross-References

Physical layout analysis tells you where regions are. Reading order and document hierarchy tell you how they connect. This module covers the full reading order problem — column-first vs row-first strategies, full-width region interleaving, the stack-based section hierarchy algorithm, font-size rank for heading level assignment, and cross-reference resolution linking "Table 3" references to actual table regions. These algorithms transform a flat list of detected regions into a structured document tree ready for information extraction.

01 · Reading Order Strategies

Column-First vs Row-First:
Choosing the Right Strategy Per Document

Reading order is not a single algorithm — it is a family of strategies indexed by document layout type. Academic papers with independent columns need column-first. Forms and tables where content flows across columns row by row need row-first. Documents with both layout types need strategy detection before ordering. Getting this wrong produces text that jumps between columns mid-sentence.

reading_order_v2.py — strategy detection and dual-mode ordering

from dataclasses import dataclass

@dataclass
class Region:
    id: int; x1: float; y1: float; x2: float; y2: float; type: str
    @property
    def cx(self): return (self.x1+self.x2)/2

def detect_layout_strategy(regions: list, page_width: float) -> str:
    """
    Detect reading order strategy from column region y-extent overlap.
    If column regions have heavily overlapping y-extents across columns:
    -> row-first (content flows across columns at the same vertical level)
    If column regions have non-overlapping y-extents:
    -> column-first (each column is an independent text flow)
    """
    full = [r for r in regions if (r.x2-r.x1)/page_width > 0.6]
    cols_r = [r for r in regions if r not in full]
    if not cols_r: return "column_first"
    xs = sorted({r.cx for r in cols_r})
    if len(xs) < 2: return "column_first"
    mid = (xs[0] + xs[-1]) / 2
    left = [r for r in cols_r if r.cx < mid]
    right = [r for r in cols_r if r.cx >= mid]
    if not left or not right: return "column_first"
    left_ys  = {(r.y1, r.y2) for r in left}
    right_ys = {(r.y1, r.y2) for r in right}
    overlaps = 0
    for ly1,ly2 in left_ys:
        for ry1,ry2 in right_ys:
            if min(ly2,ry2) > max(ly1,ry1): overlaps += 1
    overlap_rate = overlaps / (len(left_ys)*len(right_ys))
    return "row_first" if overlap_rate > 0.5 else "column_first"

def reading_order(regions: list, page_width: float) -> list[int]:
    """
    Adaptive reading order: detect strategy then apply it.
    Full-width regions (title, abstract, wide figures) are interleaved
    at their y-position regardless of strategy.
    """
    strategy = detect_layout_strategy(regions, page_width)
    full = sorted([r for r in regions if (r.x2-r.x1)/page_width > 0.6],
                   key=lambda r: r.y1)
    cols_r = [r for r in regions if r not in full]

    if strategy == "row_first":
        ordered = sorted(cols_r, key=lambda r: (r.y1, r.cx))
    else:  # column_first
        mid = (min(r.cx for r in cols_r) + max(r.cx for r in cols_r)) / 2 if cols_r else 0
        left  = sorted([r for r in cols_r if r.cx < mid], key=lambda r: r.y1)
        right = sorted([r for r in cols_r if r.cx >= mid], key=lambda r: r.y1)
        ordered = left + right

    result, fi, used_ids = [], 0, {r.id for r in ordered}
    for region in ordered:
        while fi < len(full) and full[fi].y1 < region.y1:
            result.append(full[fi].id); fi += 1
        result.append(region.id)
    result.extend(r.id for r in full[fi:])
    return result
02 · Section Hierarchy Construction

Stack-Based Tree Building From
Ordered Headings

section_hierarchy.py

from dataclasses import dataclass, field

@dataclass
class SectionNode:
    heading: str; level: int; region_id: int
    children: list = field(default_factory=list)

def heading_level(font_size: float, all_font_sizes: list[float]) -> int:
    """
    Assign heading level by font size rank.
    Largest font = level 1 (h1), next = level 2, etc.
    Requires pre-filtering to heading-only regions (see note below).
    """
    unique = sorted(set(all_font_sizes), reverse=True)
    return unique.index(font_size) + 1

def build_section_hierarchy(regions_in_order: list, heading_regions: set) -> SectionNode:
    """
    Build document section tree using a stack.
    heading_regions: set of region IDs classified as headings by layout model.
    Each heading pops the stack back to its parent level, then pushes itself.
    Body text attaches to the current top-of-stack section.
    """
    root = SectionNode("Document", 0, -1)
    stack = [root]
    heading_font_sizes = [r["font_size"] for r in regions_in_order
                          if r["id"] in heading_regions]
    for region in regions_in_order:
        if region["id"] in heading_regions:
            level = heading_level(region["font_size"], heading_font_sizes)
            while len(stack) > 1 and stack[-1].level >= level:
                stack.pop()
            node = SectionNode(region["text"], level, region["id"])
            stack[-1].children.append(node)
            stack.append(node)
        else:
            stack[-1].children.append({"type":region["type"],"id":region["id"]})
    return root
03 · Cross-Reference Resolution

Linking "Table 3" References
to Physical Region IDs

cross_references.py

import re

def cross_reference_table(paragraph_text: str,
                            table_captions: dict,
                            caption_to_table: dict,
                            table_regions_in_order: list) -> int | None:
    """
    Resolve a "Table N" reference in paragraph text to a table region_id.

    table_captions: {caption_id: caption_ocr_text}
    caption_to_table: {caption_id: table_region_id}  (from caption_figure_association)
    table_regions_in_order: list of table region IDs in reading order (fallback)

    Dependency chain:
    1. caption_figure_association must have correctly linked caption to table
    2. OCR on caption region must have correctly read the table number
    If either fails: fall back to ordinal position.
    """
    match = re.search(r"[Tt]able\s*(\d+)", paragraph_text)
    if not match: return None
    table_num = int(match.group(1))

    # Primary: search caption OCR text for matching table number
    for cap_id, cap_text in table_captions.items():
        if re.search(rf"[Tt]able\s*{table_num}", cap_text):
            table_id = caption_to_table.get(cap_id)
            if table_id is not None: return table_id

    # Fallback: ordinal position in reading order
    idx = table_num - 1
    if 0 <= idx < len(table_regions_in_order):
        return table_regions_in_order[idx]
    return None

def resolve_all_references(document_tree: dict,
                             table_captions: dict,
                             caption_to_table: dict,
                             table_regions_in_order: list) -> dict:
    """
    Walk the document tree and resolve all table/figure cross-references.
    Returns a dict mapping (paragraph_id, ref_text) -> region_id.
    """
    refs = {}
    def walk(node):
        if isinstance(node, dict) and node.get("type") == "paragraph":
            text = node.get("text", "")
            linked = cross_reference_table(text, table_captions,
                                              caption_to_table, table_regions_in_order)
            if linked is not None:
                refs[(node["id"], text[:40])] = linked
        for child in node.get("children", []):
            walk(child)
    walk(document_tree)
    return refs
04 · Full Document Tree Pipeline

From Regions to Structured JSON
Document Representation

document_tree.py — end-to-end pipeline

def build_document_tree(layout_regions: list,
                          page_width: float,
                          ocr_results: dict,
                          font_sizes: dict) -> dict:
    """
    Full pipeline: layout regions + OCR + font metadata -> document tree.

    layout_regions: list of {id, bbox, type, score}
    ocr_results:    {region_id: text}
    font_sizes:     {region_id: float}  (estimated from bbox height or PDF metadata)

    Pipeline:
    1. Classify heading regions from font size threshold
    2. Compute reading order
    3. Build section hierarchy
    4. Resolve caption-figure associations
    5. Resolve cross-references
    6. Return structured document JSON
    """
    # 1. Identify heading candidates
    heading_types = {"title"}  # from layout model
    heading_ids = {r["id"] for r in layout_regions
                   if r["type"] in heading_types}

    # 2. Reading order
    regions_obj = [Region(r["id"],*r["bbox"],r["type"]) for r in layout_regions]
    ordered_ids = reading_order(regions_obj, page_width)
    id_to_region = {r["id"]: r for r in layout_regions}
    ordered_regions = [{**id_to_region[i],
                        "text": ocr_results.get(i,""),
                        "font_size": font_sizes.get(i,12.0)}
                       for i in ordered_ids if i in id_to_region]

    # 3. Section hierarchy
    tree = build_section_hierarchy(ordered_regions, heading_ids)

    # 4. Caption-figure associations
    cap_to_fig = caption_figure_association(regions_obj)
    table_caps = {r["id"]: ocr_results.get(r["id"],"")
                  for r in layout_regions if r["type"] == "caption"}
    table_order = [r["id"] for i in ordered_ids
                   if id_to_region.get(i,{}).get("type")=="table"
                   for r in [id_to_region[i]]]

    # 5. Cross-references (returns dict, not stored in tree here)
    refs = resolve_all_references(tree.__dict__, table_caps, cap_to_fig, table_order)
    return {"tree": tree, "cross_refs": refs, "reading_order": ordered_ids}
05 · Assessment

Module 3 Quiz

1. Reading order output: [title, col1_p1, col1_p2, col2_p1, col2_p2, abstract]. Correct order: [title, abstract, col1_p1, col2_p1, col1_p2, col2_p2]. What two errors?

Correct. Both errors expose distinct algorithmic gaps: full-width interleaving must compare y-positions before column traversal begins; column-first vs row-first must be selected based on column y-extent overlap analysis.

2. build_section_hierarchy() processes headings at font sizes [18pt, 14pt, 12pt, 12pt, 18pt]. What tree is produced?

Correct. Font-size ranking correctly builds the tree in this case. The failure mode — 12pt captions assigned heading status — is the most common section hierarchy bug in production. Pre-filtering with multiple signals before font-size ranking is the correct fix.

3. cross_reference_table() links "Table 3" in paragraph text to one of two Table regions. How does it determine which region is Table 3?

Correct. Cross-reference depends on the caption-table association chain, which has two independent failure points. The ordinal fallback is the correct robustness strategy when caption OCR confidence is low.

4. Two consecutive 14pt headings are incorrectly placed as parent-child instead of siblings. Font size alone cannot distinguish them. What is the strongest disambiguation signal?

Correct. Numbering prefix depth is the most reliable signal because it is explicitly encoded in the document. Font-size-based ranking cannot handle same-size multi-level headings. Treating same-size unnumbered headings as siblings is the correct default heuristic that fails least often.

5. section_from_layout() is run on a 10-page document. Pages 3-5 have no heading regions — only body text. What does the hierarchy tree look like for pages 3-5 content?

Correct. The stack-based hierarchy builder correctly extends the last active section across pages with no headings. The only edge case is documents with no headings at all — these require a synthetic root section or direct document-root attachment for all body text to avoid orphaned nodes.
