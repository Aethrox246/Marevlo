01 · Architecture Synthesis

Modular vs Unified: Choosing the
Right Architecture for Multi-Document Systems

The most important architectural decision in a document intelligence system is not which model to use — it is whether to build a unified model that handles all document types or a modular pipeline that routes each type to a specialised processor. This decision determines extraction accuracy, system maintainability, failure isolation, and the cost of adding a new document type. The answer depends on how different the document types are from each other across five dimensions: OCR requirements, layout structure, entity vocabulary, extraction schema, and validation logic.

Decision factorFavour unified modelFavour modular pipeline
Document type similarityHigh — same layout, similar vocabularyLow — different OCR engines, entity types, schemas
Training data availabilityLarge diverse dataset for multitask trainingDomain-specific datasets per type
Failure isolation requirementLow — any failure affects all types equallyHigh — invoice degradation must not affect contract extraction
Update cadenceInfrequent — retrain entire model for any changeFrequent — update only the affected type component
Latency requirementSingle model forward passMulti-stage pipeline — may need parallel execution
02 · Systematic F1 Drift Investigation

Five-Step Diagnosis Before
Any Retraining Decision

Investigation order for unexplained F1 drift

Step 1: Input distribution — plot document type, vendor, scan quality distribution by week. New vendor = likely cause. Check DynamoDB job records.
Step 2: Per-stage decomposition — measure layout AP, OCR CER, and extraction F1 independently on a 200-document sample. Isolates whether degradation is in layout, OCR, or extraction.
Step 3: Failure example analysis — manually inspect 50 high-human-review documents. Look for systematic patterns: same vendor, same field, same scan quality tier.
Step 4: Monitor audit — verify that the rolling validation F1 monitor (M8) triggered an alert. If not, the sampling window or threshold is misconfigured.
Step 5: Targeted remediation — annotate 200-300 examples from the identified failure mode. Fine-tune, not full retrain. Expected recovery: 0.87-0.90 F1.
03 · Assessment

Capstone Quiz

1. You are building a document intelligence system for an insurance company. Documents include: handwritten claims forms (HTR), printed policy documents (OCR), scanned invoices (layout + extraction), and medical records (clinical NER + HIPAA). All must be processed within 60 seconds. The CEO asks for a single unified model. What do you recommend and why?

Correct. The modular architecture is the correct production answer for a multi-document-type system. Each document type has unique requirements at the OCR, layout, extraction, and validation layers that specialised models handle better than a unified model. The classifier routes each document type to its appropriate pipeline — the modularity is the feature, not the limitation.

2. Six months after deployment, F1 on invoice extraction drops from 0.91 to 0.74. Human review rate rises from 8% to 22%. No code changes were made. Describe the complete investigation and remediation process.

Correct. The five-step investigation (distribution analysis, per-stage decomposition, failure example sampling, monitor verification, targeted fine-tuning) is the correct production response to unexplained F1 drift. Retraining without investigation risks fixing the wrong problem. The 22% human review rate combined with 0.74 F1 is consistent with a specific new document type or scan quality tier — targeted data collection and fine-tuning is more efficient than full retraining.

3. A GDPR audit finds that 0.3% of redacted documents still contain names in the OCR JSON checkpoint stored in S3. The image redaction is correct. What went wrong and what is the complete fix?

Correct. Artefact-complete redaction requires covering all pipeline stages, not just the final output. The race condition between extraction and checkpoint deletion is the systemic cause. Moving redaction earlier in the pipeline (before extraction writes) and implementing automatic checkpoint expiry are the two architectural fixes that prevent recurrence.

4. You must build a contract obligation tracker that monitors 50,000 active contracts for upcoming deadline obligations in real time. Each contract has 10-200 obligations with dates. How do you architect this?

Correct. The two-tier architecture (extract once, query continuously) is the correct pattern for a contract monitoring system. Re-extracting all 50k contracts daily wastes compute on contracts whose obligations have not changed. DynamoDB with a deadline_date sort key provides sub-millisecond time-range queries at any scale.

5. After completing this course, you are asked to estimate the effort to build a production document intelligence system for processing 100k financial documents per day with 95% field extraction accuracy. What are the four highest-effort components?

Correct. Annotation, domain calibration, validation logic, and monitoring infrastructure are consistently the four highest-effort components in production document intelligence systems. They are also the four most underestimated in project scoping. Model training — the most visible component — is typically the shortest effort once these four are complete.
