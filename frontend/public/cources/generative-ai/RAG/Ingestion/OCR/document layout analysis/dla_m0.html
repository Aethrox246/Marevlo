Foundations of Document Layout Analysis
Region Taxonomy · Physical vs Logical Structure · Reading Order · Caption Association · Evaluation

Document layout analysis is the step that turns a page image into structured geometry — identifying where text blocks, figures, tables, headers, and captions are, and in what order they should be read. Without correct layout, OCR output is a jumbled sequence of strings with no document structure. This module covers why layout analysis is harder than OCR, the full taxonomy of document region types, physical vs logical structure, reading order as a column-first problem, caption-figure association, and the evaluation metrics used to benchmark layout systems.

01 · Why Layout Is a Distinct Problem

OCR Reads Characters.
Layout Reads Structure.

OCR answers "what does this pixel region say?" Layout analysis answers "what kind of thing is this region, where does it fit, and in what order should it be consumed?" These require different models, different ground truth, and different metrics. A pipeline doing OCR without layout produces a flat string sequence with no document semantics.

What layout provides

Region classification. Paragraph, table, figure, caption, header, footer, footnote, list, formula — typed and bounded.
Reading order. In a two-column paper, which column is first? Does the caption belong before or after its figure?
Logical hierarchy. This is a section heading. These paragraphs are its body. This figure is referenced by paragraph 3.
Content isolation. Which pixels are main body vs running header/footer to exclude from the text flow?

Why layout is harder than OCR

No universal schema. Scientific papers, legal contracts, newspapers, and invoices have completely different region types — no single model generalises without domain adaptation.
Ambiguous boundaries. Where does a table end and a caption begin? Is this a section header or a bold paragraph? Pixel evidence alone is often insufficient.
Scale mismatch. Layout is page-level; OCR is character-level. Layout models must reason about spatial relationships across the full page simultaneously.
Ground truth cost. Layout annotation requires drawing bounding boxes with type labels — orders of magnitude more expensive per page than character transcription.

What Can Appear on a Page:
The Standard Region Vocabulary

PubLayNet (360k pages, scientific papers): 5 classes — text, title, table, figure, list. DocLayNet (IBM, 11 genres): 11 classes including headers, footers, captions, formulas. PRImA: 16+ classes including advertisement and separator regions. Richer taxonomies improve downstream extraction at the cost of annotation complexity and inter-annotator agreement.

03 · Physical vs Logical Structure

Two Representations of the
Same Document

Physical structure — from pixels

Bounding boxes with region type labels. A model can label a box as "table" from visual appearance without understanding its content. Represented as a list of (bbox, class, confidence). Evaluation: IoU-based precision/recall.

regions = [
  {"bbox":[72,80,540,110], "type":"title", "conf":.97},
  {"bbox":[72,120,260,480], "type":"text", "conf":.94},
  {"bbox":[280,120,540,340],"type":"figure", "conf":.91},
  {"bbox":[280,345,540,380],"type":"caption","conf":.88},
]

Logical structure — from semantics

Section hierarchy, figure-caption associations, cross-references. Requires reading order as prerequisite — you cannot assign section numbers without knowing which heading comes first. Represented as a tree or graph.

{"type":"section", "level":1,
 "heading":"Introduction","children":[
  {"type":"paragraph","region_id":1},
  {"type":"figure","id":1,
   "caption_id":2,"ref_by":[1]}]}
04 · Reading Order and Caption Association

Column-First Order and
Proximity-Based Caption Linking

reading_order.py

from dataclasses import dataclass

@dataclass
class Region:
    id: int; x1: float; y1: float; x2: float; y2: float; type: str
    @property
    def cx(self): return (self.x1+self.x2)/2

def detect_columns(regions, page_width, gap_frac=0.05):
    """Cluster region x-centres into column groups."""
    xs = sorted({r.cx for r in regions})
    cols, cur = [], [xs[0]]
    for x in xs[1:]:
        if x-cur[-1] < gap_frac*page_width: cur.append(x)
        else: cols.append(cur); cur = [x]
    cols.append(cur)
    centres = [sum(c)/len(c) for c in cols]
    grouped = [[] for _ in cols]
    for r in regions:
        grouped[min(range(len(centres)), key=lambda i: abs(r.cx-centres[i]))].append(r)
    return [sorted(g, key=lambda r: r.y1) for g in grouped]

def reading_order_column_first(regions, page_width):
    """
    Column-first: complete each column top-to-bottom before moving right.
    Correct for academic papers and newspapers with independent columns.
    Full-width regions (title, abstract) inserted at their y-position.
    """
    full = [r for r in regions if (r.x2-r.x1)/page_width > 0.6]
    cols = [r for r in regions if r not in full]
    groups = detect_columns(cols, page_width) if cols else []
    fw, ordered, fi = sorted(full, key=lambda r: r.y1), [], 0
    for col in groups:
        for region in col:
            while fi < len(fw) and fw[fi].y1 < region.y1:
                ordered.append(fw[fi].id); fi += 1
            ordered.append(region.id)
    ordered.extend(r.id for r in fw[fi:])
    return ordered

def caption_figure_association(regions):
    """
    Associate captions with nearest figure/table by minimum edge distance.
    Separate from reading order — captions can be above OR below their target.
    """
    captions = [r for r in regions if r.type == "caption"]
    targets  = [r for r in regions if r.type in ("figure","table")]
    def edge_dist(a, b):
        dx = max(0, max(a.x1,b.x1) - min(a.x2,b.x2))
        dy = max(0, max(a.y1,b.y1) - min(a.y2,b.y2))
        return (dx**2 + dy**2)**0.5
    return {c.id: min(targets, key=lambda t: edge_dist(c,t)).id
            for c in captions if targets}

06 · Assessment

Module 0 Quiz

1. A layout model achieves mAP=0.91 on PubLayNet. The team deploys it on legal contracts and gets poor table detection. What is the primary cause?

Correct. Domain mismatch between training genre and production genre is the most common layout model failure cause. Fine-tuning on 100-500 annotated pages from the target genre typically recovers most of the performance gap.

2. caption_figure_association() associates a caption at (300,500,540,520) with a figure at (280,200,540,490) rather than a table at (50,510,260,650). Is this correct?

Correct. Edge distance (minimum distance between box boundaries) is the correct proximity measure — not center distance, which ignores region size. The figure is 10px above the caption; the table is 40px to the left. The figure is the correct association.

3. One annotator labels "Table 3: Revenue by Segment" as "caption". Another labels it "title". Neither guideline is definitive. What should happen?

Correct. Underspecified guidelines produce low IAA, which produces low model reliability on the ambiguous class. The fix is always to specify the decision rule first, then remeasure IAA to confirm annotators now agree before training begins.

4. reading_order_column_first() reads column 1 fully before column 2, even though column 2 content starts at y=50 (above column 1 content at y=80). A colleague says column 2 should come first since it starts higher on the page. Who is correct?

Correct. Column-first is the correct semantic strategy for independent-column layouts. Each column is a complete, independent text stream read top-to-bottom. Row-first is the wrong strategy because it would interleave independent column text flows. The y-position of where each column starts is irrelevant to which column is read first — left column always precedes right column in LTR documents.

5. Your layout model has per-class AP: text=0.94, title=0.91, table=0.61, figure=0.88, list=0.83. Overall mAP=0.834. For an invoice extraction pipeline, which metric matters most and what should you do?

Correct. Per-class AP on domain-critical region types is the correct deployment gate. For invoices, table AP is the most important single metric — invoice line items, totals, and tax fields are all inside table structures. An overall mAP of 0.834 with table AP=0.61 describes a model that looks good in aggregate but will fail on the most important document structure in the target domain.
