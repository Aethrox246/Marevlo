Document Classification and Routing
Taxonomy Design · LayoutLMv3 Classifier · TF-IDF Baseline · Hybrid Cascade · Confidence Routing

Before a document can be processed, it must be identified. Document classification determines which pipeline to run — the invoice extractor, the contract analyser, the form parser. Getting this wrong routes documents to the wrong downstream logic and produces silent failures that are harder to detect than outright errors. This module covers multi-class taxonomy design, LayoutLMv3 for classification, TF-IDF baselines and hybrid cascade routing, confidence gap-based human review, handling unknown document types, and the decision logic for when to add a new class versus add a post-classification rule.

01 · Document Taxonomy Design

Defining Classes Before
Training Any Model

Taxonomy design is the highest-leverage decision in document classification — it determines what the model can and cannot express, what annotation looks like, and what downstream pipelines must be built. A taxonomy built from business requirements produces a useful system. A taxonomy built from what was easy to annotate produces an accurate model that solves the wrong problem.

Design principleQuestion to answerFailure mode
Downstream impactDoes this class distinction drive a different extraction pipeline?Classes that share the same downstream logic waste annotation budget
AnnotabilityCan annotators reliably distinguish these classes? Measure IAA before training.IAA below 0.8 means the class boundary is ambiguous — the model cannot learn it reliably
Volume justificationIs there enough production volume to justify the class?A class with 10 documents/month is not worth the annotation cost of 300 training examples
Training feasibilityCan you collect 300+ training examples per class?Under-represented classes produce high false-negative rates and unreliable precision
Unknown handlingWhat happens to document types not in the taxonomy?Without an "other" class and monitoring, novel types are silently misclassified
02 · LayoutLMv3 Classifier and TF-IDF Baseline

When the Expensive Model Wins
and the Cascade Pattern

document_classifier.py — hybrid cascade routing

from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from transformers import LayoutLMv3Processor, LayoutLMv3ForSequenceClassification
import numpy as np
import torch, pickle

class HybridDocumentClassifier:
    """
    Cascade classifier: fast TF-IDF baseline first; expensive LayoutLMv3 only
    when baseline confidence (top1-top2 margin) is below a threshold.
    Handles 80%+ of documents at CPU speed, reserves GPU for uncertain cases.
    """
    def __init__(self, classes: list[str],
                 baseline_margin_threshold: float = 0.30,
                 layoutlm_margin_threshold: float = 0.15):
        self.classes = classes
        self.bmt = baseline_margin_threshold
        self.lmt = layoutlm_margin_threshold
        self.tfidf = TfidfVectorizer(max_features=20000, ngram_range=(1,2))
        self.lr    = LogisticRegression(max_iter=1000, C=1.0)
        self.processor, self.lm_model = None, None

    def fit_baseline(self, texts: list[str], labels: list[str]) -> None:
        X = self.tfidf.fit_transform(texts)
        self.lr.fit(X, labels)

    def classify(self, text: str, image=None,
                  ocr_words=None, ocr_boxes=None) -> dict:
        # Stage 1: fast TF-IDF baseline
        X = self.tfidf.transform([text])
        probs = self.lr.predict_proba(X)[0]
        top2  = sorted(zip(self.lr.classes_, probs), key=lambda x: -x[1])
        margin = top2[0][1] - top2[1][1]

        if margin >= self.bmt:
            return {"class": top2[0][0], "confidence": top2[0][1],
                    "margin": round(margin,3), "stage": "baseline",
                    "route": "auto"}

        # Stage 2: LayoutLMv3 for uncertain cases
        if self.lm_model is None: self._load_layoutlm()
        lm_result = self._layoutlm_classify(image, ocr_words, ocr_boxes)
        lm_margin = lm_result["top1"] - lm_result["top2"]

        route = "auto" if lm_margin >= self.lmt else "human_review"
        return {"class": lm_result["class"], "confidence": lm_result["top1"],
                "margin": round(lm_margin, 3), "stage": "layoutlmv3",
                "route": route,
                "candidates": [top2[0][0], lm_result["top2_class"]]}

    def _layoutlm_classify(self, image, words, boxes) -> dict:
        inputs = self.processor(image, words, boxes=boxes,
                                return_tensors="pt", truncation=True)
        with torch.no_grad():
            logits = self.lm_model(**inputs).logits[0]
        probs = torch.softmax(logits, dim=-1).tolist()
        top2  = sorted(zip(self.classes, probs), key=lambda x: -x[1])
        return {"class":top2[0][0], "top1":top2[0][1],
                "top2_class":top2[1][0], "top2":top2[1][1]}

    def _load_layoutlm(self):
        self.processor = LayoutLMv3Processor.from_pretrained("microsoft/layoutlmv3-base")
        self.lm_model  = LayoutLMv3ForSequenceClassification.from_pretrained(
            "./classifier_weights", num_labels=len(self.classes))
        self.lm_model.eval()
03 · Confidence Gap Routing

Top1-Top2 Margin as the
Primary Routing Signal

routing.py — confidence-gap routing logic

from dataclasses import dataclass
from enum import Enum

class Route(Enum):
    AUTO_PROCESS = "auto"
    HUMAN_REVIEW = "human_review"
    UNKNOWN_TYPE = "unknown"

@dataclass
class RoutingDecision:
    route: Route
    doc_class: str
    confidence: float
    margin: float
    reason: str

def route_document(prediction: dict,
                    margin_threshold: float = 0.20,
                    confidence_threshold: float = 0.60,
                    unknown_class: str = "other") -> RoutingDecision:
    """
    Route a document based on classifier output.
    Three routing cases:
    1. Unknown type: top class is "other" with any confidence → UNKNOWN_TYPE
    2. Low margin: top1-top2 gap < margin_threshold → HUMAN_REVIEW
    3. Low confidence: top1 < confidence_threshold → HUMAN_REVIEW
    4. All thresholds met → AUTO_PROCESS
    """
    cls  = prediction["class"]
    conf = prediction["confidence"]
    marg = prediction.get("margin", conf)  # fallback if margin not computed

    if cls == unknown_class:
        return RoutingDecision(Route.UNKNOWN_TYPE, cls, conf, marg,
                               "Predicted as unknown class — manual inspection required")
    if marg < margin_threshold:
        candidates = prediction.get("candidates", [cls])
        return RoutingDecision(Route.HUMAN_REVIEW, cls, conf, marg,
                               f"Low margin {marg:.2f}: ambiguous between {candidates}")
    if conf < confidence_threshold:
        return RoutingDecision(Route.HUMAN_REVIEW, cls, conf, marg,
                               f"Low confidence {conf:.2f} below threshold {confidence_threshold}")
    return RoutingDecision(Route.AUTO_PROCESS, cls, conf, marg,
                           "Classification accepted")

def monitor_unknown_rate(predictions: list[dict], window_size: int = 1000) -> dict:
    """
    Monitor the rate of unknown-type predictions over a rolling window.
    A rising unknown rate signals new document types entering the pipeline.
    """
    recent = predictions[-window_size:]
    unknown_count = sum(1 for p in recent if p["class"] == "other")
    rate = unknown_count / len(recent)
    return {"unknown_rate": round(rate, 3), "window": window_size,
            "alert": rate > 0.05,  # alert if > 5% unknown
            "recommendation": "Sample unknown documents — possible new document type"
                               if rate > 0.05 else "Within normal range"}
04 · Rule vs Retrain Decision

When Post-Classification Rules
Beat Model Retraining

post_classification_rules.py

import re as regex

class PostClassificationRule:
    """
    Override classifier output based on high-precision textual signals.
    Use when:
    (1) The distinction is primarily textual and reliable (keywords in 95%+ of target docs)
    (2) Training data is scarce (< 300 examples for a new class)
    (3) Deployment speed matters (rule deploys in hours vs days for retraining)
    (4) Rule precision is measurable on known examples before deployment
    """
    def __init__(self, name: str, override_class: str,
                 patterns: list[str], min_matches: int = 1):
        self.name = name
        self.override_class = override_class
        self.regexes = [regex.compile(p, regex.IGNORECASE) for p in patterns]
        self.min_matches = min_matches

    def apply(self, text: str, current_class: str) -> str | None:
        """Return override class if rule fires, else None."""
        matches = sum(1 for r in self.regexes if r.search(text))
        if matches >= self.min_matches: return self.override_class
        return None

    def measure_recall(self, texts: list[str], labels: list[str]) -> dict:
        """Measure rule recall on known positive examples before deployment."""
        positives = [(t,l) for t,l in zip(texts,labels) if l==self.override_class]
        hits = sum(1 for t,_ in positives if self.apply(t,"") is not None)
        recall = hits/len(positives) if positives else 0.0
        return {"recall":recall, "hits":hits, "total":len(positives),
                "deploy": recall >= 0.95}

# Example: tax document rule
tax_rule = PostClassificationRule(
    name="tax_document_override", override_class="tax_document",
    patterns=[r"tax\s+return", r"IRS\s+Form", r"HMRC",
              r"Schedule\s+[A-Z]", r"Form\s+\d{4}"],
    min_matches=2)

def apply_rules(text: str, classifier_result: dict,
                  rules: list[PostClassificationRule]) -> dict:
    for rule in rules:
        override = rule.apply(text, classifier_result["class"])
        if override:
            return {**classifier_result, "class": override,
                    "rule_override": rule.name}
    return classifier_result
05 · Assessment

Module 7 Quiz

1. Your document classifier achieves 94% accuracy on the 8-class taxonomy (invoice, contract, receipt, form, report, letter, id_document, other). In production, 3% of documents per day are classified as "other" with confidence below 0.5. What does this indicate and what should you do?

Correct. Low-confidence "other" predictions are the canonical signal for out-of-vocabulary document types. The 94% in-distribution accuracy tells you nothing about how the model handles types it was never trained on. Manual inspection of the low-confidence "other" documents is always the first step before any model or threshold changes.

2. classify_document() uses a softmax classifier. A document returns probabilities: invoice=0.41, contract=0.38, other=0.21. The top-1 prediction is "invoice". Should you trust this prediction?

Correct. The top1-top2 margin is a more informative routing signal than the absolute top-1 probability. A high absolute probability with a close competitor (e.g. 0.41 vs 0.38) indicates genuine document ambiguity that a downstream extraction pipeline will fail on if given the wrong class.

3. Your taxonomy has 8 classes. A business analyst requests adding "email" as a 9th class because 200 email PDFs per day are being misclassified as "letter". What is the correct process before adding the class?

Correct. Adding a new taxonomy class has upstream costs (annotation), training costs (rebalancing all classes), and operational costs (new downstream pipeline if extraction logic differs). All four checks — volume, annotability, retrospective purity, and training data feasibility — must pass before committing to a new class.

4. build_document_classifier() is fine-tuned on LayoutLMv3. A simpler TF-IDF + logistic regression baseline achieves 89% accuracy vs LayoutLMv3's 94%. Should you deploy LayoutLMv3?

Correct. The deployment decision requires failure mode analysis, not just accuracy comparison. The hybrid cascade — fast baseline first, expensive model only on uncertain cases — is the standard production pattern for high-throughput classification with a strong but slow model available.

5. Your classifier handles 8 known classes. A new regulatory requirement means all "tax_document" types (currently classified as "report") must be routed to a separate compliance pipeline. You have 150 annotated tax documents. Two options: (A) add a new class and retrain, (B) add a post-classification rule. When should you choose option B?

Correct. Post-classification rules are the right choice when the signal is high-precision textual, data is scarce, and deployment speed matters. The rule-vs-retrain decision should be made empirically: measure rule recall on known examples before committing to either path. Rules and models are not mutually exclusive — a rule can handle the majority of cases while the model handles the rest.
