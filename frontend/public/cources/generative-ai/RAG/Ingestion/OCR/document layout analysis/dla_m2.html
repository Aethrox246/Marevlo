01 · Faster R-CNN for Document Layout

Region Proposal Network Adapted
for Document Region Scales

Faster R-CNN was designed for natural scene object detection — cars, people, animals at variable sizes. Document layout requires a different anchor configuration: regions are axis-aligned, often span most of the page width, and have very different aspect ratios than natural scene objects. Adapting Faster R-CNN for documents requires tuning the Region Proposal Network anchors, adjusting NMS thresholds, and feeding appropriate resolution images.

faster_rcnn_layout.py — Detectron2 config for document layout

from detectron2.config import get_cfg
from detectron2 import model_zoo
from detectron2.engine import DefaultPredictor

def build_layout_cfg(model_weights: str,
                       num_classes: int = 5,
                       score_thresh: float = 0.5) -> object:
    """
    Detectron2 config for PubLayNet-style document layout detection.
    num_classes: 5 for PubLayNet (text, title, list, table, figure)
    Anchor tuning: document regions are large, axis-aligned, wide-aspect.
    """
    cfg = get_cfg()
    cfg.merge_from_file(model_zoo.get_config_file(
        "COCO-Detection/faster_rcnn_R_50_FPN_3x.yaml"))

    # Document-specific anchor configuration
    cfg.MODEL.ANCHOR_GENERATOR.SIZES       = [[32], [64], [128], [256], [512]]
    cfg.MODEL.ANCHOR_GENERATOR.ASPECT_RATIOS = [[0.25, 0.5, 1.0, 2.0, 4.0]]
    # Add wide-aspect ratios for landscape tables and full-width text blocks

    # RPN thresholds — documents have fewer, larger overlapping proposals
    cfg.MODEL.RPN.NMS_THRESH               = 0.7
    cfg.MODEL.RPN.PRE_NMS_TOPK_TEST        = 1000
    cfg.MODEL.RPN.POST_NMS_TOPK_TEST       = 200

    cfg.MODEL.ROI_HEADS.NUM_CLASSES        = num_classes
    cfg.MODEL.ROI_HEADS.SCORE_THRESH_TEST  = score_thresh
    cfg.MODEL.ROI_HEADS.NMS_THRESH_TEST    = 0.5

    # Input resolution: 800x1333 covers most document page sizes at 300 DPI
    cfg.INPUT.MIN_SIZE_TEST                = 800
    cfg.INPUT.MAX_SIZE_TEST                = 1333

    cfg.MODEL.WEIGHTS = model_weights
    return cfg

def layout_inference(image_path: str, cfg) -> list[dict]:
    """Run layout detection and return sorted region list."""
    import cv2
    predictor = DefaultPredictor(cfg)
    img = cv2.imread(image_path)
    outputs = predictor(img)
    instances = outputs["instances"].to("cpu")
    CLASS_NAMES = ["text", "title", "list", "table", "figure"]
    regions = []
    for i in range(len(instances)):
        box  = instances.pred_boxes.tensor[i].tolist()
        cls  = int(instances.pred_classes[i])
        conf = float(instances.scores[i])
        regions.append({"bbox": box, "type": CLASS_NAMES[cls], "score": conf})
    return sorted(regions, key=lambda r: r["bbox"][1])
02 · DETR: Detection Transformer

Bipartite Matching Eliminates NMS —
Global Attention Captures Full-Page Context

DETR reformulates object detection as a direct set prediction problem. A CNN extracts image features; a transformer encoder adds positional context; a fixed set of learned object queries attend to the encoder output; and a bipartite matching loss enforces a one-to-one assignment between queries and ground truth objects. For document layout, DETR's global attention is particularly valuable: it can model the relationship between a figure and its caption across the full page, which local convolutional features cannot.

detr_layout.py — DETR inference and cross-class conflict resolution

import torch
from transformers import DetrImageProcessor, DetrForObjectDetection
import numpy as np
from PIL import Image

def load_detr(model_name: str = "facebook/detr-resnet-50"):
    processor = DetrImageProcessor.from_pretrained(model_name)
    model = DetrForObjectDetection.from_pretrained(model_name)
    model.eval()
    return processor, model

def detect_layout(image_path: str, processor, model,
                   score_thresh: float = 0.7) -> list[dict]:
    img = Image.open(image_path).convert("RGB")
    inputs = processor.preprocess(images=img, return_tensors="pt")
    with torch.no_grad():
        outputs = model(**inputs)
    W, H = img.size
    results = processor.post_process_object_detection(
        outputs, threshold=score_thresh,
        target_sizes=torch.tensor([[H, W]]))[0]
    regions = []
    for score, label, box in zip(results["scores"], results["labels"],
                                    results["boxes"]):
        regions.append({
            "bbox":  box.tolist(),   # [x1, y1, x2, y2]
            "type":  model.config.id2label[int(label)],
            "score": float(score),
        })
    return resolve_cross_class_conflicts(regions)

def resolve_cross_class_conflicts(regions: list[dict],
                                    iou_thresh: float = 0.5) -> list[dict]:
    """
    Post-NMS cross-class conflict resolution.
    Standard NMS is per-class and leaves cross-class overlaps intact.
    Document layout regions are spatially mutually exclusive —
    when two different-class predictions overlap, keep the higher-confidence one.
    """
    def box_iou(a, b):
        ix1,iy1 = max(a[0],b[0]),max(a[1],b[1])
        ix2,iy2 = min(a[2],b[2]),min(a[3],b[3])
        inter = max(0,ix2-ix1)*max(0,iy2-iy1)
        aa = (a[2]-a[0])*(a[3]-a[1]); bb = (b[2]-b[0])*(b[3]-b[1])
        return inter/(aa+bb-inter) if (aa+bb-inter) > 0 else 0
    regions = sorted(regions, key=lambda r: -r["score"])
    suppressed = set()
    for i in range(len(regions)):
        if i in suppressed: continue
        for j in range(i+1, len(regions)):
            if j in suppressed: continue
            if regions[i]["type"] == regions[j]["type"]: continue
            if box_iou(regions[i]["bbox"], regions[j]["bbox"]) >= iou_thresh:
                suppressed.add(j)  # i has higher score (sorted desc)
    return [r for i,r in enumerate(regions) if i not in suppressed]
03 · LayoutParser Integration

One-Line Layout Detection With
Pretrained Model Zoo

layoutparser_pipeline.py

import layoutparser as lp
import cv2

# PubLayNet model from LayoutParser model zoo
# Models: PubLayNet (scientific), TableBank (tables), Prima (general)
def build_pipeline(model_type: str = "PubLayNet",
                    score_thresh: float = 0.5):
    model_map = {
        "PubLayNet": ("lp://PubLayNet/faster_rcnn_R_50_FPN_3x/config",
                       ["Text","Title","List","Table","Figure"]),
        "TableBank": ("lp://TableBank/faster_rcnn_R_101_FPN_3x/config",
                       ["Table"]),
        "Prima":    ("lp://Prima/mask_rcnn_R_50_FPN_3x/config",
                       ["TextBlock","ImageRegion","TableRegion","MathsRegion"]),
    }
    config_path, labels = model_map[model_type]
    model = lp.Detectron2LayoutModel(config_path,
                label_map={i:l for i,l in enumerate(labels)},
                extra_config=["MODEL.ROI_HEADS.SCORE_THRESH_TEST", score_thresh])
    return model, labels

def detect_page(image_path: str, model) -> lp.Layout:
    img = cv2.imread(image_path); img = cv2.cvtColor(img, cv2.COLOR_BGR2RGB)
    layout = model.detect(img)
    return layout

def extract_text_regions(layout: lp.Layout, img, ocr_agent) -> list[dict]:
    """
    Extract text from each layout region using an OCR agent.
    Filter to text-bearing region types only; skip figures and tables.
    Sort by reading order (y-then-x for single-column, requires column detection for multi).
    """
    text_types = {"Text", "Title", "List"}
    results = []
    text_blocks = [b for b in layout if b.type in text_types]
    text_blocks = sorted(text_blocks, key=lambda b: (b.block.y_1, b.block.x_1))
    for block in text_blocks:
        segment = block.pad(left=5, right=5, top=5, bottom=5).crop_image(img)
        text = ocr_agent.detect(segment)
        results.append({"type": block.type, "text": text,
                         "bbox": [block.block.x_1, block.block.y_1,
                                   block.block.x_2, block.block.y_2]})
    return results
04 · Fine-Tuning for Domain Adaptation

Adapting PubLayNet Models to
Target Document Domains

finetune_layout.py — Detectron2 training configuration

from detectron2.engine import DefaultTrainer
from detectron2.data import DatasetCatalog, MetadataCatalog
from detectron2.data.datasets import register_coco_instances
import os

def register_domain_dataset(name: str, ann_path: str, img_dir: str):
    """Register annotated domain dataset in COCO format."""
    register_coco_instances(name, {}, ann_path, img_dir)

def build_finetune_cfg(base_weights: str,
                         train_dataset: str,
                         val_dataset: str,
                         num_classes: int,
                         max_iter: int = 2000,
                         freeze_backbone: bool = True):
    """
    Fine-tuning config for domain adaptation from PubLayNet weights.
    freeze_backbone=True: only RPN and detection heads are trained.
    Recommended for small datasets (<500 annotated pages).
    """
    cfg = get_cfg()
    cfg.merge_from_file(model_zoo.get_config_file(
        "COCO-Detection/faster_rcnn_R_50_FPN_3x.yaml"))
    cfg.DATASETS.TRAIN = (train_dataset,)
    cfg.DATASETS.TEST  = (val_dataset,)
    cfg.MODEL.WEIGHTS  = base_weights
    cfg.MODEL.ROI_HEADS.NUM_CLASSES = num_classes
    cfg.SOLVER.MAX_ITER    = max_iter
    cfg.SOLVER.BASE_LR     = 0.001      # lower LR for fine-tuning
    cfg.SOLVER.STEPS       = [1500, 1800]
    cfg.SOLVER.IMS_PER_BATCH = 2
    cfg.TEST.EVAL_PERIOD   = 200

    # Data augmentation — critical for small domain datasets
    cfg.INPUT.MIN_SIZE_TRAIN = (640, 672, 704, 736, 800)  # scale jitter
    cfg.INPUT.MAX_SIZE_TRAIN = 1333
    cfg.INPUT.RANDOM_FLIP    = "horizontal"

    if freeze_backbone:
        # Freeze backbone and FPN; train only RPN + ROI heads
        cfg.MODEL.BACKBONE.FREEZE_AT = 5   # freeze all ResNet stages
    return cfg

06 · Assessment

Module 2 Quiz

1. Faster R-CNN on PubLayNet gets table AP=0.88 but 0.41 on financial reports. Two causes and a fix for each.

Correct. Visual domain shift and anchor shape mismatch are the two most actionable root causes. Both can be measured independently via per-class AP on a held-out financial validation set.

2. DETR eliminates NMS. Why does Faster R-CNN require it but DETR does not?

Correct. The bipartite matching loss (Hungarian algorithm) is the architectural reason DETR needs no NMS. Deformable DETR addresses slow convergence by replacing global attention with deformable attention over a small set of key sampling points, reducing training to under 50 epochs.

3. LayoutParser returns Table (score=0.43) and Figure (score=0.81) with IoU=0.67. NMS threshold=0.5. Which block survives?

Correct. Per-class NMS is appropriate for general detection. Document layout regions are spatially mutually exclusive — cross-class conflict resolution is a mandatory post-processing step that must be implemented manually after layout.detect().

4. Fine-tuning on 200 invoice pages: training loss falls but validation loss plateaus after 500 steps. What is happening and the two best fixes?

Correct. The two fixes address the two sides of overfitting: augmentation expands the effective training set; backbone freezing reduces the number of parameters adapted to the small dataset while preserving general document features learned from PubLayNet.

5. You run layout inference on a 40-page scientific paper with a PubLayNet DETR model. Inference takes 6 minutes (9s/page). Your SLA is under 60s total. What are the two most impactful latency reduction strategies?

Correct. Resolution reduction and model substitution are the two most impactful latency levers for DETR-based layout inference. TensorRT (option D) is also valid but 5-10x is optimistic for transformer models — the actual speedup depends heavily on sequence length and batch size. Resolution reduction is the most reliable and controllable lever: it directly addresses the O(n^2) attention bottleneck.
