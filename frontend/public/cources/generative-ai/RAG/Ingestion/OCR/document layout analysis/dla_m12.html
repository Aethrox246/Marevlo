Invoice and Financial Document Extraction
Invoice Schema · Multi-Table Extraction · Decimal Arithmetic · Vendor Normalisation · Cross-Field Validation

Invoices are the highest-volume document type in most enterprise document pipelines and the most demanding for extraction accuracy — a 1% error rate on a 50-field invoice schema means one wrong field on every other invoice. This module covers the full invoice extraction pipeline: multi-table line item extraction with source table identity, floating-point vs Decimal arithmetic for monetary amounts, three-stage vendor normalisation, locale-aware amount parsing for European and US number formats, and the five cross-field validation checks that catch extraction errors the basic total check misses.

01 · Invoice Extraction Schema

Defining What to Extract
Before Building the Extractor

Invoice extraction schemas define the target fields, their types, and their validation rules. A schema designed without understanding the validation requirements produces fields that look extracted but cannot be verified. The schema must include both the extracted values and the cross-field relationships that enable validation: subtotal, tax rate, tax amount, and total must form a consistent algebraic system — not just be individually extracted.

invoice_schema.py — extraction schema and field types

from dataclasses import dataclass, field
from decimal import Decimal
from typing import Optional
from datetime import date

@dataclass
class LineItem:
    description:  str
    quantity:     Decimal
    unit_price:   Decimal
    amount:       Decimal
    source_table_id: str     # which Table region this came from
    confidence:   float = 1.0

    def validate(self, tolerance: Decimal = Decimal("0.01")) -> bool:
        expected = (self.quantity * self.unit_price).quantize(Decimal("0.01"))
        return abs(expected - self.amount) <= tolerance

@dataclass
class Invoice:
    invoice_number: str
    invoice_date:   date
    vendor_name:    str
    vendor_id:      Optional[str]    # canonical vendor ID after normalisation
    currency:       str              # ISO 4217: "GBP", "EUR", "USD"
    subtotal:       Decimal
    tax_rate:       Decimal          # e.g. Decimal("0.20") for 20%
    tax_amount:     Decimal
    total_amount:   Decimal
    line_items:     list[LineItem] = field(default_factory=list)
    source_doc:     str = ""

    def validate(self, tolerance: Decimal = Decimal("0.02")) -> list[str]:
        """
        Five cross-field consistency checks. Returns list of validation errors.
        All arithmetic uses Decimal to avoid floating-point mismatch.
        """
        errors = []
        # 1. tax_amount == subtotal * tax_rate
        expected_tax = (self.subtotal * self.tax_rate).quantize(Decimal("0.01"))
        if abs(expected_tax - self.tax_amount) > tolerance:
            errors.append(f"Tax mismatch: {expected_tax} vs {self.tax_amount}")
        # 2. total == subtotal + tax_amount
        expected_total = self.subtotal + self.tax_amount
        if abs(expected_total - self.total_amount) > tolerance:
            errors.append(f"Total mismatch: {expected_total} vs {self.total_amount}")
        # 3. sum(line_items) == subtotal
        line_sum = sum(li.amount for li in self.line_items)
        if abs(line_sum - self.subtotal) > tolerance:
            errors.append(f"Line item sum {line_sum} != subtotal {self.subtotal}")
        # 4. quantity * unit_price == line_item.amount for each item
        for i, li in enumerate(self.line_items):
            if not li.validate(tolerance):
                errors.append(f"Line {i}: qty*price != amount")
        # 5. currency consistency (all Decimal amounts in same currency)
        if not self.currency: errors.append("Missing currency field")
        return errors
02 · Multi-Table Line Item Extraction

Per-Table-Region Processing With
Source Table Identity

line_item_extractor.py

from decimal import Decimal, InvalidOperation

def parse_amount(text: str, locale: str = "en_GB") -> Decimal:
    """
    Locale-aware amount parsing using babel.
    Handles: "1,234.56" (US/UK), "1.234,56" (DE/FR), "1 234,56" (SE).
    Never use float() for monetary values — use Decimal throughout.
    """
    from babel.numbers import parse_decimal
    try:
        return Decimal(str(parse_decimal(text.strip(), locale=locale)))
    except Exception:
        cleaned = text.replace(" ","").replace("€","").replace("£","").replace("$","")
        return Decimal(cleaned)

def extract_line_items(table_regions: list[dict],
                         cell_grids: dict[str, list],
                         ocr_results: dict,
                         locale: str = "en_GB") -> list[LineItem]:
    """
    Extract line items per table region — not per page.
    Each Table region is processed as a self-contained unit.
    table_regions: list of {id, bbox, type} from layout model
    cell_grids: {table_id: [[Cell, ...], ...]} from TSR
    ocr_results: {cell_id: text}
    """
    line_items = []
    table_regs = [r for r in table_regions if r["type"] == "table"]

    for table in table_regs:
        grid = cell_grids.get(table["id"], [])
        if not grid: continue
        # Identify column roles from header row
        header = {ci: ocr_results.get(f"{table['id']}_0_{ci}", "").lower()
                  for ci in range(len(grid[0]))}
        col_map = map_columns(header)

        for ri, row in enumerate(grid[1:], start=1):  # skip header
            try:
                desc  = ocr_results.get(f"{table['id']}_{ri}_{col_map['desc']}",  "")
                qty   = parse_amount(ocr_results.get(f"{table['id']}_{ri}_{col_map['qty']}", "1"), locale)
                price = parse_amount(ocr_results.get(f"{table['id']}_{ri}_{col_map['price']}", "0"), locale)
                amt   = parse_amount(ocr_results.get(f"{table['id']}_{ri}_{col_map['amount']}", "0"), locale)
                line_items.append(LineItem(desc, qty, price, amt, table["id"]))
            except (InvalidOperation, KeyError): continue
    return line_items

def map_columns(header: dict[int, str]) -> dict[str, int]:
    """Map column roles from header text to column indices."""
    role_keywords = {
        "desc":   ["description", "item", "product", "service"],
        "qty":    ["qty", "quantity", "units"],
        "price":  ["price", "unit", "rate", "each"],
        "amount": ["amount", "total", "line total", "net"],
    }
    col_map = {}
    for role, keywords in role_keywords.items():
        for ci, cell_text in header.items():
            if any(kw in cell_text for kw in keywords):
                col_map[role] = ci; break
    return col_map
03 · Vendor Normalisation

Three-Stage Pipeline from Raw Name
to Canonical Vendor ID

vendor_normalisation.py

import re
from rapidfuzz import fuzz
from sentence_transformers import SentenceTransformer
import numpy as np

LEGAL_SUFFIXES = re.compile(
    rr"(corp|corporation|ltd|limited|inc|incorporated|plc|llc|llp|gmbh|sa|sas|bv|nv|ag)",
    re.IGNORECASE)

def normalise_name(raw: str) -> str:
    """Stage 1: lowercase, strip punctuation and legal suffixes."""
    n = raw.lower().strip()
    n = LEGAL_SUFFIXES.sub("", n)
    n = re.sub(rr"[^\w\s]", "", n).strip()
    return re.sub(rr"\s+", " ", n)

class VendorNormaliser:
    FUZZY_ACCEPT  = 90
    FUZZY_REVIEW  = 60
    EMB_ACCEPT    = 0.88

    def __init__(self, vendor_master: dict[str, str]):
        self.master = {vid: normalise_name(name) for vid, name in vendor_master.items()}
        self._cache: dict[str, str] = {}
        self._model = None

    def normalise(self, raw_name: str) -> dict:
        norm = normalise_name(raw_name)
        if norm in self._cache: return {"vendor_id":self._cache[norm],"stage":"cache"}

        # Stage 2: fuzzy matching
        scores = {vid: fuzz.token_sort_ratio(norm, cname) for vid, cname in self.master.items()}
        best_vid = max(scores, key=scores.get)
        best_score = scores[best_vid]
        if best_score >= self.FUZZY_ACCEPT:
            self._cache[norm] = best_vid
            return {"vendor_id": best_vid, "score": best_score, "stage": "fuzzy"}

        # Stage 3: embedding similarity
        if best_score >= self.FUZZY_REVIEW:
            if self._model is None: self._model = SentenceTransformer("all-MiniLM-L6-v2")
            embs = self._model.encode([norm] + list(self.master.values()))
            sims = np.dot(embs[0], embs[1:].T) / (
                   np.linalg.norm(embs[0]) * np.linalg.norm(embs[1:], axis=1) + 1e-8)
            best_i = int(np.argmax(sims))
            if sims[best_i] >= self.EMB_ACCEPT:
                vid = list(self.master)[best_i]
                self._cache[norm] = vid
                return {"vendor_id": vid, "score": float(sims[best_i]), "stage": "embedding"}
        return {"vendor_id": None, "stage": "human_review", "raw": raw_name}
04 · Assessment

Module 12 Quiz

1. Invoice extraction merges rows from two tables — products and services. Root cause and fix?

Correct. The extractor must process each Table region as a self-contained unit. Table identity is available in the layout model output — discarding it causes multi-table invoices to merge incorrectly.

2. validate_totals() raises ValidationError on 8% of invoices even though amounts look correct. Most likely cause?

Correct. Float arithmetic is the most common cause of invoice total validation failures when amounts look correct. Decimal arithmetic eliminates this. Locale-aware separator normalisation is the second most common cause.

3. normalise_vendor() must map "ACME Corp.", "Acme Corporation", "ACME CORPORATION LTD", and "Acme Corp" to canonical ID "ACME_001". Correct approach?

Correct. The three-stage pipeline (normalise, fuzzy match, embedding similarity) handles the full range of vendor name variations in production. Human review for genuinely new vendors is the correct fallback rather than forcing an incorrect canonical assignment.

4. "1.234,56" EUR (European format) raises ValueError with float(). Same batch has "1,234.56" US format. How to handle both?

Correct. Simple replace fails on amounts like "1,234.56" where the comma is a thousands separator. Babel locale-aware parsing handles all cases. Vendor country from the invoice header is the most reliable locale signal in the pipeline.

5. Your schema validates subtotal+tax==total. But 5% of invoices have wrong amounts that pass validation. What checks are missing?

Correct. The subtotal+tax==total check is one of five necessary cross-field consistency checks. Tax rate consistency, line item subtotal reconciliation, and unit_price times quantity checks address the three most common sources of extraction errors that pass the basic total check.
