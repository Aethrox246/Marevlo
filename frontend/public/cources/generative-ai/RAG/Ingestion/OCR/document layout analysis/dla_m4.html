Table Structure Recognition
TATR · Grid Construction · Merged Cell Inference · Table-to-DataFrame · TEDS Evaluation

Table detection tells you where a table is. Table structure recognition tells you what is inside it — which pixels are row separators, which are column separators, how cells span across rows and columns, and how to extract a clean DataFrame with correct headers and data alignment. This module covers the Table Transformer (TATR) architecture, grid construction from row and column span predictions, merged-cell rowspan/colspan inference from bounding box geometry, table-to-DataFrame extraction, borderless vs bordered table detection, and evaluation with TEDS (Tree Edit Distance Score).

01 · Table Detection vs Structure Recognition

Two Distinct Problems,
Two Distinct Models in Sequence

Table detection answers "where is the table on the page?" — output is a bounding box. Table structure recognition (TSR) answers "within that bounding box, how many rows, how many columns, where are cell boundaries, which cells span multiple rows or columns?" These are separate models applied in sequence: detection feeds its output bbox to TSR as the input crop.

StepInputOutputModel
Table detectionFull page imageTable bounding boxFaster R-CNN / DETR on PubLayNet
Structure recognitionCropped table imageRow/column spans, cell gridTATR (Table Transformer)
Cell OCRIndividual cell cropsCell text contentTesseract / TrOCR / EasyOCR
DataFrame constructionCell grid + textspandas DataFrameGrid assignment algorithm

Why detection and TSR use separate models

Table detection needs page-level context to find tables among text, figures, and headers. TSR needs cell-level resolution to detect sub-pixel row/column separators. A single model at page resolution cannot achieve both — the table region occupies a fraction of the full page image, and at 800px input resolution interior grid lines are too small to detect reliably. Cropping and re-scaling the detected table bbox to a fixed input size (e.g. 800x600) before TSR is the standard approach.

Table taxonomy for TSR

Bordered. Full grid lines between all cells — strongest foreground signal for TSR.
Partially bordered. Header row has borders; body has hairline rules or none.
Borderless. No grid lines — rows distinguished only by whitespace and alignment. Hardest for classical methods; TATR handles well.
Merged-cell. Cells spanning multiple rows or columns — common in financial and scientific tables.
02 · TATR: Table Transformer

DETR Applied to Table Structure —
Predicting Rows, Columns, and Spanning Cells

TATR adapts the DETR architecture to table structure recognition. Instead of arbitrary object classes, it predicts five structural element types: table-row, table-column, table-spanning-cell, table-column-header, and table-projected-row-header. The bounding boxes of these elements define the row/column grid from which cell positions are inferred by intersection.

tatr_inference.py

from transformers import AutoImageProcessor, TableTransformerForObjectDetection
import torch
from PIL import Image

TATR_CLASSES = ["table","table-column","table-row",
                "table-column-header","table-projected-row-header",
                "table-spanning-cell","no object"]

def load_tatr(model_name="microsoft/table-transformer-structure-recognition"):
    processor = AutoImageProcessor.from_pretrained(model_name)
    model = TableTransformerForObjectDetection.from_pretrained(model_name)
    return processor, model.eval()

def predict_structure(table_img: Image.Image, processor, model,
                       score_thresh: float = 0.5) -> dict:
    """
    Run TATR on a cropped table image.
    Returns row, column, and spanning-cell predictions sorted spatially.
    Do not downscale the crop — hairline grid lines disappear below 200 DPI.
    """
    inputs = processor(images=table_img, return_tensors="pt")
    W, H   = table_img.size
    with torch.no_grad():
        outputs = model(**inputs)
    results = processor.post_process_object_detection(
        outputs, threshold=score_thresh,
        target_sizes=torch.tensor([[H, W]]))[0]
    rows, cols, spans = [], [], []
    for score, label, box in zip(results["scores"],results["labels"],results["boxes"]):
        cls = TATR_CLASSES[int(label)]
        rec = {"bbox":box.tolist(), "score":float(score), "class":cls}
        if   cls == "table-row":           rows.append(rec)
        elif cls == "table-column":      cols.append(rec)
        elif cls == "table-spanning-cell": spans.append(rec)
    return {"rows":   sorted(rows,  key=lambda r:r["bbox"][1]),
            "columns":sorted(cols,  key=lambda c:c["bbox"][0]),
            "spans":  spans}
03 · Grid Construction and Merged Cell Inference

Row/Column Intersections and
Rowspan/Colspan from BBox Geometry

table_grid.py

from dataclasses import dataclass, field
import numpy as np

@dataclass
class Cell:
    row: int; col: int
    x1: float; y1: float; x2: float; y2: float
    rowspan: int = 1; colspan: int = 1
    text: str = ""
    is_header: bool = False
    merged_child: bool = False

def build_grid(structure: dict, header_row_count: int = 1) -> list:
    """
    Construct 2D Cell grid from TATR row/column predictions.
    Cell bbox = row bbox Y-range x column bbox X-range.
    Column assignment uses boundary-interval method:
    cell belongs to col i if x-centre within [midpoint(i-1,i), midpoint(i,i+1)].
    """
    rows, cols = structure["rows"], structure["columns"]
    col_centres = [(c["bbox"][0]+c["bbox"][2])/2 for c in cols]
    col_bounds  = [0]+[(col_centres[i]+col_centres[i+1])/2
                       for i in range(len(cols)-1)]+[float("inf")]
    grid = []
    for ri, row in enumerate(rows):
        ry1, ry2 = row["bbox"][1], row["bbox"][3]
        grid.append([Cell(ri, ci,
                          col["bbox"][0], ry1, col["bbox"][2], ry2,
                          is_header=(ri < header_row_count))
                      for ci, col in enumerate(cols)])
    return grid

def infer_spans(grid: list, spans: list) -> list:
    """
    Infer rowspan/colspan from TATR spanning-cell bbox predictions.
    A spanning cell covers multiple row and/or column bboxes.
    Top-left covered cell (r0, c0) becomes the parent; all others are merged_child.
    """
    def ov1d(a1,a2,b1,b2): return max(0,min(a2,b2)-max(a1,b1))
    for span in spans:
        sx1,sy1,sx2,sy2 = span["bbox"]
        r_hit = [ri for ri,row in enumerate(grid)
                 if row and ov1d(sy1,sy2,row[0].y1,row[0].y2) > 5]
        c_hit = [ci for ci,c in enumerate(grid[0] if grid else [])
                 if ov1d(sx1,sx2,c.x1,c.x2) > 5]
        if not r_hit or not c_hit: continue
        r0, c0 = r_hit[0], c_hit[0]
        grid[r0][c0].rowspan = len(r_hit)
        grid[r0][c0].colspan = len(c_hit)
        for ri in r_hit:
            for ci in c_hit:
                if ri != r0 or ci != c0: grid[ri][ci].merged_child = True
    return grid
04 · Table-to-DataFrame and TEDS Evaluation

Grid to pandas DataFrame
and Measuring Extraction Quality

table_extraction.py

import pandas as pd
import numpy as np
import cv2

def table_to_dataframe(grid: list, ocr_fn) -> pd.DataFrame:
    """
    Convert Cell grid to pandas DataFrame.
    ocr_fn: callable(Cell) -> str.
    Header cells set column names; merged children are skipped (NaN).
    """
    n_rows = len(grid)
    n_cols = max(len(r) for r in grid) if grid else 0
    data    = [[np.nan]*n_cols for _ in range(n_rows)]
    headers = [f"col_{i}" for i in range(n_cols)]
    for ri, row in enumerate(grid):
        for ci, cell in enumerate(row):
            if cell.merged_child: continue
            text = ocr_fn(cell)
            if cell.is_header: headers[ci] = text or headers[ci]
            else: data[ri][ci] = text
    hdr_rows = {ri for ri,row in enumerate(grid) if row and row[0].is_header}
    body = [data[ri] for ri in range(n_rows) if ri not in hdr_rows]
    return pd.DataFrame(body, columns=headers)

def detect_table_type(binary: np.ndarray) -> str:
    """
    Classify table as bordered / partially_bordered / borderless.
    Bordered: >= 15% of rows have full-width horizontal lines (>= 70% page width).
    Uses Otsu-binarised image. Note: hairline rules may be missed by Otsu —
    lower the threshold by 20-30 or use adaptive thresholding for grey rules.
    """
    h, w = binary.shape
    h_cov = sum(1 for row in binary if row.sum() >= 0.7*w) / h
    if h_cov > 0.15: return "bordered"
    if h_cov > 0.05: return "partially_bordered"
    return "borderless"

def teds_score(pred_html: str, gt_html: str) -> float:
    """
    TEDS = 1 - normalised tree edit distance between HTML table trees.
    Structure-only TEDS: strip cell text before comparison.
    Full TEDS: include cell text.
    High structure-TEDS + low full TEDS = OCR bottleneck, not TSR bottleneck.
    Requires: pip install apted
    """
    from apted import APTED, helpers
    import re
    def to_tree(html):
        tags = re.findall(r"<(/?(?:table|thead|tbody|tr|th|td))[^>]*>", html)
        st, res = ["{root"], ""
        for t in tags:
            if t.startswith("/"): res += st.pop() + "}"
            else: st.append(f"{{{t}"); res += st[-1]
        return res
    pt = helpers.Tree.from_text(to_tree(pred_html))
    gt = helpers.Tree.from_text(to_tree(gt_html))
    dist = APTED(pt, gt).compute_edit_distance()
    return max(0.0, 1.0 - dist / max(len(pred_html), len(gt_html)))
05 · Assessment

Module 4 Quiz

1. TATR predicts a spanning-cell bbox over rows 2-4 and columns 1-2. Which cells get merged_child=True, and what does cell (2,1) receive?

Correct. rows_hit[0] and cols_hit[0] identify the top-left parent. All other covered cells are marked merged_child in place — they remain in the grid but are skipped during DataFrame construction.

2. table_to_dataframe() on a 5-column table produces mostly NaN in column index 2. Most likely cause?

Correct. Nearest-centre assignment is the most common column-shift NaN cause. Boundary-interval assignment is the fix. Diagnosis: print grid cell coordinates before DataFrame construction and check whether any cells were assigned to column index 2.

3. detect_table_type() returns borderless for a table with 0.5pt hairline rules. Why, and what is the fix?

Correct. Global Otsu misclassifies low-contrast border pixels as background. The fixed-offset threshold reduction and adaptive thresholding are the two most reliable hairline-rule fixes.

4. TEDS=0.71 on the test set. Structure-only TEDS=0.93. What does the gap reveal and what do you fix first?

Correct. The structure vs full TEDS gap directly localises the failure. High structure-TEDS means the model finds cells correctly; low full TEDS means it cannot read their content. Always compute both metrics separately before deciding where to invest improvement effort.

5. Fine-tuning TATR on 150 annotated financial tables: training loss falls but validation TEDS plateaus at 0.68 after 300 steps. Two most effective fixes?

Correct. Backbone freezing and synthetic augmentation address overfitting from opposite sides: freezing reduces adapted parameter space; synthetic data expands the effective training distribution. Both are validated strategies for TATR fine-tuning on small domain-specific datasets.
