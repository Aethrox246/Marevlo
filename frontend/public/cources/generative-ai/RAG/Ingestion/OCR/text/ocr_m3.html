01 · Why Layout Analysis Exists

Text Without Structure Is
Just Pixel Soup

A page image contains pixels. Layout analysis converts those pixels into a structured hierarchy: page → regions (columns, headers, tables, figures) → paragraphs → lines → words → characters. Every subsequent step — reading order determination, table extraction, field localisation — depends on this hierarchy being correct. A single layout error propagates through all downstream processing.

The layout analysis failure that ruins everything downstream

Right column line 1: "Blood pressure: 140/90"
Left column line 2: "on 15 March 2024 with"
Right column line 2: "Heart rate: 72 bpm"

Tesseract PSM 3 on full page → reads horizontally:
"The patient was admitted Blood pressure: 140/90 on 15 March 2024 with Heart rate: 72 bpm"

Completely garbled. A downstream NER model extracts "admitted blood pressure" as a clinical event.

02 · Pixel Projection Profiles

The Classical Approach:
Finding Lines and Columns by Counting Pixels

A horizontal projection profile sums the number of dark pixels in each row of a binary image. Text rows produce peaks (many dark pixels); inter-line gaps produce valleys (few dark pixels). Vertical projection profiles similarly reveal column structure. This is the foundation of classical layout analysis — fast, interpretable, and sufficient for simple single-column or fixed-layout documents.

projection_profile.py

import numpy as np
import cv2
from scipy.signal import find_peaks

def horizontal_projection(binary: np.ndarray) -> np.ndarray:
    """Sum dark pixels per row. Returns 1D array of length=height."""
    # Invert: text=255→ invert→ text=0, background=255→0
    inv = 255 - binary
    return inv.sum(axis=1) // 255  # count of dark pixels per row

def vertical_projection(binary: np.ndarray) -> np.ndarray:
    """Sum dark pixels per column. Returns 1D array of length=width."""
    inv = 255 - binary
    return inv.sum(axis=0) // 255

def find_text_line_bounds(binary: np.ndarray,
                          min_gap: int = 5) -> list[tuple[int, int]]:
    """
    Detect text line bounding rows using horizontal projection.
    Returns list of (y_top, y_bottom) tuples for each text line.
    min_gap: minimum gap width (in pixels) between consecutive lines.
    """
    profile = horizontal_projection(binary)
    
    # Find runs of non-zero rows (text) separated by zero rows (gaps)
    in_text = False
    lines = []
    y_start = 0
    gap_count = 0
    
    for y, count in enumerate(profile):
        if count > 0 and not in_text:
            in_text = True
            y_start = y
            gap_count = 0
        elif count == 0 and in_text:
            gap_count += 1
            if gap_count >= min_gap:
                lines.append((y_start, y - gap_count))
                in_text = False
    
    if in_text:  # last line reaches image bottom
        lines.append((y_start, len(profile) - 1))
    
    return lines

def find_column_bounds(binary: np.ndarray,
                        min_gap: int = 20) -> list[tuple[int, int]]:
    """
    Detect column boundaries using vertical projection.
    Returns list of (x_left, x_right) tuples.
    min_gap: minimum column separator width in pixels.
    """
    profile = vertical_projection(binary)
    
    # Find wide vertical gaps (inter-column whitespace)
    in_col = False
    cols, x_start, gap_count = [], 0, 0
    for x, count in enumerate(profile):
        if count > 0 and not in_col:
            in_col = True; x_start = x; gap_count = 0
        elif count == 0 and in_col:
            gap_count += 1
            if gap_count >= min_gap:
                cols.append((x_start, x - gap_count))
                in_col = False
    if in_col: cols.append((x_start, len(profile) - 1))
    return cols
⚠️

When projection profiles fail: figures and drop caps

Projection profiles assume that dark pixels equal text. Large figures, filled tables, and decorative drop capitals create huge continuous dark regions that the projection profile misinterprets as giant text blocks. Drop caps (oversized first letters spanning multiple text rows) break line detection entirely — the capital spans several lines but is a single character. For documents with figures or complex typography, use connected component analysis or deep learning layout models instead of projection profiles.

03 · Connected Component Analysis

Grouping Pixels Into Meaningful Regions:
From Blobs to Text Blocks

Connected Component Analysis (CCA) labels each connected group of dark pixels with a unique ID. Each connected component has a bounding box, area, and aspect ratio — properties that allow classification into characters, words, lines, or noise. CCA is more robust than projection profiles for complex layouts because it operates on individual objects rather than row/column averages.

connected_components.py

import cv2
import numpy as np

def extract_text_regions(binary: np.ndarray,
                          min_area: int = 100,
                          max_area: int = 500_000) -> list[dict]:
    """
    Find candidate text regions using connected component analysis.
    Returns list of region dicts with bbox and classification hint.
    """
    inv = cv2.bitwise_not(binary)  # text=white for CCA
    
    # Find all connected components
    n_labels, labels, stats, centroids = cv2.connectedComponentsWithStats(
        inv, connectivity=8
    )
    
    regions = []
    for i in range(1, n_labels):  # skip label 0 = background
        x = stats[i, cv2.CC_STAT_LEFT]
        y = stats[i, cv2.CC_STAT_TOP]
        w = stats[i, cv2.CC_STAT_WIDTH]
        h = stats[i, cv2.CC_STAT_HEIGHT]
        area = stats[i, cv2.CC_STAT_AREA]
        
        if not (min_area <= area <= max_area): continue
        
        aspect = w / h if h > 0 else 0
        
        # Classify by geometry
        if   area < 800  and 0.3 <= aspect <= 2.5: region_type = "character"
        elif area < 8000 and 1.0 <= aspect <= 10:  region_type = "word"
        elif area > 50000:                             region_type = "figure_or_table"
        else:                                          region_type = "text_block"
        
        regions.append({
            "bbox":        (x, y, w, h),
            "area":        area,
            "aspect":      round(aspect, 2),
            "type_hint":   region_type,
            "centroid":    (int(centroids[i][0]), int(centroids[i][1]))
        })
    
    return sorted(regions, key=lambda r: (r["bbox"][1], r["bbox"][0]))  # top→bottom, left→right

def merge_to_text_lines(regions: list[dict],
                         y_tolerance: int = 8) -> list[list[dict]]:
    """
    Group nearby regions into text lines by Y proximity.
    Regions within y_tolerance pixels of the same Y band → same line.
    """
    if not regions: return []
    lines, current_line = [], [regions[0]]
    
    for reg in regions[1:]:
        prev_y = current_line[-1]["bbox"][1]
        curr_y = reg["bbox"][1]
        if abs(curr_y - prev_y) <= y_tolerance:
            current_line.append(reg)
        else:
            lines.append(sorted(current_line, key=lambda r: r["bbox"][0]))
            current_line = [reg]
    lines.append(current_line)
    return lines
04 · Reading Order Determination

Top-to-Bottom, Left-to-Right:
But Documents Are More Complex Than That

Reading order in most Western documents is top-to-bottom, left-to-right — but at the column level, not the page level. A two-column document should be read: column 1 top-to-bottom, then column 2 top-to-bottom. Magazine layouts add pull quotes, sidebars, and captions that interrupt the main text flow. Determining reading order requires understanding the column structure first, then applying a topological sort within each column.

Reading order algorithm: column-first, then top-to-bottom

Step 1: Detect column separators
Find vertical whitespace gaps of width > 40px spanning > 50% of page height. These are column gutters. Group text blocks by which column they belong to based on their x-coordinate ranges.

Step 2: Assign blocks to columns
For each text block: if block.x_center < gutter_x → column 1. Else → column 2.

Step 3: Sort within each column
Within each column: sort blocks by y_top (ascending). This gives correct reading order within each column.

Step 4: Concatenate columns in order
Final order: [col1_block1, col1_block2, ..., col2_block1, col2_block2, ...]

Exception: header and footer span all columns
Regions that span the full page width (x covers >80% of page) are headers/footers — read before columns (header) or after columns (footer), regardless of their column assignment.

reading_order.py

from dataclasses import dataclass
from typing import List

@dataclass
class TextBlock:
    x: int; y: int; w: int; h: int
    text: str = ""
    region_type: str = "body"

def assign_reading_order(
    blocks: List[TextBlock],
    page_width: int,
    header_zone: int = 150,   # pixels from top = header
    footer_zone: int = 150,   # pixels from bottom = footer
    page_height: int = 3507
) -> List[TextBlock]:
    """
    Sort text blocks into correct reading order.
    Handles single and double-column layouts.
    """
    # Separate header, footer, body
    headers = [b for b in blocks if b.y < header_zone]
    footers = [b for b in blocks if b.y > page_height - footer_zone]
    body    = [b for b in blocks if b not in headers and b not in footers]
    
    # Detect columns by looking for blocks with x_center in left vs right half
    midpoint = page_width // 2
    left_col  = [b for b in body if (b.x + b.w // 2) < midpoint]
    right_col = [b for b in body if (b.x + b.w // 2) >= midpoint]
    
    # Check if this is actually multi-column (large gap between left/right)
    if left_col and right_col:
        left_max_x  = max(b.x + b.w for b in left_col)
        right_min_x = min(b.x for b in right_col)
        gap = right_min_x - left_max_x
        is_two_column = gap > 40  # 40px gap = likely column gutter
    else:
        is_two_column = False
    
    if is_two_column:
        ordered_body = (
            sorted(left_col,  key=lambda b: b.y) +
            sorted(right_col, key=lambda b: b.y)
        )
    else:
        ordered_body = sorted(body, key=lambda b: (b.y, b.x))
    
    return (
        sorted(headers, key=lambda b: b.y) +
        ordered_body +
        sorted(footers, key=lambda b: b.y)
    )

06 · Deep Learning Layout Analysis: LayoutParser + Detectron2

When Rules Are Not Enough:
Learning Layout from Annotated Documents

Classical projection profiles and CCA work well for simple layouts — single column, standard margins, no complex graphics. For the full diversity of real-world documents (scientific papers, newspapers, legal filings, mixed-media), deep learning layout models trained on large annotated corpora dramatically outperform rule-based approaches. LayoutParser provides a unified API over these models.

PubLayNet — the standard document layout dataset

PubLayNet contains 360,000 annotated scientific paper pages with five region types: Text, Title, List, Table, Figure. Models trained on PubLayNet achieve mAP > 0.90 on scientific documents. The LayoutParser library wraps Detectron2-based models trained on PubLayNet and other corpora into a simple API.

model = lp.Detectron2LayoutModel(
    config_path="lp://PubLayNet/faster_rcnn_R_50_FPN_3x/config",
    model_path="lp://PubLayNet/faster_rcnn_R_50_FPN_3x/model_final",
    label_map={0: "Text", 1: "Title", 2: "List",
               3: "Table", 4: "Figure"},
    extra_config=["MODEL.ROI_HEADS.SCORE_THRESH_TEST", 0.8]

def analyse_layout(image_path: str) -> list[dict]:
    """
    Detect and classify document regions using LayoutParser.
    Returns list of regions with type, bbox, and OCR text.
    """
    img = cv2.imread(image_path)
    img_rgb = cv2.cvtColor(img, cv2.COLOR_BGR2RGB)
    
    # Detect layout blocks
    layout = model.detect(img_rgb)
    
    # Sort by reading order (top-to-bottom, left-to-right)
    layout = lp.Layout([b for b in layout if b.score > 0.8])
    layout = layout.sort(key=lambda b: (b.block.y_1, b.block.x_1))
    
    results = []
    for block in layout:
        region_type = block.type
        x1, y1, x2, y2 = [int(c) for c in
                           [block.block.x_1, block.block.y_1,
                            block.block.x_2, block.block.y_2]]
        
        # Crop the region from image
        crop = img_rgb[y1:y2, x1:x2]
        
        # OCR text regions only (skip Figure and Table for now)
        text = ""
        if region_type in ("Text", "Title", "List"):
            psm = "--psm 6"  # single uniform block
            text = pytesseract.image_to_string(
                Image.fromarray(crop), config=f"--oem 1 {psm}"
            ).strip()
        
        results.append({
            "type":  region_type,
            "bbox":  (x1, y1, x2 - x1, y2 - y1),
            "score": round(block.score, 3),
            "text":  text
        })
    
    return results

07 · Bounding Box Hierarchies and IoU

Relating Regions to Each Other:
Overlap, Containment, and Conflict Resolution

Layout detectors often produce overlapping bounding boxes — two regions assigned to slightly different boundaries for the same physical area. Intersection over Union (IoU) measures how much two bounding boxes overlap. Non-Maximum Suppression (NMS) uses IoU to eliminate duplicate detections. Understanding these tools is essential for building robust layout pipelines.

IoU calculation: worked example

Box A (layout model): x=100, y=200, w=400, h=300 → area = 120,000px²
Box B (layout model): x=120, y=180, w=380, h=320 → area = 121,600px²

Intersection:
x_inter = max(100,120) = 120, x_end = min(500,500) = 500 → inter_w = 380
y_inter = max(200,180) = 200, y_end = min(500,500) = 500 → inter_h = 300
Intersection area = 380 × 300 = 114,000 px²

Union: 120,000 + 121,600 - 114,000 = 127,600 px²

IoU = 114,000 / 127,600 = 0.893
IoU > 0.85 → these are duplicate detections of the same region → suppress the lower-confidence one

iou_nms.py — overlap and deduplication

import numpy as np

def compute_iou(box_a: tuple, box_b: tuple) -> float:
    """
    Compute IoU between two (x, y, w, h) bounding boxes.
    Returns float in [0, 1]. 0 = no overlap, 1 = identical.
    """
    ax, ay, aw, ah = box_a
    bx, by, bw, bh = box_b
    
    inter_x1 = max(ax, bx);       inter_y1 = max(ay, by)
    inter_x2 = min(ax+aw, bx+bw); inter_y2 = min(ay+ah, by+bh)
    
    inter_w = max(0, inter_x2 - inter_x1)
    inter_h = max(0, inter_y2 - inter_y1)
    intersection = inter_w * inter_h
    
    union = aw * ah + bw * bh - intersection
    return intersection / union if union > 0 else 0.0

def nms(regions: list[dict],
        iou_threshold: float = 0.5) -> list[dict]:
    """
    Non-Maximum Suppression: remove duplicate bounding boxes.
    Keeps highest-confidence box when IoU > threshold.
    regions: list of {"bbox": (x,y,w,h), "score": float, ...}
    """
    if not regions: return []
    
    # Sort by score descending
    sorted_regions = sorted(regions, key=lambda r: r["score"], reverse=True)
    kept = []
    
    while sorted_regions:
        best = sorted_regions.pop(0)
        kept.append(best)
        sorted_regions = [
            r for r in sorted_regions
            if compute_iou(best["bbox"], r["bbox"]) < iou_threshold
        ]
    
    return kept
08 · Full Layout-Aware OCR Pipeline

Combining Layout Analysis
With Tesseract for Any Document Type

layout_ocr_pipeline.py — complete production pipeline

import cv2, numpy as np, pytesseract
from PIL import Image
from dataclasses import dataclass, field

@dataclass
class DocumentRegion:
    region_type: str      # header|title|body|table|figure|footer
    bbox: tuple           # (x, y, w, h)
    text: str = ""
    reading_order: int = 0

def layout_aware_ocr(
    image: np.ndarray,
    use_ml_layout: bool = False,  # True = LayoutParser, False = classical
    lang: str = "eng"
) -> list[DocumentRegion]:
    """
    Full layout-aware OCR pipeline.
    1. Pre-process image
    2. Detect layout regions (classical or ML)
    3. Sort by reading order
    4. OCR each text region with appropriate PSM
    5. Return ordered list of regions with text
    """
    h, w = image.shape[:2]
    
    # Pre-process
    grey = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY) if image.ndim == 3 else image
    clahe = cv2.createCLAHE(clipLimit=2.0, tileGridSize=(8,8))
    grey = clahe.apply(grey)
    _, binary = cv2.threshold(grey, 0, 255, cv2.THRESH_BINARY + cv2.THRESH_OTSU)
    
    # Detect layout regions
    if use_ml_layout:
        import layoutparser as lp
        model = lp.Detectron2LayoutModel("lp://PubLayNet/faster_rcnn_R_50_FPN_3x/config")
        raw_layout = model.detect(cv2.cvtColor(image, cv2.COLOR_BGR2RGB))
        regions = [DocumentRegion(
            region_type=b.type.lower(),
            bbox=(int(b.block.x_1), int(b.block.y_1),
                  int(b.block.x_2-b.block.x_1), int(b.block.y_2-b.block.y_1))
        ) for b in raw_layout if b.score > 0.75]
    else:
        # Classical: project profiles → find column bounds → create regions
        inv = cv2.bitwise_not(binary)
        col_profile = inv.sum(axis=0) // 255
        # Simple heuristic: split at widest vertical gap
        mid = w // 2
        gutter = min(range(mid - 100, mid + 100), key=lambda x: col_profile[x])
        gap_width = sum(1 for v in col_profile[gutter-20:gutter+20] if v < 5)
        
        if gap_width > 30:  # two-column layout
            regions = [
                DocumentRegion("body", (0, 0, gutter, h)),
                DocumentRegion("body", (gutter + 20, 0, w - gutter - 20, h))
            ]
        else:
            regions = [DocumentRegion("body", (0, 0, w, h))]
    
    # OCR each text region
    for i, region in enumerate(regions):
        if region.region_type in ("figure", "table"): continue
        x, y, rw, rh = region.bbox
        crop = grey[y:y+rh, x:x+rw]
        psm = "7" if region.region_type == "title" else "6"
        region.text = pytesseract.image_to_string(
            Image.fromarray(crop),
            lang=lang, config=f"--oem 1 --psm {psm}"
        ).strip()
        region.reading_order = i
    
    return sorted(regions, key=lambda r: r.reading_order)
09 · Assessment

Module 3 Quiz

1. A two-column medical report processed with Tesseract PSM 3 produces "The patient presented Blood pressure 140/90 with chest pain Heart rate 72 on 14 March". What is the layout failure and the exact fix?

Correct. PSM 3's auto-segmentation detects column separators but reads within its detected structure using horizontal bands — the interleaving of left and right columns occurs when PSM 3 incorrectly estimates the column boundaries or reads across a narrow gutter. The reliable fix is to take control of column detection explicitly: compute the vertical projection profile, find the gutter, split, and OCR each column independently. This guarantees correct reading order regardless of PSM 3's internal column detection quality. Running PSM 6 on individual column crops is faster and more accurate than PSM 3 on the full page for multi-column documents.

2. LayoutParser with PubLayNet detects a signature block at the bottom of a business contract as a "Figure" region (IoU=0.87 with the correct region). What caused this and which fix has the lowest implementation cost?

Correct. Domain mismatch is the most frequent LayoutParser failure mode in production. PubLayNet's training distribution (360K scientific paper pages) contains zero business contract pages with signature blocks. The model generalises by assigning the nearest known label — the mixed-ink content of a signature block resembles a Figure more than any other PubLayNet category. The text-content post-processing check is the fastest production fix: a Figure region with substantial OCR output is not a figure. DocLayNet is the correct long-term fix as it was trained on diverse business documents. Full fine-tuning is only cost-effective when document volume is high enough to justify the annotation investment.

3. A horizontal projection profile shows row values [0,0,12,14,15,8,0,0,0,18,19,17,0,0]. With min_gap=2, how many text lines are detected and what are their y-boundaries?

Correct. The algorithm tracks transitions: zero→nonzero opens a segment, nonzero→zero begins gap counting, gap_count≥min_gap closes the segment and resets. At row 6 (first zero), gap_count=1. At row 7, gap_count=2 which equals min_gap=2 — segment 1 closes. At row 9 (nonzero), a new segment opens. End of array closes segment 2. Result: two segments. The min_gap parameter is the most important tuning variable for projection-based line detection: it must be set larger than within-character gaps (dots of 'i', gaps in ':') but smaller than inter-line whitespace.

4. Two layout detections have bounding boxes: A=(x=50, y=100, w=300, h=200) and B=(x=200, y=150, w=300, h=200). Compute IoU. Does NMS with threshold=0.5 suppress either box?

Correct. IoU = intersection / union = 22,500 / 97,500 = 0.231. This is a partial overlap between two adjacent text blocks — common in complex layouts where a paragraph extends into the margin area of an adjacent column. At NMS threshold 0.5, boxes with IoU < 0.5 are always kept as separate regions. Only IoU ≥ 0.5 triggers suppression. The threshold 0.5 is the standard starting point for document layout NMS: it retains adjacent/overlapping distinct regions while eliminating near-duplicate detections of the same region (which typically have IoU > 0.8).

5. A scientific paper has a full-width abstract, then two body columns, then a full-width references section. Why does "sort by y then x" produce wrong reading order, and what is the correct algorithm?

Correct. The failure of "sort by y then x" on multi-column documents is fundamental: both columns start at approximately the same y-coordinate, so the sort interleaves them at each row rather than reading each column completely before starting the next. The zone-based algorithm (identify spanning regions, assign narrow regions to columns, sort within each zone) is the correct approach.
