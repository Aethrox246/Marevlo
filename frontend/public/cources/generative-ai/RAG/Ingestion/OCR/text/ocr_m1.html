01 · Why Pre-processing Matters More Than the OCR Engine

Garbage In, Garbage Out:
The Pre-processing Hierarchy

The OCR engine (Tesseract, TrOCR, PaddleOCR) is only as good as the image it receives. A state-of-the-art transformer model given a poorly binarised, skewed image will produce worse results than Tesseract 3 given a clean, well-prepared image. Pre-processing is not a nice-to-have — it is typically the highest-leverage step in the entire pipeline, capable of dropping Character Error Rate by 50% or more on difficult documents.

Pre-processing transformation order

① Greyscale conversion

Collapse 3-channel RGB to 1-channel intensity. Reduces compute by 3×. Eliminates colour variation that confuses binarisation. Standard for all document OCR — colour is rarely informative for text recognition.

↓

② Contrast enhancement (CLAHE)

Boost local contrast without amplifying global noise. Critical for uneven illumination (curved pages, phone-camera captures). Run BEFORE binarisation so the threshold has meaningful contrast to work with.

↓

③ Denoising

Remove salt-and-pepper noise (scanner dust) and Gaussian noise (camera ISO). Run BEFORE binarisation — noise amplifies into isolated black pixels that the OCR mistakes for punctuation.

↓

④ Binarisation

Convert greyscale to pure black/white. The single most impactful step. Otsu for uniform illumination; Sauvola/adaptive for uneven. A wrong threshold deletes entire words.

↓

⑤ Deskew

Detect and correct document rotation. Run AFTER binarisation — the Hough line detector works better on binary images. Correct before Tesseract's line segmentation fires.

↓

⑥ Morphological operations (optional)

Dilate to close gaps in broken characters. Erode to separate touching characters. Use carefully — aggressive morphology damages character shapes.

02 · Greyscale and Contrast Enhancement

RGB to Luminance:
The Right Conversion and Why It Matters

Converting RGB to greyscale is not simply averaging the three channels — the human visual system is most sensitive to green (59%), then red (30%), then blue (11%). The ITU-R BT.601 luminance formula weights accordingly. Using the wrong conversion (arithmetic mean) reduces contrast for text printed in colours where blue dominates.

Greyscale conversion: the correct luminance formula

ITU-R BT.601 (standard, used by OpenCV cv2.COLOR_BGR2GRAY):
Y = 0.299×R + 0.587×G + 0.114×B

Example: dark blue ink on white paper (R=20, G=20, B=180)
BT.601: 0.299×20 + 0.587×20 + 0.114×180 = 5.98 + 11.74 + 20.52 = 38.2 (dark — correct)
Simple avg: (20+20+180)/3 = 73.3 (much brighter — blue ink appears lighter, harder to threshold)
💡

CLAHE for uneven illumination

Contrast Limited Adaptive Histogram Equalisation (CLAHE) divides the image into small tiles (8×8 by default) and equalises each tile's histogram independently. This boosts contrast in dim regions (e.g., the centre of a curved book page) without blowing out bright regions. The "contrast limited" part clips the histogram before redistribution, preventing noise amplification. Always apply CLAHE on greyscale before binarisation for phone-camera captures and curved documents.

greyscale_contrast.py

import cv2
import numpy as np

def greyscale_and_enhance(image_path: str) -> np.ndarray:
    """
    Load image, convert to greyscale with correct luminance weights,
    apply CLAHE for local contrast enhancement.
    """
    img = cv2.imread(image_path)  # BGR by default
    
    # Correct luminance conversion (ITU-R BT.601)
    grey = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
    
    # CLAHE — essential for uneven illumination
    clahe = cv2.createCLAHE(
        clipLimit=2.0,      # prevent noise amplification
        tileGridSize=(8, 8)  # 8×8 tiles; smaller = more local
    )
    enhanced = clahe.apply(grey)
    
    # Gamma correction for very dark scans
    # gamma < 1 brightens midtones; gamma > 1 darkens
    gamma = 1.2
    lut = np.array([
        int((min(i / 255.0, 1.0) ** (1.0 / gamma)) * 255)
        for i in range(256)
    ], dtype=np.uint8)
    brightened = cv2.LUT(enhanced, lut)
    
    return brightened

# Quick check: mean pixel value should be 100-150 for well-lit doc
# If mean < 80: very dark scan, increase gamma
# If mean > 200: very bright (mostly white) — likely already good
03 · Binarisation: Otsu's Method Step by Step

Finding the Optimal Threshold
Without Knowing It in Advance

Binarisation converts a greyscale image to pure black and white by choosing a threshold intensity value T: pixels above T become white (background), below T become black (text). The challenge: the correct T varies by document. Otsu's method finds T automatically by maximising the inter-class variance between the foreground (text) and background pixel distributions.

Otsu's method: worked numerical example

Simplified 8-pixel image (2 text pixels, 6 background pixels):
Pixel intensities: [30, 40, 180, 190, 200, 195, 185, 210]

Try threshold T = 100:
Class 0 (text, ≤100): pixels [30, 40] → mean μ₀=35, weight ω₀=0.25
Class 1 (bg, >100): pixels [180..210] → mean μ₁=193, weight ω₁=0.75

Inter-class variance = ω₀ × ω₁ × (μ₀ - μ₁)²
= 0.25 × 0.75 × (35 - 193)² = 0.1875 × 24964 = 4,680.75

Try T = 150 (suboptimal):
Class 0: [30,40,180?] — no, 180>150 so: [30,40] still → same result
At this data, T=100 and T=150 give same classes.
Otsu tests all 256 possible T values and picks the one with maximum inter-class variance.
❌ When Otsu fails: uneven illumination
Document photographed under a desk lamp: left side bright (background=220), right side dim (background=140). Otsu finds a single global threshold T≈180. Left side: text pixels at 80 → correctly below T. Right side: background at 140 → below T → classified as text. The entire right margin becomes black noise.
✓ Adaptive thresholding solves this
Sauvola thresholding computes T(x,y) = μ(x,y) × (1 + k × (σ(x,y)/R - 1)) at each pixel using a local window. Left side: T≈180 (high local mean). Right side: T≈120 (lower local mean). Both correctly separate text from background regardless of global illumination variation.
04 · Adaptive Thresholding: Sauvola and Bradley

Local Thresholds for Uneven
Illumination and Aged Documents

Adaptive thresholding computes a different threshold for each pixel based on the statistics of its local neighbourhood. This handles illumination gradients, paper colour variation, ink bleed, and age-related browning — all of which cause global threshold methods to fail catastrophically.

binarisation.py — Otsu and adaptive methods

import cv2
import numpy as np
from skimage.filters import threshold_sauvola

def binarise_otsu(grey: np.ndarray) -> np.ndarray:
    """Global Otsu threshold. Best for uniform illumination."""
    _, binary = cv2.threshold(
        grey, 0, 255,
        cv2.THRESH_BINARY + cv2.THRESH_OTSU  # 0 = find automatically
    )
    return binary

def binarise_adaptive(grey: np.ndarray,
                       block_size: int = 35,
                       C: int = 10) -> np.ndarray:
    """
    Adaptive Gaussian threshold.
    block_size: neighbourhood size (must be odd). Larger = smoother.
    C: constant subtracted from local mean. Higher = darker threshold.
    Best for: even text density, mild illumination variation.
    """
    binary = cv2.adaptiveThreshold(
        grey, 255,
        cv2.ADAPTIVE_THRESH_GAUSSIAN_C,  # Gaussian-weighted neighbourhood
        cv2.THRESH_BINARY,
        block_size,
        C
    )
    return binary

def binarise_sauvola(grey: np.ndarray,
                      window_size: int = 25,
                      k: float = 0.2) -> np.ndarray:
    """
    Sauvola method — best for aged/degraded documents, uneven illumination.
    T(x,y) = mean × (1 + k × (std/R - 1))
    window_size: local window. k: sensitivity (0.1=lenient, 0.3=strict).
    R: dynamic range of standard deviation (default 128).
    """
    thresh_map = threshold_sauvola(grey, window_size=window_size, k=k)
    binary = (grey > thresh_map).astype(np.uint8) * 255
    return binary

def choose_binarisation(grey: np.ndarray) -> np.ndarray:
    """
    Heuristic selector: choose method based on illumination uniformity.
    Measure: coefficient of variation of a blurred version of the image.
    High CV = uneven illumination → use Sauvola.
    """
    blurred = cv2.GaussianBlur(grey, (51, 51), 0)
    mean = blurred.mean()
    std  = blurred.std()
    cv_illum = std / (mean + 1e-6)  # coefficient of variation
    
    if cv_illum > 0.15:   # >15% illumination variation → adaptive
        print(f"CV={cv_illum:.3f}: using Sauvola (uneven illumination)")
        return binarise_sauvola(grey)
    else:                   # uniform illumination → Otsu
        print(f"CV={cv_illum:.3f}: using Otsu (uniform illumination)")
        return binarise_otsu(grey)

05 · Denoising Methods

Removing Scanner Dust and Camera Noise
Without Destroying Character Detail

Noise in document images comes from two primary sources: salt-and-pepper noise (isolated white or black pixels from scanner dust or sensor hot pixels) and Gaussian noise (random intensity variation from camera ISO). Each requires a different denoising approach — the wrong method either fails to remove the noise or smooths away fine character strokes.

Salt-and-pepper noise → Median filter

How median filter works on a 3×3 window:
Neighbours: [255, 30, 255, 28, 0, 255, 255, 40, 255]
(the 0 is a salt-and-pepper black dot in background)
Sorted: [0, 28, 30, 40, 255, 255, 255, 255, 255]
Median: 255 ← the noise pixel becomes background (correct)

Gaussian blur would give mean ≈ 194 — grey, not clean white
# 3×3 median removes isolated noise pixels denoised = cv2.medianBlur(grey, ksize=3) # ksize=3: removes single-pixel noise # ksize=5: removes larger noise clusters # WARNING: ksize>5 smears fine strokes (serifs, thin lines)

Gaussian noise → NLMeans or Gaussian blur

Non-Local Means (NLMeans) denoising compares patches across the entire image — pixels with similar surroundings average together. Better than Gaussian blur for preserving character edges because it is edge-aware.

# NLMeans — best quality, slower denoised = cv2.fastNlMeansDenoising( grey, h=10, # filter strength: 5-15 typical templateWindowSize=7, # patch size to compare searchWindowSize=21 # search area ) # Gaussian blur — faster, less edge-aware blurred = cv2.GaussianBlur(grey, (3, 3), sigmaX=0) # (3,3) kernel: gentle. (5,5): stronger. Never use >5 for text.
⚠️

When denoising harms OCR: over-smoothing fine strokes

Aggressive denoising is one of the most common causes of introduced OCR errors. A median filter with ksize=7 or Gaussian with sigma=3 will smear the thin strokes of letters like "i", "l", "1", the serif details that distinguish "l" from "I", and the dots of ":", ";", "!". Always validate with a visual check on character-level crops after denoising. If serifs are smearing, reduce the kernel size. If thin character strokes are disappearing, the filter is too strong.

06 · Deskew: Detecting and Correcting Document Rotation

The Hough Transform for Lines:
Finding the True Horizontal

A document rotated by even 1-2° causes Tesseract's line segmentation to merge adjacent text lines, producing word salad. Deskew detects the dominant text baseline angle using the Hough line transform, then rotates the image to correct it. The key insight: text lines produce clusters of parallel line detections — the dominant cluster angle is the skew angle.

deskew.py — Hough transform deskew

import cv2
import numpy as np
from scipy.ndimage import interpolation

def detect_skew_angle(binary: np.ndarray,
                       angle_range: float = 15.0) -> float:
    """
    Detect document skew using Hough probabilistic line transform.
    Returns angle in degrees (positive = clockwise rotation needed).
    binary: binarised image (text=black, background=white or vice versa).
    """
    # Invert if background is white (Hough works on bright features)
    inv = cv2.bitwise_not(binary)
    
    # Detect lines using Hough probabilistic transform
    lines = cv2.HoughLinesP(
        inv,
        rho=1,              # pixel resolution
        theta=np.pi/180,   # angle resolution: 1 degree
        threshold=100,      # minimum votes (line length)
        minLineLength=100,  # minimum line segment length in pixels
        maxLineGap=20       # maximum gap within a line
    )
    
    if lines is None: return 0.0
    
    # Compute angle of each detected line
    angles = []
    for line in lines:
        x1, y1, x2, y2 = line[0]
        if x2 - x1 == 0: continue  # skip vertical lines
        angle = np.degrees(np.arctan2(y2 - y1, x2 - x1))
        # Only keep near-horizontal lines (text baselines)
        if abs(angle) < angle_range:
            angles.append(angle)
    
    if not angles: return 0.0
    
    # Median angle — robust to outlier lines from figures/borders
    skew_angle = np.median(angles)
    print(f"Detected {len(angles)} text lines, skew angle: {skew_angle:.2f}°")
    return skew_angle

def deskew(image: np.ndarray, angle: float) -> np.ndarray:
    """
    Rotate image by -angle to correct skew.
    Uses scipy for high-quality rotation (no black borders from cv2 crop).
    """
    if abs(angle) < 0.5:  # skip trivial corrections
        return image
    return interpolation.rotate(
        image,
        -angle,           # negate: rotate opposite to detected tilt
        reshape=False,   # keep original dimensions
        mode='nearest',  # fill border with nearest pixel (white for bg)
        cval=255          # fallback fill colour (white)
    ).astype(np.uint8)

def deskew_image(grey: np.ndarray) -> tuple[np.ndarray, float]:
    """Full deskew pipeline: binarise → detect → correct."""
    _, binary = cv2.threshold(grey, 0, 255, cv2.THRESH_BINARY + cv2.THRESH_OTSU)
    angle = detect_skew_angle(binary)
    corrected = deskew(grey, angle)
    return corrected, angle
⚠️

When Hough deskew goes wrong: decorative borders and tables

The Hough transform finds all straight lines in the image — not just text baselines. Decorative borders, table ruling lines, and figures introduce near-horizontal lines at 0°, which can pull the median angle toward 0° even when text is skewed. Mitigation: filter lines by length (text baselines are long and consistent) and by position (avoid lines at the very edge of the page where borders live). For documents with complex graphics, use the minimum enclosing bounding box of large text blocks instead of Hough lines for angle estimation.

07 · Morphological Operations

Dilate, Erode, Open, Close:
Fixing Broken Characters and Removing Noise

Morphological operations transform binary images using a structuring element (kernel). They can: close gaps in broken characters (dilation), remove isolated noise pixels (erosion), or combine both (opening = erode then dilate; closing = dilate then erode). Use sparingly — morphology changes character shapes and can create new recognition errors.

morphological_ops.py

import cv2
import numpy as np

def remove_noise_blobs(binary: np.ndarray,
                        min_area: int = 50) -> np.ndarray:
    """
    Remove connected components smaller than min_area pixels.
    More targeted than morphological opening — preserves punctuation.
    """
    # Find all connected components
    n_labels, labels, stats, _ = cv2.connectedComponentsWithStats(
        cv2.bitwise_not(binary), connectivity=8
    )
    clean = binary.copy()
    for i in range(1, n_labels):  # skip label 0 (background)
        area = stats[i, cv2.CC_STAT_AREA]
        if area < min_area:         # small blob = noise
            clean[labels == i] = 255  # paint it white (remove)
    return clean

def close_character_gaps(binary: np.ndarray) -> np.ndarray:
    """
    Closing: fill small gaps in broken character strokes.
    Use for degraded or photocopied documents.
    """
    # Work on inverted (text=white, bg=black) for closing
    inv = cv2.bitwise_not(binary)
    kernel = cv2.getStructuringElement(cv2.MORPH_RECT, (2, 2))
    closed = cv2.morphologyEx(inv, cv2.MORPH_CLOSE, kernel)
    return cv2.bitwise_not(closed)

# Border removal — useful for scanned documents with frame artefacts
def remove_border(binary: np.ndarray, margin: int = 10) -> np.ndarray:
    """Remove scanner border artefacts by masking the edge region."""
    h, w = binary.shape
    mask = np.zeros_like(binary)
    mask[margin:h-margin, margin:w-margin] = 255
    return cv2.bitwise_and(binary, mask)
08 · The Complete Pre-processing Pipeline

Putting It All Together:
One Function, Production-Ready

preprocess_pipeline.py — full production pipeline

import cv2
import numpy as np
from dataclasses import dataclass
from skimage.filters import threshold_sauvola
from scipy.ndimage import interpolation

@dataclass
class PreprocessResult:
    image:      np.ndarray  # final processed binary image
    skew_angle: float       # corrected rotation in degrees
    method:     str         # binarisation method used
    warnings:   list[str]   # e.g. "low contrast", "high skew"

def preprocess(
    image_path: str,
    target_dpi: int = 300,
    doc_type: str = "standard"  # "standard" | "degraded" | "photo"
) -> PreprocessResult:
    warnings = []
    
    # ① Load and validate
    img = cv2.imread(image_path)
    if img is None: raise ValueError(f"Cannot load: {image_path}")
    
    # ② Greyscale conversion
    grey = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
    
    # ③ Contrast check and CLAHE
    contrast_cv = grey.std() / (grey.mean() + 1e-6)
    if contrast_cv < 0.1: warnings.append("low_contrast")
    clahe = cv2.createCLAHE(clipLimit=2.0, tileGridSize=(8,8))
    grey = clahe.apply(grey)
    
    # ④ Denoising (method by doc type)
    if doc_type == "photo":
        grey = cv2.fastNlMeansDenoising(grey, h=10)
    else:
        grey = cv2.medianBlur(grey, ksize=3)
    
    # ⑤ Binarisation (adaptive for degraded)
    if doc_type == "degraded":
        thresh_map = threshold_sauvola(grey, window_size=25, k=0.2)
        binary = (grey > thresh_map).astype(np.uint8) * 255
        method = "sauvola"
    else:
        _, binary = cv2.threshold(grey, 0, 255, cv2.THRESH_BINARY+cv2.THRESH_OTSU)
        method = "otsu"
    
    # ⑥ Deskew
    inv = cv2.bitwise_not(binary)
    lines = cv2.HoughLinesP(inv, 1, np.pi/180, 100, 100, 20)
    skew = 0.0
    if lines is not None:
        angles = [np.degrees(np.arctan2(l[0][3]-l[0][1],l[0][2]-l[0][0]))
                 for l in lines if abs(l[0][2]-l[0][0]) > 50]
        if angles:
            skew = float(np.median(angles))
            if abs(skew) > 3.0: warnings.append(f"high_skew_{skew:.1f}deg")
    if abs(skew) > 0.5:
        binary = interpolation.rotate(binary, -skew, reshape=False,
                                       mode='nearest', cval=255).astype(np.uint8)
    
    # ⑦ Remove small noise blobs
    n, labels, stats, _ = cv2.connectedComponentsWithStats(cv2.bitwise_not(binary))
    for i in range(1, n):
        if stats[i, cv2.CC_STAT_AREA] < 30:
            binary[labels == i] = 255
    
    return PreprocessResult(binary, skew, method, warnings)

09 · Assessment

Module 1 Quiz

1. You apply Otsu binarisation to a document photographed with a desk lamp shining from the left side. The left half is correct but the right half is entirely black. What is the root cause and the correct fix?

Correct. This is the canonical Otsu failure mode. A single global threshold cannot correctly separate foreground and background when the illumination level changes significantly across the image. The histogram shows two overlapping distributions rather than two clean peaks, and the threshold falls in the wrong place for the dim region. CLAHE (Contrast Limited Adaptive Histogram Equalisation) normalises local contrast before binarisation, shrinking the illumination gradient so a global threshold becomes viable again. Sauvola is the more robust choice when CLAHE cannot fully correct the gradient.

2. After applying a 5×5 median filter to a scan, Tesseract starts confusing "l" (lowercase L) with "I" (uppercase I) much more frequently. What caused this new error and what is the correct filter size?

Correct. Filter kernel size must be proportional to the feature size you want to preserve. At 300 DPI, serif details are 2–4 pixels wide; a ksize=5 kernel with 2.5-pixel radius smooths these entirely. Connected component filtering is the superior alternative for removing scanner dust because it operates on the binary image after binarisation, identifying and removing isolated blobs by area — a 3-pixel dust speck has area ≈9 pixels, while the dot on an "i" has area ≈30–50 pixels, allowing precise removal without any smoothing of character shapes.

3. Your Hough deskew pipeline detects a 0.3° skew and skips correction (threshold: |angle| < 0.5°). A colleague insists this will cause line merging. Who is correct?

Correct. The impact of a skew angle depends on both the angle and the page width. At 0.3° on A4 at 300 DPI, the 18-pixel vertical offset is well within the inter-line gap for standard fonts. Rotation correction is not free — warpAffine or scipy.interpolation.rotate introduces sub-pixel interpolation errors that slightly blur character edges at every rotation step. Correcting sub-0.5° skews costs accuracy in exchange for a correction that provides no measurable benefit. The threshold should be set based on this tradeoff, not on "always correct" or "correct everything".

4. You are processing a 19th-century newspaper. After Otsu binarisation, characters in the degraded areas are fragmented into broken strokes. Morphological closing with a 3×3 kernel fixes some characters but merges others. What is the underlying problem and the correct solution?

Correct. Applying morphology to fix binarisation errors is treating the symptom rather than the cause. Sauvola's window-based local statistics are specifically designed for this scenario: even when faded ink produces only a slight local contrast difference from the aged background, the local standard deviation σ captures this signal. The threshold T(x,y) = μ × (1 + k × (σ/R − 1)) adapts to be lower in faded regions, correctly capturing the ink. Global Otsu sees the full-image histogram dominated by the background distribution and places the threshold too high for the faded ink regions.

5. A document has a yellow highlighted section. After greyscale conversion and Otsu binarisation, text inside the highlight is correctly classified, but the overall Otsu threshold is higher than optimal for the rest of the page, causing some light grey text to be lost. What is the most targeted fix?

Correct. The yellow highlight's high-luminance pixels (Y ≈ 226 from BT.601 formula) inflate the global histogram's bright peak, pushing Otsu's threshold upward from where it should be for the non-highlighted text. Option B describes the masking approach but doesn't specify using the local background intensity — just setting highlighted pixels to white achieves the same effect. Option D is the most complete: both the masking strategy and the Sauvola alternative are valid. Sauvola is often simpler in practice because it handles the influence of the highlight region automatically through local windowing.
