Levenshtein · RapidFuzz · Domain Vocabulary · Regex Validation · BERT Rescoring · Routing

Raw OCR output is a draft. Post-processing turns that draft into structured, validated data. This module covers what post-processing can and cannot fix, Levenshtein edit distance with length-adaptive thresholds, OCR substitution pre-normalisation, RapidFuzz vocabulary matching, domain word list construction, abbreviation exclusion sets, regex field validators for dates, amounts, postcodes, and NHS numbers, BERT masked LM rescoring of n-best candidates, confidence-based rejection routing, and the compound error model that explains why field accuracy degrades faster than CER.

01 · What Post-processing Can and Cannot Fix

The Correction Boundary:
Where Errors Become Unrecoverable

Correctable

Single-char substitution in known vocab. "diseasc" to "disease" via domain fuzzy match.
Missing word spaces. "bloodpressure" to "blood pressure" via tokenisation.
Format normalisation. "12/03/24" to ISO 8601; "l,234.50" to 1234.50 via DIGIT_FIX.
Consistent OCR substitutions. rn to m, vv to w, 0 to O in alpha context — systematic and reversible.

Not correctable

Deleted characters. "prssure" from "pressure" — candidate set too ambiguous.
Short strings with multiple errors. "St" from "Statin" — too few characters for reliable match.
Multiple simultaneous errors. 2+ substitutions in one token — wrong match probability high.
OOV proper nouns. "Dr. Hjálmarsdóttir" — not in any vocabulary; no anchor for correction.
02 · Levenshtein With Adaptive Threshold

Length-Proportional Matching:
max(2, len // 4)

A fixed edit distance threshold of 2 is appropriate for a 10-character word but catastrophically permissive for a 4-character word — "cold" at edit-2 matches "cold", "cord", "fold", and many others. The threshold must scale with word length: max(2, len // 4).

fuzzy_correction.py

from rapidfuzz import process, fuzz
import re

OCR_SUBS = [
    (re.compile(r"rn"),  "m"),
    (re.compile(r"vv"),  "w"),
    (re.compile(r"(?<=\d)O(?=\d)"), "0"),
    (re.compile(r"(?<=\d)l(?=\d)"), "1"),
    (re.compile(r"(?<=[a-z])0(?=[a-z])", re.I), "o"),
]

def prenormalize(text: str) -> str:
    for pat, repl in OCR_SUBS: text = pat.sub(repl, text)
    return text

def adaptive_threshold(word: str) -> int:
    return max(2, len(word) // 4)

def fuzzy_correct_token(token: str, vocabulary: list,
                         abort_short: int = 4) -> str:
    """
    abort_short: skip fuzzy matching for tokens shorter than this.
    Short tokens: degenerate threshold, candidate set too large.
    """
    if len(token) < abort_short: return token
    normalised = prenormalize(token)
    threshold  = adaptive_threshold(normalised)
    result     = process.extractOne(
        normalised, vocabulary, scorer=fuzz.ratio,
        score_cutoff=100 - threshold * 10)
    return result[0] if result else token

MEDICAL_ABBREVS = {
    "NHS","GP","COPD","HTN","T2DM","MI","CVA","ECG",
    "BP","HR","SpO2","BMI","ICU","PRN","QDS","TDS",
}

def correct_text(text: str, vocabulary: list,
                  abbreviations: set = None) -> str:
    abbrevs = abbreviations or MEDICAL_ABBREVS
    tokens  = text.split()
    corrected = []
    for tok in tokens:
        clean = tok.strip(".,;:")
        if clean.upper() in abbrevs: corrected.append(tok)
        else:  corrected.append(fuzzy_correct_token(clean, vocabulary))
    return " ".join(corrected)
03 · Domain Vocabulary Construction

Frequency-Weighted Corpus Learning
Plus Authoritative Drug and Procedure Terms

domain_vocabulary.py

from collections import defaultdict
import re, unicodedata

class DomainVocabulary:
    def __init__(self):
        self.word_freq    = defaultdict(int)
        self.authoritative = set()

    def ingest_document(self, text: str) -> None:
        words = re.findall(r"[A-Za-z][a-z]{2,}", text)
        for w in words:
            self.word_freq[unicodedata.normalize("NFC", w.lower())] += 1

    def add_authoritative(self, terms: list) -> None:
        """
        Add terms that must appear in vocabulary regardless of corpus frequency.
        Drug names, procedure codes, specialist terms are rare in text but
        critical for extraction — give them high synthetic frequency weight.
        """
        for term in terms:
            t = term.lower()
            self.authoritative.add(t)
            self.word_freq[t] = max(self.word_freq[t], 1000)

    def get_vocabulary(self, min_freq: int = 3) -> list:
        return sorted([w for w, c in self.word_freq.items()
                        if c >= min_freq or w in self.authoritative])

DRUG_NAMES = [
    "metformin","atorvastatin","amlodipine","ramipril",
    "omeprazole","sertraline","levothyroxine","salbutamol",
    "lisinopril","paracetamol","ibuprofen","prednisolone",
]
vocab = DomainVocabulary()
vocab.add_authoritative(DRUG_NAMES)
04 · Regex Field Validation

Dates, Amounts, UK Postcodes,
and NHS Number Checksum

field_validators.py

import re
from datetime import datetime

DIGIT_FIX = str.maketrans("lLoOBSZI", "11008520")

def validate_date(raw: str) -> str:
    s = raw.translate(DIGIT_FIX)
    s = re.sub(r"(\d+)(st|nd|rd|th)", r"", s, flags=re.I)
    patterns = [
        (r"(\d{1,2})[/\-.]\s*(\d{1,2})[/\-.]\s*(\d{2,4})", "%d %m %Y"),
        (r"(\d{1,2})\s+(\w{3,9})\s+(\d{4})",               "%d %B %Y"),
        (r"(\w{3,9})\s+(\d{1,2}),?\s+(\d{4})",             "%B %d %Y"),
    ]
    for pattern, fmt in patterns:
        m = re.search(pattern, s)
        if not m: continue
        try:
            return datetime.strptime(" ".join(m.groups()), fmt).strftime("%Y-%m-%d")
        except: continue
    return ""

def validate_nhs_number(raw: str) -> str:
    """Modulus-11 checksum: sum(digit[i] * (10-i) for i in 0..8) mod 11 == digit[9]."""
    s = re.sub(r"\D", "", raw.translate(DIGIT_FIX))
    if len(s) != 10: return ""
    total = sum(int(s[i]) * (10 - i) for i in range(9))
    check = (11 - total % 11) % 11
    return s if check == int(s[9]) else ""

def recover_nhs_number(raw: str) -> dict:
    """
    If 9-digit input, try all 10 check digit appensions.
    NHS checksum guarantees exactly one valid completion.
    Returns: {value: str, recovered: bool}
    """
    s = re.sub(r"\D", "", raw.translate(DIGIT_FIX))
    if len(s) == 10:
        v = validate_nhs_number(s)
        return {"value": v, "recovered": False}
    if len(s) == 9:
        valid = [s + d for d in "0123456789"
                 if validate_nhs_number(s + d)]
        if len(valid) == 1:
            return {"value": valid[0], "recovered": True}
    return {"value": "", "recovered": False}

def validate_postcode_uk(raw: str) -> str:
    s = re.sub(r"\s+", "", raw).upper()
    s = s[:-3] + " " + s[-3:] if len(s) >= 5 else s
    return s if re.match(r"^[A-Z]{1,2}\d{1,2}[A-Z]?\s\d[A-Z]{2}$", s) else ""
05 · BERT Masked LM Rescoring

N-Best Candidates Reranked
by Clinical Language Model Probability

lm_rescoring.py

from transformers import AutoTokenizer, AutoModelForMaskedLM
import torch

# Domain-specific BERTs outperform bert-base on their target text:
# "emilyalsentzer/Bio_ClinicalBERT"   — clinical notes (recommended)
# "allenai/scibert_scivocab_uncased"  — scientific papers
# "bert-base-uncased"                 — general fallback

tokeniser = AutoTokenizer.from_pretrained("emilyalsentzer/Bio_ClinicalBERT")
model     = AutoModelForMaskedLM.from_pretrained(
    "emilyalsentzer/Bio_ClinicalBERT").eval()

def pseudo_log_likelihood(sentence: str) -> float:
    """
    Mask each token in turn, sum log-probabilities.
    Always apply prenormalize() before scoring —
    OCR errors should be normalised before LM sees them.
    Higher score = more probable under the LM.
    """
    tokens = tokeniser(f"[CLS] {sentence} [SEP]", return_tensors="pt")
    ids    = tokens.input_ids[0]
    score  = 0.0
    for i in range(1, len(ids) - 1):
        masked    = ids.clone()
        masked[i] = tokeniser.mask_token_id
        with torch.no_grad():
            logits = model(masked.unsqueeze(0)).logits[0, i]
        score += torch.log_softmax(logits, dim=-1)[ids[i]].item()
    return score

def rescore_candidates(context_words: list, candidates: list,
                         target_pos: int) -> str:
    """
    Rescore n-best OCR candidates in context.
    Applies prenormalize() to each candidate before scoring.
    Returns highest-scoring candidate.
    """
    scored = []
    for cand in candidates:
        words = context_words.copy()
        words[target_pos] = prenormalize(cand)  # normalise before LM scores
        scored.append((cand, pseudo_log_likelihood(" ".join(words))))
    return max(scored, key=lambda x: x[1])[0]
06 · Confidence-Based Rejection Routing

Three Zones Per Field:
Accept, Review, Reject

rejection_routing.py

from dataclasses import dataclass
from enum import Enum

class Zone(Enum):
    ACCEPT = "accept"
    REVIEW = "review"
    REJECT = "reject"

ZONE_CONFIG = {
    "critical": (90, 70),  # NHS number, account number: tight
    "standard": (75, 55),  # names, dates, addresses
    "optional": (60, 40),  # notes, secondary descriptions
}
FIELD_TIER = {
    "nhs_number":  "critical", "account_number": "critical",
    "patient_name":"standard", "dob":           "standard",
    "postcode":   "standard",  "notes":         "optional",
}

@dataclass
class RoutingDecision:
    field: str; value: str; conf: float; zone: Zone; reason: str

def route_field_by_conf(field: str, value: str, conf: float) -> RoutingDecision:
    tier = FIELD_TIER.get(field, "standard")
    hi, lo = ZONE_CONFIG[tier]
    if   conf >= hi: zone, reason = Zone.ACCEPT, f"conf {conf:.0f} >= {hi}"
    elif conf >= lo: zone, reason = Zone.REVIEW, f"conf {conf:.0f} in [{lo},{hi})"
    else:            zone, reason = Zone.REJECT, f"conf {conf:.0f} < {lo}"
    return RoutingDecision(field, value, conf, zone, reason)

08 · Assessment

Module 11 Quiz

1. fuzzy_correct_token("St", vocabulary) returns "St" unchanged even though "Street" is in the vocabulary. Is this a bug?

Correct. The abort_short threshold is a deliberate safety mechanism. A 2-character token with an allowed edit distance of 2 matches any token 1–4 characters long — the candidate set is enormous and the correction would be random. Short abbreviations require a separate rule-based expansion map: {"St": "Street", "Ave": "Avenue", "Rd": "Road"} applied before fuzzy matching.

2. validate_nhs_number("487 345 678") returns "". The correct number is "487 345 6782". The final character was dropped by OCR. What recovery approach is safe to automate?

Correct. The modulus-11 checksum property is the key: for any valid 9-digit prefix, exactly one check digit satisfies the checksum. This makes the recovery deterministic and unambiguous — unlike general fuzzy matching where multiple candidates compete. The recovered=True flag ensures audit trails distinguish auto-recovered values from directly extracted ones, supporting downstream compliance requirements.

3. pseudo_log_likelihood() scores "The patient was diagnosed with hypertensi0n" as high as "hypertension". How does prenormalize() in rescore_candidates() prevent this problem?

Correct. The purpose of prenormalize() before LM scoring is to convert systematic OCR substitutions into their correct characters before asking the LM to score the sentence. Without prenormalize(), the LM would score "hypertensi0n" and "hypertension" differently only if its tokeniser creates different subword sequences — which is often not the case, making the scoring meaningless. After prenormalize(), both candidates are already in their corrected form, and the LM scores them on their actual linguistic properties.

4. A document has nhs_number field extracted at conf=74 and patient_name at conf=52. What does route_document() decide for each, and what is the overall document disposition?

Correct. The three-zone routing must be computed per-field using each field's tier configuration, not a single global threshold. nhs_number (critical tier: hi=90, lo=70) at conf 74 falls in the review band [70, 90) — uncertain but above the critical reject floor. patient_name (standard tier: hi=75, lo=55) at conf 52 falls below the reject threshold of 55 — actively rejected. A rejected field means the extracted value is too low confidence to use even for review; it must be re-extracted or manually entered. A review field means the value may be correct but needs human verification.

5. You measured CER=1.8% on a medical form dataset. The most critical field is "medication_name" with average length 12 characters. What is the exact-match field accuracy for medication_name, and what single post-processing step most improves it?

Correct. The compound error formula is (1-CER)^field_length = 0.982^12 = 80.4%. The linear approximation in B (78.4%) is wrong — it overestimates the error because it does not account for the decreasing marginal probability of additional errors. The CER-direct formula in A (98.2%) is the single-character accuracy, not the field accuracy. Domain vocabulary fuzzy correction provides the largest single-step improvement for medical text: drug names are exactly the class of terms that are rare in training corpora (low word frequency → low Tesseract confidence) but critical for extraction accuracy.
