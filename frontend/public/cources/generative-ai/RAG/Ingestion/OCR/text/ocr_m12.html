OCR Evaluation Metrics and Monitoring
CER · WER · Field Accuracy · IoU · Detection Metrics · Benchmarks · Production Monitoring

Measuring OCR quality is as important as improving it — you cannot optimise what you cannot measure, and the wrong metric leads to the wrong optimisation target. This module covers evaluation pitfalls that produce falsely optimistic CER, proper stratified test set design, CER and WER formulas with implementation, field-level accuracy metrics (exact match, approximate match, field error rate), the compound error model at field level, bounding box IoU for layout evaluation, detection metrics (precision, recall, F1 with configurable IoU threshold), standard benchmark datasets, inter-annotator agreement as a measurement floor, and production monitoring with stratified confidence sampling.

01 · Evaluation Pitfalls

Three Ways a CER Score Can
Be Right but Meaningless

An OCR benchmark reporting CER=0.8% sounds excellent. But that number may be measured on a clean, hand-curated test set that looks nothing like production documents. Understanding evaluation pitfalls is the prerequisite to building a measurement framework that predicts real-world performance rather than benchmarking performance.

Pitfall 1: Clean-test-set bias

Test sets assembled from "clear" scans or screenshots overrepresent easy documents. If 15% of your production volume is phone-photographed thermal receipts, but your test set has none, your measured CER tells you nothing about that 15% — which is often where 80% of extraction errors occur.

Fix: Stratify test set by document quality tier. Match production quality distribution in test set composition.

Pitfall 2: Whitespace normalisation

Comparing reference "blood pressure" against OCR "bloodpressure" with whitespace normalisation ON gives CER=0%. Without normalisation, CER=6/14=43%. If production code does not normalise whitespace, the benchmark normalisation is misleading. Evaluate with the same normalisation your production pipeline applies.

Fix: Document all normalisation steps applied during evaluation. Evaluate with production-equivalent normalisation only.

Pitfall 3: Annotation error as a floor

Reference transcriptions contain errors. If two annotators producing the same label disagree on 0.5% of characters (Inter-Annotator Agreement WER=0.5%), then a CER of 0.3% on that test set is impossible to trust — the labels themselves have 0.5% noise. IAA sets the measurement floor: no CER improvement below the IAA level is statistically meaningful.

Fix: Measure IAA on a random 10% sample before using any test set. Report IAA alongside all CER figures.
02 · CER and WER Implementation

Levenshtein-Based Metrics
With Correct Normalisation

ocr_metrics.py

import re
from Levenshtein import distance
from statistics import mean, quantiles
import numpy as np

def normalise_for_eval(text: str) -> str:
    """
    Standard normalisation before CER/WER computation.
    Apply SAME steps in evaluation and in production post-processing.
    """
    text = text.lower()
    text = re.sub(r"\s+", " ", text).strip()
    text = re.sub(r"[''`]", "'", text)
    text = re.sub(r"[""«»]", '"', text)
    return text

def cer(reference: str, hypothesis: str,
        normalise: bool = True) -> float:
    """
    Character Error Rate = Levenshtein(ref, hyp) / len(ref).
    Returns 0.0 for empty reference (undefined — log and skip).
    """
    if normalise:
        reference  = normalise_for_eval(reference)
        hypothesis = normalise_for_eval(hypothesis)
    if not reference: return 0.0
    return min(1.0, distance(reference, hypothesis) / len(reference))

def wer(reference: str, hypothesis: str) -> float:
    """Word Error Rate: Levenshtein at word level."""
    ref = normalise_for_eval(reference).split()
    hyp = normalise_for_eval(hypothesis).split()
    if not ref: return 0.0
    dp = [[0] * (len(hyp)+1) for _ in range(len(ref)+1)]
    for i in range(len(ref)+1): dp[i][0] = i
    for j in range(len(hyp)+1): dp[0][j] = j
    for i, r in enumerate(ref,1):
        for j, h in enumerate(hyp,1):
            dp[i][j] = (min(dp[i-1][j]+1, dp[i][j-1]+1,
                         dp[i-1][j-1] + (r != h)))
    return min(1.0, dp[len(ref)][len(hyp)] / len(ref))

def batch_cer(pairs: list) -> dict:
    """
    Compute aggregate CER stats over a list of (reference, hypothesis) pairs.
    Returns mean CER, P90, P99, and per-document distribution.
    """
    scores = [cer(r, h) for r, h in pairs]
    qs     = quantiles(scores, n=100)
    return {"mean": round(mean(scores)*100,2),
            "p90":  round(qs[89]*100, 2),
            "p99":  round(qs[98]*100, 2),
            "n":    len(scores),
            "scores": scores}
03 · Field-Level Accuracy

Exact Match, Approximate Match,
and Field Error Rate

field_accuracy.py

from dataclasses import dataclass
from typing import Optional

@dataclass
class FieldEval:
    field:       str
    reference:   str
    hypothesis:  str
    exact_match: bool
    approx_match: bool
    cer:         float
    n_docs:      int = 0

def field_accuracy(field_name: str,
                    ref_values: list[str],
                    hyp_values: list[str],
                    approx_cer_threshold: float = 0.1) -> dict:
    """
    Evaluate per-field extraction accuracy across N documents.
    exact_match:  hypothesis == reference (after normalisation)
    approx_match: CER(ref, hyp) < approx_cer_threshold
    field_error_rate: 1 - exact_match_rate (strict)
    """
    assert len(ref_values) == len(hyp_values)
    exact, approx, cers = [], [], []
    for ref, hyp in zip(ref_values, hyp_values):
        r = normalise_for_eval(ref)
        h = normalise_for_eval(hyp)
        c = cer(ref, hyp)
        exact.append(r == h)
        approx.append(c < approx_cer_threshold)
        cers.append(c)
    n = len(ref_values)
    return {
        "field":              field_name,
        "n":                 n,
        "exact_match_rate":  sum(exact) / n,
        "approx_match_rate": sum(approx) / n,
        "field_error_rate":  1 - sum(exact) / n,
        "mean_cer":          mean(cers),
    }

def evaluate_pipeline(ground_truth: list[dict],
                        predictions: list[dict],
                        fields: list[str]) -> dict:
    """
    End-to-end field evaluation across a document set.
    ground_truth and predictions: lists of dicts keyed by field name.
    """
    results = {}
    for field in fields:
        refs = [gt.get(field, "") for gt in ground_truth]
        hyps = [pr.get(field, "") for pr in predictions]
        results[field] = field_accuracy(field, refs, hyps)
    overall_exact = mean(v["exact_match_rate"] for v in results.values())
    return {"fields": results, "overall_exact_match": overall_exact}
04 · Bounding Box IoU and Detection Metrics

Intersection over Union, Precision,
Recall, and F1 for Layout Evaluation

bbox_iou.py

import numpy as np
from dataclasses import dataclass

@dataclass
class BBox:
    x1: float; y1: float; x2: float; y2: float

    @property
    def area(self) -> float:
        return max(0, self.x2-self.x1) * max(0, self.y2-self.y1)

def iou(a: BBox, b: BBox) -> float:
    """Intersection over Union = intersection_area / union_area."""
    ix1 = max(a.x1, b.x1); iy1 = max(a.y1, b.y1)
    ix2 = min(a.x2, b.x2); iy2 = min(a.y2, b.y2)
    inter = max(0, ix2-ix1) * max(0, iy2-iy1)
    union = a.area + b.area - inter
    return inter / union if union > 0 else 0.0

def detection_metrics(predictions: list[BBox],
                       ground_truth:  list[BBox],
                       iou_threshold: float = 0.5) -> dict:
    """
    Compute Precision, Recall, F1 for bounding box detection.
    IoU threshold: match is TP if IoU >= threshold (default 0.5).
    Each ground truth box can only be matched once (greedy matching).
    """
    matched_gt = set()
    tp, fp = 0, 0
    for pred in predictions:
        best_iou, best_gt = 0.0, -1
        for gi, gt in enumerate(ground_truth):
            if gi in matched_gt: continue
            sc = iou(pred, gt)
            if sc > best_iou: best_iou, best_gt = sc, gi
        if best_iou >= iou_threshold:
            tp += 1; matched_gt.add(best_gt)
        else:
            fp += 1
    fn = len(ground_truth) - len(matched_gt)
    precision = tp / (tp + fp)  if (tp + fp) > 0 else 0.0
    recall    = tp / (tp + fn)  if (tp + fn) > 0 else 0.0
    f1 = (2*precision*recall/(precision+recall) if (precision+recall) > 0
          else 0.0)
    return {"tp":tp,"fp":fp,"fn":fn,
            "precision":round(precision,3),
            "recall":round(recall,3),
            "f1":round(f1,3)}

Inter-annotator agreement as measurement floor

IAA is the ceiling of what your evaluation can distinguish. If two expert annotators agree on 99.2% of characters (IAA CER = 0.8%), a CER improvement from 1.2% to 0.9% is within the measurement noise. You cannot reliably attribute a 0.3pp improvement to your system change when the labels themselves have 0.8% error.

Standard practice: measure IAA on 10% random sample before any evaluation. Report IAA alongside all CER/F1 figures. Only claim improvements larger than 2× IAA as statistically meaningful without additional significance testing.

06 · Production Monitoring

Stratified Sampling, Drift Detection,
and Confidence-Calibrated Sampling

production_monitor.py

from collections import defaultdict
from datetime import datetime
import random

class OCRProductionMonitor:
    """
    Production CER monitoring with stratified confidence sampling.
    Why confidence-stratified sampling vs random:
    Random 1% gives ~0 low-confidence documents in typical traffic
    (low-confidence docs are rare — that is by definition).
    Stratified sampling oversamples low-confidence documents to
    ensure the worst-quality tail is represented in ground-truth.
    """
    def __init__(self, weekly_budget: int = 500):
        self.budget     = weekly_budget
        self.buckets    = {"high":0,"mid":0,"low":0}
        self.targets    = {"high":0.1,"mid":0.3,"low":0.6}
        self.sample_log = []

    def classify_confidence(self, mean_conf: float) -> str:
        return ("high" if mean_conf >= 85 else
                "mid"  if mean_conf >= 65 else "low")

    def should_sample(self, mean_conf: float) -> bool:
        """Decide whether to send this document for human ground-truth labelling."""
        bucket = self.classify_confidence(mean_conf)
        target = self.targets[bucket] * self.budget
        sampled_in_bucket = self.buckets[bucket]
        if sampled_in_bucket >= target: return False
        sample = random.random() < self.targets[bucket]
        if sample:
            self.buckets[bucket] += 1
            self.sample_log.append({"conf":mean_conf, "bucket":bucket,
                                     "ts":datetime.now().isoformat()})
        return sample

    def weekly_report(self, cer_by_bucket: dict) -> dict:
        """
        Generate weekly CER report with drift alerts.
        Alert triggers: P90 CER > 5% OR week-over-week increase > 0.5pp.
        """
        alert = (cer_by_bucket.get("low_p90", 0) > 5.0 or
                 cer_by_bucket.get("wow_delta", 0) > 0.5)
        return {"report_date": datetime.now().date().isoformat(),
                "sampled": self.buckets,
                "cer": cer_by_bucket,
                "alert": alert,
                "alert_reason": "P90 CER > 5% or WoW delta > 0.5pp" if alert else ""}
07 · Assessment

Module 12 Quiz

1. A benchmark reports CER=0.6% for a production invoice extraction system. The test set was assembled by the engineering team selecting "representative" invoices. Annotator IAA WER on the same set is 0.9%. What is wrong and what should the report say instead?

Correct. Both problems are real and compound each other. IAA is the measurement floor: you cannot trust CER below the annotation noise level regardless of how the system performs. Clean-set bias means the CER is measured on a different distribution from production. Together, the report describes a system that may perform far worse on real production documents than the benchmark suggests. The correct response is to fix both — improve annotation consistency and stratify the test set — before claiming the measured CER as meaningful.

2. batch_cer() returns mean=1.2%, P90=4.8%, P99=12.1% for a dataset of 5,000 invoices. Mean CER meets your SLA target of 1.5%. Is the system SLA-compliant?

Correct. Mean CER is a poor SLA metric for production OCR because it is dominated by the large majority of easy documents and masks systematic failure on a minority. P90=4.8% means 500 documents per day at this volume receive 4.8%+ CER — which at the compound error rate for a 20-character field (0.952^20 = 36% exact match) means those documents are essentially not being extracted correctly. Well-designed SLAs specify P90 or P95 CER thresholds in addition to or instead of mean CER.

3. detection_metrics() returns precision=0.94, recall=0.71, F1=0.81 for text block detection on a document layout evaluation. What does this profile indicate and what is the likely cause?

Correct. The precision-recall imbalance (0.94 vs 0.71) is the key diagnostic signal. High precision means the model's predictions are mostly correct — when it detects a block, it is usually really there. Low recall means many genuine blocks are missed. This is the fingerprint of a conservative detector. The IoU threshold diagnosis is important: strict IoU=0.5 penalises predictions with correct location but slightly wrong extent — a block detected at 90% of its true area has IoU=0.82 (TP), but a block detected at 40% of its area has IoU=0.57 (barely TP at 0.5 threshold). Evaluating across multiple IoU thresholds (0.3, 0.5, 0.75) as in COCO mAP reveals whether the issue is detection or localisation.

4. You want to detect CER drift in production. A colleague proposes random 1% sampling for ground-truth labelling. You propose confidence-stratified sampling. What is the statistical argument for stratification?

Correct. The statistical argument for stratification is variance reduction in the tail estimate. Random 1% sampling gives a good estimate of mean CER but a poor estimate of tail CER — the quantity that actually determines whether the system is failing on hard documents. Stratified sampling allocates labelling effort proportionally to where errors are likely to occur, maximising the information content of each labelled document. The resulting tail CER estimate has far lower variance than the random sample estimate, enabling earlier detection of drift in the high-error subpopulation.

5. You upgrade your OCR pipeline from Tesseract to PaddleOCR and rerun evaluation. Mean CER improves from 2.1% to 1.4%. Before announcing the result, what validation steps confirm the improvement is real and not a measurement artefact?

Correct. The three validations target the three most common artefact sources in model comparison: evaluation inconsistency (different normalisation producing apparent gains), subpopulation reversal (gains on easy documents masking regressions on hard ones), and metric-to-business-value translation (CER improving without meaningful field accuracy improvement). Statistical significance testing (C) confirms the improvement is not sampling noise but does not rule out evaluation artefacts or subpopulation reversals. Cost/performance (D) is a deployment decision factor but not a validation step for measurement accuracy.
