Video Encoders — How Models See Temporal Data

3D Conv · Patch Tokenisation · Divided Space-Time Attention · VideoMAE · CLIP vs VideoMAE · Optical Flow

The fundamental challenge of video encoding is time. An image encoder sees one moment; a video encoder must build representations that capture not just what things look like, but how they move, change, and relate to each other across time. 3D convolutions address this directly by extending spatial kernels into the temporal dimension. Video transformers address it more efficiently through factored space-time attention, reducing the quadratic cost of full spatiotemporal attention by 8× while learning the same temporal relationships. This module covers the architectural decisions — 3D conv vs transformers, joint vs factored attention, pre-training strategy — that determine whether a video model can actually see time.

01 · Why 2D Encoders Are Temporally Blind

3D Convolutions:
The Kernel That Sees Motion

A 2D convolutional encoder applied independently to each video frame produces identical features for a running person and a still photograph of that same person mid-stride. It cannot distinguish motion from appearance because its kernel has no temporal dimension. 3D convolutions extend the spatial kernel into time — a (t×h×w) kernel activates when the same spatiotemporal pattern of pixel changes appears in the video volume. This direct encoding of motion is the core architectural insight behind C3D (Tran et al. 2015) and I3D (Carreira & Zisserman 2017).

2D per-frame conv (temporally blind) vs 3D spatiotemporal conv (motion-aware)

video_tokenise.py — clip tokenisation and temporal positional embeddings

import torch
import torch.nn as nn
import einops

class VideoTokeniser(nn.Module):
    """
    Convert a video clip (T, H, W, 3) into a sequence of patch tokens
    with temporal positional embeddings — input format for video transformers.

    Spatial patches: divide each frame into (H/P × W/P) non-overlapping patches
    of size P×P pixels. Each patch → linear projection to D dimensions.
    For H=W=224, P=16: 14×14 = 196 patches per frame.

    Temporal tokens: each frame contributes 196 spatial tokens.
    For T=8 frames: 8 × 196 = 1568 total tokens.

    Positional encoding strategies:
      - 3D sinusoidal: encode (t, h, w) position independently
      - Factored: separate temporal and spatial positional embeddings added
      - Learnable: 1568 learnable position vectors (standard ViT approach)

    TimeSformer uses factored learned embeddings (separate spatial+temporal).
    VideoMAE uses 3D position encodings with tube masking during pre-training.
    Video-LLaVA uses CLIP ViT patch embeddings + temporal concat.
    """
    def __init__(self, img_size: int=224, patch_size: int=16,
                 n_frames: int=8, embed_dim: int=768):
        super().__init__()
        self.P = patch_size
        self.T = n_frames
        self.n_patches = (img_size // patch_size) ** 2   # 196 for 224/16
        # Patch embedding: flatten P×P×3 → D
        self.patch_embed = nn.Linear(patch_size * patch_size * 3, embed_dim)
        # Factored positional embeddings (TimeSformer style)
        self.spatial_pos  = nn.Parameter(torch.zeros(1, self.n_patches, embed_dim))
        self.temporal_pos = nn.Parameter(torch.zeros(1, n_frames, embed_dim))
        nn.init.trunc_normal_(self.spatial_pos,  std=0.02)
        nn.init.trunc_normal_(self.temporal_pos, std=0.02)

    def patchify(self, frames: torch.Tensor) -> torch.Tensor:
        """
        frames: (B, T, C, H, W)  float32 in [0,1]
        Returns: (B, T*N_patches, D) token sequence
        """
        B, T, C, H, W = frames.shape
        # Extract P×P patches from each frame
        patches = einops.rearrange(
            frames,
            'b t c (h p1) (w p2) -> b t (h w) (p1 p2 c)',
            p1=self.P, p2=self.P
        )  # (B, T, N, P²C)
        tokens = self.patch_embed(patches)   # (B, T, N, D)
        # Add factored positional encodings
        tokens = tokens + self.spatial_pos.unsqueeze(1)   # broadcast over T
        tokens = tokens + self.temporal_pos.unsqueeze(2)  # broadcast over N
        return einops.rearrange(tokens, 'b t n d -> b (t n) d')

    def forward(self, frames: torch.Tensor) -> torch.Tensor:
        return self.patchify(frames)
        # Output: (B, T×196, D) — ready for transformer encoder
02 · Video Transformers — Factored Space-Time Attention

TimeSformer: 8× Cheaper
Than Joint Attention

For a clip of T=8 frames with N=196 patches per frame, joint space-time attention operates on 1568 tokens — 2.46M attention weights per head. TimeSformer's divided space-time attention splits this into two sequential operations: temporal attention (each patch attends across frames at the same spatial position) and spatial attention (standard ViT within each frame). The total cost is 320K attention weights — 8× reduction.

Divided space-time attention: temporal step (across frames) then spatial step (within frame)

space_time_attention.py — factored space-time attention (TimeSformer style)

import torch
import torch.nn as nn
import torch.nn.functional as F
import einops

class DividedSpaceTimeAttention(nn.Module):
    """
    Divided Space-Time Attention (TimeSformer, Bertasius et al. 2021).

    Why factored attention?
    Joint space-time attention over T×N tokens (e.g. 8×196=1568) has
    O((T×N)²) complexity — 1568² ≈ 2.4M attention weights per head.
    This is 64× the cost of standard spatial attention on 196 patches.

    Factored approach: alternate between:
      1. Temporal attention: each spatial patch attends across T frames
         at the SAME spatial position. Query=(T, D), Key/Value=(T, D).
         Complexity: O(N × T²) = O(196 × 64) ≈ 12K per head.
      2. Spatial attention: within each frame, patches attend to each
         other. Standard ViT attention.
         Complexity: O(T × N²) = O(8 × 38416) ≈ 307K per head.
    Total: O(N×T² + T×N²) vs joint O((TN)²) — ~8× reduction for T=8,N=196.

    The temporal attention layer is initialised to identity (zero weight)
    so at the start of fine-tuning, the model behaves like a ViT.
    This enables initialising from ImageNet-pretrained ViT weights.
    """
    def __init__(self, dim: int, n_heads: int=12, n_frames: int=8):
        super().__init__()
        self.T = n_frames
        self.n_heads = n_heads
        self.head_dim = dim // n_heads
        # Standard spatial multi-head attention (inherited from ViT)
        self.spatial_attn  = nn.MultiheadAttention(dim, n_heads, batch_first=True)
        # Temporal attention — init weights near zero so we start ≈ identity
        self.temporal_attn = nn.MultiheadAttention(dim, n_heads, batch_first=True)
        with torch.no_grad():
            self.temporal_attn.out_proj.weight.fill_(0)
            self.temporal_attn.out_proj.bias.fill_(0)
        self.norm1 = nn.LayerNorm(dim)
        self.norm2 = nn.LayerNorm(dim)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        """x: (B, T*N, D) — flattened space-time token sequence"""
        B, TN, D = x.shape
        N = TN // self.T

        # ── Temporal attention: each patch attends across frames ──
        # Reshape: treat each spatial position as a separate 'batch'
        xt = einops.rearrange(x, 'b (t n) d -> (b n) t d', t=self.T, n=N)
        xt_norm = self.norm1(xt)
        t_out, _ = self.temporal_attn(xt_norm, xt_norm, xt_norm)
        xt = xt + t_out    # residual connection
        x  = einops.rearrange(xt, '(b n) t d -> b (t n) d', b=B, n=N)

        # ── Spatial attention: patches attend within each frame ──
        xs = einops.rearrange(x, 'b (t n) d -> (b t) n d', t=self.T, n=N)
        xs_norm = self.norm2(xs)
        s_out, _ = self.spatial_attn(xs_norm, xs_norm, xs_norm)
        xs = xs + s_out    # residual connection
        x  = einops.rearrange(xs, '(b t) n d -> b (t n) d', b=B, t=self.T)
        return x
03 · Pre-Training Strategy and Model Selection

VideoMAE vs CLIP-ViT:
Reconstruction vs Alignment

🔑

Pre-training strategy determines downstream capability

VideoMAE (masked autoencoding, 90% masking): learns to reconstruct spatiotemporal structure from sparse observations. Strong for action recognition, temporal reasoning, motion understanding. Not aligned with text — poor for retrieval from text queries. CLIP-ViT per-frame: image-text contrastive pre-training at 400M pairs. Strong semantic-visual alignment — excellent for text-to-video retrieval. No temporal modelling beyond frame averaging. VideoCLIP/InternVideo: combines both — contrastive video-text + masked video modelling.

Model selection decision tree

Text-to-video retrieval → CLIP-ViT per-frame + temporal average pooling. Action recognition (Kinetics, UCF101) → VideoMAE fine-tuned. Video QA / VideoChat → Video-LLaVA (CLIP-ViT frames → LLM). Temporal grounding (find the 10-second clip where the action occurs) → TimeSformer + moment proposal head. Low-data domain (medical, satellite) → start with VideoMAE for structure, CLIP for semantics, fine-tune both.

Question 1 of 8

A VideoTokeniser processes an 8-frame clip of 224×224 RGB frames with patch size P=16. What is the total number of tokens in the sequence passed to the transformer, and what is the shape of a single patch before linear projection?

Correct. Patches per frame = (224/16)² = 14² = 196. Total tokens = 8 frames × 196 patches = 1568. Each patch is 16×16 pixels × 3 channels = 768 values, projected to D=768 embedding dimensions. The linear projection maps (768,) → (D,). This is identical to ViT-B/16 spatial tokenisation, extended across T time steps.
Question 2 of 8

TimeSformer initialises the temporal attention layer with zero output projection weights. You are fine-tuning TimeSformer from a pre-trained ImageNet ViT-B/16 checkpoint. What does this initialisation strategy achieve?

Correct. The zero output projection trick is the standard method for inserting new attention modules into pre-trained transformers. At initialisation, temporal attention output = Wout @ (attention output) = 0, so x = x + 0 = x — the residual connection passes the spatial features unchanged. The model starts as ViT, then gradually learns temporal patterns as the output projection weights grow from zero via gradient descent. This technique appears in TimeSformer, Lora, and ControlNet.
Question 3 of 8

You need to choose between a 3D conv video model (C3D) and a factored space-time transformer (TimeSformer) for action recognition on 1-second clips (8 frames, 224×224). Your deployment constraint is inference latency < 50ms on a single GPU. Which do you choose and why?

Correct. TimeSformer with factored attention is typically the right choice at this resolution and clip length. The key insight: factored attention reduces complexity from O((TN)²) to O(N×T² + T×N²) ≈ 8× reduction for T=8, N=196. Combined with FlashAttention's memory-efficient attention kernels, TimeSformer achieves competitive latency. C3D's 3D conv stacks are slower because each layer requires materialising the full 3D feature volume. Two-stream networks (option D) require optical flow computation which typically adds 30-50ms — worse than either option.
Question 4 of 8

VideoMAE pre-trains a ViT on video by masking 90% of spatiotemporal patch tokens and predicting the masked pixel values. Why is a 90% masking ratio much higher than BERT's 15% text masking, and what does this high ratio force the model to learn?

Correct. The key insight is semantic redundancy vs linguistic redundancy. In text, every word carries distinct semantic content — masking 15% means the model must infer specific words from context. In video, adjacent patches at the same spatial position in nearby frames are nearly identical. Masking 15% of video tokens is trivially solved by copying neighbours. 90% masking creates a genuine understanding task: reconstruct the full spatiotemporal structure from scattered glimpses. The training efficiency benefit (fewer tokens processed per step) is also significant — VideoMAE trains 5-10× faster than contrastive video methods.
Question 5 of 8

You are applying a per-frame ViT encoder to 8-frame video clips for action recognition. The encoder produces (8, D) frame embeddings. You then apply temporal average pooling to get a single (D,) clip embedding for classification. A colleague proposes replacing average pooling with temporal self-attention. Under what conditions does temporal attention outperform average pooling?

Correct. The key condition is temporal asymmetry. Actions where temporal order matters (before/after the action completes, actions with a clear temporal peak) benefit from temporal attention. Symmetric, steady-state actions (walking, cycling at constant speed) show minimal difference. In practice, for T=8 frames from a 1-second clip of a single action category, average pooling often achieves within 1-2% of temporal attention while being 5× simpler. Temporal attention's benefit grows with clip length and action complexity.
Question 6 of 8

What is optical flow, and why was the two-stream architecture (Simonyan & Zisserman 2014) important before transformers solved temporal modelling?

Correct. Optical flow (the 2D velocity field of pixel motion) was the key to temporal understanding before video transformers. Computing it requires methods like Farneback, TVL1, or RAFT — computationally expensive (100-500ms per frame pair), but providing explicit motion information that CNNs could not extract from static kernels. The two-stream architecture was the dominant approach from 2014-2020. Modern video transformers (TimeSformer, VideoMAE) learn motion representations directly from RGB through temporal attention, making optical flow less necessary but not obsolete — RAFT-based optical flow still boosts performance in specialised tasks like fine-grained action recognition.
Question 7 of 8

A video encoder produces (T=8, D=768) frame embeddings. You want to add temporal positional embeddings so the model knows the temporal order of frames. You have three options: (A) learned 1D positional embeddings indexed by frame number, (B) sinusoidal positional encoding with 1D position index, (C) relative positional bias (RoPE) applied within temporal attention. For a model that needs to generalise to variable-length clips (4, 8, 16, 32 frames) at inference, which is most appropriate?

Correct. RoPE (Rotary Position Embedding) encodes relative temporal distances — the attention pattern between frame t=2 and t=5 depends on their temporal gap (3 frames) rather than their absolute positions. This generalises naturally: a model trained on 8-frame clips can process 16-frame or 32-frame clips at inference because the relative distances are interpretable at any clip length. Learned absolute embeddings (option A) cannot generalise beyond the training T — they have no mechanism to assign embeddings to position 9 if only trained up to T=8. Sinusoidal encoding (option B) extrapolates but with degraded performance for positions far outside the training range. RoPE is now the standard for video and long-context language models for exactly this reason.
Question 8 of 8

You are choosing a video encoder for a production video retrieval system. Videos are product demonstrations (3-10 minutes, 30fps). You need clip-level embeddings every 2 seconds for downstream retrieval. The system must handle 100,000 videos per day. Compare VideoMAE (masked autoencoder pre-training) vs CLIP-ViT (image-text contrastive) applied per-frame then averaged. Which produces better retrieval embeddings and why?

Correct. The choice between VideoMAE and CLIP-ViT depends on the downstream task. Retrieval with text queries requires semantic alignment — CLIP-ViT's image-text contrastive pre-training directly optimises for this. VideoMAE's pixel reconstruction objective builds rich spatiotemporal features but without the semantic-text alignment needed for retrieval. Per-frame CLIP-ViT + temporal averaging is the standard approach for text-to-video retrieval (used by VideoCLIP, InternVideo). VideoMAE features are used downstream by fine-tuning on labelled video action datasets — not directly for retrieval from text queries.
