STFT · Mel Spectrogram · Whisper ASR · CLAP · Wav2Vec2 · AV-HuBERT · Word Timestamps · Sample Rate

Audio is the most neglected modality in multimodal ML — and the most information-rich for human communication. A video without audio loses tone, emotion, prosody, background sound, and spoken content. This module covers the complete audio processing pipeline: waveform → mel spectrogram → audio encoder, and the two dominant audio models with completely different objectives: Whisper (what was SAID) and CLAP (what SOUNDS are present). Understanding when each is appropriate, how to align audio timestamps with video frames, and how audio-visual synchronisation models work is the foundation of production-grade multimodal video systems.

01 · The Audio Processing Pipeline

Waveform → Mel Spectrogram →
Audio Encoder Input

Every audio encoder starts with the same preprocessing chain: raw PCM waveform → Short-Time Fourier Transform (STFT) → mel filterbank compression → log amplitude. The mel filterbank maps linear frequency bins to the mel scale — a perceptually uniform scale that compresses the high-frequency range where human hearing is less sensitive. The resulting log-mel spectrogram is treated as a 2D image (frequency × time) by the audio encoder. Every parameter in this chain — n_mels, n_fft, hop_length, sample_rate — is fixed by the model's training configuration and must be matched exactly at inference.

Audio processing pipeline — waveform → STFT → mel spectrogram → three encoder architectures

whisper_asr.py — Whisper ASR pipeline with word-level timestamps

import torch
import whisper
from dataclasses import dataclass

@dataclass
class WordTimestamp:
    word:  str
    start: float   # seconds from video start
    end:   float
    prob:  float   # confidence score


def transcribe_video_audio(
    audio_path: str,
    model_size: str = 'large-v3',
    language:   str | None = None,   # None = auto-detect
    task:       str = 'transcribe',   # or 'translate' → English
) -> tuple[str, list[WordTimestamp]]:
    """
    Transcribe audio using OpenAI Whisper with word-level timestamps.

    Whisper architecture:
    - Audio encoder: 80-mel log-spectrogram → 2 Conv1D layers (stride 2) →
      Transformer encoder (positional encoding covers 30s window).
    - Text decoder: autoregressive Transformer decoder, cross-attention
      to encoder output, generates BPE tokens with timestamps.

    Word-level timestamps: added in Whisper large-v2/v3 via dynamic time
    warping (DTW) alignment of decoder cross-attention to encoder frames.
    Each token is aligned to the mel spectrogram frame where its cross-
    attention weight peaks — providing ms-level timestamp accuracy.

    Chunk processing:
    Whisper processes 30-second windows. For longer audio, it uses
    voice activity detection (VAD) to find natural chunk boundaries,
    overlapping chunks by 1s to prevent boundary artefacts.
    Each chunk produces: text segment + per-word timestamps offset
    by the chunk start time.

    Usage:
    The (text, word_timestamps) output enables:
    - Synchronising transcript to video frames (which frame shows each word)
    - Extracting video clips from natural language queries
    - Building searchable video indices by spoken content
    """
    model = whisper.load_model(model_size)
    result = model.transcribe(
        audio_path,
        language=language,
        task=task,
        word_timestamps=True,
        fp16=torch.cuda.is_available(),
    )
    full_text = result['text'].strip()
    word_times: list[WordTimestamp] = []
    for segment in result['segments']:
        for w in segment.get('words', []):
            word_times.append(WordTimestamp(
                word=w['word'].strip(),
                start=w['start'],
                end=w['end'],
                prob=w['probability'],
            ))
    return full_text, word_times


def align_words_to_frames(
    word_timestamps: list[WordTimestamp],
    fps: float = 1.0,               # frame extraction rate
    frame_offsets: list[float] = None,  # seconds of each extracted frame
) -> dict[int, list[str]]:
    """
    Map word timestamps to extracted video frame indices.
    Returns {frame_idx: [words spoken during that frame]}.
    Used to build frame-level text descriptions for multimodal indexing.
    """
    frame_words: dict[int, list[str]] = {}
    for w in word_timestamps:
        frame_idx = int(w.start * fps)
        frame_words.setdefault(frame_idx, []).append(w.word)
    return frame_words
02 · CLAP — Audio-Text Contrastive at Scale

The Audio Equivalent of CLIP:
Any Sound, Any Description

CLAP (Contrastive Language-Audio Pre-training) trains an audio encoder and a text encoder with a symmetric InfoNCE loss on 630K audio-text pairs. The result: a shared embedding space where audio clips and their natural language descriptions are close together. Zero-shot audio classification — embed audio and class descriptions, find the highest cosine similarity — emerges without any labelled audio training data.

CLAP symmetric InfoNCE — audio and text embeddings aligned in shared space

clap_inference.py — CLAP audio-text contrastive embedding and retrieval

import torch
import torch.nn.functional as F
from transformers import ClapModel, ClapProcessor

class CLAPAudioTextMatcher:
    """
    CLAP (Contrastive Language-Audio Pre-training) — the audio equivalent of CLIP.

    Architecture:
    - Audio encoder: CNN14 or HTSAT (Hierarchical Token-Semantic Audio Transformer)
      → processes 64-bin mel spectrogram → audio embedding (D=512)
    - Text encoder: RoBERTa → text embedding (D=512)
    - Pre-trained with InfoNCE on 630K audio-text pairs (AudioCaps + AudioSet + FreeSound)

    What CLAP learns:
    The shared embedding space aligns audio events with their natural language
    descriptions: 'dog barking', 'rain on window', 'piano music', 'crowd cheering'.
    Unlike Whisper (which transcribes speech), CLAP understands audio events
    and environmental sounds — it is NOT primarily a speech model.

    Use cases:
    1. Zero-shot audio classification: embed audio + category descriptions,
       find highest cosine similarity → class prediction.
    2. Audio-text retrieval: query 'sound of thunder' → retrieve matching clips.
    3. Audio event detection in video: tag video segments by acoustic content.
    4. Multimodal fusion: CLAP audio features + CLIP visual features + text
       for comprehensive video-language understanding.

    Key difference from Whisper:
    Whisper: speech audio → text transcript (what was SAID)
    CLAP: any audio → semantic embedding (what SOUNDS are present)
    """
    def __init__(self, model_name: str = 'laion/clap-htsat-unfused',
                 device: str = 'cuda'):
        self.device    = device
        self.model     = ClapModel.from_pretrained(model_name).to(device).eval()
        self.processor = ClapProcessor.from_pretrained(model_name)

    @torch.no_grad()
    def embed_audio(self, waveforms: list,
                    sample_rate: int = 48000) -> torch.Tensor:
        """Embed list of audio waveforms → (N, D) L2-normalised."""
        inputs = self.processor(
            audios=waveforms,
            sampling_rate=sample_rate,
            return_tensors='pt',
            padding=True,
        ).to(self.device)
        feats = self.model.get_audio_features(**inputs)
        return F.normalize(feats, dim=-1)

    @torch.no_grad()
    def embed_text(self, texts: list[str]) -> torch.Tensor:
        """Embed list of text descriptions → (N, D) L2-normalised."""
        inputs = self.processor(
            text=texts,
            return_tensors='pt',
            padding=True,
        ).to(self.device)
        feats = self.model.get_text_features(**inputs)
        return F.normalize(feats, dim=-1)

    def zero_shot_classify(self, waveform,
                             class_descriptions: list[str]) -> dict[str, float]:
        """Classify audio clip into one of the class descriptions."""
        a_emb = self.embed_audio([waveform])           # (1, D)
        t_emb = self.embed_text(class_descriptions)   # (C, D)
        scores = (a_emb @ t_emb.T).squeeze(0)         # (C,)
        probs  = scores.softmax(dim=-1).cpu().tolist()
        return dict(zip(class_descriptions, probs))
03 · Audio Model Selection and Integration

Whisper vs CLAP vs Wav2Vec2:
Three Different Audio Questions

🔑

Which model for which question

What was SAID? → Whisper (speech-to-text, word timestamps, multilingual). What SOUNDS are present? → CLAP (audio event detection, acoustic retrieval, zero-shot classification). How does the speaker SOUND? → Wav2Vec2 / HuBERT (prosody, emotion, speaker identity, SSL representations). Are audio and video in SYNC? → AV-HuBERT / SyncNet (audio-visual correspondence, lip-sync verification).

Production: comprehensive video audio indexing

YouTube lecture video pipeline: (1) Whisper large-v3 → transcript with word timestamps → full-text search index. (2) CLAP → per-30s audio segment embeddings → semantic audio retrieval ('find videos with crowd applause', 'find videos with background music'). (3) Align word timestamps to extracted frames at 1fps → frame-level spoken content labels → multimodal CLIP+text embeddings per frame. All three in parallel: Whisper on 16kHz stream, CLAP on 48kHz stream, frame extraction independently.

Question 1 of 8

Whisper transcribes a 45-minute lecture video. After transcription you have word-level timestamps. You extracted frames at 1fps (2700 frames). How do you build a per-frame text context for multimodal indexing?

Correct. Word-level timestamp alignment is the key to frame-text pairing. Whisper's word timestamps (enabled with word_timestamps=True) provide start/end times per word with ms accuracy via dynamic time warping of decoder cross-attention. The alignment formula is simple: frame_idx = floor(word.start × fps). For 1fps extraction, this bins words into 1-second windows. This approach enables semantic frame indexing: searching 'gradient descent' retrieves the frame where that concept was explained.
Question 2 of 8

What is the fundamental difference between what Whisper and CLAP output, and when would you use each for video understanding?

Correct. Whisper and CLAP address different questions about audio. Whisper: 'What words were spoken?' CLAP: 'What sounds are present?' They are complementary, not redundant. A video of a chef explaining a recipe has: Whisper output → transcript of the explanation; CLAP output → embeddings matching 'cooking sounds', 'knife chopping', 'background music'. Both are needed for complete multimodal video understanding. Wav2Vec2/HuBERT (self-supervised speech models) occupy a third niche: rich contextual speech representations for speaker identification, emotion recognition, and linguistic feature extraction.
Question 3 of 8

A CLAP audio encoder was pre-trained at 48kHz sample rate. You extract audio from a video at 16kHz (for Whisper). Before running CLAP inference, what must you do and why?

Correct. Audio encoder sample rate mismatch is one of the most common bugs in multimodal video pipelines. CLAP's mel spectrogram frontend is calibrated to 48kHz. Passing 16kHz audio causes the frequency axis of the spectrogram to be misaligned with the filterbank — the model sees energy in the wrong frequency bins relative to its training distribution. The ClapProcessor's sampling_rate parameter triggers automatic resampling via torchaudio, handling this correctly. Best practice: always extract audio separately for each model at its required sample rate (16kHz for Whisper, 48kHz for CLAP), or extract once at the highest rate and downsample per-model.
Question 4 of 8

AV-HuBERT is pre-trained to predict masked audio features from visual lip motion (and vice versa). How does this audio-visual self-supervised learning differ from CLAP's audio-text contrastive learning, and what task does each excel at?

Correct. The key distinction is temporal vs semantic alignment. AV-HuBERT operates at the frame level and learns the precise temporal correspondence between audio and visual modalities — the model must predict masked acoustic features from the visual stream, requiring understanding of the millisecond-level synchrony between lip movements and speech sounds. CLAP operates at the clip level and learns semantic correspondence — 'a 3-second clip of dog barking' should be close to the text 'sound of a dog' regardless of the exact temporal structure within the clip.
Question 5 of 8

Whisper uses dynamic time warping (DTW) on decoder cross-attention weights to produce word-level timestamps. What is DTW doing in this context and why is cross-attention the right signal for alignment?

Correct. Cross-attention as alignment is the key insight. The Whisper decoder generates each token by attending to specific encoder positions — the attention weight matrix (output_tokens × encoder_frames) encodes which audio frame was most informative for each output token. DTW finds the monotonic path through this matrix that gives each token a frame-level start and end time. The monotonicity constraint is essential: words cannot be generated in reverse temporal order. This gives word-level timestamps without any forced alignment model or separate alignment step — the timestamps emerge naturally from the attention mechanism.
Question 6 of 8

You build a multimodal video search system that indexes cooking videos. Users can query with: (A) text descriptions ('garlic being chopped'), (B) reference audio clips (audio of chopping sounds), or (C) reference video frames (image of a cutting board with garlic). Which combination of models enables all three query types?

Correct. The joint embedding space approach (option D) is the production-grade solution. ImageBind (Meta 2023) is the canonical example: a single model that maps images, text, audio, video, depth, and IMU signals to a shared embedding space. Any modality can be used as a query to retrieve any other modality. The key is alignment training: CLIP image-text pairs plus CLAP audio-text pairs provide two 'bridges' that, when combined, align all three modalities. Without the shared space (option A — three separate indices), cross-modal retrieval requires an audio-to-text transcription step, which fails for non-speech audio.
Question 7 of 8

A podcast transcription pipeline uses Whisper large-v3 with 30-second chunks and 1-second overlap. A guest speaker's name 'Krishnamurthy' spans the boundary between chunk 1 (ends at 30s) and chunk 2 (starts at 29s with 1s overlap). What outputs does the pipeline produce for this word and how do you handle the duplication?

Correct. Boundary word duplication is a real and common issue in long-form Whisper transcription. The overlap window ensures no words are lost at boundaries, but creates duplicates. The deduplication strategy must handle both exact duplicates (same word, similar timestamps) and near-duplicates (same word, different timestamps due to Whisper's variable chunking) and inconsistent transcriptions (same word spelled differently across chunks due to different acoustic context). Production pipelines (WhisperX, faster-whisper) handle this with word-level alignment and explicit deduplication logic.
Question 8 of 8

You need audio features for a video emotion recognition task (detecting whether speakers sound happy, sad, angry, neutral). You have three options: (A) CLAP embeddings, (B) Wav2Vec2 contextual embeddings, (C) MFCC hand-crafted features. Rank these by expected performance and explain the ranking.

Correct. Wav2Vec2 (and HuBERT) are the right choice for speech emotion recognition. These models were pre-trained on massive speech corpora specifically to learn contextual speech representations — their internal representations capture prosody (intonation, rhythm, stress patterns), voice quality, and temporal dynamics that are directly relevant to emotion. CLAP was pre-trained on 630K audio-text pairs describing environmental sounds ('dog barking', 'rain') — it has limited exposure to speech prosodic variation and its text supervision did not include emotion labels. MFCC features are powerful for phoneme-level analysis but lack the contextual modelling that transformers provide — they cannot capture sentence-level prosodic patterns that span seconds. The ranking for emotion: Wav2Vec2 >> CLAP > MFCC.
