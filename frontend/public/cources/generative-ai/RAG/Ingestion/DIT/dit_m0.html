01 · The Attention Mechanism

Scaled Dot-Product Attention —
Why Every Component Exists

Attention allows every token in a sequence to communicate with every other token. The key insight: instead of fixed connection patterns (like CNNs) or sequential processing (like RNNs), attention computes dynamic, content-dependent relationships. Every word can attend to every other word in one forward pass — and the weights that determine "how much attention" are computed from the content itself.

🔑

Why three matrices — Q, K, V?

Q (Query) is what this token is looking for. K (Key) is what each token broadcasts about itself. V (Value) is what each token contributes if selected. The dot product QKᵀ measures compatibility between what you are looking for and what each token offers. Softmax converts these compatibility scores to weights. The weighted sum of V values is the output — a blended representation shaped by relevance.

⚠️

The √dₖ scaling is not optional

For d_k=64, the standard deviation of QKᵀ dot products is √64=8 without scaling. Softmax of values with std=8 approaches a one-hot distribution — attention collapses onto a single token. The √dₖ divisor keeps dot product variance at 1.0 regardless of dimension, preserving smooth gradient flow through softmax during training.

02 · Multi-Head Attention

Parallel Attention Streams for
Richer Document Representations

Single-head attention computes one set of attention weights. Multi-head attention runs h independent attention computations in parallel, each with a reduced dimension d_k = d_model/h. The outputs are concatenated and projected back to d_model. This allows the model to simultaneously attend to different aspects — layout position, token semantics, and structural relationships — in the same layer.

▸ Multi-Head Attention — h parallel heads with concatenation

What each head learns

Analysis of trained transformer heads shows specialisation: some heads track syntactic dependencies, others track coreference, others attend to positional neighbours. In document transformers, heads specialise on spatial relationships (tokens in the same table row), semantic relationships (label-value pairs), and structural relationships (headings and their content sections).

Parameter count

Each head has three weight matrices: W_Q, W_K, W_V ∈ ℝ^(d_model × d_k). Plus the output projection W_O ∈ ℝ^(d_model × d_model). For h=12 heads, d_model=768, d_k=64: 3 × 768 × 64 × 12 + 768² = 1,769,472 + 589,824 = 2.36M parameters per attention layer.

03 · The Transformer Block and Positional Encoding

Block Structure, Residual Connections,
and 2D Position for Documents

A transformer encoder is a stack of identical blocks. Each block applies multi-head attention followed by a feed-forward network, with residual connections and layer normalisation after each. The residual connections are critical — they allow gradients to flow directly from the output to any earlier layer, enabling training of very deep networks.

💡

Why 2D encoding is essential for documents

In a standard NLP transformer, "position 42" means the 42nd token in the sequence. In a document, two tokens can be sequence-distant but spatially adjacent (e.g. a form label and its value separated by other content in reading order). 2D bounding box encoding makes spatial proximity explicit — the model can learn that tokens with similar y-coordinates are on the same line, and tokens with similar x-coordinates are in the same column, regardless of their sequence distance.

Question 1 of 5

A colleague claims that removing the √dₖ scaling from attention (i.e. using QKᵀ instead of QKᵀ/√dₖ) would make training faster because there is one fewer division. What actually happens and why?

Correct. Without √dₖ scaling, dot products have variance proportional to dₖ. For dₖ=64, the standard deviation is 8× larger than the scaled version. Softmax maps these large inputs to near-one-hot distributions, collapsing gradient flow. The scaling is mathematically necessary, not just numerically convenient.
Question 2 of 5

LayoutLMv3 uses 2D positional embeddings that encode the bounding box coordinates (x0, y0, x1, y1) of each token on the page. A standard BERT model uses 1D sinusoidal position embeddings that encode sequence position. Why is 2D encoding essential for document understanding that 1D encoding cannot provide?

Correct. The critical insight: a label like 'Invoice Date' and its value '15 March 2024' may be spatially adjacent (in the same row of a form) but separated by dozens of sequence positions if other content appears between them in reading order. 1D position cannot represent this spatial relationship. 2D bbox encoding allows attention to be guided by both sequence proximity and spatial proximity simultaneously.
Question 3 of 5

The feed-forward network (FFN) in each transformer block expands the hidden dimension from d_model=768 to 4×d_model=3072, then projects back to 768. Why 4× specifically, and what does the FFN actually compute?

Correct. Research by Geva et al. (2021) showed that FFN layers function as key-value memories. Each row of the first weight matrix is a 'key pattern'; the GELU activation determines which keys fire; each row of the second weight matrix is the corresponding 'value'. The 4× ratio is a practical choice — large enough to store sufficient associations, small enough to keep parameter count manageable. For DiT models, FFN layers store visual-semantic associations learned from document pretraining.
Question 4 of 5

A transformer encoder processes a 512-token document. Computing full self-attention requires O(n²) memory where n=512. Which of the following is the correct memory cost for the attention matrix, and what makes this problematic for long documents?

Correct. The n×n attention matrix is the fundamental bottleneck. At n=512 it is manageable; at n=2048 (a typical legal contract) it requires 2.4GB just for attention. This O(n²) cost is why efficient attention variants (Longformer, BigBird, flash attention) were developed for long documents. Flash attention does tile the computation to avoid materialising the full matrix, but standard attention does store it.
Question 5 of 5

You are choosing between two configurations for a LayoutLM-style document encoder: Config A uses 12 attention heads with d_k=64 (d_model=768), and Config B uses 3 attention heads with d_k=256 (d_model=768). Both have the same parameter count. Which should you prefer for document understanding and why?

Correct. Multiple heads with smaller d_k empirically outperform fewer heads with larger d_k at constant parameter count. The intuition: each head learns a different attention pattern — some heads attend to spatially adjacent tokens (layout), others to semantically similar tokens (content), others to document structure markers (headers). With only 3 heads, the model must represent all of these in fewer parallel streams. The original transformer paper explicitly motivates multi-head attention as allowing 'jointly attending to information from different representation subspaces at different positions'.
