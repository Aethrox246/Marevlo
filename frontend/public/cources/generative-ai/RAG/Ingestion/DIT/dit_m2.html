01 · The LayoutLM Progression

Three Versions, Three Architectural
Insights

LayoutLM (2020) proved that spatial layout is as important as text content for document understanding. LayoutLMv2 (2021) proved that image features provide additional signal beyond layout. LayoutLMv3 (2022) proved that cross-modal attention between text and image tokens within a unified transformer outperforms modality-specific encoding followed by fusion. Each version is a lesson in what the previous version was missing.

▸ LayoutLM progression — inputs added at each version
🔑

Why layout alone beat expectations

LayoutLMv1 achieved state-of-the-art on FUNSD with no image features. This revealed a key insight about structured documents: positional regularity is a strong prior. In an invoice, the total appears at the bottom-right. In a form, field labels appear left of their values. The 2D position embedding encodes these spatial regularities, allowing the model to learn position-conditional semantics — "what a token means depends on where it appears."

02 · LayoutLMv3 — Unified Cross-Modal Architecture

Text Tokens and Image Patches in
a Single Sequence with Shared Position

LayoutLMv3's key innovation: text tokens and image patch tokens are concatenated into one sequence and processed by a single transformer. Both share the same 2D position embedding space — text tokens get the bbox of the OCR word, image patches get the bbox of their position on the page. This shared coordinate system enables the attention mechanism to learn spatial correspondences between text and visual content.

▸ LayoutLMv3 input construction — how three modalities fuse into one sequence

Why replace CNN with linear projection?

ResNeXt-101 in LayoutLMv2 produces a feature map that is fused with text features through concatenation. The two modalities interact only through the final fusion step — they are encoded separately. With ViT-style patch tokens, text and image tokens exist in the same sequence and attend to each other in every layer. A text token for "Invoice" can query image patches in the same row to see what the printed header looks like. This deep cross-modal interaction is not possible with CNN fusion.

Shared 2D position embeddings

Both text tokens and image patch tokens receive 2D bounding box embeddings. A text token for "15 March" gets the bbox of that text on the page. The image patch covering the same area gets a matching bbox. When these two tokens attend to each other, the shared position embedding creates a spatial "anchor" — the attention between them is boosted by their spatial alignment, helping the model learn that the text and the visual rendering of "15 March" are the same entity.

ANLS — why F1 is wrong for DocVQA

DocVQA answers are strings that may differ slightly from ground truth due to OCR errors or normalisation. F1 would penalise "£1,234.56" vs "£1234.56" as wrong despite being equivalent. ANLS (Average Normalised Levenshtein Similarity) measures edit distance — it rewards near-correct answers proportionally rather than treating them as binary correct/wrong. For document extraction evaluation where OCR introduces character-level noise, ANLS is always preferred over exact match or F1.

Question 1 of 5

LayoutLMv1 achieved strong results on FUNSD form understanding despite having no image features — only text tokens and 2D bounding box positions. What does this reveal about the relative importance of layout vs visual appearance for structured document understanding?

Correct. LayoutLMv1 demonstrated that spatial layout is the dominant signal for structured document understanding. A token's position on the page carries strong semantic information: headers appear in the top third, dates appear in specific form fields, totals appear in right-aligned bottom rows. This spatial regularity is the structural prior that layout-aware models exploit. Image features (added in v2 and v3) provide additional signal for visually complex documents (stamps, signatures, logos) but are less critical than layout for clean structured forms.
Question 2 of 5

LayoutLMv2 uses a ResNeXt-101 CNN to extract visual features from document images. LayoutLMv3 replaces the CNN with a linear projection of image patches (ViT-style). Why did this architectural change improve performance?

Correct. The architectural reason is cross-modal attention. With CNN features, text and image are separate streams that are combined through feature-level fusion (addition or concatenation) after encoding — the two modalities never directly interact within the attention mechanism. With ViT-style patch tokens, text tokens and image patch tokens are concatenated into a single sequence and attend to each other within the transformer. Shared 2D position embeddings mean both modalities share a common spatial coordinate system. This allows text token representations to be directly shaped by the visual appearance of the corresponding image region.
Question 3 of 5

You are using LayoutLMv3 for named entity recognition on FUNSD forms. The model is fine-tuned with IOB2 token labelling. A word token 'Amount' with bbox (0.45, 0.82, 0.56, 0.87) should be labelled B-KEY. What information does the model use to make this prediction, and which modality is most important?

Correct. All three modalities contribute but with different weights depending on context. For 'Amount' as a key field label, 2D position is typically the dominant signal — its vertical position distinguishes it from a column header and horizontal position distinguishes it from a value field. Text semantics provides strong prior evidence. Image features confirm visual formatting (bold label text vs. regular body text). The power of LayoutLMv3 is that cross-modal attention learns these relative modality weights from labelled examples rather than requiring manual feature engineering.
Question 4 of 5

Fine-tuning LayoutLMv3 on DocVQA (document visual question answering) requires the model to answer questions like 'What is the total amount on this invoice?' given the document image and OCR text. The answer must be extracted as a text span from the document. Why is this task harder than standard NER and what architectural property of LayoutLMv3 makes it suitable?

Correct. The critical mechanism is question-document cross-attention. By concatenating the question before the document, question tokens can attend to every document token and patch, and document tokens can attend back to the question. This bidirectional attention allows the question semantics to guide which document regions are relevant. LayoutLMv3's multi-modal cross-attention adds image patch attention on top of text cross-attention — for questions about visual attributes ('What colour is the header?') or visual layout ('What is in the bottom-right corner?'), image patch attention is essential.
Question 5 of 5

LayoutLMv3 is pretrained with two objectives: Masked Language Modelling (MLM) on text tokens and Masked Image Modelling (MIM) on image patches. Why are both objectives necessary — why isn't MLM alone sufficient?

Correct. Both pretraining objectives are necessary to ensure both modalities develop useful representations. MLM creates gradient signal for the text pathway; MIM creates gradient signal for the image pathway. Without MIM, the visual encoder receives no training signal from pretraining and would contribute only noise to the cross-modal attention. The complementary objectives also align the two representation spaces: masked tokens in one modality can be predicted from unmasked tokens in both modalities, forcing the model to learn meaningful cross-modal associations during pretraining rather than relying entirely on fine-tuning to build text-image alignment.
