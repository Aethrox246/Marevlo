Document Pre-training at Scale

MIM · BEiT · IIT-CDIP · DocBank · SynthDoG · Weak Supervision · Curriculum Design

Every powerful document AI model starts with pretraining — learning document representations from large unlabelled datasets before any task-specific fine-tuning. The quality of pretraining determines the upper bound on downstream performance. This module covers the key pretraining datasets (IIT-CDIP, DocBank, SynthDoG, PubLayNet), the objectives used to learn from them (MIM, MLM, pseudo-OCR), why some objectives work better than others, and how to design pretraining curricula for multi-domain production systems.

01 · Pretraining Objectives for Document Images

What the Model Must Learn
Before Seeing Any Labels

Self-supervised pretraining creates learning signal from unlabelled data by defining a prediction task that can only be solved by developing useful internal representations. For document images, Masked Image Modelling (MIM) masks random patches and requires the encoder to predict them from context — forcing it to learn the visual grammar of documents: what text regions look like, how tables are structured, where figures appear.

▸ Masked Image Modelling — BEiT-style discrete token prediction
🔑

Why discrete tokens, not raw pixels?

Raw pixel prediction is dominated by low-frequency image content — smooth backgrounds, colour gradients — which are easy to predict but semantically uninformative. Discrete visual tokens from a dVAE tokeniser force the model to predict the semantic category of each patch (dense text, table border, figure, white space) rather than exact pixel values. This produces semantic representations aligned with document understanding tasks rather than pixel-accurate reconstruction.

02 · Pretraining Datasets at Scale

IIT-CDIP, DocBank, SynthDoG —
How Document AI Gets Its Training Data

Large-scale labelled datasets for document understanding are expensive to create — annotating bounding boxes and field values for millions of documents requires enormous human effort. The field has developed three strategies: (1) use unlabelled scanned document archives with self-supervised objectives; (2) exploit structured document formats (LaTeX, XML, HTML) to auto-generate labels; (3) generate synthetic documents with known ground truth.

Question 1 of 5

BEiT-style MIM predicts discrete visual tokens (from a dVAE tokeniser) rather than raw pixel values for masked patches. Why is predicting raw pixels a poor pretraining objective for document understanding?

Correct. The low-frequency dominance problem with raw pixel prediction is fundamental. Documents have large uniform regions (white background, solid text blocks) that are trivially predictable, contributing high loss weight despite providing no useful semantic signal. Discrete token prediction forces the model to classify each patch semantically. This is analogous to why BERT predicts masked words (discrete categories) rather than masked continuous word embeddings — the discrete objective creates a meaningful signal at the level of semantic units.
Question 2 of 5

DocBank is created by rendering academic LaTeX papers to PDF and using the LaTeX source to automatically generate bounding box labels for document regions (title, abstract, paragraph, figure, table, equation). What is the key advantage of this 'weak supervision' approach over manual annotation?

Correct. The weak supervision pipeline is the key innovation — structured document formats (LaTeX, HTML, XML) contain semantic layout information that can be automatically aligned with rendered pixel positions. PubLayNet uses the same approach with PubMed XML. This pattern — exploit existing structured source to generate labels automatically — is the standard technique for creating large-scale document understanding datasets without prohibitive annotation costs.
Question 3 of 5

IIT-CDIP contains 42 million scanned document images but NO text labels — only images. DiT pretraining uses these unlabelled images with a MIM objective. How can a model learn useful document representations from images alone, without any text labels or layout annotations?

Correct. Self-supervised learning exploits the structure inherent in the data distribution itself. Documents have strong visual regularity: text regions have consistent local texture patterns, tables have regular grid structure, headers have distinct size and position patterns. The MIM objective creates a prediction task that can only be solved by learning these regularities — the prediction signal comes from the data structure itself, not from external labels. This is the same principle as word2vec learning word semantics from word co-occurrence patterns without any explicit semantic labels.
Question 4 of 5

A paper claims their new document pretraining method achieves SOTA on RVL-CDIP (document classification) by training on 100M web-scraped PDFs. A reviewer objects: 'The improvement may be purely due to scale — 100M vs 42M images — not the new pretraining objective.' How should the authors address this?

Correct. Scale-objective confounding is one of the most common validity threats in pretraining research. The standard ablation protocol: run method A on N samples, run method B on N samples (matched scale), then separately investigate scaling behaviour. If method B outperforms method A at matched scale, the objective is the cause. Many published improvements in pretraining have been partially or fully attributed to scale when controlled ablations were eventually conducted. This is why the NeurIPS Datasets and Benchmarks track specifically asks for scale-controlled ablations.
Question 5 of 5

You are designing a pretraining curriculum for a document model that must handle three domains: financial reports (structured tables, dense numbers), legal contracts (long paragraphs, clause structure), and medical records (handwritten and printed mixed, clinical terminology). Should you pretrain on all three domains simultaneously or sequentially, and why?

Correct. Catastrophic forgetting is the key risk of sequential pretraining — the reason to mix domains simultaneously. The mixing ratio is the critical implementation decision: naive uniform mixing gives equal weight to all domains regardless of their size or importance, while production-distribution sampling reflects actual usage. The medical domain's handwriting component is a real complication — it may require a separate pretraining stage or a hybrid approach where HTR-pretrained weights are used as initialisation for the mixed pretraining. This kind of multi-domain curriculum design is a core skill in production document AI engineering.
