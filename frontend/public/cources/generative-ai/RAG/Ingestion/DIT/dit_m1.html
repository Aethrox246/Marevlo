Patch Tokenisation · CLS Token · O(n²) Cost · Swin Windowed Attention · Domain Pretraining

Before transformers could understand documents, they had to learn to see them. Vision Transformers (ViT) brought the transformer architecture to image understanding by treating an image as a sequence of patches — making visual processing compatible with the attention mechanism. Swin Transformer extended this to high-resolution images with windowed attention. These two architectures form the visual backbone of every modern document intelligence model, from LayoutLMv2 to Donut to DiT itself.

01 · ViT — Patch Tokenisation

How Vision Transformers
Turn an Image into a Sequence

Transformers operate on sequences of vectors. Images are 2D grids of pixels. ViT bridges this gap by dividing the image into non-overlapping 16×16 patches, flattening each patch into a vector, and projecting to the transformer's hidden dimension d_model. The result: a document image becomes a sequence of 196 tokens — each representing one spatial region of the page.

▸ ViT pipeline — from document image to classification via patch tokens
🔑

Why patches, not pixels?

A 224×224 image has 50,176 pixels. If each pixel were a transformer token, self-attention would require 50,176² ≈ 2.5 billion operations per layer — completely intractable. 16×16 patches reduce the sequence to 196 tokens, making attention feasible while preserving enough spatial resolution to distinguish document layout regions.

The CLS token

A learnable vector prepended to the patch sequence. It has no spatial meaning — it starts as random noise and learns, through gradient descent, to aggregate global document information across all attention layers. Only CLS is used for classification. It is the transformer's mechanism for pooling a variable-length sequence to a fixed representation.

Sequence length calculation

For a 224×224 image with 16×16 patches: n_patches = (224/16)² = 196. With CLS prepended: 197 tokens. For 448×448: (448/16)² + 1 = 785 tokens. The O(n²) attention cost means 448×448 requires (785/197)² ≈ 15.9× more memory than 224×224 — a critical constraint for high-resolution document processing.

02 · Swin Transformer — Windowed Attention for Documents

Hierarchical Features at
Linear Complexity

ViT's global attention is powerful but O(n²) expensive. For high-resolution document images, this is prohibitive. Swin Transformer limits attention to local windows of patches (e.g. 7×7 = 49 patches), reducing complexity to O(n × w²) where w is the window size. Shifted windows in alternating layers provide cross-window context. The hierarchical design produces feature maps at 4 scales — critical for detecting document elements ranging from individual characters to full-page regions.

03 · Fine-Tuning Strategies and Domain Pretraining

From ImageNet Features to
Document Understanding

💡

DiT: the case for document-domain pretraining

DiT (Document Image Transformer) pretrained ViT-Base on IIT-CDIP — 42 million scanned documents — using masked image modelling. The result: a ViT that understands text density patterns, table grid structures, and form layouts from scratch, before any task-specific fine-tuning. On RVL-CDIP document classification, DiT achieves 92.1% accuracy vs 89.5% for ImageNet-pretrained ViT-Base — a 2.6-point gain from domain pretraining alone, using the same architecture and parameter count.

Question 1 of 5

A ViT-Base model processes a 224×224 document image using 16×16 patches. How many tokens does the transformer encoder receive, and what is the quadratic memory cost of self-attention relative to a 448×448 image of the same document?

Correct. At 224×224 with 16×16 patches: (224/16)² = 196 patches + 1 CLS = 197 tokens. At 448×448: (448/16)² = 784 patches + 1 CLS = 785 tokens. The attention matrix scales as n², so (785²)/(197²) ≈ 15.9× more memory. This quadratic scaling is why high-resolution document images (A4 scans at 300 DPI = 2480×3508 pixels) cannot be processed by ViT without hierarchical or window-based approaches like Swin Transformer.
Question 2 of 5

The CLS token in ViT is a learnable vector prepended to the patch sequence. After transformer processing, only the CLS token is fed to the classification head — not the individual patch representations. Why does attending to all patches allow CLS to represent the whole document?

Correct. The CLS token's information gathering is emergent — it learns through backpropagation to query relevant patches across all layers. By layer 12, its representation encodes a global summary of the entire document image that is optimal for the downstream classification task. Visualising the attention weights from CLS in trained ViTs reveals that it learns to attend to semantically meaningful regions — for invoice classification, it attends to header regions and key number fields.
Question 3 of 5

You are deciding between ViT-Base and Swin-Base for a document layout detection task on high-resolution (1024×1024) scanned pages. The task requires detecting bounding boxes for text regions, tables, and figures. Which model is more appropriate and why?

Correct. The three advantages of Swin for document layout detection are fundamental: memory tractability at high resolution, multi-scale hierarchical features for multi-size element detection, and cross-window context via shifted windows. ViT's O(n²) attention becomes prohibitive at 1024×1024 — this is precisely why Swin Transformer was proposed as a general-purpose vision backbone for dense prediction tasks including object detection and semantic segmentation.
Question 4 of 5

When fine-tuning ViT-Base (pretrained on ImageNet-21k) for invoice classification, you have 500 annotated invoices. A colleague suggests freezing all 12 transformer layers and only training the classification head. Another suggests fine-tuning the last 4 layers plus the head. Which strategy should you choose and why?

Correct. The partial fine-tuning strategy (last N layers + head) is the standard approach for limited-data fine-tuning of large vision transformers. Early ViT layers learn general visual features (edges, textures, low-level patterns) that transfer universally across image domains. Later layers encode task-specific representations that are more domain-dependent. For 500 examples, fine-tuning all 86M parameters risks overfitting — fine-tuning the last 4 layers (≈12M parameters) with the head is a principled trade-off. Monitor validation loss carefully: stop training when validation loss begins to increase.
Question 5 of 5

DiT (Document Image Transformer, Microsoft 2022) uses a ViT-Base backbone pretrained on IIT-CDIP — a dataset of 42 million scanned document images. Why does document-domain pretraining on IIT-CDIP produce better document understanding than ImageNet pretraining, even though ImageNet has higher image quality?

Correct. Domain pretraining is about feature distribution alignment, not just scale. ImageNet photographs contain dogs, cars, and landscapes — none of which share visual structure with invoices, contracts, or forms. A ViT pretrained on ImageNet must learn document-specific features from scratch during fine-tuning. A ViT pretrained on 42M scanned documents already has robust representations of text density patterns, table structures, and form layouts before fine-tuning begins. This is why DiT significantly outperforms ImageNet-pretrained ViT on all document understanding benchmarks with the same downstream labelled data.
