Ranking, Deduplication, and Output Assembly

Composite Scoring · NMS Dedup · Hard Removal · Soft Weighting · Threshold Calibration · Boilerplate Drift

The greedy expander produces a raw set of MFP candidates — but raw candidates are not a retrieval-ready output. Some candidates overlap heavily (near-duplicates that waste suppression budget); some are correctly scored but in the wrong order; some need different treatment depending on whether they feed a BM25 index or a dense encoder. This module covers the full output assembly pipeline: composite scoring, NMS-style deduplication, the hard-removal vs soft-downweighting integration choice, and the calibration methodology that determines whether the suppression list actually improves retrieval.

01 · Scoring and Ranking — From Candidates to Ordered Output

Composite Score:
Frequency × Lengthβ

The greedy expander produces every valid MFP — but not in retrieval-useful order. Ranking requires a composite score that balances two desiderata: how ubiquitous is the pattern (high df → boilerplate), and how much content does suppressing it remove (long phrase → larger suppression gain). The score function Score(P) = df(P)^α × length(P)^β is the standard parameterisation, with α and β calibrated per corpus on a held-out annotation set.

MFP output pipeline — score, NMS deduplication, top-K selection, retrieval integration

mfp_ranker.py — MFP scoring, deduplication, and output ranking

from dataclasses import dataclass, field
from collections import defaultdict
import heapq

@dataclass(order=True)
class MFPCandidate:
    """
    One candidate MFP after greedy expansion.
    sort_key is used by heapq for the priority queue (max-heap via negation).
    """
    sort_key:  float = field(compare=True)
    tokens:    tuple = field(compare=False)
    df:        int   = field(compare=False)   # document frequency
    positions: list  = field(compare=False)   # [(doc_id, start, end), ...]
    length:    int   = field(compare=False)   # token count


def score_mfp(candidate: MFPCandidate,
               N: int,
               alpha: float = 1.0,
               beta:  float = 0.5) -> float:
    """
    Composite MFP score that balances frequency and length.

    Score(P) = df(P)^alpha × length(P)^beta

    Rationale:
    - df(P): high document frequency → ubiquitous boilerplate.
      Navigation menus appear in 90%+ of pages → very high df.
      Product descriptions appear in 1-2% of pages → low df.
    - length(P): longer phrases carry more information — suppressing
      "copyright 2024 All Rights Reserved" (6 tokens) is more
      informative than suppressing "copyright" alone (1 token).
    - alpha=1.0: linear frequency weight (default).
    - beta=0.5: sub-linear length weight — prevents very long but
      rare phrases from dominating short ubiquitous ones.

    Alternative: IDF-weighted score
      Score(P) = df(P) × length(P) × (-log(df(P)/N))
    This explicitly penalises near-universal phrases (idf→0)
    in favour of domain-boilerplate (common but not universal).
    """
    return (candidate.df ** alpha) * (candidate.length ** beta)


def deduplicate_mfps(
    candidates: list[MFPCandidate],
    overlap_threshold: float = 0.8,
) -> list[MFPCandidate]:
    """
    Remove MFP candidates that are largely subsumed by higher-ranked ones.

    Two MFPs P and Q overlap if their token sets share > overlap_threshold
    fraction of tokens (Jaccard similarity on token positions).

    Problem: greedy expander may produce near-duplicate phrases:
      "all rights reserved"       df=92400   length=3
      "all rights reserved 2024"  df=87200   length=4
    Both are valid MFPs, but keeping both wastes suppression budget.

    Strategy: sort by score descending; for each candidate, check if it
    overlaps with any already-accepted MFP. If overlap > threshold, skip.
    This is NMS (Non-Maximum Suppression) applied to phrase space.

    Note: position-level deduplication is already handled by the global
    bitmask during expansion. This deduplication is at the phrase-type
    level — removing semantically redundant phrases from the output list.
    """
    candidates = sorted(candidates, key=lambda c: c.sort_key, reverse=True)
    accepted = []
    accepted_token_sets = []
    for cand in candidates:
        cand_set = set(cand.tokens)
        dominated = False
        for acc_set in accepted_token_sets:
            intersection = len(cand_set & acc_set)
            union        = len(cand_set | acc_set)
            jaccard      = intersection / union if union > 0 else 0
            if jaccard > overlap_threshold:
                dominated = True
                break
        if not dominated:
            accepted.append(cand)
            accepted_token_sets.append(cand_set)
    return accepted


def assemble_mfp_output(
    expanded_candidates: list[MFPCandidate],
    N: int,
    top_k: int = 500,
    overlap_threshold: float = 0.8,
) -> list[MFPCandidate]:
    """Full output pipeline: score → dedup → top-k selection."""
    for c in expanded_candidates:
        c.sort_key = score_mfp(c, N)
    deduped = deduplicate_mfps(expanded_candidates, overlap_threshold)
    return sorted(deduped, key=lambda c: c.sort_key, reverse=True)[:top_k]
02 · Hard Removal vs Soft Downweighting

Integration Mode Determines
What the Index Sees

The MFP list is only as useful as how it is integrated into the downstream retrieval system. Hard removal deletes MFP-covered token positions from the document before indexing — appropriate for BM25 where term frequency is the signal. Soft downweighting multiplies each covered token's embedding weight by (1 − df(P)/N) — appropriate for dense retrieval where the encoder still benefits from positional context. The integration mode must match the retrieval architecture.

Hard removal (BM25) vs soft downweighting (dense) — same MFP, different integration effects

mfp_retrieval_filter.py — integrate MFP suppression into a retrieval pipeline

import re
from typing import Iterator

class MFPBoilerplateFilter:
    """
    Post-expansion integration: use ranked MFP list to strip boilerplate
    from documents before indexing into a retrieval system (BM25 / dense).

    Two suppression modes:
    1. HARD REMOVAL: delete all tokens covered by any MFP occurrence.
       Best for BM25 — removes boilerplate from the term-frequency map.
       Risk: may remove too-short MFPs that are also content words.

    2. SOFT DOWNWEIGHTING: multiply term weights by (1 - coverage_score).
       Best for dense retrieval — the encoder still sees the tokens but
       the training signal is downweighted.

    Coverage score for token t in document d:
       coverage(t, d) = max over all MFP occurrences covering t:
                        df(P) / N   (fraction of corpus containing this MFP)
    High coverage → likely boilerplate → downweight.
    Low coverage  → likely content    → keep full weight.
    """

    def __init__(self, mfp_list: list, N: int,
                 df_threshold: float = 0.02):
        # Only suppress MFPs that appear in > df_threshold fraction of corpus
        self.suppressed = {
            m.tokens
            for m in mfp_list
            if m.df / N >= df_threshold
        }
        self.N = N

    def _find_mfp_spans(self, tokens: list) -> list[tuple[int,int]]:
        """Return list of (start, end) spans covered by any suppressed MFP."""
        spans = []
        for mfp_tokens in self.suppressed:
            L = len(mfp_tokens)
            for i in range(len(tokens) - L + 1):
                if tuple(tokens[i:i+L]) == mfp_tokens:
                    spans.append((i, i + L))
        return sorted(set(spans))

    def hard_remove(self, tokens: list[str]) -> list[str]:
        """Remove all token positions covered by a suppressed MFP."""
        covered = set()
        for start, end in self._find_mfp_spans(tokens):
            covered.update(range(start, end))
        return [t for i, t in enumerate(tokens) if i not in covered]

    def coverage_weights(self, tokens: list[str],
                           mfp_df_map: dict) -> list[float]:
        """
        Soft downweighting: return per-token weight in [0, 1].
        weight = 1.0 - coverage_score
        coverage_score = max df(P)/N over all MFPs covering this token.
        """
        weights = [1.0] * len(tokens)
        for mfp_tokens in self.suppressed:
            L = len(mfp_tokens)
            df_frac = mfp_df_map.get(mfp_tokens, 0) / self.N
            for i in range(len(tokens) - L + 1):
                if tuple(tokens[i:i+L]) == mfp_tokens:
                    for j in range(i, i+L):
                        weights[j] = min(weights[j], 1.0 - df_frac)
        return weights
⚠️

Train-inference asymmetry in soft downweighting

If you apply MFP weights to document tokens during training but NOT to query tokens at inference, the encoder learns an asymmetric space: document representations minimise boilerplate tokens while query representations treat them at full weight. Always apply the same preprocessing to both documents and queries — or use hard removal, which is naturally symmetric (same tokens deleted from both sides).

03 · Calibration and Production Maintenance

Threshold Calibration and
Boilerplate Drift

🔑

The three calibration knobs

σ (seed threshold): minimum df for a seed n-gram to be queued for expansion. Set as σ = max(floor, N × fraction). Typical: max(50, N × 0.01). τ_overlap (NMS threshold): Jaccard similarity above which a lower-ranked MFP is dropped. Typical: 0.8 for web corpora, 0.6 for tightly-structured domain corpora. K (output size): number of MFPs in the final suppression list. Typical: 200–1000. All three are calibrated via downstream MAP/nDCG change on a held-out retrieval benchmark.

Production scenario: e-commerce boilerplate drift over 6 months

A fashion e-commerce platform runs MFP offline monthly. After GDPR update in month 3, every page gains 'Manage cookie preferences personalised ads' (new MFP, not in original list). MAP drops 2.1 points. Detection method: monitor the fraction of new documents with token spans not covered by any existing MFP. When uncovered fraction rises above 15% of document length, trigger re-computation. Result: MFP re-computation restores MAP within the same indexing cycle.

Question 1 of 8

The MFP scoring function Score(P) = df(P)^α × length(P)^β uses α=1.0 and β=0.5 by default. A news aggregator finds that long-tail boilerplate phrases (length 8–12 tokens, df=5000) are being ranked below very short phrases (length 2, df=80000). Which parameter adjustment corrects this ranking?

Correct. β controls how aggressively length is rewarded relative to frequency. β=0.5 (square root) gives sub-linear length reward; β=1.0 gives linear; β>1.0 gives super-linear. The calibration question is always: given your specific boilerplate distribution (what fraction is long vs short?), what β makes the ranking match human annotation? This is always determined empirically on a held-out annotated corpus, not set theoretically.
Question 2 of 8

NMS deduplication computes Jaccard similarity between MFP token sets. MFP P = ('all','rights','reserved','copyright','2024') scores 184800. MFP Q = ('all','rights','reserved') scores 151000. Jaccard(P,Q) = |P∩Q|/|P∪Q| = 3/5 = 0.6. With threshold τ=0.8, does Q get dropped?

Correct. The Jaccard threshold is the key calibration knob for NMS deduplication. At τ=0.8 and Jaccard=0.6, Q survives. Whether this is correct behaviour depends on your retrieval objective: if you want both 'all rights reserved' and 'all rights reserved copyright 2024' in the suppression list (to catch both variants across documents), τ=0.8 is appropriate. If you want to keep only the longest match, lower τ to 0.5.
Question 3 of 8

A corpus of 500,000 English web documents is processed by MFP. The output list contains 'cookie policy' (df=180000, length=2) ranked #3. Your BM25 retrieval system then hard-removes this phrase from all documents. A user queries 'chocolate cookie recipe'. What retrieval failure occurs and how do you prevent it?

Correct. Position-aware removal is the critical implementation requirement. MFP provides (doc_id, start, end) position tuples for each occurrence — these positions are what should be suppressed, not all occurrences of constituent tokens. A naive token-type-level removal ('remove the word cookie everywhere it appears in MFP spans') is safe only if the MFP tokens are purely boilerplate words with no content dual use. Always implement position-level suppression.
Question 4 of 8

The soft downweighting mode assigns weight = 1 - df(P)/N to each token covered by MFP P. For a corpus of N=500,000 documents and MFP 'all rights reserved' with df=435,000, the weight is 1 - 0.87 = 0.13. A dense retrieval model is fine-tuned on documents preprocessed with these weights. What risk does this introduce for query-time retrieval?

Correct. Train-inference asymmetry is the key failure mode for soft downweighting in dual-encoder retrieval. Document and query representations must be processed consistently. This is why most production systems use hard removal (identical for documents and queries) rather than soft weighting — soft weighting requires consistent application at both training and inference time, which adds infrastructure complexity. The exception: if boilerplate never appears in queries (users don't query 'all rights reserved'), soft weighting is safe because the query-side asymmetry never triggers.
Question 5 of 8

You set the df threshold at 2% (df/N ≥ 0.02) for suppression. Your corpus is 200,000 documents from an Indian e-commerce site. MFP 'अधिकार सुरक्षित' (Hindi: 'rights reserved') appears in 3,800 documents (df/N=0.019) — just below the 2% threshold. Should you suppress it?

Correct. Per-language threshold calibration is a critical production consideration for multilingual corpora. Global df thresholds systematically under-detect boilerplate in minority languages because their phrases have lower corpus-wide df. The correct approach: segment the corpus by detected language, compute df within each language segment, and apply language-specific (or at least normalised) thresholds. This is one of the most commonly missed issues when deploying MFP on multilingual enterprise corpora.
Question 6 of 8

After running the full MFP pipeline on a 1.7M document corpus, you produce 500 ranked MFP phrases. A retrieval engineer asks: 'How do we know these 500 phrases are actually boilerplate and not content?' Describe the evaluation methodology.

Correct. The dual evaluation methodology — direct annotation precision/recall + downstream IR metric improvement — is the gold standard for validating boilerplate detection systems. Direct annotation measures whether the MFPs are correct at the phrase level; downstream IR measurement validates whether suppressing them actually helps retrieval. Both are necessary: a system with high phrase-level precision but no IR improvement is suppressing real boilerplate that happened to not harm retrieval; conversely, a system that improves MAP without high phrase precision may be removing content that accidentally helps disambiguation.
Question 7 of 8

The MFP pipeline is integrated into a streaming document ingestion system where new documents arrive at 1000/second. The existing MFP list (computed offline on a historical corpus) is used to strip boilerplate. After 3 months, retrieval quality degrades. What is the most likely cause and the fix?

Correct. Boilerplate drift is the primary maintenance challenge for production MFP systems. Web corpus boilerplate is not static: cookie consent banners change with regulations, copyright years update, navigation structures evolve. A static MFP list computed once becomes progressively stale. The sliding-window re-computation strategy balances freshness against computational cost. In practice, weekly or monthly re-computation is sufficient for most web corpora; real-time streaming updates are only needed for rapidly evolving sources like news aggregators.
Question 8 of 8

Two retrieval engineers debate the suppression threshold σ. Engineer A says: 'Lower σ means more patterns found — always use σ=10 for maximum recall.' Engineer B says: 'σ must be set relative to corpus size, not as an absolute count.' Who is correct and why?

Correct. Relative threshold calibration is the principled approach. The MFP algorithm's σ is fundamentally a document frequency concept — phrases occurring in at least σ documents. The meaning of σ=10 is completely different at N=100 vs N=1,700,000. Production MFP deployments always parameterise σ as a fraction of N (with a floor for statistical reliability) and calibrate that fraction using retrieval quality on a held-out evaluation set. The formula σ = max(floor, N × fraction) is standard practice.
