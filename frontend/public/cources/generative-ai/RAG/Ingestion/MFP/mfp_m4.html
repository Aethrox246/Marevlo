Evaluation, Production Deployment, and Extensions

Direct Annotation · ΔMAP · Wilcoxon · Coverage Drift · Streaming Re-computation · Structural Boilerplate

Building the MFP pipeline is only half the problem. Knowing whether it works — and keeping it working as the corpus evolves — is the other half. This module covers the dual evaluation methodology that separates correctness from utility: token-level direct annotation (does the system correctly identify boilerplate?) vs downstream IR measurement (does it actually improve retrieval?). It then covers the production maintenance problem: boilerplate drifts over time, and a static MFP list becomes stale. The coverage drift monitor and near-duplicate extensions are the tools that keep the system fresh without re-running the full pipeline every week.

01 · Dual Evaluation — Annotation Precision and Downstream MAP

Two Metrics, Two Questions,
Both Required

MFP evaluation requires two independent measurement tracks. Direct annotation evaluation answers: "Is the system suppressing the right tokens?" Token-level precision and recall against human-annotated boilerplate spans provides a direct quality signal. Downstream IR evaluation answers: "Does suppression actually improve retrieval?" Paired MAP comparison before and after suppression provides the evidence that the system helps users. Neither metric alone is sufficient — high precision with no MAP gain means the boilerplate wasn't hurting retrieval; high MAP gain with low precision means the system accidentally removes content that happens to reduce query ambiguity.

Dual evaluation tracks — direct annotation (left) and downstream IR measurement (right)

mfp_evaluation.py — precision, recall, and IR metric evaluation for MFP suppression

from dataclasses import dataclass
from typing import NamedTuple
import numpy as np

@dataclass
class BoilerplateAnnotation:
    """Ground-truth annotation for one document."""
    doc_id: str
    boilerplate_spans: list[tuple[int,int]]   # [(start, end), ...]
    total_tokens:      int


def mfp_precision_recall(
    mfp_suppressed_spans:  dict[str, list[tuple[int,int]]],
    annotations:           list[BoilerplateAnnotation],
) -> tuple[float, float, float]:
    """
    Compute token-level precision and recall of MFP suppression.

    Precision: of all tokens suppressed by MFP, what fraction
               were truly boilerplate (in annotator spans)?
               High precision → MFP is not suppressing content.

    Recall:    of all annotated boilerplate tokens, what fraction
               were covered by some MFP?
               High recall → MFP catches most boilerplate.

    F1:        harmonic mean. The primary optimisation target.

    Inputs:
        mfp_suppressed_spans: {doc_id: [(start, end), ...]}
            — position-level spans suppressed by the MFP list
        annotations: ground-truth boilerplate spans per document
    """
    tp = fp = fn = 0
    ann_map = {a.doc_id: set() for a in annotations}
    for ann in annotations:
        for s, e in ann.boilerplate_spans:
            ann_map[ann.doc_id].update(range(s, e))
    for doc_id, spans in mfp_suppressed_spans.items():
        suppressed = set()
        for s, e in spans:
            suppressed.update(range(s, e))
        gold = ann_map.get(doc_id, set())
        tp += len(suppressed & gold)
        fp += len(suppressed - gold)
        fn += len(gold - suppressed)
    prec   = tp / (tp + fp) if (tp + fp) > 0 else 0.0
    recall = tp / (tp + fn) if (tp + fn) > 0 else 0.0
    f1     = 2 * prec * recall / (prec + recall) if (prec + recall) > 0 else 0.0
    return prec, recall, f1


def retrieval_delta(
    baseline_scores:  np.ndarray,   # (N_queries,) MAP without MFP
    mfp_scores:       np.ndarray,   # (N_queries,) MAP with MFP
    alpha:            float = 0.05,
) -> dict:
    """
    Statistical significance test for MAP improvement from MFP suppression.

    Uses paired Wilcoxon signed-rank test (non-parametric, query-level paired).
    Paired because each query is evaluated with/without MFP on the same index.

    Returns dict with:
        delta_map:    mean MAP improvement across queries
        p_value:      Wilcoxon p-value
        significant:  bool — whether improvement is significant at alpha
        effect_size:  Cohen's d for the paired differences

    Why not t-test?
    Per-query AP distributions are highly skewed (many queries near 0,
    few near 1). Wilcoxon is more robust to non-normality.
    """
    from scipy.stats import wilcoxon
    diffs = mfp_scores - baseline_scores
    stat, p = wilcoxon(diffs, alternative='greater')
    d = diffs.mean() / (diffs.std() + 1e-9)
    return {
        'delta_map':   float(diffs.mean()),
        'p_value':     float(p),
        'significant': p < alpha,
        'effect_size': float(d),
    }
02 · Production Maintenance — Drift Detection and Extensions

Boilerplate Changes:
Detecting and Responding to Drift

A static MFP suppression list computed at time T becomes stale as the corpus evolves. New boilerplate emerges (cookie consent banners, new navigation structures, updated copyright notices); old boilerplate disappears (site redesigns, discontinued product lines). The coverage drift monitor detects these changes by tracking the fraction of token positions covered by the current suppression list in a rolling window of new documents — a significant drop signals new boilerplate; a significant rise signals the list is now suppressing content.

Coverage ratio ρ over time — drift detection threshold δ and re-computation trigger

mfp_streaming.py — incremental MFP update for streaming document ingestion

import time
from collections import deque

class StreamingMFPMonitor:
    """
    Monitors a streaming document corpus for boilerplate drift.
    Triggers re-computation when coverage degradation is detected.

    Core idea:
    After the offline MFP run, the suppression list covers a known
    fraction of tokens per document (baseline coverage ratio ρ₀).
    As new boilerplate emerges and old boilerplate disappears,
    the coverage ratio of new documents diverges from ρ₀.

    Drift detection:
    Maintain a sliding window of the last W documents.
    Compute ρ_window = mean coverage fraction over the window.
    If |ρ_window - ρ₀| > δ_threshold → trigger re-computation.

    When to re-compute:
    - Coverage DROPS (ρ_window < ρ₀ - δ): new boilerplate not in list.
    - Coverage RISES (ρ_window > ρ₀ + δ): MFP phrases now match content.
    Both cases indicate the suppression list needs refreshing.

    Production parameters:
    - W = 10,000 documents (rolling window)
    - δ = 0.03 (3 percentage points coverage change)
    - Re-computation cost: ~4 CPU-hours for 1.7M docs
      → trigger threshold set to avoid false re-computations
    """
    def __init__(self, baseline_coverage: float,
                 window_size: int = 10000,
                 delta_threshold: float = 0.03):
        self.rho_0     = baseline_coverage
        self.W         = window_size
        self.delta     = delta_threshold
        self.window    = deque(maxlen=window_size)
        self.recompute_count = 0

    def ingest(self, doc_tokens: list[str],
               suppressed_positions: set[int]) -> bool:
        """
        Record coverage for one new document.
        Returns True if re-computation should be triggered.
        """
        n = len(doc_tokens)
        if n == 0: return False
        coverage = len(suppressed_positions) / n
        self.window.append(coverage)
        if len(self.window) < self.W // 10:
            return False   # warm-up period
        rho_w = sum(self.window) / len(self.window)
        if abs(rho_w - self.rho_0) > self.delta:
            self.recompute_count += 1
            return True    # trigger re-computation
        return False

    def coverage_report(self) -> dict:
        if not self.window: return {}
        rho_w = sum(self.window) / len(self.window)
        return {
            'baseline_coverage': self.rho_0,
            'current_coverage':  rho_w,
            'drift':             rho_w - self.rho_0,
            'window_docs':       len(self.window),
            'recomputes_triggered': self.recompute_count,
        }


def near_duplicate_mfp_extension(
    mfp_tokens: tuple,
    edit_distance_threshold: int = 1,
    vocabulary: set = None,
) -> list[tuple]:
    """
    Generate near-duplicate variants of an MFP for fuzzy matching.

    Exact MFP matching misses year-varying copyright notices:
      "copyright 2024 all rights reserved"  (in MFP list)
      "copyright 2025 all rights reserved"  (new document — NOT matched)

    Near-duplicate variants via single-token substitution:
    Replace numeric tokens with a wildcard pattern, or enumerate
    likely substitutions from a vocabulary of similar tokens.

    Returns list of token tuples that should also be suppressed.
    This extends MFP coverage without re-running the full pipeline.
    """
    variants = []
    for i, tok in enumerate(mfp_tokens):
        if tok.isdigit() and len(tok) == 4:  # year token
            year = int(tok)
            for delta in range(-2, 5):      # ±2 years for robustness
                variant = list(mfp_tokens)
                variant[i] = str(year + delta)
                variants.append(tuple(variant))
    return variants
🔑

Re-computation strategy

Full re-computation (re-run all phases: CMS, seed generation, expansion, ranking) is expensive — typically 2–8 CPU-hours for 1M+ document corpora. Trigger it only on confirmed drift (|ρ_window - ρ₀| > δ sustained over W/2 documents). Between triggers, use the near-duplicate extension (year variants, synonym variants) to patch the suppression list incrementally. Monitor MAP in parallel — if MAP degrades even without coverage drift, the cause is external and re-computation won't help.

Extension: non-contiguous boilerplate via co-occurrence mining

Web navigation menus follow the pattern: [fixed prefix] + [variable content] + [fixed suffix]. MFP's contiguity requirement cannot capture this. Two-stage fix: (1) MFP finds 'Home About' and 'Privacy Policy Terms' as separate high-df fragments. (2) Co-occurrence mining identifies pairs that appear within 100 tokens in 80%+ of documents — these become structural templates. Suppression applies to both anchor fragments but NOT the variable middle, preserving page-specific content while eliminating structural boilerplate.

Question 1 of 8

Direct annotation evaluation of an MFP system on 300 annotated documents yields Precision=0.94, Recall=0.71, F1=0.81. The system is then evaluated via downstream MAP on 500 queries and shows ΔMAP=+0.038 (p<0.001). How do you interpret the gap between F1=0.81 and the strong MAP improvement?

Correct. Direct annotation F1 and downstream MAP measure orthogonal properties. F1 measures coverage and accuracy at the token level relative to human judgement. MAP measures retrieval quality improvement at the query level. The two can diverge because: (1) uncovered boilerplate may already be down-ranked by IDF; (2) suppressed content tokens may not be in queries. Both metrics are needed: F1 ensures the system behaves correctly in principle; MAP ensures it helps in practice.
Question 2 of 8

You use a paired Wilcoxon signed-rank test to evaluate MAP improvement. Why is a paired t-test inappropriate for this comparison?

Correct. The non-normality of per-query AP distributions is the specific statistical reason to prefer Wilcoxon. IR researchers have long known that AP distributions are skewed — the distribution is bounded [0,1], often bimodal (many easy and many hard queries), and sensitive to relevance assessment noise. Wilcoxon's rank-based approach is robust to these characteristics. In practice, both tests often agree on significance; the preference for Wilcoxon is about correctness of assumptions, not outcome.
Question 3 of 8

A streaming MFP monitor detects drift when |ρ_window - ρ₀| > 0.03 (3 percentage points). After a GDPR update, a new cookie consent phrase appears in 90% of new documents, each contributing ~15 tokens of new boilerplate out of ~500 total document tokens. What is the expected coverage drop, and how many documents does the monitor need to process before triggering re-computation?

Correct. The coverage monitor detects drift via the ABSENCE of suppression — new boilerplate appears but is not suppressed by the stale list, so coverage ratio falls. This is the key insight: the monitor doesn't need to know what the new boilerplate IS, only that token positions are increasingly uncovered. The trigger threshold δ=3% is calibrated to detect meaningful drift without false-alarm re-computations triggered by normal corpus variation.
Question 4 of 8

The near-duplicate MFP extension generates year-variant phrases: 'copyright 2024 all rights reserved' generates 'copyright 2023 all rights reserved', 'copyright 2025 all rights reserved', etc. What failure mode does this extension introduce and how do you prevent it?

Correct. Year-variant generation is a double-edged extension: it improves recall for date-varying boilerplate at the cost of potential false positives from over-generalisation. The safeguard is validation against actual corpus frequencies — generated variants that don't appear in the corpus (or appear below threshold) are harmless, but variants that accidentally match content phrases must be filtered. The 'validate before adding' pattern is essential for any MFP extension that generates candidates without running the full expansion pipeline.
Question 5 of 8

You evaluate two MFP configurations on a corpus of legal documents: Config A (aggressive, K=1000, σ=0.005) achieves F1=0.78, ΔMAP=+0.012. Config B (conservative, K=200, σ=0.02) achieves F1=0.89, ΔMAP=+0.019. Config A has higher recall but lower precision and lower MAP. Explain why higher recall (more boilerplate removed) produces lower MAP improvement.

Correct. The precision-MAP coupling is the central calibration insight for production MFP deployment. Low-threshold MFPs (rare phrases) have low IDF and hence low BM25 influence — removing them provides little MAP benefit but risks removing content. High-threshold MFPs (common phrases) have very low IDF and hence negligible BM25 influence — removing them is safe and the MAP gain comes from cleaning up the vocabulary statistics. The optimal σ is always calibrated via downstream MAP, not by maximising token-level recall.
Question 6 of 8

A system that uses MFP for boilerplate removal is deployed in production. Six months later, the IR team notices that MAP has dropped below the original baseline (before MFP was introduced). What four diagnostic steps would you run in order to identify the cause?

Correct. The ordered 4-step diagnosis prevents premature re-computation. Re-running MFP is expensive (hours of computation); understanding WHY MAP degraded first ensures the re-computation actually fixes the issue. Coverage drift analysis and suppression list audits are fast (minutes); A/B comparison is definitive but takes days of traffic. Running them in order minimises diagnostic cost while maximising information gain before committing to the expensive fix.
Question 7 of 8

MFP is designed for contiguous n-gram boilerplate. A web corpus contains structural boilerplate that is NOT contiguous: 'Home | About | Contact | [variable content] | Privacy Policy'. The variable middle section prevents MFP from finding the full navigation pattern. How would you extend MFP to handle this?

Correct. The two-stage (MFP fragments + co-occurrence structural templates) approach is the principled extension for non-contiguous boilerplate. Pure MFP cannot handle variable-gap patterns because its contiguity requirement is fundamental to the greedy expansion algorithm. The co-occurrence mining step after MFP recovery is a lightweight addition that identifies structural relationships between fixed anchor phrases without modifying the core algorithm. This is also how production systems handle navigational boilerplate where the specific anchor texts vary by site section.
Question 8 of 8

A corpus of 500,000 product review documents is processed by MFP. After suppression, retrieval MAP improves by +0.031 for navigational queries but DROPS by −0.018 for product-specific queries. What does this tell you about the MFP list and how do you fix the retrieval degradation?

Correct. Query-type-specific evaluation is essential for diagnosing MFP degradation. Averaging MAP across all 500 queries hides the fact that MFP simultaneously helps and hurts different query intents. Production MFP deployments should always stratify MAP evaluation by query type (navigational, informational, product-specific, etc.) to detect this pattern. The conditional suppression approach — suppressing at the vocabulary level but not deleting from documents — is the most surgical fix, allowing the system to benefit from cleaner IDF statistics while retaining content for relevance scoring.
