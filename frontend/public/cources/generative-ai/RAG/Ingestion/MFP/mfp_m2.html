Greedy Expansion and Global Occupancy Bitmask

Greedy Argmax · Inverted Index · Bidirectional Expansion · Bitmask Suppression · MFP vs PrefixSpan

The greedy expander is MFP's algorithmic core — and the reason MFP scales to 1.7 million documents where PrefixSpan cannot. Starting from each ranked seed, the expander selects t* = argmax df(P∪{t}) subject to df ≥ σ at every step, committing to one path without backtracking. The global occupancy bitmask marks covered positions after each MFP is found, suppressing all sub-phrase seeds before any expensive expansion is attempted. Together, greedy expansion and bitmask suppression reduce the search from exponential recursive projections to linear expansion paths.

01 · Greedy Expansion — Linear Path, No Branching

One Winner Per Step —
Linear Time vs Exponential Projection

PrefixSpan creates a projected database for every frequent extension — one projected database per branch, recursively. For a phrase with 5 frequent extensions at each of 10 steps, that is 5¹⁰ ≈ 10 million projected databases. MFP selects one winner (argmax df) at every step and commits: 10 steps, 10 inverted index lookups, zero projections. The greedy choice reliably finds the dominant boilerplate phrase because boilerplate, by definition, appears in as many documents as possible — the greedy maximum tracks exactly this.

greedy_expander.py — linear greedy expansion via inverted index

from collections import defaultdict

class GreedyExpander:
    """
    Greedy MFP expansion using an inverted index.

    Core algorithm (from paper Section 4):
    Given seed S, repeatedly:
      1. Query inverted index for all successors: tokens t that appear
         immediately after S in some document.
      2. For each candidate t, compute exact df(S + t) via the index.
      3. Select t* = argmax df(S + t)  s.t.  df ≥ σ  (greedy choice).
      4. If no such t* exists → stop. S is maximal → it's an MFP.
      5. Otherwise commit to S ← S + t* and repeat.

    This is the greedy LEFT extension (can also extend right → left).
    The paper expands bi-directionally: first right, then left from seed.

    Why greedy (not exhaustive)?
    PrefixSpan recursively projects the database for each branch.
    MFP greedy: one winner per step, no branching, no projections.
    Linear time per expansion: O(|expansion_path| × |index_lookup|).
    """
    def __init__(self,
                 index: dict[tuple, list[tuple[int,int]]],
                 sigma: int):
        self.index = index   # phrase → [(doc_id, pos), ...]
        self.sigma = sigma

    def exact_df(self, phrase: tuple) -> int:
        """Exact document frequency via inverted index."""
        postings = self.index.get(phrase, [])
        return len(set(doc_id for doc_id, _ in postings))

    def successors(self, phrase: tuple) -> list[int]:
        """
        Find all tokens that immediately follow `phrase` in the corpus.
        Uses the inverted index: look up each (doc_id, pos) for phrase,
        then check position pos + len(phrase) in that document.
        """
        succs: dict[int, set] = defaultdict(set)
        for doc_id, pos in self.index.get(phrase, []):
            next_pos = pos + len(phrase)
            # In practice: look up next_pos in the document token array
            # (stored separately). Here we simulate with index lookup.
            for token in self._tokens_at(doc_id, next_pos):
                succs[token].add(doc_id)
        return [(t, len(docs)) for t, docs in succs.items()
                if len(docs) >= self.sigma]

    def expand(self, seed: tuple) -> tuple:
        """
        Greedily expand seed to its MFP.
        Returns the maximal phrase — the longest extension with df ≥ σ.

        Each step: try all successors, pick the one with highest df.
        Commit immediately — no backtracking, no branching.
        Stop when no successor meets σ → seed is maximal.
        """
        phrase = seed
        while True:
            candidates = self.successors(phrase)
            if not candidates:
                break
            # Greedy: select t* with maximum df(phrase + t*)
            best_token, best_df = max(candidates, key=lambda x: x[1])
            phrase = phrase + (best_token,)
        return phrase   # MFP: cannot be extended while df ≥ σ

    def _tokens_at(self, doc_id: int, pos: int) -> list[int]:
        """Retrieve token at position `pos` in document `doc_id`."""
        raise NotImplementedError("Inject document store")
02 · Global Occupancy Bitmask — Suppression in O(1)

Once Covered, Always Suppressed —
The Maximality Enforcement Mechanism

Every token position in the corpus has one bit in the global bitmask. When the expander finds an MFP covering positions [start, end), it marks those bits. Any subsequent seed whose token positions are entirely occupied is suppressed without expansion — the bitmask check replaces an expensive expansion with a single integer bit operation. This is the implementation of the maximality property: a sub-phrase of a known MFP cannot itself be an MFP.

Bitmask state before and after MFP "All rights reserved copyright 2024" — positions 0–4 marked, sub-phrase suppressed

global_bitmask.py — occupancy tracking with numpy bitarray

import numpy as np

class GlobalBitmask:
    """
    Global occupancy bitmask over all token positions in the corpus.

    One bit per token position: 0 = free, 1 = covered by a found MFP.

    Why a bitmask?
    After the greedy expander finds MFP P at positions [start, end) in
    document d, all positions in [start, end) are marked as occupied.
    Any subsequent seed whose tokens fall entirely within occupied positions
    is suppressed without expansion — the bitmask check is O(phrase_length)
    bit operations, far cheaper than a full expansion attempt.

    This implements the 'path compression' / sub-phrase suppression property:
    once the MFP containing a position is found, that position can never
    be part of a DIFFERENT MFP (by the maximality definition).

    Memory: total_corpus_tokens / 8 bytes.
    For 1.7M docs × 500 tokens = 850M tokens → 850M / 8 = ~106MB.
    """
    def __init__(self, total_positions: int):
        # Flat bit array across entire corpus
        # Position encoding: doc_offset[d] + position_in_doc
        n_bytes = (total_positions + 7) // 8
        self.bits = np.zeros(n_bytes, dtype=np.uint8)
        self.total = total_positions

    def _idx(self, pos: int) -> tuple[int, int]:
        """Return (byte_index, bit_index) for flat position pos."""
        return pos >> 3, 1 << (pos & 7)

    def mark(self, start: int, end: int):
        """Mark positions [start, end) as occupied by an MFP."""
        for pos in range(start, end):
            byte_i, bit_mask = self._idx(pos)
            self.bits[byte_i] |= bit_mask

    def is_free(self, start: int, end: int) -> bool:
        """
        True if ALL positions [start, end) are currently unoccupied.
        A seed is only processed if its positions are all free.

        Optimisation: check the first and last position first (O(1))
        before scanning the full range — seeds are often fully covered
        by a single previous MFP, so the quick check short-circuits.
        """
        byte_s, bit_s = self._idx(start)
        byte_e, bit_e = self._idx(end - 1)
        if self.bits[byte_s] & bit_s: return False
        if self.bits[byte_e] & bit_e: return False
        for pos in range(start + 1, end - 1):
            byte_i, bit_mask = self._idx(pos)
            if self.bits[byte_i] & bit_mask: return False
        return True

    def coverage_fraction(self) -> float:
        """What fraction of corpus positions are covered by MFPs?"""
        ones = int(np.unpackbits(self.bits).sum())
        return ones / self.total
03 · Full Expansion-Suppression Loop

Seeds → Expand → Mark → Suppress —
Until Queue Is Empty

🔑

The complete expansion algorithm (paper Algorithm 1)

For each seed S in ranked order: (1) check bitmask — if any seed position is occupied, skip. (2) expand greedily rightward until no extension has df ≥ σ. (3) expand leftward from the current phrase until no left extension has df ≥ σ. (4) the resulting phrase is the MFP. (5) find all corpus positions of this MFP via the inverted index. (6) mark all those positions in the bitmask. (7) add MFP to output. Repeat until all seeds processed.

Scenario: Web corpus of 10,000 e-commerce product pages (India)

Top seed S1 = "free delivery on orders above rs" df=8,400. Right expand: "free delivery on orders above rs 499" df=8,400 → "free delivery on orders above rs 499 ." df=8,390 → extend again: "free delivery on orders above rs 499 . terms apply" df=7,200 → no further extension ≥ σ=100. Left expand: "get free delivery on orders above rs 499 . terms apply" df=7,200 → "enjoy get free …" df=180, commit → no further. Final MFP: "get free delivery on orders above rs 499. terms apply" — a perfect promotional boilerplate phrase covering 7,200 of 10,000 product pages.

Question 1 of 8

The greedy expander selects t* = argmax df(P∪{t}) subject to df ≥ σ at each step. At step 3, the current phrase P = "all rights reserved" has df=12,400. Candidate extensions: "copyright" (df=12,400), "company" (df=2,800), "2024" (df=11,900). Which token is selected, and what is the MFP output?

Correct. The greedy rule is simply: argmax df over all frequent extensions. "copyright" (df=12,400) is selected because it has the highest df among extensions that meet σ=100. The greedy choice is deterministic and commits immediately — no backtracking. This is the key speed advantage over PrefixSpan: PrefixSpan would spawn separate projected databases for all three candidates; MFP picks one winner and continues linearly.
Question 2 of 8

A seed "rights reserved" at position 5 in document D1 (positions 5–6) is queued for expansion. Before starting expansion, the greedy expander checks the global bitmask and finds positions 5 and 6 are both set to 1. What does this mean, and what does the algorithm do?

Correct. Bitmask suppression is the mechanism that enforces the maximality property without redundant computation. Once any position is covered by an MFP, any phrase whose tokens are entirely within that covered region is guaranteed to be a sub-phrase (not maximal). The O(phrase_length) bitmask check avoids the O(expansion_depth × inverted_index_lookup) cost of a full expansion. For a well-behaved corpus, most lower-ranked seeds are suppressed by the top few MFPs, making the total expansion work nearly linear in the number of actual MFPs found.
Question 3 of 8

PrefixSpan and BIDE+ both enumerate patterns by recursive projection — they project the database onto the suffixes of each prefix and recurse. MFP uses greedy expansion instead. What is the fundamental complexity difference, and what does MFP sacrifice by being greedy?

Correct. The greedy approach trades completeness for linear time. PrefixSpan guarantees finding all frequent sequential patterns (complete enumeration), but requires exponential projected databases. MFP's greedy selection commits to one path per seed and never backtracks. For the specific task of boilerplate detection, this tradeoff is excellent: the greedy maximum-df choice reliably finds the dominant long boilerplate phrase from each seed, and the bitmask prevents redundant enumeration of sub-phrases. The paper demonstrates that for real corpora, the greedy output is empirically complete — all significant boilerplate is found.
Question 4 of 8

The global bitmask requires one bit per token position across the entire corpus. For a corpus of 1.7M documents with average length 500 tokens, what is the total bitmask memory, and why is this preferable to storing the complete list of MFP positions as a hash set?

Correct. The bitmask's 106MB requirement and O(1) bit-test lookup make it the optimal data structure for this problem. One byte per token would be 850MB — but one BIT per token is 850M/8 = 106MB. The key computation: byte_index = position >> 3 (divide by 8), bit_mask = 1 << (position & 7) (remainder). This is a single integer division and bit operation — the fastest possible lookup. For the millions of suppression checks performed during expansion, this sub-nanosecond operation is crucial.
Question 5 of 8

The greedy expander queries "successors" of phrase P by looking up positions in the inverted index. Specifically, for each (doc_id, pos) entry for P, it checks position pos + len(P) in that document. What is the time complexity of a single successor query, and how does this compare to PrefixSpan's projected database construction?

Correct. The inverted index successor query processes exactly |postings| entries for the current phrase — only the documents where P appears. PrefixSpan must construct and scan a projected database which, at the root level, contains all documents. The inverted index is more selective: for a phrase P with df=12,400 in a 1.7M-document corpus, the index lookup touches only 0.73% of documents (12,400/1,700,000). Each expansion step further reduces |postings| as the phrase becomes more specific. This is why MFP's expansion is fast: the most expensive step (seed expansion with highest df) processes at most O(df_seed) entries, and subsequent steps process fewer.
Question 6 of 8

After the greedy expander identifies MFP P1 = "all rights reserved copyright 2024" in document D1, a subsequent seed S2 = "reserved copyright" at different positions in document D2 is checked. The bitmask shows D2's positions for S2 are all free (bits = 0). Should S2 be expanded?

Correct. The bitmask tracks positions per-document. Marking P1's positions in D1 does not affect the free status of any positions in D2. S2 in D2 may legitimately be part of a boilerplate phrase in D2, even if it is a sub-phrase of an MFP found in D1. The global bitmask correctly handles this: it suppresses seeds whose positions are already covered IN THAT DOCUMENT, not globally across all documents. This is essential for correctness — the same phrase can appear at different positions across documents.
Question 7 of 8

MFP expands seeds both rightward (appending tokens to the end) and leftward (prepending tokens to the start). Starting from seed "rights reserved" (df=12,400), right expansion gives "rights reserved copyright 2024". Then left expansion is applied to the result. The candidates for left extension are: "all" (df=12,400), "our" (df=800), nothing with df<σ. What is the final MFP?

Correct. Left extension selects t* = "all" (df=12,400) — the maximum df candidate meeting σ. "Our" (df=800 ≥ σ=100) would also qualify but loses the greedy maximum competition. The bidirectional expansion ensures maximality in both directions: the MFP cannot be extended to the left OR right while remaining frequent. Without left expansion, a right-expanded phrase might be a strict sub-phrase of a longer MFP that starts earlier in the document.
Question 8 of 8

You are implementing MFP for a multilingual corpus containing English, French, and Spanish documents. The tokenizer maps "rights" and "droits" (French for "rights") to different token IDs. Does MFP correctly identify "tous droits réservés" (French equivalent of "all rights reserved") as a separate MFP from "all rights reserved"?

Correct. MFP is language-agnostic at the token level. Token IDs are arbitrary integers — the algorithm has no knowledge of language, semantics, or meaning. Any token sequence that appears with high document frequency across the corpus will be detected as a potential MFP, regardless of the language. The multilingual corpus will produce separate MFPs for each language's boilerplate. The only caveat: if the corpus is very multilingual, σ should be set relative to the per-language subcorpus size, not the full corpus — otherwise minority-language boilerplate may not reach the threshold.
