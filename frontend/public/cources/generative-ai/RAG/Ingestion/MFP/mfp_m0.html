The Problem and the Algorithm

Boilerplate Detection · Sequential Pattern Mining · df Support · Closed · Maximal · MFP Definition

Modern document corpora are riddled with boilerplate — navigation menus, cookie banners, copyright disclaimers, and site-wide footers that appear on hundreds of thousands of pages. These repeated fragments inflate term frequencies, corrupt TF-IDF rankings, and pollute RAG retrieval pipelines. The MFP (Maximal Frequent Phrase) algorithm is a sequential pattern mining system that identifies and removes these fragments at scale, without DOM parsing or layout analysis — using only the text itself. This module establishes the problem, the mathematical foundations, and the key definition that makes MFP practical.

02 · Sequential Pattern Mining Foundations

FIM vs SPM — Why Contiguity
Is the Key Constraint

Frequent Itemset Mining (FIM) finds items that co-occur frequently across transactions — order and adjacency are irrelevant. Sequential Pattern Mining (SPM) adds order and contiguity: the tokens must appear consecutively, forming a phrase. For boilerplate detection, contiguity is mandatory — "All rights reserved" is meaningful only when these three tokens appear consecutively, not when they appear anywhere in a document.

corpus_support.py — document frequency and phrase support over a corpus

from collections import defaultdict
from typing import Iterator

def tokenize(text: str) -> list[int]:
    """
    Map raw text to a sequence of integer token IDs.
    In the MFP paper this is done via a vocabulary Σ mapping
    every unique word/subword to a stable integer ID.

    Simple whitespace tokenizer shown here; in production use
    a BPE or WordPiece tokenizer for multilingual corpora.
    """
    vocab: dict[str, int] = {}
    tokens = []
    for word in text.lower().split():
        if word not in vocab:
            vocab[word] = len(vocab)
        tokens.append(vocab[word])
    return tokens   # caller should share a global vocab dict


def ngrams(tokens: list[int], n: int) -> Iterator[tuple]:
    """Yield all contiguous n-grams from a token sequence."""
    for i in range(len(tokens) - n + 1):
        yield tuple(tokens[i:i+n])


def document_frequency(
    corpus: list[list[int]],   # list of tokenised documents
    phrase: tuple[int, ...],   # phrase P as token-ID tuple
) -> int:
    """
    df(P) = |{d ∈ corpus : P appears in d}|

    Document frequency: count how many documents contain
    phrase P at least once. Contiguity is required — there
    must be no gaps between tokens in P within any document.

    This is the core support measure in MFP (not raw occurrence
    count, which inflates boilerplate score for long docs).
    """
    n = len(phrase)
    count = 0
    for doc in corpus:
        # Sliding window: does phrase appear anywhere in doc?
        for i in range(len(doc) - n + 1):
            if tuple(doc[i:i+n]) == phrase:
                count += 1
                break   # count doc once regardless of occurrences
    return count


def build_inverted_index(
    corpus: list[list[int]],
    n: int,                    # seed length (typically 4–5)
) -> dict[tuple, list[tuple[int, int]]]:
    """
    Build an inverted index: phrase → [(doc_id, position), ...]

    This is the key data structure for greedy expansion (Module 2).
    Instead of scanning the full corpus for each candidate extension,
    the inverted index lets us look up all positions of a phrase in O(1).

    Memory: O(|corpus| × avg_doc_length) — may require external sort-merge
    for corpora > RAM capacity (the paper uses sort-merge for this).
    """
    index: dict[tuple, list[tuple[int, int]]] = defaultdict(list)
    for doc_id, doc in enumerate(corpus):
        for pos, gram in enumerate(ngrams(doc, n)):
            index[gram].append((doc_id, pos))
    return dict(index)
03 · Closed, Maximal, and MFP — The Pattern Taxonomy

Three Levels of Pattern Compactness —
Only MFP Is Directly Usable

The space of all frequent patterns is exponential. Three subsets provide compact representations: closed patterns (no super-pattern with the same df), maximal patterns (no frequent super-pattern), and MFPs (maximal + contiguous + df-based). MFPs are the most compact and most directly usable for boilerplate detection.

pattern_types.py — closed, maximal, and MFP pattern definitions

from dataclasses import dataclass, field

@dataclass
class Pattern:
    tokens: tuple[int, ...]
    df:     int               # document frequency

    def is_sub_phrase(self, other: "Pattern") -> bool:
        """True if self.tokens appears as a contiguous sub-sequence of other.tokens."""
        n, m = len(self.tokens), len(other.tokens)
        if n >= m: return False
        return any(other.tokens[i:i+n] == self.tokens for i in range(m - n + 1))


def is_closed(p: Pattern, all_patterns: list[Pattern]) -> bool:
    """
    A pattern P is CLOSED if no super-pattern Q ⊃ P has the same df.
    CloSpan and BIDE+ mine closed patterns.

    Closed patterns preserve ALL information: from the closed set you
    can derive the df of every sub-pattern. But the number of closed
    patterns can still be exponential in the number of MFPs.

    Example:
      P = ("rights", "reserved")           df = 500
      Q = ("all", "rights", "reserved")    df = 500  ← same df
      → P is NOT closed (Q has same df and is a super-pattern of P)
    """
    for q in all_patterns:
        if p.is_sub_phrase(q) and q.df == p.df:
            return False
    return True


def is_maximal(p: Pattern, all_patterns: list[Pattern],
                sigma: int) -> bool:
    """
    A pattern P is MAXIMAL if no super-pattern Q ⊃ P has df ≥ σ.
    MaxSP and VMSP mine maximal patterns.

    Maximal patterns are the longest frequent patterns — no extension
    of them is still frequent. They are more compact than closed patterns
    but lose sub-pattern df information.

    Example (σ=100):
      P = ("all", "rights", "reserved")          df = 500 ≥ σ ✓
      Q = ("all", "rights", "reserved", "2024")  df = 80 < σ  ✗
      → P IS maximal (no frequent super-pattern exists)
    """
    for q in all_patterns:
        if p.is_sub_phrase(q) and q.df >= sigma:
            return False
    return True


def is_mfp(p: Pattern, all_patterns: list[Pattern],
            sigma: int) -> bool:
    """
    MFP (Maximal Frequent Phrase) — the paper's key definition:
    P is an MFP if:
      1. df(P) ≥ σ  (P is frequent)
      2. No extension P' = P + {t} or {t} + P has df(P') ≥ σ
         (P cannot be grown while remaining frequent)

    MFP is equivalent to maximal frequent sequential pattern with
    contiguity constraint (no gaps allowed in text phrases).
    The contiguity constraint is what makes MFPs useful for boilerplate
    detection: "rights reserved" and "reserved copyright" are different
    MFPs even if they overlap in the same document.

    Key difference from generic maximal patterns:
    MFP uses document frequency (df), not occurrence count,
    and requires strict contiguity — no skipped tokens.
    """
    if p.df < sigma:
        return False   # not frequent
    return is_maximal(p, all_patterns, sigma)

Question 1 of 8

A web corpus of 500K documents contains navigation menus like "Home | About | Contact | Privacy Policy" that appear on every page. A TF-IDF retrieval system built on this corpus performs poorly on the query "contact information." What is the fundamental cause, and what does MFP solve?

Correct. The boilerplate problem is fundamentally a df inflation problem. Tokens that appear in every document get IDF=0 and become invisible to TF-IDF. MFP's role is to identify the specific phrases (not individual tokens) that constitute boilerplate, so that only those phrase positions are stripped. This is more precise than removing individual high-frequency tokens (which would also remove genuinely common but meaningful terms like 'the').
Question 2 of 8

The MFP paper uses document frequency df(P) rather than raw occurrence count (term frequency) as the support measure. A legal corpus has 1,000 documents. Document D1 contains 'All rights reserved' 47 times (it's a 300-page contract). Document D2 contains it once. What is df('All rights reserved') and why is df the correct support measure for boilerplate detection?

Correct. df(P) = |{d ∈ corpus : P ∈ d}| is a binary membership count over documents. Each document contributes at most 1 to df regardless of how many times P appears within it. This is the correct measure for boilerplate detection because boilerplate is defined by cross-document recurrence (it appears in many different documents), not by within-document repetition. A long legal contract that repeats 'All rights reserved' on every page is still just one document.
Question 3 of 8

Sequential Pattern Mining (SPM) differs from Frequent Itemset Mining (FIM) in a critical way relevant to text. Why does the contiguity constraint in SPM make it more appropriate for boilerplate phrase detection than FIM?

Correct. Contiguity is the defining property of a text phrase. 'All rights reserved' means something specific because these tokens are adjacent. FIM would combine any frequently co-occurring tokens into itemsets, regardless of whether they form a recognisable phrase. The SPM contiguity constraint directly models the definition of a phrase, making it the correct framework for boilerplate phrase detection.
Question 4 of 8

Given σ=100, a corpus of 10,000 documents, and the following patterns with their document frequencies: P1='copyright' (df=8200), P2='copyright 2024' (df=8200), P3='© copyright 2024' (df=8200), P4='© copyright 2024 acme corp' (df=95). Which patterns are closed, which are maximal, and which are MFPs?

Correct. The chain: P1 ⊂ P2 ⊂ P3 all share df=8200, so only P3 (the longest in the chain) is closed. P3 is also maximal because its only super-pattern P4 is not frequent. Therefore P3 is the unique MFP in this set. The key insight: MFPs are always maximal (longest frequent contiguous phrase), and the greedy expansion algorithm finds exactly these — it grows the phrase as long as adding any token keeps df ≥ σ, and stops exactly when no extension is frequent.
Question 5 of 8

Why does the MFP algorithm use n-grams of a fixed length (typically n=4 or 5) as seeds rather than starting expansion from individual tokens (n=1)?

Correct. Seed length n=4–5 is a discriminating pre-filter. A 5-gram with df≥σ is almost certainly part of boilerplate — random 5-gram co-occurrences across hundreds of documents are statistically implausible. 1-grams with high df include every common English function word, producing enormous false-positive candidate sets. The seed generation step efficiently identifies the most promising starting points for greedy expansion, reducing the expansion problem to a tractable size.
Question 6 of 8

The MFP paper describes 'path compression' (suppress overlapping sub-phrases). After the greedy expander identifies the MFP 'All rights reserved Copyright 2024', why must the algorithm suppress the sub-phrases 'All rights reserved' and 'rights reserved Copyright 2024' from subsequent processing?

Correct. The global occupancy bitmask is what makes MFP expansion non-redundant. Once a position is marked as belonging to an identified MFP, it cannot be re-used as a seed or expansion target. This implements the maximality constraint efficiently: instead of checking all possible super-patterns (as BIDE+ does with projected databases), MFP simply checks whether any position in a candidate pattern is already bitmask-occupied. If yes, the candidate is suppressed. This reduces redundancy checks from O(pattern_count²) to O(pattern_length) per candidate.
Question 7 of 8

A researcher proposes using MFP on social media posts to detect viral phrases (phrases shared by many users). The corpus has 50M short posts (avg 15 tokens each). They set σ=10,000 (must appear in 10K+ posts). What is the primary algorithmic challenge, and which MFP component addresses it?

Correct. Scale is the core challenge that motivates the probabilistic filtering stage. At 50M posts, exact n-gram counting via hash tables exceeds memory. The Count-Min Sketch provides a memory-bounded approximate count: for a fixed memory budget M, it estimates df for any n-gram with controllable error probability. High-frequency patterns (σ≥10,000) are estimated reliably because their true count is far above the estimation error floor. The tradeoff: occasional false positives (rare n-grams over-estimated as frequent) enter the expansion stage, where exact df verification via the inverted index immediately rejects them.
Question 8 of 8

The MFP output for a corpus of 1.7M web documents includes the phrase 'This website uses cookies to improve your experience. We\'ll assume you\'re ok with this.' with df=1,420,000 (83% of all documents). A downstream RAG system strips all MFPs before indexing. What might go wrong if σ is set too low (σ=10), and what might go wrong if σ is too high (σ=500,000)?

Correct. σ is the most consequential hyperparameter in MFP. Setting it wrong produces either over-cleaning (σ too low, removes legitimate content) or under-cleaning (σ too high, leaves boilerplate). The practical calibration approach: examine the distribution of candidate phrase df values across the corpus. A natural 'elbow' separates true boilerplate (very high df, hundreds of thousands of documents) from domain-specific repeated content (moderate df, tens to hundreds of documents). Setting σ just above this elbow captures true boilerplate while preserving domain-specific repeated content.
