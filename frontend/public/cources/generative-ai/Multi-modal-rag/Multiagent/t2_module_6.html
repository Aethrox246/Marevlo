01 · LangChain Q&A Object Model

The Two-Stage Architecture:
Indexing and Retrieval

LangChain's Q&A system is divided into two clean stages with well-defined interfaces. The indexing stage transforms raw documents into a searchable vector store — run once, updated incrementally. The retrieval stage answers questions against the indexed store — run on every user query. Understanding this division is essential for designing ingestion pipelines that do not need to be rebuilt from scratch every time you add a document.

The Q&A object model: complete class hierarchy

Indexing Stage

DocumentLoader

Converts any source (PDF, URL, CSV, folder) to List[Document]. Every loader outputs the same interface.

TextSplitter

Splits Document objects into smaller chunks. RecursiveCharacterTextSplitter is the default.

EmbeddingModel

Converts text to float vectors. Pluggable: OpenAI, HuggingFace, Cohere. Must match at query time.

VectorStore

Stores (embedding, text, metadata) tuples. Provides .add_documents() and .as_retriever().

Retrieval Stage

Retriever

Wraps a VectorStore. Exposes .invoke(query) → List[Document]. Handles similarity search config.

PromptTemplate

Defines the RAG prompt with {context} and {question} slots.

LLM / ChatModel

Receives the formatted prompt with retrieved context and generates the answer.

OutputParser

Extracts the answer string from the LLM response. StrOutputParser for text.

💡

Why separate indexing and retrieval?

The separation lets you update each stage independently. Adding 10 new PDFs? Run the ingestion pipeline without touching the retrieval code. Switching from Chroma to Qdrant? Change one line in the ingestion stage; the retrieval chain is unchanged. Upgrading the embedding model? Re-run ingestion with the new model; the prompt and LLM are unaffected. This decoupling is what makes RAG systems maintainable at production scale.

02 · Vector Store Content Ingestion

A Production Ingestion Pipeline
With Deduplication and Incremental Updates

The simplest ingestion pipeline runs Chroma.from_documents() once and rebuilds from scratch every time you add documents. Production ingestion pipelines add document IDs for deduplication (avoid re-indexing unchanged documents), handle errors gracefully (one bad PDF should not stop ingestion of 99 others), and support incremental updates (add_documents for new content, delete for removed content).

Problem: rebuilding the index from scratch

✗ Every re-run re-embeds ALL documents — even unchanged ones
✗ Re-embedding 10,000 docs × $0.02/M tokens = $0.20 per rebuild
✗ Duplicate chunks appear if script runs twice on same files
✗ Index is unavailable during rebuild — downtime

Solution: ID-based deduplication

✓ Assign deterministic IDs: hash(source_path + chunk_index)
✓ Before add, check if ID already exists in the store
✓ Skip existing IDs → only NEW or CHANGED chunks are embedded
✓ Index stays live during incremental add_documents() calls

Production ingestion code with deduplication

import hashlib from langchain_community.vectorstores import Qdrant def make_doc_id(source: str, chunk_idx: int) -> str: # Deterministic ID: same file + chunk = same ID always raw = f"{source}::{chunk_idx}" return hashlib.md5(raw.encode()).hexdigest() def ingest_documents(docs, store: Qdrant): chunks = splitter.split_documents(docs) # Assign deterministic IDs ids, new_chunks = [], [] for i, chunk in enumerate(chunks): doc_id = make_doc_id(chunk.metadata["source"], i) ids.append(doc_id) new_chunks.append(chunk) # Check which IDs already exist existing = store.get(ids=ids) # Qdrant: returns existing docs existing_ids = {d.id for d in existing} to_add = [(c, id_) for c, id_ in zip(new_chunks, ids) if id_ not in existing_ids] if to_add: chunks_to_add, ids_to_add = zip(*to_add) store.add_documents(list(chunks_to_add), ids=list(ids_to_add)) print(f"Added {len(to_add)} new chunks ({len(chunks)-len(to_add)} skipped as duplicates)") else: print("No new chunks to add")

Ingesting multiple documents from a folder with error handling

from pathlib import Path from langchain_community.document_loaders import PyPDFLoader def ingest_folder(folder: str, store) -> dict: results = {"success": 0, "failed": 0, "errors": []} for pdf_path in Path(folder).glob("**/*.pdf"): try: docs = PyPDFLoader(str(pdf_path)).load() ingest_documents(docs, store) results["success"] += 1 except Exception as e: results["failed"] += 1 results["errors"].append(f"{pdf_path.name}: {e}") print(f"⚠ Skipped {pdf_path.name}: {e}") # log, don't crash return results
03 · Q&A Across Stored Documents

Querying the Vector Store:
Direct Search vs the RAG Chain

There are two ways to get information from a vector store: direct similarity search (retrieve chunks, inspect them yourself) and the full RAG chain (retrieve chunks, pass to LLM, get generated answer). Direct search is useful for debugging — you can see exactly which chunks the retriever found and whether they contain the answer. The RAG chain is what users interact with.

Direct similarity search (for debugging)

# Method 1: similarity_search — returns List[Document] docs = vector_store.similarity_search( query="refund policy annual plan", k=5 # return 5 most similar chunks ) for doc in docs: print(f"Source: {doc.metadata['source']} p.{doc.metadata.get('page','?'}")}) print(doc.page_content[:200]) # Method 2: with relevance scores (cosine similarity) results = vector_store.similarity_search_with_score( query="refund policy annual plan", k=5 ) for doc, score in results: print(f"Score: {score:.3f} | {doc.page_content[:100]}")

Full RAG chain with score threshold filtering

# score_threshold: only include chunks above this similarity retriever = vector_store.as_retriever( search_type="similarity_score_threshold", search_kwargs={ "k": 5, "score_threshold": 0.75 # discard low-confidence chunks } ) # MMR: Maximum Marginal Relevance — diversity retrieval retriever_mmr = vector_store.as_retriever( search_type="mmr", search_kwargs={ "k": 5, "fetch_k": 20, # fetch 20, pick 5 most diverse "lambda_mult": 0.5 # 0=max diversity, 1=max relevance } ) # MMR avoids 5 nearly identical chunks from the same section

Three retriever search types and when to use each

search_typeHow it worksWhen to useRisk
"similarity"Returns the K chunks with highest cosine similarity to the query. Pure relevance ranking.Default for most use cases. When you want the most relevant chunks regardless of diversity.May return 5 nearly identical chunks from the same paragraph if corpus is repetitive.
"similarity_score_threshold"Returns chunks above a minimum cosine similarity score. K is the maximum, not a fixed count.When you want to refuse answers for out-of-domain queries (score < threshold → empty context → LLM says "I don't know").May return 0 chunks if all are below threshold — need to handle empty retrieval gracefully.
"mmr"Fetches fetch_k candidates, then picks K that balance relevance and diversity using Maximal Marginal Relevance.When corpus is repetitive and you want each chunk to contribute new information.Slightly slower (fetches more candidates). May include a less-relevant chunk to improve diversity.
04 · Chatbot Memory

Multi-Turn Conversations:
Message History and Context Window Management

A stateless RAG chain answers each question independently. A chatbot remembers the conversation history, allowing follow-up questions ("What about the pricing?"), reference resolution ("How much does that cost?"), and contextual refinement ("Make your last answer shorter"). Implementing memory requires passing message history into the prompt and managing how much history to include.

Why stateless RAG fails for multi-turn conversations

User [1]: What is the refund policy for annual plans?
Bot [1]: Annual plans are non-refundable after 30 days...
User [2]: What about monthly plans? ← references context from turn 1
Bot [2] (stateless): I don't have information about "what about monthly plans?" ← FAIL: no history
Bot [2] (with memory): Monthly plans can be cancelled anytime with a prorated refund... ← CORRECT

The three-component memory setup

1. Chat history store

Holds the conversation as a list of HumanMessage and AIMessage objects. ChatMessageHistory (in-memory) for simple use; RedisChatMessageHistory for multi-session production.

2. History-aware retriever

Rewrites the current question using history context before retrieving. "What about monthly plans?" + history → "What is the refund policy for monthly plans?" → retriever gets a complete, standalone query.

3. RAG chain with history

The final chain combines: history-aware retrieval + formatted context + full message history → LLM generates a response that can reference both retrieved docs and prior conversation.

Context window management: trimming old history

A long conversation accumulates thousands of tokens in history. Including all of it in every prompt eventually hits the context window limit and inflates costs. Production chatbots trim history to the last N turns or N tokens.

from langchain_core.messages import trim_messages # Keep last 10 messages (5 turns) trimmer = trim_messages( max_tokens=2000, # or trim by token count strategy="last", # keep most recent messages token_counter=llm, # use LLM tokenizer for counting include_system=True, # always keep system message allow_partial=False # don't cut mid-message ) # Apply before passing history to chain trimmed = trimmer.invoke(chat_history.messages)
⚠️

The history-aware retriever: the critical component

Without a history-aware retriever, the follow-up question "What about that pricing?" goes directly to the vector store, which returns pricing documents unrelated to the conversation topic. The history-aware retriever first calls an LLM to rewrite the follow-up question into a standalone, complete question incorporating history context, then retrieves with the full question. This "contextual compression" step is what makes multi-turn Q&A coherent.

05 · Memory Chatbot Code

Complete Multi-Turn RAG Chatbot
With History-Aware Retrieval

rag_chatbot_memory.py

from langchain_anthropic import ChatAnthropic
from langchain_openai import OpenAIEmbeddings
from langchain_community.vectorstores import Chroma
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough, RunnableLambda
from langchain_core.messages import HumanMessage, AIMessage
from langchain.chains import create_history_aware_retriever, create_retrieval_chain
from langchain.chains.combine_documents import create_stuff_documents_chain

llm = ChatAnthropic(model="claude-sonnet-4-20250514", temperature=0)
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vector_store = # ... built via ingest_folder() from previous section
retriever = vector_store.as_retriever(search_kwargs={"k": 4})

# ── Prompt 1: Rewrite standalone question from history ────────
CONTEXTUALIZE_PROMPT = ChatPromptTemplate.from_messages([
    ("system",
     "Given the chat history, reformulate the latest question into a standalone,\n"
     "self-contained question. Do NOT answer it. If it is already standalone, return it unchanged."),
    MessagesPlaceholder("chat_history"),
    ("human", "{input}")
])

# ── Prompt 2: Answer with context + history ──────────────────
QA_PROMPT = ChatPromptTemplate.from_messages([
    ("system",
     "Answer the question using ONLY the context below.\n"
     "If not in context: 'I don't have that information.'"),
    ("system", "Context:\n{context}"),
    MessagesPlaceholder("chat_history"),
    ("human", "{input}")
])

# ── Build history-aware retriever ─────────────────────────────
history_aware_retriever = create_history_aware_retriever(
    llm, retriever, CONTEXTUALIZE_PROMPT
)

# ── Build the full conversational chain ──────────────────────
question_answer_chain = create_stuff_documents_chain(llm, QA_PROMPT)
rag_chain = create_retrieval_chain(history_aware_retriever, question_answer_chain)

# ── Stateful chat loop ────────────────────────────────────────
chat_history = []

def chat(question: str) -> str:
    result = rag_chain.invoke({
        "input": question,
        "chat_history": chat_history[-10:]  # last 5 turns
    })
    chat_history.extend([
        HumanMessage(content=question),
        AIMessage(content=result["answer"])
    ])
    return result["answer"]

print(chat("What is the refund policy for annual plans?"))
print(chat("What about monthly plans?"))  # uses history context
print(chat("Can I get a prorated refund?"))  # still in refund context
06 · LangSmith Observability

Tracing Every Retrieval Decision
With LangSmith

When a user reports a wrong answer, how do you debug it? Without observability, you add print statements and re-run the query. With LangSmith, every run is a structured trace: you see the input question, which chunks were retrieved, what the final prompt looked like, and what the LLM responded — all in a UI without changing any code.

Enabling LangSmith with two environment variables

import os # Add to your .env file: os.environ["LANGCHAIN_TRACING_V2"] = "true" os.environ["LANGCHAIN_API_KEY"] = "ls__your_key_here" os.environ["LANGCHAIN_PROJECT"] = "marevlo-prod-qa" # That's it. 07 · Retriever Fine-Tuning

Score Thresholds, MMR, and
Handling Out-of-Scope Questions

A retriever that always returns K chunks will answer any question — even if the knowledge base contains nothing relevant. A production RAG system must detect when a question is out of scope and respond with "I don't have information on that" rather than hallucinating an answer from marginally relevant chunks.

Implementing graceful out-of-scope handling

# Strategy: score_threshold + empty-context detection in prompt retriever = vector_store.as_retriever( search_type="similarity_score_threshold", search_kwargs={"k": 5, "score_threshold": 0.72} ) # Prompt handles empty context explicitly PROMPT = ChatPromptTemplate.from_messages([ ("system", "Answer ONLY from the context provided.\n" "If context is empty or says NO_CONTEXT, respond:\n" "'I don't have information about this in my knowledge base.'"), ("human", "Context: {context}\n\nQuestion: {question}") ]) def format_docs_safe(docs): if not docs: return "NO_CONTEXT" # triggers the fallback instruction return "\n\n".join(d.page_content for d in docs)

MMR: when your top-5 chunks all say the same thing

Standard similarity search on a corpus where a topic appears in 20 different documents might return 5 near-identical chunks all from the same section. MMR diversifies: after selecting the first chunk, subsequent selections favor chunks that are relevant but also different from already-selected chunks.

Standard: top-5 results for "refund policy"

[0.94] refund-policy.pdf p.2: "Annual plans non-refundable after 30 days"
[0.93] refund-policy.pdf p.2: "Annual subscriptions cannot be refunded"
[0.91] refund-policy.pdf p.3: "30-day window for annual plan refunds"
[0.90] refund-policy.pdf p.2: "Non-refundable annual subscription terms"
[0.88] refund-policy.pdf p.4: "Annual plan refund exceptions"

MMR: diverse top-5 — each covers a different sub-topic

faq.pdf p.5: "Monthly plan refunds: prorated within 7 days" ← different topic

08 · Production Code

Complete Production Q&A System
Ingestion + Chatbot + LangSmith

production_qa_system.py

import os, hashlib
from pathlib import Path
from langchain_anthropic import ChatAnthropic
from langchain_openai import OpenAIEmbeddings
from langchain_community.vectorstores import Qdrant
from langchain_community.document_loaders import PyPDFLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.messages import HumanMessage, AIMessage
from langchain.chains import create_history_aware_retriever, create_retrieval_chain
from langchain.chains.combine_documents import create_stuff_documents_chain

# ── LangSmith auto-tracing ────────────────────────────────────
os.environ["LANGCHAIN_TRACING_V2"] = "true"
os.environ["LANGCHAIN_API_KEY"] = os.getenv("LANGSMITH_KEY", "")
os.environ["LANGCHAIN_PROJECT"] = "marevlo-prod-qa"

llm = ChatAnthropic(model="claude-sonnet-4-20250514", temperature=0)
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
splitter = RecursiveCharacterTextSplitter(chunk_size=600, chunk_overlap=60)

# ── Ingestion with deduplication ─────────────────────────────
def ingest_folder(folder: str, store: Qdrant):
    for path in Path(folder).glob("**/*.pdf"):
        try:
            chunks = splitter.split_documents(PyPDFLoader(str(path)).load())
            ids = [hashlib.md5(f"{path}::{i}".encode()).hexdigest() for i in range(len(chunks))]
            existing_ids = {d.id for d in store.get(ids=ids)}
            new = [(c, id_) for c, id_ in zip(chunks, ids) if id_ not in existing_ids]
            if new: store.add_documents([c for c, _ in new], ids=[i for _, i in new])
        except Exception as e: print(f"⚠ {path.name}: {e}")

# ── Build conversational chain ────────────────────────────────
def build_chatbot(store: Qdrant):
    retriever = store.as_retriever(
        search_type="mmr", search_kwargs={"k": 4, "fetch_k": 15})

    ctx_prompt = ChatPromptTemplate.from_messages([
        ("system", "Reformulate the question as standalone given history. Don't answer."),
        MessagesPlaceholder("chat_history"), ("human", "{input}")
    ])
    qa_prompt = ChatPromptTemplate.from_messages([
        ("system", "Answer from context only. If missing: 'I don't have that information.'"),
        ("system", "Context:\n{context}"),
        MessagesPlaceholder("chat_history"), ("human", "{input}")
    ])

    return create_retrieval_chain(
        create_history_aware_retriever(llm, retriever, ctx_prompt),
        create_stuff_documents_chain(llm, qa_prompt)
    )

# ── Runtime session ──────────────────────────────────────────
store = Qdrant(... connect to existing collection ...)
chain = build_chatbot(store)
history = []

def chat(q: str) -> str:
    r = chain.invoke({"input": q, "chat_history": history[-8:]})
    history.extend([HumanMessage(content=q), AIMessage(content=r["answer"])])
    return r["answer"]
09 · Assessment

Module 6 Quiz

1. You run your ingestion script twice on the same folder of PDFs. Without deduplication, what happens, and how does ID-based deduplication fix it?

Correct. Without deduplication, repeated ingestion silently corrupts the index with duplicate entries. Retrieved results for any query will contain the same chunk multiple times, degrading quality and wasting context window tokens. Deterministic IDs (hash of source path + chunk index) are the standard solution: the ID is content-addressable, so the same chunk always gets the same ID, and the existence check before add_documents prevents any duplication.

2. A user asks "What about the enterprise tier?" as a follow-up after a conversation about pricing. Your RAG chain returns wrong results. What is the likely cause?

Correct. Follow-up questions with pronouns ("it", "that", "what about") and implicit references ("the enterprise tier" — enterprise tier of what?) are the canonical failure mode of stateless RAG. The contextualize prompt (CONTEXTUALIZE_PROMPT) + create_history_aware_retriever() fixes this by first generating a standalone question from the history context, then passing that complete question to the retriever.

3. You enable LangSmith and check the trace for a slow query (4.2 seconds total). The trace shows: ContextualizeQuestion: 1.1s, VectorStoreRetriever: 0.03s, ChatAnthropic: 3.07s. Where should you optimize?

Correct. LangSmith's latency breakdown reveals exactly where time is spent. At 73% of total time, LLM generation dominates — streaming is the highest-impact fix for perceived latency (first token appears in ~400ms). The contextualize step at 26% is the second target: since question rewriting is a simple transformation, a fast cheap model (Claude Haiku, 4× faster and 5× cheaper than Sonnet) is perfectly adequate. These two changes together reduce perceived latency from 4.2s to under 1s.

4. Your score_threshold is set to 0.72. A user asks "Who is Albert Einstein?" (completely unrelated to your product knowledge base). What happens?

Correct. The score_threshold + NO_CONTEXT pattern is the standard production approach for graceful out-of-scope handling. Without it, a retriever with k=5 always returns 5 chunks — even if the best match has a similarity of 0.23, which means the chunks are essentially random relative to the query. The LLM then generates a plausible-sounding answer from this irrelevant context. score_threshold prevents this by allowing 0 results, and the explicit "NO_CONTEXT" string in the context field gives the prompt a clear signal to refuse.

5. What does create_history_aware_retriever do internally, and what would break if you replaced it with the base retriever?

Correct. create_history_aware_retriever wraps any retriever with a contextualization LLM call. Internally it: (1) formats the current input + chat_history into the CONTEXTUALIZE_PROMPT, (2) calls the LLM to produce a standalone question, (3) passes that standalone question to the wrapped retriever. Removing it means the raw input goes to the retriever — which works perfectly for the first question ("What is the refund policy?") but fails completely for follow-ups that reference prior context.
