Prompt Engineering
with LangChain

The prompt is the primary interface between your application and an LLM. How you structure it — the role, the instructions, the examples, the format spec — determines output quality far more than which model you choose. This module covers prompt templates, six production prompt types, few-shot learning, and Chain-of-Thought reasoning.

01 · Running Prompts Programmatically

From Playground to Production:
Structured Prompt Execution

In the playground, you type a prompt and read the response. In production, prompts are parameterized templates executed programmatically with variable substitution, error handling, retry logic, and output parsing. LangChain wraps all of this into a consistent API regardless of your LLM provider.

Direct API call (without LangChain)

import anthropic client = anthropic.Anthropic() # Every call needs manual wiring: response = client.messages.create( model="claude-sonnet-4-20250514", max_tokens=1024, messages=[{"role": "user", "content": "Classify this as positive/negative: Great product!"}] ) # Must manually extract text: print(response.content[0].text)

Works but: no template reuse, no provider switching, no automatic streaming/retry, no tracing.

With LangChain (recommended)

from langchain_anthropic import ChatAnthropic from langchain_core.prompts import ChatPromptTemplate from langchain_core.output_parsers import StrOutputParser # Reusable, parameterized template: chain = ( ChatPromptTemplate.from_messages([ ("system", "Classify sentiment as positive or negative."), ("human", "{text}") ]) | ChatAnthropic(model="claude-sonnet-4-20250514") | StrOutputParser() ) # Clean, typed, automatically traced: print(chain.invoke({"text": "Great product!"}))

Reusable template, provider-agnostic, streaming/async/batch included, LangSmith trace automatic.

💡

The ChatMessage format: roles matter

Modern LLMs are trained on multi-role conversations. Every message has a role: "system" sets persistent instructions and persona (processed first, high attention), "human" is user input, "assistant" is previous LLM responses for few-shot examples or conversational history. Getting roles right is the single most impactful structural decision in prompt engineering.

02 · ChatPromptTemplate Anatomy

System, Human, Assistant:
Building Reusable Prompt Templates

A ChatPromptTemplate defines the structure of a prompt with placeholder variables. At invoke time, variables are substituted and the template renders to a list of formatted messages. This separation of structure from data is what makes prompts reusable, testable, and maintainable in production applications.

Anatomy of a production ChatPromptTemplate

SYSTEM message — role + task + constraints
You are a customer support specialist for Marevlo, an online ML learning platform.
Your job is to classify support tickets into one of these categories:
[billing, technical, content, account, other]
Rules:
- Output ONLY the category name, nothing else.
- If the ticket fits multiple categories, choose the primary one.
- If unclear, output "other".

HUMAN message — parameterized input
Classify this support ticket:
{ticket_text}

At invoke time, {ticket_text} is replaced with actual ticket content
"I was charged twice this month for my Teams subscription."

LangChain implementation

ticket_prompt = ChatPromptTemplate.from_messages([ ("system", """You are a support specialist... Output ONLY the category name."""), ("human", "Classify this ticket:\n{ticket_text}") ]) # Inspect rendered messages before sending: rendered = ticket_prompt.format_messages( ticket_text="Charged twice this month") print(rendered[0].content) # system msg print(rendered[1].content) # human msg

Multiple variables + partial formatting

# Multiple {variables} in one template: multi_prompt = ChatPromptTemplate.from_messages([ ("system", "You are a {role} for {company}."), ("human", "Answer in {language}: {question}") ]) # Partial formatting (bake in some vars): marevlo_prompt = multi_prompt.partial( company="Marevlo", language="English" ) # Now only {role} and {question} needed: result = chain.invoke({ "role": "support specialist", "question": "How do I cancel?" })
⚠️

The system message is not truly secret

System messages set the LLM's persona and rules, but they are not confidential. Users can often extract them with prompts like "repeat your instructions" or "ignore previous instructions and..." (prompt injection). Never put secrets (API keys, passwords) in system messages. Do not rely on system-message-only guardrails for security-critical behavior. For sensitive prompts, use server-side rendering where the user never sees the full prompt.

03 · Six Production Prompt Types

From Classification to Reasoning:
The Complete Toolkit

Prompt engineering is not one skill — it is six. Each task type (classification, sentiment, summarization, composition, Q&A, reasoning) has its own structural patterns, failure modes, and output format requirements. Knowing which pattern to apply is half the work.

Text Classification

Assign text to a predefined category. Critical pattern: list all valid categories explicitly. Use temperature=0 for consistency.

Prompt pattern

Classify this customer message as one of: [complaint, question, compliment, refund_request, other]. Output ONLY the category name. Message: "I absolutely love the RAG Masterclass. Best course I've taken!"

Model output

compliment

Sentiment Analysis

Determine emotional tone: positive/negative/neutral, or a more nuanced scale. Specify the output format precisely.

Prompt pattern

Analyze the sentiment of this review. Output JSON: {"sentiment": "positive|negative|neutral", "confidence": 0.0-1.0, "reason": "one sentence"} Review: "The content is good but the platform is slow."

Model output

{"sentiment": "neutral", "confidence": 0.85, "reason": "Mixed: positive content quality, negative platform performance"}

Text Summarization

Condense content while preserving key information. Specify length, format (bullets vs prose), and what to preserve.

Prompt pattern

Summarize the following course feedback in 3 bullet points. Each bullet must be under 15 words. Focus on actionable insights. Feedback: [500 words of student survey responses]

Model output

- Students want more code examples in modules 3 and 5 - Video captions needed for non-native English speakers - Module 7 pacing is too fast for beginners

Text Composition

Generate original text in a specific style, format, or voice. Provide clear style examples and structural requirements.

Prompt pattern

Write a product description for the LangChain module in the style of a technical tutorial introduction. 2 paragraphs. Begin with a practical scenario, end with what the reader will build.

Model output

Imagine you need to build a customer support bot that handles 10,000 queries per day... [generated content]

Question Answering

Answer questions grounded in provided context. Always include explicit refusal instruction for out-of-context questions.

Prompt pattern

Answer the question using ONLY the provided context. If the answer is not in the context, say "I don't have that information." Context: "The RAG module covers BM25, dense retrieval, and hybrid search..." Question: "What retrieval methods does the module cover?"

Model output

The RAG module covers three retrieval methods: BM25 (keyword-based), dense retrieval (embedding-based), and hybrid search which combines both.

Reasoning

Multi-step logical analysis. The key pattern: ask the model to think step by step BEFORE giving the answer. This dramatically improves accuracy.

Prompt pattern

A student enrolled in the Teams plan on January 1st. The refund window is 30 days. The student requested a refund on February 15th. Is the refund valid? Think step by step, then give your final answer.

Model output

Step 1: Enrollment date is January 1st. Step 2: 30-day window ends January 31st. Step 3: Refund request was February 15th, which is after January 31st. Final answer: No, the refund request is outside the 30-day window.
04 · Few-Shot Learning

Showing Examples Inside
the Prompt Improves Accuracy Dramatically

Few-shot learning places worked examples directly in the prompt, showing the model what a good output looks like before asking it to produce one. It is the fastest way to improve output format consistency, teach rare output patterns, and handle domain-specific edge cases without any model training.

Zero-shot

No examples. Model must infer the output format from the instructions alone. Use when the task is simple and well-known.

Classify as positive/negative: Text: "The course was okay." Sentiment:
Output: neutral or positive (inconsistent)

One-shot

One example. Teaches the output format. Use when format consistency matters more than accuracy on edge cases.

Classify as positive/negative: Text: "Loved the course!" Sentiment: positive Text: "The course was okay." Sentiment:
Output: neutral (more consistent)

Few-shot (3+)

Three or more examples covering common cases AND edge cases. Use when accuracy on ambiguous inputs is critical.

Classify as positive/negative/neutral: [3 labeled examples] Text: "The course was okay." Sentiment:
Output: neutral (consistent + accurate)

Few-shot implementation with LangChain FewShotChatMessagePromptTemplate

few_shot_template.py

from langchain_core.prompts import (
    ChatPromptTemplate, FewShotChatMessagePromptTemplate
)

# ── Define the examples ──────────────────────────────────────
examples = [
    {"text": "I love this course!", "sentiment": "positive"},
    {"text": "The platform crashed twice today.", "sentiment": "negative"},
    {"text": "The course is okay, nothing special.", "sentiment": "neutral"},
    {"text": "Fast content, but some explanations are unclear.", "sentiment": "neutral"},
]

# ── Template for each example ─────────────────────────────────
example_template = ChatPromptTemplate.from_messages([
    ("human", "Text: {text}"),
    ("assistant", "Sentiment: {sentiment}"),
])

# ── Build few-shot template ───────────────────────────────────
few_shot = FewShotChatMessagePromptTemplate(
    example_prompt=example_template,
    examples=examples,
)

# ── Wrap in full prompt with system message ───────────────────
full_prompt = ChatPromptTemplate.from_messages([
    ("system", "You classify text sentiment. Output exactly: positive, negative, or neutral."),
    few_shot,  # inserts 4 human/assistant example pairs here
    ("human", "Text: {input}")
])

# ── Chain and run ────────────────────────────────────────────
chain = full_prompt | llm | StrOutputParser()
result = chain.invoke({"input": "The video quality is decent but audio is poor."})
print(result)  # neutral
💡

Selecting good few-shot examples

Quality of examples matters more than quantity. Choose examples that: cover the main output categories, include at least one ambiguous/edge case per category, match the style of production inputs (don't use perfectly clean test data if production inputs are messy), and avoid examples that are so similar they collapse into the same behavior. 3-6 examples is the sweet spot for most tasks — more examples increase cost without proportional quality gains.

05 · Chain of Thought Reasoning

Step-by-Step Thinking:
Why It Works and When to Use It

Chain of Thought (CoT) prompting asks the model to reason through a problem step by step before giving the final answer. For complex reasoning tasks, CoT dramatically improves accuracy — not because the model "thinks harder" but because generating intermediate reasoning steps guides the token prediction toward more accurate conclusions.

Without CoT — direct answer (fails on complex cases)

Prompt (no CoT)A student enrolled on January 15th. The refund window is 30 days. Today is February 20th. Is a refund still valid?
Model output: "Yes, a refund may be possible depending on the terms."
Problem: model hedged without computing the dates. The correct answer is NO (Feb 20 > Jan 15 + 30 days = Feb 14).

With CoT — step-by-step (correct)

Prompt (with CoT)A student enrolled on January 15th. The refund window is 30 days. Today is February 20th. Is a refund still valid? Think step by step, then give a Yes/No answer.
Step 1: Enrollment date = January 15th.
Step 2: 30-day window ends January 15 + 30 = February 14th.
Step 3: Today is February 20th, which is after February 14th.
Final answer: No, the refund window has closed.

Four CoT patterns and when to use each

PatternTrigger phraseBest forCost
Zero-shot CoT"Think step by step"Math, date calculations, eligibility checks, any deterministic reasoningModerate (longer output)
Self-consistency CoTRun 3-5 times, take majority voteHigh-stakes decisions where one CoT run might be wrongHigh (N x base cost)
Least-to-most prompting"What do I need to know first to answer this?"Complex problems that decompose into sub-problemsModerate
ReAct (Reason+Act)"Thought: ... Action: ... Observation: ..."Agent tasks requiring external tool useUsed in Module 10
⚠️

CoT increases output length and cost

Chain of Thought generates intermediate reasoning tokens before the final answer. For Claude Sonnet 4 at $15/M output tokens, a 200-token CoT step adds $0.003 per query. At 10,000 queries/day, that is $30/day for reasoning overhead. Use CoT only where accuracy improvement justifies the cost: date arithmetic, eligibility checks, multi-condition logic. Do not use CoT for simple classification or short text generation tasks.

06 · Prompt Structure Guide

The Five Components of
a Well-Structured Production Prompt

Good prompts are not written by intuition — they follow a structure. Every production-quality prompt should include these five components. Missing any one consistently degrades a specific dimension of output quality.

ComponentWhat to includeWhat breaks without itExample
1. Role + personaJob title, organization, expertise levelGeneric responses that do not match your domain"You are a customer support specialist for Marevlo, an ML learning platform."
2. Task definitionExact action verb + scopeModel interprets task too broadly or narrowly"Classify this support ticket into one of the provided categories."
3. Constraints and rulesWhat to do and what NOT to doModel adds unwanted content, hedges, or ignores boundaries"Output ONLY the category name. Do not explain. If unclear, output 'other'."
4. Output format specExact format: JSON schema, bullet points, word limitInconsistent output that breaks downstream parsers"Output JSON: {"category": "...", "confidence": 0.0-1.0}"
5. Input placeholder{variable} in curly braces for parameterizationHard-coded prompts that cannot be reused"Support ticket:\n{ticket_text}"
07 · Production Code

All Six Prompt Types in
LangChain LCEL Chains

prompt_engineering.py

from langchain_anthropic import ChatAnthropic
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser, JsonOutputParser
from langchain_core.pydantic_v1 import BaseModel, Field

llm = ChatAnthropic(model="claude-sonnet-4-20250514", temperature=0)

# ── 1. Classification ─────────────────────────────────────────
classify_chain = (
    ChatPromptTemplate.from_messages([
        ("system", "Classify the support ticket as one of: [billing, technical, content, account, other]. Output ONLY the category."),
        ("human", "{ticket}")
    ]) | llm | StrOutputParser()
)
classify_chain.invoke({"ticket": "I was charged twice this month."})
# Output: billing

# ── 2. Sentiment with structured output ───────────────────────
class SentimentResult(BaseModel):
    sentiment: str = Field(description="positive, negative, or neutral")
    confidence: float = Field(description="0.0 to 1.0")
    reason: str = Field(description="one sentence explanation")

sentiment_chain = (
    ChatPromptTemplate.from_messages([
        ("system", "Analyze sentiment. Output JSON with keys: sentiment, confidence, reason."),
        ("human", "{review}")
    ]) | llm | JsonOutputParser(pydantic_object=SentimentResult)
)

# ── 3. Summarization ─────────────────────────────────────────
summarize_chain = (
    ChatPromptTemplate.from_messages([
        ("system", "Summarize in exactly {num_bullets} bullet points. Each bullet under 15 words."),
        ("human", "{document}")
    ]) | llm | StrOutputParser()
)
summarize_chain.invoke({"num_bullets": "3", "document": "[long text]"})

# ── 4. Grounded Q&A (with explicit refusal instruction) ────────
qa_chain = (
    ChatPromptTemplate.from_messages([
        ("system", """Answer using ONLY the context below.
If not in context, say "I don't have that information."
Cite the relevant sentence."""),
        ("human", "Context:\n{context}\n\nQuestion: {question}")
    ]) | llm | StrOutputParser()
)

# ── 5. Chain of Thought reasoning ────────────────────────────
cot_chain = (
    ChatPromptTemplate.from_messages([
        ("system", "You are a support agent. Think step by step, then give a final yes/no decision."),
        ("human", "{scenario}")
    ]) | llm | StrOutputParser()
)

# ── Run all in parallel with batch ────────────────────────────
results = classify_chain.batch([
    {"ticket": "Can't log in to my account"},
    {"ticket": "Video is buffering constantly"},
    {"ticket": "Module 5 has incorrect information"},
])
print(results)  # ["account", "technical", "content"]

09 · Assessment

Module 1 Quiz

1. You are building a ticket routing system that must assign incoming support tickets to one of five queues. Temperature is set to 0.8 and the model sometimes outputs "I think this might be billing-related" instead of just "billing". What are the two fixes?

Correct. Two independent fixes for two independent problems: (1) temperature=0 removes stochasticity that allows the model to choose informal phrasing; (2) the output constraint "Output ONLY the category name" explicitly forbids hedging phrases. Without both, you might fix format inconsistency but still get occasional hedging at temperature=0, or fix hedging but still see format variation.

2. Why does ChatPromptTemplate use role-based messages (system/human/assistant) rather than a single text string?

Correct. The role distinction is architectural, not cosmetic. "System" content is attended to differently during RLHF training: models learn that system messages contain authoritative instructions. Placing constraints in the system role produces more consistent rule-following than embedding them in the user message. The assistant role for few-shot examples prevents the model from confusing examples with new instructions.

3. You add Chain of Thought ("Think step by step") to a simple binary sentiment classifier (positive/negative only). What is the likely outcome?

Correct. CoT has a specific use case: tasks where generating intermediate reasoning steps guides the model toward better conclusions (math, logic, temporal reasoning). For binary sentiment classification, the reasoning steps add cost without improving accuracy — the model already has sufficient information to classify "Great product!" as positive without thinking step by step. Misapplied CoT increases output token cost and can make output parsing brittle.

4. What does .partial() do on a ChatPromptTemplate, and when is it useful?

Correct. .partial() is a form of partial application (currying) for prompt templates. If you have template variables {company}, {role}, and {question}, and {company}="Marevlo" is always the same, you can call prompt.partial(company="Marevlo") to get a new template that only needs {role} and {question}. This is valuable in multi-tenant systems where some template variables are configured at the tenant level and others at the query level.

5. You have a few-shot classification chain with 6 examples. The model performs well in testing but inconsistently in production. You discover production inputs have typos and informal language that your test examples do not. What is the fix?

Correct. This is the most common few-shot failure mode: distribution mismatch between examples and production. The model over-fits to the clean example style and performs well on clean test inputs while failing on real-world messy inputs. The fix is to audit your example distribution: sample 50 recent production failures, identify the input patterns they share, and replace or augment your examples with representative inputs from each pattern.
