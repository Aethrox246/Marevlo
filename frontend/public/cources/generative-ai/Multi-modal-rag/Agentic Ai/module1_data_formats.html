JSON — JavaScript Object Notation

JSON is the most widely used data format on the internet. If you've ever used an app that fetches data from a server — whether it's loading your Instagram feed, checking weather, or using ChatGPT — JSON was almost certainly involved behind the scenes.

What does JSON look like?

Imagine you want to describe a person. In JSON, that looks like this:

JSON
{
  "name": "Aryan",
  "age": 24,
  "is_student": true,
  "skills": ["Python", "Machine Learning", "SQL"],
  "address": {
    "city": "Bengaluru",
    "country": "India"
  }
}
💡
The 3 golden rules of JSON: Always use double quotes for keys and strings. Separate key-value pairs with commas. Never leave a trailing comma after the last item.

The 6 Data Types in JSON

TypeExampleNotes
string"hello"Always double-quoted
number42, 3.14No quotes, supports decimals
booleantrue, falseAlways lowercase
nullnullRepresents "no value"
array[1, 2, 3]Ordered list of values
object{"key": "val"}Key-value pairs in curly braces

Reading JSON in Python

import json

# Convert a Python dict TO JSON string

# Convert a JSON string BACK to Python dict

print(data["name"])  # → Aryan

Parsing Nested JSON from API Responses

import json
import anthropic

client = anthropic.Anthropic()

response = client.messages.create(

    max_tokens=1024,

JSON for Multi-Turn Agent Memory

Production agentic systems maintain conversation history as JSON arrays. Managing this efficiently — especially context window limits — is a critical engineering challenge.

Python — Agent Memory Manager
from dataclasses import dataclass, asdict
from typing import Literal
import json, tiktoken

@dataclass
class Message:
    role: Literal["user", "assistant", "tool"]
    content: str | list
    tool_call_id: str | None = None

class AgentMemory:
    def __init__(self, max_tokens: int = 100_000):
        self.messages: list[Message] = []
        self.max_tokens = max_tokens
        self.enc = tiktoken.encoding_for_model("gpt-4")

    def add(self, msg: Message):
        self.messages.append(msg)
        self._trim_to_budget()

    def _count_tokens(self, msg: Message) -> int:
        text = json.dumps(asdict(msg))
        return len(self.enc.encode(text))

    def _trim_to_budget(self):
        # Always keep system + last N messages
        total = sum(self._count_tokens(m) for m in self.messages)
        while total > self.max_tokens and len(self.messages) > 2:
            removed = self.messages.pop(1)  # Keep index 0 (system)
            total -= self._count_tokens(removed)

    def to_api_format(self) -> list[dict]:
        return [asdict(m) for m in self.messages]

    def save_checkpoint(self, path: str):
        with open(path, "w") as f:
            json.dump(self.to_api_format(), f, indent=2)

Streaming JSON Parsing

When using streaming APIs, you receive partial JSON chunks. You need to accumulate and parse safely:

Python — Safe Streaming JSON Accumulator
import json
from json import JSONDecodeError

class StreamingJSONParser:
    def __init__(self):
        self.buffer = ""
        self.depth = 0

    def feed(self, chunk: str) -> dict | None:
        self.buffer += chunk
        for char in chunk:
            if char == "{": self.depth += 1
            elif char == "}": self.depth -= 1

        if self.depth == 0 and self.buffer.strip():
            try:
                result = json.loads(self.buffer)
                self.buffer = ""
                return result
            except JSONDecodeError:
                pass
        return None

High-Throughput JSON in Production AI Systems

At scale, naive JSON parsing becomes a bottleneck. Here's what expert-level JSON handling looks like in a production ML inference pipeline.

Python — orjson + msgspec for 10x Speed
# pip install orjson msgspec
import orjson          # C-extension JSON, ~3-10x faster than stdlib
import msgspec         # Schema-validated, zero-copy deserialization
from msgspec import Struct

# Define schema with msgspec — faster than Pydantic for pure validation
class TelemetryEvent(Struct):
    device_id: str
    metric: str
    value: float
    timestamp: int
    anomaly_score: float | None = None

decoder = msgspec.json.Decoder(list[TelemetryEvent])

# Decode 100k events from a JSONL stream — near zero GC pressure
def process_batch(raw_bytes: bytes) -> list[TelemetryEvent]:
    return decoder.decode(raw_bytes)

# orjson for serialization with numpy/datetime support
import numpy as np
data = {"scores": np.array([0.1, 0.9, 0.4])}
# stdlib json.dumps would FAIL on numpy arrays
serialized = orjson.dumps(data, option=orjson.OPT_SERIALIZE_NUMPY)

# Benchmark: stdlib vs orjson on 1M records
# stdlib:  ~4.2s   orjson:  ~0.4s   msgspec: ~0.2s

JSON Patch (RFC 6902) for Incremental Agent State

Instead of sending full state objects on every agent step, use JSON Patch to send only diffs — critical for bandwidth-constrained multi-agent systems:

Python — JSON Patch for Agent State Diffs
# pip install jsonpatch
import jsonpatch

state_v1 = {"step": 1, "memory": [], "tools_called": []}
state_v2 = {"step": 2, "memory": ["retrieved docs"], "tools_called": ["search"]}

patch = jsonpatch.make_patch(state_v1, state_v2)
print(patch)
# [{"op": "replace", "path": "/step", "value": 2},
#  {"op": "add", "path": "/memory/0", "value": "retrieved docs"},
#  {"op": "add", "path": "/tools_called/0", "value": "search"}]

# Apply patch to reconstruct state
restored = patch.apply(state_v1)
assert restored == state_v2
🚀
Production pattern: In a multi-agent orchestration system with 50+ agents sharing state, JSON Patch can reduce inter-agent communication payload by 60–90% compared to full state retransmission.

YAML — Human-Readable Pipelines

YAML (YAML Ain't Markup Language) is designed to be read by humans. If JSON is a data format, YAML is a config format — you use it to describe how your system should behave, not just what data to store.

YAML vs JSON — Same data, different feel

📋 JSON
{
  "agent": {
    "name": "MIRA",
    "model": "claude-opus-4-5",
    "tools": [
      "search",
      "memory"
    ],
    "temperature": 0.7
  }
}
📄 YAML
agent:
  name: MIRA
  model: claude-opus-4-5
  tools:
    - search
    - memory
  temperature: 0.7

Notice: no curly braces, no quotes everywhere, no commas. YAML uses indentation (2 spaces) to show structure, and dashes for list items.

YAML Basics

YAML — Core Syntax
# This is a comment in YAML

# Key-value pairs

version: 2.0
active: true

# Nested structure (use 2 spaces)

  host: localhost
  port: 5432
  name: marevlo_db

# Lists

  - gpt-4
  - claude-opus-4-5
  - gemini-1.5

# Multi-line strings

  This is a multi-line

  This is a folded string

🚨
The Norway Problem: YAML's auto-type detection can bite you. The string NO gets parsed as boolean false. The string 2024-01-15 becomes a date. Always quote strings that could be misinterpreted: country: "NO"

TOML — Config Done Right

TOML stands for "Tom's Obvious Minimal Language." It was created to be the simplest possible config file format — opinionated, unambiguous, and easy to parse without surprises.

You've already seen TOML if you've worked with Python packaging (pyproject.toml), Rust (Cargo.toml), or Hugo static sites.

TOML — Basic Syntax
# This is a TOML comment

# Simple key-value pairs
title = "Marevlo AI Platform"
version = "2.0.0"
debug = false
max_workers = 8
threshold = 0.85

# Sections use [brackets]
[database]
host = "localhost"
port = 5432
name = "marevlo_db"

[model]
name = "hunter-xgb-v2"
features = ["cpu_util", "mem_util", "error_rate"]
created = 2024-03-15  # TOML has native date type!

# Array of tables (list of objects)
[[agents]]
name = "researcher"
model = "claude-opus-4-5"

[[agents]]
name = "writer"
model = "claude-sonnet-4-5"

Key differences from YAML

FeatureTOMLYAML
Comments✓ # syntax✓ # syntax
Native dates✓ First-class type~ Parsed as string
Boolean traps✓ No surprises✗ NO/YES = false/true
Indentation-sensitive✓ Not sensitive✗ Very sensitive
Multi-document✗ One doc only✓ Supports ---

import tomllib
from dataclasses import dataclass
from datetime import datetime

@dataclass
class ExperimentConfig:
    name: str
    started_at: datetime
    seed: int

def load_experiment(path: str) -> dict:
    with open(path, "rb") as f:
        cfg = tomllib.load(f)

    # TOML dates become Python datetimes automatically
    exp = cfg["experiment"]
    assert isinstance(exp["started_at"], datetime)

    return cfg

TOML Schema Validation at Scale

At the expert level, you enforce TOML schemas programmatically — critical when 50+ data scientists are pushing experiment configs through CI.

Python — Pydantic-Validated TOML Config
# pip install pydantic tomllib
import tomllib
from pydantic import BaseModel, field_validator, model_validator
from typing import Literal
from datetime import datetime

class XGBoostConfig(BaseModel):
    n_estimators: int
    max_depth: int
    learning_rate: float
    subsample: float

    @field_validator("learning_rate")
    def lr_range(cls, v):
        if not (0 < v < 1):
            raise ValueError("learning_rate must be in (0,1)")
        return v

class ExperimentConfig(BaseModel):
    name: str
    started_at: datetime
    seed: int = 42
    tags: list[str] = []

class ModelConfig(BaseModel):
    xgboost: XGBoostConfig

class FullConfig(BaseModel):
    experiment: ExperimentConfig
    model: ModelConfig

# Load + validate in one step
with open("experiment.toml", "rb") as f:
    raw = tomllib.load(f)

config = FullConfig.model_validate(raw)  # Raises on invalid
print(config.model.xgboost.learning_rate)  # 0.05 (validated float)

JSONL — JSON Lines for AI Data

JSONL (JSON Lines) is the format powering AI training data. The idea is brilliantly simple: one complete JSON object per line. No wrapping array, no commas between records — just newline-separated JSON objects.

Regular JSON (whole file)
[
  {"id": 1, "text": "hello"},
  {"id": 2, "text": "world"},
  {"id": 3, "text": "bye"}
]
JSONL (one object per line)
{"id": 1, "text": "hello"}
{"id": 2, "text": "world"}
{"id": 3, "text": "bye"}
💡
Why JSONL wins for big data: Regular JSON requires loading the entire file into memory to parse it. JSONL lets you read one line at a time — you can process 100GB files with constant memory usage.

LLM Fine-Tuning Data Format

JSONL — OpenAI Fine-Tuning Format
{"messages": [{"role": "system", "content": "You are a network engineer."}, {"role": "user", "content": "What causes FPC errors?"}, {"role": "assistant", "content": "FPC errors typically indicate memory failures..."}]}
{"messages": [{"role": "system", "content": "You are a network engineer."}, {"role": "user", "content": "How do I detect anomalies in CPU utilization?"}, {"role": "assistant", "content": "Use a sliding window with IsolationForest..."}]}
Python — Reading & Writing JSONL
import json

# Reading JSONL — memory efficient line by line
with open("training_data.jsonl") as f:
    for line in f:
        record = json.loads(line.strip())
        print(record["messages"][0])

# Writing JSONL

    {"id": 1, "text": "hello"},
    {"id": 2, "text": "world"},
]

with open("output.jsonl", "w") as f:
    for record in records:
        f.write(json.dumps(record) + "\n")  # Critical: \n between records

Python — JSONL Trace Logger
import json, time
from datetime import datetime, timezone
from pathlib import Path

class AgentTraceLogger:
    def __init__(self, session_id: str, log_dir: str = "traces"):
        Path(log_dir).mkdir(exist_ok=True)
        self.path = f"{log_dir}/{session_id}.jsonl"

    def log(self, event_type: str, **kwargs):
        record = {
            "ts": datetime.now(timezone.utc).isoformat(),
            "type": event_type,
            **kwargs
        }
        with open(self.path, "a") as f:
            f.write(json.dumps(record) + "\n")

    def replay(self) -> list[dict]:
        with open(self.path) as f:
            return [json.loads(l) for l in f if l.strip()]

logger = AgentTraceLogger("sess_abc123")
logger.log("tool_call", tool="get_telemetry", device="JNP-001")
logger.log("tool_result", value=94.2, anomaly=True)

Streaming JSONL from S3 at Scale

Your Hunter pipeline reads telemetry JSONL from S3. Here's how to do it without loading full files into memory — critical for TB-scale datasets.

Python — Streaming JSONL from S3
import boto3, json, io
from typing import Iterator

def stream_jsonl_from_s3(
    bucket: str,
    key: str,
    batch_size: int = 1000
) -> Iterator[list[dict]]:
    s3 = boto3.client("s3")
    response = s3.get_object(Bucket=bucket, Key=key)
    stream = response["Body"]

    batch = []
    buffer = ""

    for chunk in stream.iter_chunks(chunk_size=65536):
        buffer += chunk.decode("utf-8")
        lines = buffer.split("\n")
        buffer = lines.pop()  # Keep incomplete last line

        for line in lines:
            if line.strip():
                batch.append(json.loads(line))
                if len(batch) >= batch_size:
                    yield batch
                    batch = []

    if batch:
        yield batch  # Final partial batch

# Usage in Hunter pipeline
for batch in stream_jsonl_from_s3("marevlo-data", "telemetry/2024-03.jsonl"):
    predictions = model.predict(batch)  # Process 1000 records at a time

Parallel JSONL Processing with Ray

For petabyte-scale JSONL datasets (fine-tuning corpora, evaluation benchmarks), use distributed processing:

Python — Parallel JSONL Processing
# pip install ray datasets
from datasets import load_dataset
import ray

# HuggingFace datasets natively reads JSONL
ds = load_dataset("json", data_files="training_data.jsonl", split="train")

# Map processing in parallel across CPU cores
def preprocess(example):
    msgs = example["messages"]
    example["token_count"] = sum(len(m["content"].split()) for m in msgs)
    example["valid"] = example["token_count"] < 4096
    return example

processed = ds.map(preprocess, num_proc=16, batched=False)
filtered = processed.filter(lambda x: x["valid"])

print(f"Kept {len(filtered)}/{len(ds)} examples")

# Save back to JSONL
filtered.to_json("clean_training.jsonl", lines=True)

# Shard for distributed training
for i, shard in enumerate(filtered.iter(batch_size=10_000)):
    pass  # Each shard → separate JSONL file on S3
