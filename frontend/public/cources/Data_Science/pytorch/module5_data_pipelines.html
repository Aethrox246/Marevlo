The cleanest choice here is not stylistic. Ask whether you can randomly index samples or whether data arrives as a stream you consume once in order.

2. Collate Functions — Handling Variable-Length Sequences

The Problem

By default, DataLoader tries to stack samples into a single tensor. This works when all samples have the same shape. But log sequences, text, or time-series windows often have variable length — stacking fails.

Key Takeaway

Streaming datasets shine when each incoming record can be parsed and yielded immediately. They let you process logs and event streams without pretending the whole source behaves like a finite in-memory table.

  1. def make_collate_fn(max_len: int = 32, pad_value: int = 0):
"""Returns a collate_fn that truncates to max_len then pads."""

  1. def collate(batch):
  2. sequences, labels = zip(*batch)
  3. truncated = [s[:max_len] for s in sequences]
  4. lengths = torch.tensor([len(s) for s in truncated])
  5. padded = pad_sequence(truncated, batch_first=True, padding_value=pad_value)

Streaming Massive Datasets with Memory Mapping
Page 09 / 15
Back to top
Mental Model

When data outgrows RAM, the pipeline must stop thinking in terms of “load everything first.” The right move is to read just enough bytes to serve the next sample or shard.

The Memory Problem

A large log file (100GB+) cannot be loaded into RAM. Solutions:

1. IterableDataset — stream line by line.

2. Memory-mapped files — np.memmap or torch.frombuffer for binary data.

3. Chunked HDF5/Parquet — load one shard at a time.
