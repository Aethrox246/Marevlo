1. The Canonical Training Loop

The Four Steps — Every Time, In Order

Code Example
  1. for each batch:

1. optimizer.zero_grad() ← clear old gradients

2. output = model(X) ← forward pass

3. loss = criterion(output, y) ← compute loss

4. loss.backward() ← backward pass (compute grads)

5. optimizer.step() ← update parameters

This never changes. Every training loop you write, ever, follows this structure.

Real-World Analogy: A Student Sitting Exams

1. Zero grad — forget last week’s exam feedback.

2. Forward pass — sit the exam (make predictions).

Key Takeaway

The training loop is a fixed contract: clear stale gradients, run the forward pass, compute loss, backpropagate, and only then update parameters.

Knowledge Check
  1. Why must optimizer.zero_grad() happen before the next backward pass instead of after it?
  2. Which step in the loop actually changes the model weights?

Multi-class classification

Use CrossEntropyLoss when the model predicts one class out of many and your targets are integer class ids.

Input: raw logits
Binary classification

Use BCEWithLogitsLoss when each example is yes/no and the target is 0.0 or 1.0.

Input: binary logits
Clean regression

Use MSELoss when you care about squared error and the targets are fairly well-behaved.

Penalizes big misses hard
Noisy or outlier-heavy regression

Use HuberLoss when extreme targets can dominate training and you want more robustness.

Safer with messy data

4. Learning Rate Scheduling

Why Schedule the LR?

A high LR early on helps explore the loss landscape quickly. A low LR later helps converge to a good minimum without overshooting. LR scheduling automates this.

Training loop                             zero_grad → forward → loss → backward → step.

Mixed precision                           autocast + GradScaler for 2× speed on GPU.
Overfit tiny batch                        First sanity check when loss won’t decrease.
