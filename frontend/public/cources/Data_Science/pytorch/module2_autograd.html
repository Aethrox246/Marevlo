1. Computation Graph Intuition

What is a Computation Graph?

Every time you do math with PyTorch tensors that have requires_grad=True, PyTorch
silently builds a directed acyclic graph (DAG) in the background. Each node in this graph
is either:

  • A tensor (the data), or
  • A function (an operation like +, *, sin, matmul)

When you call .backward(), PyTorch traverses this graph in reverse — from the output back
to the inputs — applying the chain rule of calculus at each step to compute gradients.


Real-World Analogy: A Factory Assembly Line (in Reverse)

Imagine a factory: raw materials go in, a product comes out. To figure out how much each raw
material contributed to the final product’s quality, you trace backwards through the assembly
steps — that’s exactly what backprop does.
x  -> [square] ->  x²    -> [add b] ->  x²+b    -> [multiply w] ->  w(x²+b) = loss
Key Takeaway

Autograd records the forward pass, stores local derivative rules, and uses the chain rule to push gradients back to the parameters that matter.

Knowledge Check
  1. If a loss depends on a tensor through multiple operations, what must autograd remember from the forward pass?
  2. Why does backprop travel from the loss back toward the inputs instead of the other direction?

The Classic Gradient Accumulation Bug

This is one of the most common PyTorch bugs — gradients accumulate across .backward() calls unless you explicitly zero them.

Code Example
  1. x = torch.tensor(2.0, requires_grad=True)
  2.  
  3. # Simulating a training loop WITHOUT zeroing gradients
  4. for step in range(3):
  5. loss = x ** 2
loss.backward()
Code Example
  1. print(f"Step {step}: x.grad = {x.grad.item()}") # 4, 8, 12 — keeps adding!
  2.  
  3. # The correct pattern: zero gradients before each backward pass
x.grad.zero_()                         # or use optimizer.zero_grad() in training
Code Example
  1. for step in range(3):
  2. if x.grad is not None:
x.grad.zero_()                 # ← CRITICAL: clear before each step
Code Example
  1. loss = x ** 2
loss.backward()
Code Example
  1. print(f"Step {step}: x.grad = {x.grad.item()}") # 4, 4, 4 — correct!
Step 0: x.grad = 4.0
Step 1: x.grad = 8.0
Step 2: x.grad = 12.0
Key Takeaway

Leaf tensors store their gradients in .grad, and PyTorch accumulates new values there until you explicitly clear them.

Knowledge Check
  1. Why is .grad attached to leaf tensors rather than every intermediate tensor by default?
  2. If you see gradients growing across training steps, what is the first line you should look for?
Common Mistakes
  • Assuming .backward() overwrites old gradients instead of accumulating them.
  • Calling zero_() after the update and forgetting the next backward will start from stale values.
  • Inspecting only the loss value when the real bug is hidden in .grad.

.detach(): Break the Graph

.detach() creates a new tensor that shares the same data but is removed from the com-
putation graph. No gradients flow through it.
Code Example

  2. y = x ** 2 # y is part of the graph
  3.  
  4. # Detach — same values, no gradient connection

  7. print("y_detached value:", y_detached.item())

  9.  
  10. # Common use: logging metrics without affecting training

  13. print("Loss for logging:", loss_value)

Key Takeaway

detach() keeps the same data without gradient history, while torch.no_grad() prevents new graph construction for inference, logging, and parameter updates.

Knowledge Check

  • Using detach() on something you still need gradients for later.

4. Numerical Gradient Checking

How do you know your custom backward is correct? Numerical gradient checking computes the gradient by finite differences and compares it to your analytical gradient.

Mental Model

Analytical gradient is what your code claims. Numerical gradient is the slow external judge. If they disagree badly, your backward logic is wrong.

Key Takeaway

A custom autograd function is only trustworthy when its backward behavior matches the math you intended and survives a numerical check.

Knowledge Check
  1. Why should the gradient be zero outside the unclamped region of this custom ReLU?
  2. If analytical and numerical gradients disagree badly, which one do you trust first?
Common Mistakes
  • Trusting a custom backward pass without checking it numerically.
  • Using an epsilon that is too large or too tiny and then misreading the difference.
  • Expecting exact equality instead of “small enough disagreement.”
