Track 5 · Regression & Relationships

Multiple Linear Regression
& The Assumptions

Multiple predictors unlock serious modeling power — and come with a checklist of assumptions to verify. The matrix form $\mathbf Y = \mathbf X \boldsymbol\beta + \boldsymbol\varepsilon$ and its closed-form solution $\hat{\boldsymbol\beta} = (\mathbf X^T \mathbf X)^{-1} \mathbf X^T \mathbf Y$. The Gauss-Markov theorem that justifies OLS. Six assumptions. Six diagnostics. And what to do when each fails.

Module 5.2 Matrix form · Gauss-Markov · VIF · Breusch-Pagan · Durbin-Watson · Cook's D · AIC/BIC Kartify: multi-driver revenue model with diagnostics Wasserman Ch. 13 · ISLR Ch. 3 · Kutner et al. Chs. 6–10
⚡ Kartify — When One Predictor Isn't Enough
Module 5.1's Kartify model had one predictor: ad spend. The CMO asks the follow-up: "Ad spend explains most of the variation, but 27% is unexplained. What else is driving daily conversions?"

Natural candidates: day of week (weekends perform differently), concurrent promo intensity, session volume, mobile-vs-desktop mix, seasonality. Each might add a little explanatory power. Multiple regression is the tool: one response $Y$, multiple predictors $X_1, X_2, \ldots, X_p$. We fit $Y = \beta_0 + \beta_1 X_1 + \beta_2 X_2 + \ldots + \beta_p X_p + \varepsilon$.

But here's what changes from Module 5.1: assumptions start to matter in ways they didn't before. Two correlated predictors can give unstable coefficients (multicollinearity). Residual variance may grow with $\hat Y$ (heteroscedasticity). Time-series data may have autocorrelated errors. A single unusual customer can flip a coefficient sign (influential observations). A model with 20 predictors might fit the training data perfectly while failing on new data (overfitting).

Module 5.2 walks through all of this. First, the matrix form — once you're comfortable with it, multiple regression is conceptually the same as simple regression. Then the Gauss-Markov theorem — why OLS is special among all unbiased linear estimators. Then the six classical assumptions, each with a diagnostic test and a remedy when violated. Finally, feature selection via AIC/BIC and model comparison tools.

The running example. Kartify's extended dataset: 200 days, with $Y$ = daily conversions and $X$ = ad spend, session volume, day-of-week indicator, promo intensity, and mobile share. We'll fit the model, run every diagnostic, and see what the data actually says.
// Section 1 · Matrix Form

Matrix Form — The Single Equation That Says Everything

With $p$ predictors and $n$ observations, writing out $n$ equations one-by-one is painful. Matrix notation compresses all of them into one equation.

Multiple regression — scalar vs matrix
$$Y_i = \beta_0 + \beta_1 X_{i1} + \beta_2 X_{i2} + \ldots + \beta_p X_{ip} + \varepsilon_i, \quad i = 1, \ldots, n$$
$$\mathbf Y = \mathbf X \boldsymbol\beta + \boldsymbol\varepsilon$$
ObjectShapeWhat it isKartify example
$\mathbf Y$$n \times 1$Vector of responses200 daily conversion counts
$\mathbf X$$n \times (p+1)$Design matrix — first column is 1s (intercept), others are predictors$200 \times 6$: ones, ad-spend, sessions, day-of-week, promo, mobile-share
$\boldsymbol\beta$$(p+1) \times 1$Coefficient vector $(\beta_0, \beta_1, \ldots, \beta_p)^T$Six coefficients to estimate
$\boldsymbol\varepsilon$$n \times 1$Error vector, iid $N(0, \sigma^2)$Unobserved day-level noise
The design matrix $\mathbf X$ — the most important object in regression
$\mathbf X$ encodes every modeling choice you make. Which predictors to include is the columns of $\mathbf X$. Want an interaction term $X_1 \cdot X_2$? Add a column that's the product. Want a polynomial $X^2$ term? Add a column with squared values. Want a categorical variable? One-hot encode it into multiple indicator columns. All of these changes are just different design matrices. The OLS machinery that follows works identically for any of them.
// Section 2 · The OLS Solution

Deriving $\hat{\boldsymbol\beta} = (\mathbf X^T \mathbf X)^{-1} \mathbf X^T \mathbf Y$ — From Calculus in Matrix Form

Module 5.1 derived $\hat\beta_0, \hat\beta_1$ by scalar calculus. Here we do it in matrix form. Same idea — minimize RSS by setting gradient to zero — but now the gradient is a vector of $p + 1$ partial derivatives, handled simultaneously.

Matrix derivation of OLS
1
Objective. $\text{RSS}(\boldsymbol\beta) = \|\mathbf Y - \mathbf X \boldsymbol\beta\|^2 = (\mathbf Y - \mathbf X\boldsymbol\beta)^T (\mathbf Y - \mathbf X\boldsymbol\beta)$.
2
Expand. $\text{RSS} = \mathbf Y^T \mathbf Y - \mathbf Y^T \mathbf X\boldsymbol\beta - \boldsymbol\beta^T \mathbf X^T \mathbf Y + \boldsymbol\beta^T \mathbf X^T \mathbf X \boldsymbol\beta$. Middle two terms are scalars, hence equal: $\text{RSS} = \mathbf Y^T \mathbf Y - 2\boldsymbol\beta^T \mathbf X^T \mathbf Y + \boldsymbol\beta^T \mathbf X^T \mathbf X \boldsymbol\beta$.
3
Gradient. Using standard matrix calculus identities: $\partial(\boldsymbol\beta^T \mathbf a)/\partial\boldsymbol\beta = \mathbf a$ and $\partial(\boldsymbol\beta^T \mathbf A \boldsymbol\beta)/\partial\boldsymbol\beta = 2\mathbf A\boldsymbol\beta$ (for symmetric $\mathbf A$). Therefore $\nabla_{\boldsymbol\beta} \text{RSS} = -2\mathbf X^T \mathbf Y + 2\mathbf X^T \mathbf X \boldsymbol\beta$.
4
Set to zero. $\mathbf X^T \mathbf X \hat{\boldsymbol\beta} = \mathbf X^T \mathbf Y$. These are the normal equations.
5
Solve. If $\mathbf X^T \mathbf X$ is invertible (columns of $\mathbf X$ linearly independent), $\boxed{\hat{\boldsymbol\beta} = (\mathbf X^T \mathbf X)^{-1} \mathbf X^T \mathbf Y}$. $\blacksquare$
6
Sanity check. When $\mathbf X$ has only a 1-column and an $X$-column, this formula reduces to the Module 5.1 scalar result. (Worked as an exercise.)
Fitted values, residuals, and the hat matrix
$$\hat{\mathbf Y} = \mathbf X \hat{\boldsymbol\beta} = \mathbf X(\mathbf X^T \mathbf X)^{-1} \mathbf X^T \mathbf Y = \mathbf H \mathbf Y$$
$$\mathbf e = \mathbf Y - \hat{\mathbf Y} = (\mathbf I - \mathbf H)\mathbf Y$$

$\mathbf H = \mathbf X(\mathbf X^T \mathbf X)^{-1} \mathbf X^T$ is the hat matrix (puts the "hat" on $\mathbf Y$). It's the projection matrix onto the column space of $\mathbf X$ — the geometric interpretation from 5.1, now in matrix form.

⚡ Key properties of the hat matrix

$\mathbf H$ has three properties worth knowing:

  • Symmetric: $\mathbf H^T = \mathbf H$.
  • Idempotent: $\mathbf H^2 = \mathbf H$. (Projecting twice is the same as projecting once.)
  • Trace: $\text{tr}(\mathbf H) = p + 1$ (number of parameters including intercept). This is the "effective model dimension."
The diagonal elements $h_{ii}$ are the leverages — how much observation $i$ influences its own fitted value. We'll use these later for Cook's distance.

// Section 3 · Gauss-Markov Theorem

Why OLS? — The Gauss-Markov Theorem

With so many possible estimators (OLS, ridge, LASSO, Bayesian, robust), why is OLS the "default"? Gauss-Markov gives the mathematical answer.

Gauss-Markov Theorem
$$\text{Under classical assumptions, OLS is BLUE}$$

BLUE = Best Linear Unbiased Estimator. Unpacking:

Linear
Linear in $\mathbf Y$
$\hat{\boldsymbol\beta} = (\mathbf X^T \mathbf X)^{-1} \mathbf X^T \mathbf Y = \mathbf A \mathbf Y$. A linear function of the responses.
Unbiased
$E[\hat{\boldsymbol\beta}] = \boldsymbol\beta$
On average across hypothetical repeated samples, OLS hits the true coefficient vector. Holds if the model is correctly specified and $E[\boldsymbol\varepsilon] = \mathbf 0$.
Best
Minimum variance
Among all linear unbiased estimators, OLS has the smallest variance for every coefficient. Formally: $\mathrm{Var}(\hat{\boldsymbol\beta}_{\text{OLS}}) \preceq \mathrm{Var}(\tilde{\boldsymbol\beta})$ for any other linear unbiased $\tilde{\boldsymbol\beta}$ (matrix ordering).
Estimator
Of $\boldsymbol\beta$
Applies to each coefficient, not just the whole vector. $\hat\beta_j$ has smaller variance than any other linear unbiased estimator of $\beta_j$.
What Gauss-Markov does NOT say
It does not say OLS is the globally best estimator. It only compares within the "linear and unbiased" class. Many non-linear or biased estimators can have lower MSE — that's the whole point of ridge regression, LASSO, Bayesian shrinkage, and robust methods. Gauss-Markov's guarantee is narrow: among linear unbiased estimators, OLS wins.

It also doesn't say anything about inference — the $t$-tests and CIs from Module 5.1 require the additional assumption $\boldsymbol\varepsilon \sim N(0, \sigma^2 \mathbf I)$. Gauss-Markov is about variance, not about distribution shape.
// Section 4 · The Classical Assumptions

The Six Classical Assumptions — What OLS Requires

Gauss-Markov and the full inference machinery rest on classical assumptions. Here's the complete list, what each means, and what goes wrong if violated:

#AssumptionFormal statementConsequence if violated
A1Linearity$E[Y | \mathbf X] = \mathbf X \boldsymbol\beta$Model is mis-specified — systematic errors in predictions
A2Full rank$\mathbf X$ has full column rank$\mathbf X^T \mathbf X$ not invertible — coefficients undefined
A3Zero mean errors$E[\boldsymbol\varepsilon | \mathbf X] = \mathbf 0$Biased estimates (omitted variable bias, endogeneity)
A4Homoscedasticity$\mathrm{Var}(\varepsilon_i | \mathbf X) = \sigma^2$ for all $i$OLS still unbiased but SEs wrong — inference invalid
A5No autocorrelation$\mathrm{Cov}(\varepsilon_i, \varepsilon_j | \mathbf X) = 0$ for $i \ne j$SEs wrong — especially in time-series data
A6Normality$\boldsymbol\varepsilon | \mathbf X \sim N(\mathbf 0, \sigma^2 \mathbf I)$Exact $t$-tests, $F$-tests invalid; CLT helps for large $n$

Each has a dedicated diagnostic and remedy. We tackle them one at a time.

// Section 5 · Multicollinearity

Multicollinearity — When Predictors Overlap

Multicollinearity means some predictors are highly correlated with each other (not with $Y$). It's a violation of A2 in extreme form; in milder form, it inflates coefficient variances without breaking the math.

Why multicollinearity is a problem — intuitive version
Kartify has two near-identical predictors: "total ad spend" and "search-ad spend" (the second is about 80% of the first). Can you separate their individual effects? In principle yes, but you need cases where they differ. If they nearly always move together, the data doesn't contain enough information to tell them apart — coefficients become wildly uncertain and can flip sign across samples.

The model isn't wrong; the individual coefficients are just unidentifiable. Predictions using both together remain fine.
Variance Inflation Factor (VIF)
$$\text{VIF}_j = \frac{1}{1 - R_j^2}$$

Where $R_j^2$ is from regressing predictor $X_j$ on all the other predictors. If $X_j$ is a linear combination of others, $R_j^2 \to 1$ and VIF $\to \infty$.

VIF valueInterpretationAction
VIF $= 1$No collinearityIdeal — predictor is orthogonal to others
VIF $< 5$ModerateUsually acceptable
VIF $= 5$ to $10$ConcerningInvestigate — consider combining or removing predictors
VIF $> 10$Serious multicollinearityDrop one, combine predictors, or use ridge regression
Kartify · VIF diagnosis
Setup. Priya includes "total_ad_spend," "search_ads," "display_ads," and "video_ads" in the model. Search + display + video = total (roughly).
VIFs. total_ad_spend: 48, search_ads: 22, display_ads: 18, video_ads: 11.
Problem identified. Total is a near-linear combination of the channel-level variables. Severe multicollinearity.
Fix. Drop "total" (it's redundant given the channels) or drop the three channel-level variables (if only total matters).
After removal. VIFs for the three channels drop to 1.8, 2.1, 1.4 — clean. Coefficients become stable and interpretable.

Ridge regression — the workaround when you can't drop predictors

Ridge estimator
$$\hat{\boldsymbol\beta}_{\text{ridge}} = (\mathbf X^T \mathbf X + \lambda \mathbf I)^{-1} \mathbf X^T \mathbf Y$$

The addition of $\lambda \mathbf I$ (for $\lambda > 0$) makes $\mathbf X^T \mathbf X + \lambda \mathbf I$ always invertible — collinearity no longer breaks the computation. The cost: $\hat{\boldsymbol\beta}_{\text{ridge}}$ is biased (shrinks toward zero), but has lower variance. Net effect: often lower MSE. We revisit this in Module 5.3 and Track 6.

// Section 6 · Heteroscedasticity

Heteroscedasticity — When the Variance Isn't Constant

Homoscedasticity (assumption A4): $\mathrm{Var}(\varepsilon_i) = \sigma^2$ for every $i$. Heteroscedasticity: variance changes across observations, often growing with $\hat Y$.

Homoscedasticity vs heteroscedasticity — visualized
Toggle between the two regimes; watch the residual plot shape
datafitted lineresidual band ±2σ

Detecting heteroscedasticity — the Breusch-Pagan test

Breusch-Pagan test for heteroscedasticity
$$H_0: \mathrm{Var}(\varepsilon_i) = \sigma^2 \text{ (homoscedastic)} \qquad vs \qquad H_1: \mathrm{Var}(\varepsilon_i) = f(\mathbf X_i)$$
Breusch-Pagan procedure
1
Fit the main OLS model, obtain residuals $\hat e_i$.
2
Regress $\hat e_i^2$ on the predictors $\mathbf X_i$ — call this auxiliary regression's $R^2 = R^2_{\text{aux}}$.
3
Test statistic: $\text{BP} = n \cdot R^2_{\text{aux}} \sim \chi^2_p$ under $H_0$. Small $p$-value → reject homoscedasticity.

Consequence if heteroscedastic. OLS is still unbiased, but the standard errors are wrong. The $t$-tests and CIs become unreliable. Two fixes:

Option 1 — Robust SEs
White (HC) standard errors
Replace the naive SE formula with one that's consistent under any heteroscedasticity. OLS coefficients unchanged; inference becomes valid. Python: result.get_robustcov_results(cov_type="HC3").
Option 2 — Weighted Least Squares
WLS
Weight each observation by $1/\hat\sigma_i^2$, where $\hat\sigma_i^2$ is an estimate of that observation's variance. Recovers efficiency lost by OLS under heteroscedasticity. Harder to implement — need a model for $\sigma_i^2$.
Kartify · diagnosing and fixing heteroscedasticity
Setup. Priya fits conversions ~ ad_spend + sessions. Residual-vs-fitted plot shows a clear funnel — variance grows with $\hat Y$.
Breusch-Pagan. BP $= 14.7$, df = 2, $p = 0.0006$. Reject homoscedasticity.
Fix 1 (quick). Refit with HC3 robust SEs. Coefficients unchanged, SEs roughly 30% larger, $t$-statistics drop. Inference becomes valid.
Fix 2 (principled). Log-transform $Y$: residuals on log scale show constant variance. Or use WLS with weights proportional to $1/\hat Y_i$.
Takeaway. Heteroscedasticity is common in real data — rarely shocking. Either use robust SEs as a fallback or transform $Y$ so variance stabilizes.
// Section 7 · Autocorrelation

Autocorrelation — When Errors Remember

Assumption A5: errors are uncorrelated across observations. Common in time-series data: today's "unexplained" component is related to yesterday's. A sudden marketing pivot drives errors to be positive several days in a row.

Durbin-Watson statistic
$$\text{DW} = \frac{\sum_{i=2}^n (\hat e_i - \hat e_{i-1})^2}{\sum_{i=1}^n \hat e_i^2}$$
DW valueInterpretation
DW $\approx 2$No autocorrelation (ideal)
DW $< 1.5$Positive autocorrelation (residuals persist across observations)
DW $> 2.5$Negative autocorrelation (rare; residuals flip sign)
⚡ Connection between DW and first-order autocorrelation

If errors follow an AR(1) process $\varepsilon_t = \rho \varepsilon_{t-1} + u_t$ with first-order autocorrelation $\rho$, then $\text{DW} \approx 2(1 - \rho)$. DW $\approx 2$ ↔ $\rho \approx 0$ (no autocorrelation). DW $\approx 1$ ↔ $\rho \approx 0.5$ (moderate positive). DW $\approx 0$ ↔ $\rho \approx 1$ (severe positive).

Fix 1 — Newey-West SEs
HAC standard errors
Heteroscedasticity and Autocorrelation Consistent SEs. Robust to both heteroscedasticity and autocorrelation up to a chosen lag. Python: cov_type="HAC", cov_kwds={"maxlags": L}.
Fix 2 — AR model
Explicitly model the autocorrelation
Use ARIMA, SARIMA, or add lagged dependent variables to the regression. Proper time-series methods handle this natively (Track 6 touches on this).
// Section 8 · Influential Observations

Influential Observations — When One Point Rules the Model

An observation is influential if dropping it would substantially change the fitted coefficients. Three related concepts:

Leverage $h_{ii}$
Extremity in $\mathbf X$ space
Diagonal of the hat matrix. Measures how far $\mathbf X_i$ is from the mean of predictors. Rule of thumb: $h_{ii} > 2(p+1)/n$ is "high leverage."
Studentized residual
Scaled residual $\hat e_i / (\hat\sigma\sqrt{1 - h_{ii}})$
Large magnitude (> 2 or < -2) means the observation is an outlier in $Y$. Divide by SE to make comparable across observations.
Cook's distance $D_i$
Combined influence measure
$D_i = \dfrac{\hat e_i^2}{(p+1)\hat\sigma^2} \cdot \dfrac{h_{ii}}{(1 - h_{ii})^2}$. Combines leverage and outlier status. Rule: $D_i > 1$ or $D_i > 4/n$ is noteworthy.
DFBETAS
Change in each coefficient
$\text{DFBETAS}_{ij}$ = standardized change in $\hat\beta_j$ when observation $i$ is dropped. Shows which coefficient a point influences. Rule: $|\text{DFBETAS}| > 2/\sqrt n$ is noteworthy.
⚠ Don't just delete outliers

High leverage or large Cook's D are flags for investigation, not automatic delete orders.

  • Data error? Remove after verifying.
  • Rare but legitimate observation? Keep it; report sensitivity analysis (with/without).
  • Model mis-specified for that regime? Expand the model — e.g., allow non-linearity at the extremes.
The observation might be the most informative one in the dataset.

// Section 9 · Feature Selection

Feature Selection — Picking Predictors with AIC and BIC

With 20 candidate predictors, you have $2^{20} \approx 10^6$ possible subsets. Which one to use? Two issues:

  • $R^2$ always increases when you add predictors — even random noise predictors. Can't use $R^2$ alone for selection.
  • Overfitting. A model that fits the training data perfectly may fail on new data.
AIC (Akaike Information Criterion) and BIC (Bayesian Information Criterion)
$$\text{AIC} = -2\log L + 2k$$
$$\text{BIC} = -2\log L + k \log n$$

Where $L$ is the likelihood at the MLE and $k$ is the number of parameters. Smaller is better. Both penalize model complexity; BIC penalizes more heavily for larger $n$.

AIC
Prefers predictive fit
Asymptotic loss-minimization interpretation. Picks the model that minimizes expected prediction error. Tends to select richer models.
BIC
Prefers true model (if among candidates)
Motivation: Bayesian posterior probability of models. Penalty $k \log n$ grows with sample size → selects smaller models for large $n$. Consistent — recovers the "true" model as $n \to \infty$.
Adjusted $R^2$
$1 - (1 - R^2)(n-1)/(n-p-1)$
Penalty for additional predictors. Can decrease when adding predictors. Not as principled as AIC/BIC but commonly reported.
Cross-validation
Direct prediction-error measure
Module 5.5. The gold standard for picking among models when the goal is prediction — doesn't rely on parametric assumptions.

Stepwise selection — the classical procedure

Forward selection
1
Start with intercept-only model.
2
Try adding each unused predictor; pick the one that most improves the criterion (AIC or BIC).
3
Add it. Repeat until no further improvement.
Backward elimination
1
Start with full model (all predictors).
2
Try removing each predictor; drop the one whose removal most improves the criterion.
3
Repeat until no removal improves.
⚠ Stepwise selection has serious limitations

Stepwise methods are heavily criticized:

  • Final $p$-values are invalid (selection bias inflates significance).
  • Different starting points give different "best" models.
  • Misses important predictor combinations (greedy local search).
Modern practice: use LASSO (Track 6) for principled selection, or cross-validation over all candidate models. Stepwise is still common and useful for exploration — just don't trust its $p$-values.

// Section 10 · Model Extensions

Interactions and Polynomials — Stretching the Linear Model

Interaction terms

An interaction $X_1 \cdot X_2$ allows the effect of $X_1$ on $Y$ to depend on $X_2$.

Model with interaction
$$Y = \beta_0 + \beta_1 X_1 + \beta_2 X_2 + \beta_3 (X_1 \cdot X_2) + \varepsilon$$
$$\frac{\partial Y}{\partial X_1} = \beta_1 + \beta_3 X_2$$
Kartify · ad spend × weekend interaction
Fit. $\hat Y = \hat\beta_0 + 5.2\,\text{spend} + 3.1\,\text{weekend} + 1.8\,(\text{spend} \cdot \text{weekend})$.
On weekdays (weekend = 0): 5.2 conversions per ₹1 lakh spend.
On weekends (weekend = 1): $5.2 + 1.8 = 7.0$ conversions per ₹1 lakh spend.
Interpretation. Ad spend works 35% harder on weekends. Without the interaction term, the model would just average these and miss the pattern.

Polynomial regression

Polynomial model
$$Y = \beta_0 + \beta_1 X + \beta_2 X^2 + \beta_3 X^3 + \varepsilon$$

Still linear in the parameters — OLS applies directly. Captures curvature when residuals show non-linear patterns.

⚠ Polynomial degree — don't overfit

A polynomial of degree $n-1$ can fit $n$ data points exactly. That's not skill, that's overfitting. Start with $X^2$; only add higher terms if residuals still show pattern. Cross-validate (Module 5.5) before committing to high-degree polynomials. Alternative: splines or GAMs (non-parametric curve fitting) are often cleaner.

// Section 11 · Python

Python — Full Diagnostic Workflow

python · fit multiple regression + VIF
import numpy as np
import pandas as pd
import statsmodels.api as sm
from statsmodels.stats.outliers_influence import variance_inflation_factor

np.random.seed(42)
n = 200

# Kartify multi-predictor dataset
ad_spend = np.random.uniform(5, 25, n)          # ₹ lakh
sessions = 1200 + 80 * ad_spend + np.random.normal(0, 200, n)
weekend = np.random.binomial(1, 2/7, n)
promo = np.random.uniform(0, 1, n)
mobile_share = np.random.beta(6, 4, n)

conversions = (
    -3.6 + 5.2*ad_spend + 0.02*sessions + 4.1*weekend
    + 12*promo + 8*mobile_share + np.random.normal(0, 6, n)
)

df = pd.DataFrame({
    "ad_spend": ad_spend, "sessions": sessions, "weekend": weekend,
    "promo": promo, "mobile_share": mobile_share, "conversions": conversions
})

# Fit the model
X = sm.add_constant(df[["ad_spend", "sessions", "weekend", "promo", "mobile_share"]])
model = sm.OLS(df["conversions"], X).fit()
print(model.summary())

# Check VIF for multicollinearity
print("\nVIF values:")
for i, name in enumerate(X.columns):
    vif = variance_inflation_factor(X.values, i)
    print(f"  {name:15} VIF = {vif:.2f}")
# ad_spend and sessions are correlated (sessions depends on spend by construction).
# Watch for VIF > 5.

python · feature selection with AIC/BIC
import statsmodels.api as sm
from itertools import combinations

candidates = ["ad_spend", "sessions", "weekend", "promo", "mobile_share"]

# Brute force: try all subsets — tractable for p ≤ 10
best_aic, best_bic = {"aic": np.inf}, {"bic": np.inf}
for k in range(1, len(candidates) + 1):
    for combo in combinations(candidates, k):
        X_sub = sm.add_constant(df[list(combo)])
        m = sm.OLS(df["conversions"], X_sub).fit()
        if m.aic < best_aic["aic"]:
            best_aic = {"aic": m.aic, "features": combo}
        if m.bic < best_bic["bic"]:
            best_bic = {"bic": m.bic, "features": combo}

print(f"AIC-optimal: {best_aic['features']}, AIC = {best_aic['aic']:.1f}")
print(f"BIC-optimal: {best_bic['features']}, BIC = {best_bic['bic']:.1f}")

# BIC usually selects fewer features than AIC for large n
