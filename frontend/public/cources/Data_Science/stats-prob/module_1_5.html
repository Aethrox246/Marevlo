Percentiles & Quantiles — The Ranking Framework

A percentile is a value below which a given percentage of observations fall. The 90th percentile of delivery_days = 6.1 means: 90% of deliveries completed within 6.1 days. This is a statement about rank, not about averages.

⚡ Core Intuition

The mean tells you the "centre of gravity." The 90th percentile tells you: "if I pick a random order, what's the worst-case delivery time that 90% of my customers will experience?" These are completely different questions. SLAs, latency p99s in engineering, income inequality (P80/P20), and medical reference ranges — all use percentiles, never means.

// Pth Percentile — Linear Interpolation Method
L = (P/100) × (n + 1) → if L is integer: Pth percentile = x[L] → if fractional: interpolate between x[⌊L⌋] and x[⌈L⌉]
// numpy uses this by default. Sort data first. P=25 → Q1, P=50 → median, P=75 → Q3.
Worked Example · Kartify delivery_days percentiles
Sorted data (10 orders, days): 1, 2, 2, 3, 3, 4, 5, 6, 8, 14
Q1 (P25): L = 0.25 × 11 = 2.75 → interpolate: x[2] + 0.75×(x[3]−x[2]) = 2 + 0.75×(2−2) = 2.0 days
Median (P50): L = 0.50 × 11 = 5.5 → (x[5] + x[6])/2 = (3+4)/2 = 3.5 days
Q3 (P75): L = 0.75 × 11 = 8.25 → interpolate: x[8] + 0.25×(x[9]−x[8]) = 6 + 0.25×(8−6) = 6.5 days
P90: L = 0.90 × 11 = 9.9 → x[9] + 0.9×(x[10]−x[9]) = 8 + 0.9×(14−8) = 13.4 days
IQR = Q3 − Q1 = 6.5 − 2.0 = 4.5 days. The middle 50% of deliveries take between 2 and 6.5 days. The 14-day delivery is extreme — it's an outlier.

The Box Plot — Five Numbers, One Picture

The box plot (box-and-whisker plot) is the single most information-dense summary of a distribution's shape. It shows the five-number summary: minimum whisker, Q1, median, Q3, maximum whisker — plus outliers beyond the fences.

⚡ Reading the Box Plot

The box width = IQR = how spread the middle 50% is. A narrow box means consistent delivery. A wide box means high variability. The whiskers extend to the most extreme non-outlier values. Points beyond the whiskers are outliers (Tukey fences: Q1−1.5×IQR and Q3+1.5×IQR). The median line position inside the box tells you skewness — if it's near Q1, the distribution is right-skewed.

Outlier Detection — The Complete Toolkit

An outlier is a data point that's unusually far from the rest. But "unusual" needs a precise definition — and the right definition depends on your data and use case.

Kartify — Three Outlier Stories
Data quality outlier: A delivery_days value of 847 — this is a data entry error (should be 8.47 days or 84.7 days). Delete it.

Legitimate business outlier: A single order worth ₹89,000 — a genuine bulk corporate purchase. Keep it, but model separately or use robust statistics.

Fraud signal: A seller with 94% return rate — this is a legitimate outlier and an actionable business signal. Flag it, investigate, act.

Method 1: IQR / Tukey Fences

// Tukey Fences (Non-parametric)
Lower fence = Q1 − 1.5 × IQR Upper fence = Q3 + 1.5 × IQR Outliers: any value outside [lower fence, upper fence]
// 1.5×IQR is the standard. 3×IQR gives "extreme outliers". This method assumes nothing about the distribution — works on skewed data.
Worked Example · IQR outlier detection on delivery_days
Q1 = 2.8 days, Q3 = 6.2 days
IQR = 6.2 − 2.8 = 3.4 days
Lower fence: 2.8 − 1.5 × 3.4 = 2.8 − 5.1 = −2.3 days → no lower outliers possible (days ≥ 0)
Upper fence: 6.2 + 1.5 × 3.4 = 6.2 + 5.1 = 11.3 days
Any order with delivery_days > 11.3 is flagged as an outlier. These are orders Kartify's logistics team should investigate — possible lost parcels, address issues, carrier failures.

Method 2: Z-Score (Parametric)

// Z-Score Standardisation
z = (x − μ) / σ Outlier threshold: |z| > 3 (more conservative) or |z| > 2 (stricter)
// Assumes approximately normal distribution. For skewed data (like price_inr), use IQR method instead — z-score is pulled by the very outliers you're trying to detect.
Worked Example · Z-score on Kartify customer_rating
Mean rating: μ = 4.12, SD: σ = 0.65
Seller A rating: 1.2 stars → z = (1.2 − 4.12) / 0.65 = z = −4.49
Seller B rating: 3.6 stars → z = (3.6 − 4.12) / 0.65 = z = −0.80 (normal variation)
Seller A's z = −4.49 is way below −3. Extremely unusual. Kartify's quality team should investigate — likely a seller problem, not a product category problem. Seller B is within normal range.
⚠️ Z-Score on Skewed Data Is Unreliable

If your data is right-skewed (like Kartify's price_inr), the mean and SD are inflated by the extreme values. You end up computing z-scores using statistics that are already distorted by the outliers you're trying to find. For skewed data: use IQR method. For roughly normal data: z-score is fine. When in doubt: use IQR — it makes no distributional assumption.

Method 3: Modified Z-Score (Robust)

// Modified Z-Score (Iglewicz & Hoaglin)
M = 0.6745 × (x − median) / MAD where MAD = median(|xᵢ − median(x)|) Outlier threshold: |M| > 3.5
// Uses median and MAD instead of mean and SD — much more resistant to the influence of outliers. Best for small samples and highly skewed data.
✅ Use IQR When
Non-parametric (no distribution assumption)
Data is skewed (prices, GMV), when you don't know the distribution, for box plot visualisation. Robust and standard for EDA.
✅ Use Z-Score When
Parametric (assumes normality)
Data is approximately normal (delivery_days after transformation, standardised test scores). Works well when n is large and distribution is roughly symmetric.
✅ Use Modified Z-Score When
Small, skewed, or unknown distribution
Seller ratings, return rates — small samples per seller, skewed distributions. Modified Z is robust because it's based on median and MAD, not mean and SD.
🚨 Don't Do This
Delete outliers because they hurt the model
Outliers that are legitimate data points (real luxury orders, real bulk purchases) should never be deleted. Model them separately, use robust metrics, or apply transformations. Deleting real data is research misconduct.

Z-Scores & Standardisation — Converting to Standard Units

Z-scores serve two purposes: outlier detection (above) and feature scaling for ML. Many ML algorithms — SVM, KNN, PCA, logistic regression — require features on the same scale. Z-score standardisation achieves this.

// Z-score standardisation (Standard Scaler)
z = (x − μ) / σ Result: mean = 0, SD = 1 for every feature
// After scaling: a z = +2 on price_inr and z = +2 on delivery_days both mean "2 standard deviations above average" — directly comparable.
Worked Example · Standardising Kartify features for ML
Problem: KNN model uses price_inr (range ₹200–₹45,000) and delivery_days (range 1–15). The price feature dominates distance calculations.
price_inr: μ = ₹1,800, σ = ₹3,200. After scaling: range becomes roughly −0.5 to +13.5 z-units
delivery_days: μ = 3.8, σ = 2.1. After scaling: range becomes roughly −1.3 to +5.3 z-units
After StandardScaler: both features have μ=0, σ=1 — KNN distances now equally weighted across both
Without scaling, a ₹1,000 price difference completely swamps a 1-day delivery difference. StandardScaler ensures Kartify's KNN recommender weighs price and delivery equally (or as intended).
📌 StandardScaler vs MinMaxScaler

StandardScaler (z-score) is robust to outliers affecting scale — it uses mean and SD. Use it when you want to preserve the distribution shape and outliers are meaningful. MinMaxScaler compresses everything to [0,1] but is highly sensitive to outliers — one ₹89,000 order will compress all other prices near 0. For Kartify's skewed price data: StandardScaler after log-transform is the standard pipeline.

Python — Complete Percentile & Outlier Pipeline

Python · numpy + scipy + sklearn · Kartify Percentile Pipeline 
import numpy as np
import pandas as pd
from scipy import stats
from sklearn.preprocessing import StandardScaler

df = pd.read_csv('kartify_orders.csv')
col = df['delivery_days']

# ── 1. FIVE-NUMBER SUMMARY ──────────────────────────────
q1   = np.percentile(col, 25)
med  = np.percentile(col, 50)
q3   = np.percentile(col, 75)
iqr  = q3 - q1
p90  = np.percentile(col, 90)   # SLA claim threshold
p99  = np.percentile(col, 99)   # Worst-case

print(f"Q1={q1:.1f}d  Median={med:.1f}d  Q3={q3:.1f}d  IQR={iqr:.1f}d")
print(f"P90={p90:.1f}d  P99={p99:.1f}d")
print(f"SLA claim: '90% delivered in {p90:.0f} days'")

# ── 2. IQR OUTLIER DETECTION ───────────────────────────
lo_fence = q1 - 1.5 * iqr
hi_fence = q3 + 1.5 * iqr
outliers = df[(col < lo_fence) | (col > hi_fence)]
print(f"\nOutliers (IQR method): {len(outliers)} orders ({len(outliers)/len(df)*100:.1f}%)")

# ── 3. Z-SCORE OUTLIER DETECTION ───────────────────────
z_scores = np.abs(stats.zscore(col))
z_outliers = df[z_scores > 3]
print(f"Outliers (|z|>3 method): {len(z_outliers)} orders")

# ── 4. MODIFIED Z-SCORE (for skewed data) ──────────────
def modified_zscore(x):
    med = np.median(x)
    mad = np.median(np.abs(x - med))
    return 0.6745 * (x - med) / (mad + 1e-9)

mz = np.abs(modified_zscore(df['price_inr']))  # use for skewed price
mz_outliers = df[mz > 3.5]
print(f"Price outliers (modified z): {len(mz_outliers)} orders")

# ── 5. STANDARDISATION FOR ML ──────────────────────────
scaler = StandardScaler()
features = ['log_price', 'delivery_days', 'discount_pct']
df['log_price'] = np.log1p(df['price_inr'])
df_scaled = scaler.fit_transform(df[features])
# Now all features: mean=0, std=1. Ready for KNN, SVM, PCA.

Module 1.5 — What You Now Know
  • The Pth percentile is the value below which P% of observations fall — Kartify's "90% delivered in 6 days" is a P90 claim, not a mean claim
  • Quartiles (Q1, Q2, Q3) divide data into four equal parts; IQR = Q3 − Q1 = middle 50% spread
  • A box plot encodes the five-number summary: whisker-Q1-median-Q3-whisker, with outliers plotted individually
  • Median line position inside the box reveals skewness: near Q1 → right-skewed; near Q3 → left-skewed; centered → symmetric
  • Tukey fences (Q1−1.5×IQR, Q3+1.5×IQR) are the standard non-parametric outlier detection method — no distribution assumption required
  • Z-score outlier detection assumes normality — unreliable for skewed data because the mean and SD are already distorted by outliers
  • Modified Z-score uses median and MAD instead of mean and SD — robust for skewed or small-sample data like per-seller return rates
  • Outliers may be data errors (correct/remove), legitimate values (keep, model separately), or business signals (flag, investigate)
  • StandardScaler transforms features to mean=0, SD=1 — required before KNN, SVM, PCA. MinMaxScaler is sensitive to outliers
  • The P90 delivery metric Meera needed was answered in 2 seconds with np.percentile(delivery_days, 90)
