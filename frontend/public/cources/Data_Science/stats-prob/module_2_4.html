// Section 1

Bernoulli — The Atom of Randomness

The simplest random variable possible: a single trial, two outcomes — "success" ($X = 1$) or "failure" ($X = 0$). Every other discrete distribution in this module is built from Bernoullis.

Bernoulli($p$) · PMF, mean, variance
$$p_X(x) = p^x (1-p)^{1-x} \text{ for } x \in \{0,1\}, \qquad E[X] = p, \qquad \mathrm{Var}(X) = p(1-p)$$
Deriving mean and variance
1
$E[X] = 0 \cdot (1-p) + 1 \cdot p = p$. Direct PMF sum — only two terms.
2
$E[X^2] = 0^2(1-p) + 1^2 p = p$. Because $X \in \{0,1\}$, $X^2 = X$ — a Bernoulli special fact.
3
$\mathrm{Var}(X) = E[X^2] - (E[X])^2 = p - p^2 = p(1-p)$. Maximized at $p = 0.5$; minimized at $p = 0$ or $p = 1$ (no uncertainty).
Kartify · is this order fraud?
Setup. Let $X_i = 1$ if order $i$ is fraud, $0$ otherwise. With base rate $p = 0.01$: $X_i \sim \text{Bernoulli}(0.01)$.
Per-order stats. $E[X_i] = 0.01$, $\mathrm{Var}(X_i) = 0.01 \times 0.99 = 0.0099$, $\sigma_{X_i} \approx 0.0995$.
Why it matters. Every fraud classifier in production is ultimately predicting $E[X_i \mid \text{features}]$ — the conditional Bernoulli probability. Logistic regression, XGBoost, neural binary classifiers — all are outputting $P(X_i = 1 \mid \vec{x})$.

Binomial — Sum of i.i.d. Bernoullis

Take $n$ independent Bernoulli($p$) trials. Count how many succeed. That count is Binomial.

Binomial($n$, $p$) · PMF, mean, variance
$$p_X(k) = \binom{n}{k} p^k (1-p)^{n-k}, \quad k \in \{0, 1, \ldots, n\}, \qquad E[X] = np, \qquad \mathrm{Var}(X) = np(1-p)$$
Why the PMF has this form
1
A specific outcome with $k$ successes and $n-k$ failures in any fixed order has probability $p^k(1-p)^{n-k}$ by independence.
2
The number of orderings producing exactly $k$ successes is $\binom{n}{k}$ — combinations of which $k$ trials succeed.
3
All such orderings are disjoint events, so by Axiom A3: $P(X = k) = \binom{n}{k} p^k (1-p)^{n-k}$. $\blacksquare$
4
For mean: $X = X_1 + X_2 + \ldots + X_n$ where each $X_i \sim \text{Bernoulli}(p)$. By linearity: $E[X] = np$. (Proved in 2.7 — linearity holds even without independence.)
5
For variance: $\mathrm{Var}(X) = \sum_i \mathrm{Var}(X_i) = np(1-p)$. This step requires independence — non-independent sums need covariance terms.

Kartify — the Delhi return spike revisited

The complete Binomial analysis of Rohan's question
Model. $X$ = returns in 3,000 Delhi orders. Under the null (no change), $X \sim \text{Binomial}(3000, 0.08)$.
Expected. $E[X] = 3000 \times 0.08 = 240$. $\mathrm{Var}(X) = 3000 \times 0.08 \times 0.92 = 220.8$. $\sigma_X = \sqrt{220.8} \approx 14.86$.
Observed. 420 returns. Deviation from mean: $420 - 240 = 180 = 12.1\sigma$.
p-value. $P(X \ge 420) = \sum_{k=420}^{3000} \binom{3000}{k} 0.08^k \cdot 0.92^{3000-k}$.
Computed. $\approx 6.4 \times 10^{-38}$. 12 standard deviations above the mean.
Conclusion. Confirms Module 2.1's answer with the proper Binomial framing. A 12-sigma event is — in any serious statistical sense — not a random fluctuation. The Delhi return rate genuinely changed.

Geometric — Trials Until First Success

Flip a biased coin until you get heads. How many flips? Ship Kartify orders until the first fraud. How many orders? That count is Geometric.

Geometric($p$) · PMF, mean, variance · (success on trial form)
$$p_X(k) = (1-p)^{k-1} p, \quad k \in \{1, 2, 3, \ldots\}, \qquad E[X] = \frac{1}{p}, \qquad \mathrm{Var}(X) = \frac{1-p}{p^2}$$
⚠ Two Geometric conventions — read carefully

Trial form ($k \ge 1$): $X$ is the trial on which the first success occurs. Used above. $E[X] = 1/p$.

Failures form ($k \ge 0$): $X$ is the number of failures before the first success. $E[X] = (1-p)/p$.

scipy.stats.geom uses the trial form. NumPy's np.random.geometric also uses trial form. Wikipedia sometimes uses failures form. When reading papers: always check which convention.

Deriving the mean (trial form) — via series
1
$E[X] = \sum_{k=1}^{\infty} k(1-p)^{k-1} p = p \sum_{k=1}^{\infty} k q^{k-1}$ where $q = 1-p$.
2
Using the identity $\sum_{k=1}^{\infty} k q^{k-1} = \dfrac{1}{(1-q)^2}$. Derivative of geometric series trick: $\sum q^k = 1/(1-q)$, differentiate both sides in $q$.
3
$E[X] = p \cdot \dfrac{1}{(1-q)^2} = p \cdot \dfrac{1}{p^2} = \dfrac{1}{p}$. $\blacksquare$
Kartify · orders until the next fraud
Setup. Fraud rate $p = 0.01$. Let $X$ = number of orders until (and including) the next fraudulent one.
$E[X] = 1/0.01 = 100$. On average, 100 orders between consecutive frauds.
$\sigma_X = \sqrt{(1-0.01)/0.01^2} = \sqrt{9900} \approx 99.5$. Huge variance — highly variable wait times.
$P(X > 200)$ = $(1-p)^{200} = 0.99^{200} \approx 0.134$. A 13% chance we see no fraud in the next 200 orders.
Kartify insight. The long wait between frauds doesn't mean the system is safe — Geometric is memoryless (below). Every single order has the same 1% fraud probability regardless of history.
◆ Memoryless property — only the Geometric has it (discrete)

$P(X > s + t \mid X > s) = P(X > t)$. Translation: "given we've had no fraud in the last $s$ orders, the probability we'll get through the next $t$ without fraud is the same as starting fresh." This is why gambler's-fallacy reasoning fails — "we're due for a fraud" is wrong; the next order has rate $p$ no matter what came before.

// Section 4

Negative Binomial — Trials Until the $r$-th Success

Geometric asks "how long until 1 success?" Negative Binomial asks "how long until $r$ successes?" It generalizes Geometric.

Negative Binomial($r$, $p$) · number of failures before $r$-th success
$$p_X(k) = \binom{k + r - 1}{k} p^r (1-p)^k, \quad k \in \{0, 1, 2, \ldots\}, \qquad E[X] = \frac{r(1-p)}{p}, \qquad \mathrm{Var}(X) = \frac{r(1-p)}{p^2}$$
Kartify · emails to reach 100 coupon redemptions
Setup. Promo-email redemption rate $p = 0.12$. Marketing needs 100 redemptions for the campaign.
Model. $X$ = failures before 100th redemption ~ NegBin$(r = 100, p = 0.12)$.
Expected failures. $E[X] = 100 \cdot 0.88 / 0.12 = 733$. So expect ~733 failures before 100 successes — total ~833 emails.
Variance. $\mathrm{Var}(X) = 100 \cdot 0.88 / 0.12^2 = 6111$. $\sigma \approx 78$. So the total ranges roughly 833 ± 78 emails.
Answer. Plan for sending ~900-1000 emails to very-likely hit 100 redemptions. This is the concrete planning number Marketing needs for budget.
⚡ Why Negative Binomial shows up in ML — overdispersed counts

Poisson (next section) has $E[X] = \mathrm{Var}(X)$ — mean equals variance. Real-world count data is often overdispersed — variance much greater than mean. Negative Binomial is the standard fix: $\mathrm{Var}(X) = \mu + \mu^2/r$ under the mean-dispersion parameterization. Kartify's daily support ticket count? Overdispersed Poisson behavior. NegBin regression handles it cleanly.

Poisson — Counting Rare Events in Fixed Time

The king of count distributions. Whenever events happen independently at a steady average rate $\lambda$, the number in a unit of time (or area, or space) is Poisson.

Poisson($\lambda$) · PMF, mean, variance
$$p_X(k) = \frac{\lambda^k e^{-\lambda}}{k!}, \quad k \in \{0, 1, 2, \ldots\}, \qquad E[X] = \lambda, \qquad \mathrm{Var}(X) = \lambda$$
Poisson as the limit of Binomial — the derivation that explains everything
1
Consider Binomial$(n, p)$ where $n \to \infty$, $p \to 0$, but $np \to \lambda$ (a constant).
2
$\binom{n}{k} p^k (1-p)^{n-k} = \dfrac{n!}{k!(n-k)!} \left(\dfrac{\lambda}{n}\right)^k \left(1 - \dfrac{\lambda}{n}\right)^{n-k}$ with $p = \lambda/n$.
3
As $n \to \infty$: $\dfrac{n!}{n^k (n-k)!} \to 1$ and $(1 - \lambda/n)^n \to e^{-\lambda}$ and $(1 - \lambda/n)^{-k} \to 1$.
4
Combining: $\binom{n}{k} p^k (1-p)^{n-k} \to \dfrac{\lambda^k e^{-\lambda}}{k!}$. $\blacksquare$ Poisson = Binomial in the "many trials, rare success" regime.
Kartify · support tickets per hour
Data. Kartify receives ~12 support tickets per hour. Model: $X \sim$ Poisson($\lambda = 12$).
Mean and variance. $E[X] = 12$, $\mathrm{Var}(X) = 12$, $\sigma = \sqrt{12} \approx 3.46$. Typical range: 8.5 to 15.5.
Q1: $P(X = 0)$ — probability of a quiet hour? $e^{-12} \approx 6.1 \times 10^{-6}$. Essentially never.
Q2: $P(X \ge 20)$ — surge probability? $1 - F_X(19) \approx 0.021$. About once per 50 hours = ~once per shift-week.
Kartify decision. Staff support for 15 concurrent tickets (mean + 1σ) handles ~84% of hours. For 99% coverage, staff 20. Poisson gives the number; the SLA decides the percentile.
Poisson process — what Poisson counts are for
Rare, independent, constant rate
Events happen independently over time (or space) at a steady rate $\lambda$ per unit. Count of events in any fixed unit = Poisson. Gaps between events = Exponential (next module).
Additivity
Sums of Poissons are Poisson
If $X \sim$ Pois($\lambda_1$), $Y \sim$ Pois($\lambda_2$), independent, then $X + Y \sim$ Pois($\lambda_1 + \lambda_2$). Kartify: combine Mumbai + Delhi ticket counts. The rates just add.
Thinning
Split a Poisson by category
If events occur Poisson($\lambda$) and each event is type A with prob $p$ independently, then type-A events are Poisson($\lambda p$), type-B are Poisson($\lambda(1-p)$), independent. Useful for channel-split modeling.
When Poisson fails
Bursty or overdispersed data
Kartify's Monday-morning ticket surges violate "constant rate." Real counts often have $\mathrm{Var} > \mathrm{mean}$. Use Negative Binomial — or split Poisson by hour-of-day.

Choosing the Right Distribution — A Decision Flow

Business questionPatternDistributionParameters
Single yes/no event (is this fraud?)one trial, binaryBernoulli($p$)$p$ = success rate
How many of $n$ fixed trials succeed?fixed trials, counting successesBinomial($n, p$)$n$, $p$
How many trials until first success?waiting for the first successGeometric($p$)$p$
How many trials until the $r$-th success?waiting for multiple successesNegBin($r, p$)$r$, $p$
Count of rare events in a fixed intervalconstant rate $\lambda$, many opportunitiesPoisson($\lambda$)$\lambda$ = rate
The decision rule in three questions
(1) Is the outcome binary? Yes → Bernoulli-family. No → not in this module.
(2) What are we counting? Successes in $n$ trials → Binomial. Trials until success → Geometric/NegBin. Events in a window → Poisson.
(3) Can we fix $n$ in advance? Yes → Binomial. No → Poisson (random event count). This three-question filter handles essentially every discrete business question.

Python — All Five Distributions in Code

python · Bernoulli and Binomial — Kartify Delhi returns
from scipy.stats import bernoulli, binom
import numpy as np

# Single Bernoulli — one Kartify order, is it fraud?
p_fraud = 0.01
X = bernoulli(p_fraud)
print(f"P(fraud) = {X.pmf(1)}, mean = {X.mean()}, var = {X.var():.5f}")

# Binomial — Delhi return-spike full analysis
n, p = 3000, 0.08
Y = binom(n, p)
print(f"E[Y] = {Y.mean()}, Var[Y] = {Y.var():.1f}, sigma = {Y.std():.2f}")

# How many sigma is the observed 420?
observed = 420
sigmas = (observed - Y.mean()) / Y.std()
print(f"Delhi observed {observed} returns = {sigmas:.2f} sigmas from mean")

# p-value — probability of 420+ under null
p_value = 1 - Y.cdf(419)
print(f"P(Y ≥ 420 | null) = {p_value:.3e}")
python · Geometric and Negative Binomial — Kartify fraud spacing & campaign reach
from scipy.stats import geom, nbinom

# Geometric — orders until next fraud
p = 0.01
G = geom(p)                                   # trial-form: X=1 means fraud on first order
print(f"E[orders until fraud] = {G.mean()}")       # 100
print(f"P(no fraud in first 200 orders) = {1 - G.cdf(200):.3f}")   # 0.134
print(f"P(fraud within first 50 orders) = {G.cdf(50):.3f}")   # 0.395

# Negative Binomial — emails until 100 redemptions
r, p_redeem = 100, 0.12
NB = nbinom(r, p_redeem)                      # counts FAILURES before r-th success
print(f"E[failures before 100 redeems] = {NB.mean():.0f}")   # 733
print(f"sigma = {NB.std():.1f}")                              # ~78
print(f"Expect to send total ~{NB.mean() + r:.0f} emails")   # 833
python · Poisson — Kartify support tickets + the binomial→Poisson limit
from scipy.stats import poisson, binom
import numpy as np

# Kartify support ticket modeling — 12 per hour
lam = 12
T = poisson(lam)
print(f"P(quiet hour: X=0)     = {T.pmf(0):.2e}")       # 6.1e-06
print(f"P(surge: X ≥ 20)       = {1 - T.cdf(19):.4f}")   # 0.0213
print(f"99th percentile staffing = {T.ppf(0.99):.0f} concurrent tickets")

# Verify the Binomial → Poisson limit
# Binomial(n=100, p=0.12) vs Poisson(lambda=12) should be very close
k = np.arange(0, 25)
bin_pmf = binom.pmf(k, 100, 0.12)
poi_pmf = poisson.pmf(k, 12)
max_diff = np.abs(bin_pmf - poi_pmf).max()
print(f"Max |Binomial − Poisson| = {max_diff:.4f}  (small: limit holds)")
