// Section 1

Uniform — The Flat Baseline

Uniform$(a, b)$ · PDF, CDF, moments
$$f_X(x) = \frac{1}{b - a} \text{ for } x \in [a, b], \qquad F_X(x) = \frac{x - a}{b - a}, \qquad E[X] = \frac{a + b}{2}, \qquad \mathrm{Var}(X) = \frac{(b - a)^2}{12}$$
Kartify · random checkout time during the day
Setup. If we sample a random checkout minute in a 24-hour day: $X \sim$ Uniform$(0, 1440)$ minutes.
Mean. $E[X] = 720$ minutes = 12:00 noon.
$P(\text{checkout in evening rush, 18:00–21:00})$. $F(1260) - F(1080) = (1260 - 1080)/1440 = 180/1440 = 0.125$.
Reality check. Real Kartify checkouts are not uniform — they cluster in evenings. Uniform is the null: "if no pattern, this is what we'd expect." Deviation from Uniform reveals business patterns.
⚡ Uniform as the sampler's workhorse

Every random number generator in every programming language starts with Uniform$(0,1)$. All other distributions are generated by transforming uniforms — the inverse-CDF method: if $U \sim$ Uniform$(0,1)$, then $X = F^{-1}(U)$ has CDF $F$. This is why Uniform is the atom of simulation.

Exponential — Continuous Wait Times

Exponential$(\lambda)$ · PDF, CDF, moments
$$f_T(t) = \lambda e^{-\lambda t} \text{ for } t \ge 0, \qquad F_T(t) = 1 - e^{-\lambda t}, \qquad E[T] = \frac{1}{\lambda}, \qquad \mathrm{Var}(T) = \frac{1}{\lambda^2}$$
Deriving the mean via integration by parts
1
$E[T] = \int_0^{\infty} t \lambda e^{-\lambda t} dt$.
2
Integration by parts: $u = t$, $dv = \lambda e^{-\lambda t} dt$. Then $du = dt$, $v = -e^{-\lambda t}$.
3
$E[T] = [-t e^{-\lambda t}]_0^{\infty} + \int_0^{\infty} e^{-\lambda t} dt = 0 + \left[\dfrac{-1}{\lambda}e^{-\lambda t}\right]_0^{\infty} = \dfrac{1}{\lambda}$. $\blacksquare$
Kartify · wait time until next late delivery
Setup. Late deliveries arrive as a Poisson process at rate $\lambda = 3/\text{hour}$. Inter-arrival times $T \sim$ Exp$(3)$.
Mean wait. $E[T] = 1/3$ hour = 20 minutes.
$P(T > 1$ hour$)$. $e^{-3 \cdot 1} = e^{-3} \approx 0.0498$. About 5% chance of an hour-long quiet stretch.
Memoryless. $P(T > s + t \mid T > s) = e^{-\lambda t}$ — same as starting fresh. Like Geometric, Exponential has no "memory" of elapsed time.
◆ The Exponential ↔ Poisson connection

If events arrive as a Poisson process at rate $\lambda$, the count in a unit time is Poisson($\lambda$) and the gap between consecutive events is Exp($\lambda$). Counts and waits are two views of the same process. This duality shows up constantly: server requests per minute (Poisson) vs. seconds between requests (Exp). Same phenomenon, two distributions.

Normal — The Most Important Distribution

The Normal (Gaussian) is the single most important distribution in statistics. Revenue, heights, measurement errors, averages of large samples — all approximately Normal, by the Central Limit Theorem (Module 4.2). Every frequentist confidence interval, every Z-score, every Kalman filter rests on this shape.

Normal$(\mu, \sigma^2)$ · PDF, moments
$$f_X(x) = \frac{1}{\sigma \sqrt{2\pi}} \exp\!\left(-\frac{(x - \mu)^2}{2\sigma^2}\right), \qquad E[X] = \mu, \qquad \mathrm{Var}(X) = \sigma^2$$
Bell curve
Symmetric, unimodal, infinite support
Mean = median = mode = $\mu$. Thin tails fall off exponentially fast, but never quite hit zero. Any $x \in \mathbb{R}$ is possible — even negative revenue if $\mu$ is low enough and $\sigma$ is large.
68-95-99.7 rule
Mass within 1σ, 2σ, 3σ
$P(|X - \mu| \le \sigma) \approx 0.6827$; within 2σ: $\approx 0.9545$; within 3σ: $\approx 0.9973$. Memorize these — they're how you eyeball Normal CDFs in meetings.
Standard Normal
$Z = (X - \mu)/\sigma \sim N(0, 1)$
Standardization lets you use a single table (or scipy.stats.norm) for every Normal. $P(X \le x) = \Phi((x - \mu)/\sigma)$ where $\Phi$ is the standard Normal CDF.
Linear combinations
$aX + bY \sim$ Normal, if X, Y Normal
Sums, differences, and scalar multiples of independent Normals are Normal. This is unique to the Normal family and makes it the workhorse for regression, Kalman filters, and every Gaussian process.
Kartify · tomorrow's revenue as Normal
Setup. Daily revenue $R \sim$ Normal$(\mu = 45, \sigma = 8)$ (₹ lakh). This approximation holds by CLT because revenue is a sum over many independent order contributions.
Q: $P(R > 60)$ — great day probability? Z-score: $(60 - 45)/8 = 1.875$. $P(Z > 1.875) = 1 - \Phi(1.875) \approx 0.0304$. ~3% of days.
Q: 95% confidence band. $\mu \pm 1.96\sigma = 45 \pm 15.68 \in [29.3, 60.7]$. 19 of 20 days will fall here.
Q: $P(R < 30)$ — crisis day? Z $= -1.875$; by symmetry, same $\approx 0.0304$. About once per 33 days.
Ops planning. Budget assuming $\mu = 45$; reserve capacity for $\mu + 2\sigma = 61$ (97.5th percentile) busy days; flag investigation if $R < \mu - 2\sigma = 29$ (2.5th percentile).
Interactive Normal — shift $\mu$, stretch $\sigma$

Gamma — Sum of Exponentials, Generalized

Exponential models the wait to the first event. Gamma generalizes: wait to the $k$-th event (shape parameter $k$) at rate $\lambda$. It's the continuous cousin of Negative Binomial.

Gamma$(k, \lambda)$ · PDF, mean, variance · (shape-rate parameterization)
$$f_X(x) = \frac{\lambda^k}{\Gamma(k)} x^{k-1} e^{-\lambda x}, \quad x > 0, \qquad E[X] = \frac{k}{\lambda}, \qquad \mathrm{Var}(X) = \frac{k}{\lambda^2}$$
⚠ Two Gamma parameterizations — check before plugging in

Shape-rate $(k, \lambda)$: used in Evans & Rosenthal and most theory. $E = k/\lambda$.

Shape-scale $(k, \theta)$ with $\theta = 1/\lambda$: used by scipy.stats.gamma. $E = k\theta$.

Both describe the same distribution; just confirm which your library expects. Conversion: $\theta = 1/\lambda$.

Kartify · time until the 10th support ticket
Setup. Tickets arrive as a Poisson process at rate $\lambda = 12/\text{hour}$. Time until $k = 10$ tickets: $T \sim$ Gamma$(k=10, \lambda=12)$.
Mean. $E[T] = k/\lambda = 10/12 = 0.833$ hours $= 50$ minutes.
Variance. $\mathrm{Var}(T) = k/\lambda^2 = 10/144 = 0.0694$ hr². $\sigma \approx 0.263$ hr = 15.8 min.
Kartify answer. Expect the 10th ticket ~50 minutes into the shift, give or take 16 minutes. Useful for staffing the 10-ticket mark with on-call engineers.
⚡ Gamma is the conjugate prior for Poisson rate — Bayesian ML connection

In Bayesian statistics, if $\lambda$ has a Gamma prior and you observe Poisson data, the posterior on $\lambda$ is also Gamma. This "conjugacy" means you can update analytically without MCMC. Every Bayesian tutorial on Poisson regression reaches for Gamma — and it's the same Gamma as the "wait for $k$ events" distribution here.

// Section 5

Beta — Probabilities of Probabilities

The only distribution in this module with bounded support $[0, 1]$. That makes Beta perfect for modeling probabilities themselves — return rates, conversion rates, click-through probabilities. Given data, how uncertain are we about the true rate? Beta answers.

Beta$(\alpha, \beta)$ · PDF, mean, variance
$$f_X(x) = \frac{x^{\alpha-1}(1-x)^{\beta-1}}{B(\alpha, \beta)}, \quad x \in [0, 1], \qquad E[X] = \frac{\alpha}{\alpha + \beta}, \qquad \mathrm{Var}(X) = \frac{\alpha \beta}{(\alpha + \beta)^2 (\alpha + \beta + 1)}$$

$B(\alpha, \beta)$ is the Beta function — a normalization constant. Think of $\alpha$ and $\beta$ as pseudo-counts: $\alpha$ prior successes, $\beta$ prior failures. Larger totals → tighter distribution.

Kartify · the Delhi return rate — Bayesian estimate
Setup. Observed 420 returns in 3,000 orders. What's the posterior on the true rate $\theta$?
Prior (weak). $\theta \sim$ Beta$(1, 1)$ = Uniform$[0, 1]$. "We know nothing."
Posterior (conjugate update). $\theta \mid \text{data} \sim$ Beta$(1 + 420, 1 + 2580) = $ Beta$(421, 2581)$.
Mean. $E[\theta \mid \text{data}] = 421/3002 \approx 0.1403$ — almost exactly the observed rate.
Std. $\sigma \approx \sqrt{0.1403 \cdot 0.8597 / 3003} = 0.00634$. 95% CI: $[0.128, 0.153]$.
Conclusion. Very confident the true Delhi return rate is 12.8% – 15.3% — no overlap with the 8% baseline. This is a rigorous statement of "the rate has changed," more informative than the p-value alone.
◆ Beta is Bernoulli's conjugate — the Bayesian workflow

If $\theta$ has prior Beta$(\alpha, \beta)$ and you observe $n$ Bernoulli trials with $s$ successes, the posterior is Beta$(\alpha + s, \beta + n - s)$. Just add counts to the parameters — no calculus. This is the cleanest conjugate pair in all of Bayesian statistics. Kartify A/B tests, Thompson Sampling, Kaplan-Meier: all Beta under the hood.

The Distribution Map — Relationships

DistributionSupportMeanVarianceKartify use
Uniform$(a, b)$$[a, b]$$(a+b)/2$$(b-a)^2/12$null baseline, simulation seed
Exponential$(\lambda)$$[0, \infty)$$1/\lambda$$1/\lambda^2$time between late deliveries
Normal$(\mu, \sigma^2)$$\mathbb{R}$$\mu$$\sigma^2$daily revenue, averages
Gamma$(k, \lambda)$$(0, \infty)$$k/\lambda$$k/\lambda^2$time to 10th ticket

The relationship web — worth memorizing
Exponential = Gamma$(k=1)$. One-event wait is a special case of $k$-event wait.
Gamma = sum of $k$ i.i.d. Exponentials. Direct generalization.
Normal = sum of many i.i.d. anything (by CLT — Module 4.2).
Beta and Gamma are conjugate priors — Beta for Bernoulli/Binomial rates, Gamma for Poisson rates.
Uniform = Beta$(1, 1)$ — the "knowing nothing" prior.
These are not coincidences — they reveal the underlying probabilistic machinery.

Python — All Five in Code

python · Uniform, Exponential, Gamma — Kartify event timing
from scipy.stats import uniform, expon, gamma
import numpy as np

# Uniform — random checkout minute in a 1440-min day
U = uniform(loc=0, scale=1440)
print(f"Mean checkout minute = {U.mean()}  (= 12 PM)")
print(f"P(evening rush 18-21) = {U.cdf(21*60) - U.cdf(18*60):.4f}")

# Exponential — wait for next late delivery, rate 3/hour
lam = 3.0
T = expon(scale=1/lam)                # scipy uses scale = 1/rate
print(f"Mean wait = {T.mean():.3f} hr = {T.mean()*60:.0f} min")
print(f"P(quiet hour >1h) = {1-T.cdf(1):.4f}")     # e^-3

# Gamma — time to 10th support ticket, rate 12/hour
k, lam = 10, 12
G = gamma(a=k, scale=1/lam)           # shape-scale; scale = 1/rate
print(f"Mean time to 10th ticket: {G.mean():.3f} hr = {G.mean()*60:.0f} min")
print(f"95th percentile = {G.ppf(0.95)*60:.0f} min")
python · Normal — Kartify revenue + z-scores
from scipy.stats import norm

# Daily revenue: mu=45 lakh, sigma=8 lakh
R = norm(loc=45, scale=8)

print(f"P(R > 60)   = {1 - R.cdf(60):.4f}")   # 0.0304
print(f"P(R < 30)   = {R.cdf(30):.4f}")         # 0.0304 (symmetric)
print(f"95% CI      = [{R.ppf(0.025):.1f}, {R.ppf(0.975):.1f}]")

# Verify 68-95-99.7 rule empirically via 100k samples
import numpy as np
samples = R.rvs(100_000)
for k in [1, 2, 3]:
    inside = np.mean(np.abs(samples - 45) <= k * 8)
    print(f"Within ±{k}σ: {inside:.3f}")   # ≈ 0.683 / 0.955 / 0.997
python · Beta — Bayesian posterior for Kartify Delhi return rate
from scipy.stats import beta
import numpy as np

# Prior: Beta(1,1) = Uniform — we know nothing initially
alpha_prior, beta_prior = 1, 1

# Data: 420 returns in 3000 orders
successes, failures = 420, 3000 - 420

# Posterior: Beta is conjugate for Bernoulli — just add counts
alpha_post = alpha_prior + successes
beta_post  = beta_prior  + failures
P = beta(alpha_post, beta_post)

print(f"Posterior mean = {P.mean():.4f}")              # 0.1403
print(f"Posterior std  = {P.std():.4f}")              # 0.00634
print(f"95% credible   = [{P.ppf(0.025):.4f}, {P.ppf(0.975):.4f}]")
# [0.1282, 0.1532] — does NOT contain 0.08 baseline → Delhi rate has changed

# Probability the true rate exceeds the 8% baseline
print(f"P(θ > 0.08 | data) = {1 - P.cdf(0.08):.6f}")   # ≈ 1.0 — essentially certain
