Track 3 · Random Variables & Distributions

Key Continuous
Distributions

Six shapes for real-valued data. Uniform (null baseline), Exponential (memoryless waits), Gamma (sums of exponentials), Beta (probabilities of probabilities), and the heavy-tail pair — Log-normal and Weibull — that handle price distributions, session durations, and equipment failures. Normal gets its own module (3.4).

Module 3.3 Uniform · Exponential · Gamma · Beta · Log-normal · Weibull Kartify: order values, session times, customer lifetimes Evans & Rosenthal Ch. 2.4
⚡ Kartify — The Heavy Tail That Broke the Dashboard
Wednesday. The Finance dashboard reports mean order value ₹1,840. Arjun opens the full distribution: median ₹720. The mean is 2.5× the median. Something is seriously asymmetric — a few very expensive orders are pulling the mean way above the typical order.

This is the signature of a heavy-tailed distribution. Normal and Exponential both have light tails (probability shrinks exponentially fast). Log-normal and Weibull can have heavy tails (probability shrinks more slowly, so extreme values matter). Real-world business data is heavy-tailed surprisingly often: income, order values, session durations, time-to-failure of equipment, market returns.

Getting the shape right matters for business decisions. A Normal-fitted model of order values would predict P(order > ₹100,000) = essentially zero. Log-normal-fitted would say "happens once every few thousand orders." Kartify loses money acting on the wrong tail estimate. Module 3.3 walks through six continuous distributions, closing with the two heavy-tailed shapes that Module 2 didn't cover but real data demands.
// Section 1

Uniform — The Null Baseline

Uniform$(a, b)$ · PDF, CDF, moments
$$f_X(x) = \frac{1}{b - a}, \quad F_X(x) = \frac{x - a}{b - a}, \quad E[X] = \frac{a + b}{2}, \quad \mathrm{Var}(X) = \frac{(b - a)^2}{12}$$
Kartify · random checkout hour
If checkouts were equally likely all day: $X \sim $ Uniform$(0, 1440)$ minutes. Real data shows clustering at evenings — deviation from Uniform is the business signal.
$P(\text{evening } 18–21) = (1260 - 1080)/1440 = 0.125$ if Uniform; empirically closer to 0.31. The ratio 0.31/0.125 = 2.5× quantifies the evening-rush effect.
Use Uniform as a null. If Kartify finds "30% of checkouts are in a 2-hour window" and Uniform predicts 8.3%, that's a 3.6× concentration — worth building capacity for.
⚡ Uniform is the seed of all simulation

Every RNG starts with Uniform$(0, 1)$. Inverse-CDF method (Module 3.1) converts Uniforms into any other distribution. Monte Carlo, bootstrap, MCMC initialization — all walk through Uniform first.

// Section 2

Exponential — Memoryless Waiting

Exponential$(\lambda)$ · PDF, CDF, moments
$$f_T(t) = \lambda e^{-\lambda t}, \quad F_T(t) = 1 - e^{-\lambda t}, \quad E[T] = \frac{1}{\lambda}, \quad \mathrm{Var}(T) = \frac{1}{\lambda^2}$$
Kartify · delivery time, parameter estimation
Setup. Observed 100,000 delivery times. Sample mean $\bar{t} = 18.3$ hours.
Method-of-moments estimator. $E[T] = 1/\lambda \Rightarrow \hat{\lambda} = 1/\bar{t} = 0.0546$.
Also the MLE. For Exp$(\lambda)$, the MLE happens to equal the method-of-moments estimator (proved in Track 4).
Diagnostic. Is it actually Exponential? Check: plot $-\ln(1 - \hat{F}_n(t))$ vs $t$; should be linear with slope $\lambda$. Deviations at specific durations signal non-Exp behavior (e.g., delivery-service cutoffs).
Common failure. Kartify deliveries have a "weekend lag" — Fridays have heavier tails. Pure Exponential underestimates P(T > 72h). Mixture models or Weibull often fit better.
◆ Exponential ↔ Poisson — the bridge between counts and waits

If events arrive as a Poisson process at rate $\lambda$, the count in a unit is Poisson$(\lambda)$ and the gap is Exp$(\lambda)$. Same rate, two views. Kartify: if support tickets arrive Poisson$(12/\text{hr})$, inter-ticket times are Exp$(1/12)$ hours.

// Section 3

Gamma — Sum of Exponentials, Generalized

Gamma$(k, \lambda)$ · shape-rate parameterization
$$f_X(x) = \frac{\lambda^k}{\Gamma(k)} x^{k-1} e^{-\lambda x}, \quad x > 0, \qquad E[X] = \frac{k}{\lambda}, \quad \mathrm{Var}(X) = \frac{k}{\lambda^2}$$
⚠ Two Gamma parameterizations — always check

Shape-rate $(k, \lambda)$: Evans & Rosenthal convention. $E = k/\lambda$, $\mathrm{Var} = k/\lambda^2$.

Shape-scale $(k, \theta)$ with $\theta = 1/\lambda$: scipy.stats.gamma convention. $E = k\theta$, $\mathrm{Var} = k\theta^2$.

Both describe the same family; conversion is $\theta = 1/\lambda$. Every Gamma function call should start with "which convention does this library use?"

Kartify · time to the 10th support ticket
Setup. Tickets arrive Poisson$(\lambda = 12$/hr$)$. Time to the 10th ticket $\sim$ Gamma$(k = 10, \lambda = 12)$.
Mean: $E[T] = 10/12 \approx 0.833$ hr = 50 min.
95th percentile: numerically $\approx 82$ min. Plan staff for 85 minutes; beyond that is the 5%-tail scenario.
The generalization insight. Gamma$(1, \lambda) = $ Exp$(\lambda)$. Larger $k$ = waiting for more events = tighter distribution around its mean (variance grows linearly in $k$ but mean also grows linearly — so the coefficient of variation shrinks as $1/\sqrt{k}$).
⚡ Gamma is the conjugate prior for Poisson rates

If $\lambda$ has Gamma$(\alpha, \beta)$ prior and you observe Poisson data ($n$ intervals, $s$ total events), the posterior on $\lambda$ is Gamma$(\alpha + s, \beta + n)$. Add total events to shape, add intervals to rate. Bayesian Kartify: "prior belief $\lambda \sim$ Gamma(12, 1); observe 72 tickets in 6 hours; posterior $\lambda \sim$ Gamma(84, 7)" — posterior mean $84/7 = 12$. Same as before, but now with a full uncertainty distribution.

// Section 4

Beta — Probabilities of Probabilities

Beta$(\alpha, \beta)$ · the probability distribution for a probability
$$f_X(x) = \frac{x^{\alpha-1}(1-x)^{\beta-1}}{B(\alpha, \beta)}, \quad x \in [0, 1]$$
$$E[X] = \frac{\alpha}{\alpha + \beta}, \quad \mathrm{Var}(X) = \frac{\alpha \beta}{(\alpha + \beta)^2 (\alpha + \beta + 1)}$$

Bounded support $[0, 1]$ + flexibility to be uniform, unimodal, U-shaped, or J-shaped. Beta is the go-to for modeling proportions themselves: return rates, conversion rates, fraud rates.

Kartify · Bayesian belief about the Delhi return rate
Prior. Beta$(1, 1)$ = Uniform on $[0, 1]$ — "we know nothing."
Data. 420 returns in 3,000 orders.
Posterior (Beta conjugacy). Beta$(1 + 420, 1 + 2580) = $ Beta$(421, 2581)$.
Posterior mean. $421 / 3002 = 0.1403$. Matches the frequentist MLE.
95% credible interval. $[0.128, 0.153]$. This is a probability statement about $\theta$ itself.
Bayesian vs frequentist. Frequentist MLE: point estimate $\hat\theta = 0.140$ + sampling-distribution SE. Bayesian: full posterior distribution on $\theta$. Both yield similar numerical intervals with weak priors and large $n$; interpretations differ (Track 4).
// Section 5

Log-normal — When $\log X$ is Normal

Log-normal emerges whenever a quantity is the product of many independent positive factors. The central limit theorem says sums → Normal; its multiplicative analog says products → Log-normal (since $\log$ of product = sum of logs).

Log-normal$(\mu, \sigma^2)$ · parameters are of the log-scale
$$f_X(x) = \frac{1}{x \sigma \sqrt{2\pi}} \exp\!\left(-\frac{(\ln x - \mu)^2}{2\sigma^2}\right), \quad x > 0$$
$$E[X] = e^{\mu + \sigma^2/2}, \quad \mathrm{Var}(X) = (e^{\sigma^2} - 1) e^{2\mu + \sigma^2}, \quad \text{Median} = e^\mu$$
⚠ Mean vs median for Log-normal — the Kartify trap

Log-normal mean is ALWAYS bigger than median: $E[X] / \text{median} = e^{\sigma^2/2}$. For Kartify order values with $\sigma = 1.2$: mean/median = $e^{0.72} = 2.05$. If dashboard shows mean ₹1,840 and median ₹720, that ratio 2.56 suggests $\sigma^2/2 \approx 0.94$, i.e., $\sigma \approx 1.37$. The distribution has serious right-skew. Making business decisions off the mean alone (instead of median) over-promises — especially for "typical customer" narratives.

Kartify · fitting Log-normal to order values
Setup. Sample of 10,000 order values. Sample mean ₹1,840, sample median ₹720.
Transform. $Y = \ln X$ should be approximately Normal. Compute $\bar{Y}$ and $s_Y$.
Illustrative values. $\bar{Y} = 6.58$ (so median $= e^{6.58} \approx 720$) and $s_Y = 1.37$ (so Log-normal CV is high).
MLE. $\hat\mu = \bar Y = 6.58$; $\hat\sigma = s_Y = 1.37$.
Diagnostic. Q-Q plot of $\ln x_i$ against Normal quantiles. If linear, Log-normal fits. Deviation in the upper tail = even-heavier-tail distribution needed (Pareto).
Useful prediction. $P(X > 10{,}000) = 1 - \Phi((\ln 10000 - 6.58)/1.37) = 1 - \Phi(1.91) \approx 0.028$. So ~2.8% of orders exceed ₹10,000. This is Kartify's "high-value" segment size — crucial for checkout UX and fraud thresholds.
// Section 6

Weibull — Flexible Waits with Shape Control

Weibull generalizes Exponential with a shape parameter that controls whether the hazard rate increases, decreases, or stays constant over time. It's the default for reliability engineering (time-to-failure) and survival analysis (customer lifetime).

Weibull$(k, \lambda)$ · shape $k$, scale $\lambda$
$$f_T(t) = \frac{k}{\lambda}\!\left(\frac{t}{\lambda}\right)^{k-1}\! e^{-(t/\lambda)^k}, \quad F_T(t) = 1 - e^{-(t/\lambda)^k}, \quad t \ge 0$$
$$E[T] = \lambda \cdot \Gamma(1 + 1/k), \quad \mathrm{Var}(T) = \lambda^2 \cdot \big[\Gamma(1 + 2/k) - \Gamma(1 + 1/k)^2\big]$$
Shape $k = 1$
Becomes Exponential
Constant hazard. Time-to-failure is memoryless. Used for electronic components in their "useful life" phase.
Shape $k < 1$
Decreasing hazard — "infant mortality"
Failures concentrate early. Kartify: new-customer churn — higher probability of leaving in first weeks, drops afterward.
Shape $k > 1$
Increasing hazard — "wear-out"
Failure risk grows with age. Kartify warehouse conveyor belts: aging parts fail more frequently. $k = 2$ is Rayleigh; $k = 3.5$ approximately Normal-like.
Shape $k$ very large
Concentrates near $\lambda$
Approaches a Dirac mass at $\lambda$. Models "designed to fail at exactly $\lambda$" — like warranty-cliff electronics.
Kartify · customer lifetime (time to churn)
Setup. Kartify wants to model time from signup to first 90-day inactivity. Historical data shows new-user churn is concentrated in first 4 weeks, then drops.
Fit. Maximum likelihood estimate on lifetime data yields $\hat{k} = 0.82$ (decreasing hazard), $\hat{\lambda} = 180$ days.
Interpretation. $k < 1$ — "infant mortality" pattern. New users churn fast; survivors settle in.
Mean lifetime. $\hat\lambda \cdot \Gamma(1 + 1/\hat k) = 180 \cdot \Gamma(2.22) \approx 180 \cdot 1.15 = 207$ days.
Business action. The $k < 1$ finding tells Kartify to front-load onboarding effort — the hazard is highest in the first weeks. "Welcome series" emails, tutorial prompts, discount offers should be concentrated early, not spread evenly.

Choosing a Continuous Distribution — The Decision Tree

Data propertyRight distributionKartify example
Bounded interval, flatUniform$(a, b)$Random arrival time (null baseline)
Non-negative, single-peak decay, memorylessExponential$(\lambda)$Inter-ticket wait time
Non-negative, flexible shape, sum of ExpGamma$(k, \lambda)$Time to $k$-th ticket
Bounded $[0, 1]$Beta$(\alpha, \beta)$Conversion rate belief
Product of many positive factors / right-skewedLog-normal$(\mu, \sigma^2)$Order value, session duration
Time to failure with shape flexibilityWeibull$(k, \lambda)$Customer lifetime, part failure
Heavy tail detection — the first thing to check
Compare mean and median. If mean $\gg$ median (ratio > 1.5×), you have right-skew and should consider Log-normal or Weibull. If the maximum value is orders of magnitude above the mean, the tail may be even heavier than Log-normal — consider Pareto (for data with "80/20" or "99/1" concentration). Normal, Exponential, and Gamma all have light tails that often fail to capture real-world extremes.

Python — Continuous Distributions in Code

python · Exponential, Gamma — parameter estimation from data
from scipy.stats import expon, gamma
import numpy as np

# Simulate Kartify delivery times
np.random.seed(42)
times = np.random.exponential(scale=18, size=100_000)

# Fit Exponential — MLE is 1/sample-mean
lam_hat = 1 / times.mean()
print(f"Exp  MLE: λ̂ = {lam_hat:.4f}  (true ≈ 1/18 = 0.0556)")

# scipy fit (MLE)
loc, scale = expon.fit(times, floc=0)    # fix location at 0 for Exp
print(f"scipy: scale = {scale:.2f}  (≈ mean)")

# 95th percentile — the SLA planning number
p95 = expon.ppf(0.95, scale=scale)
print(f"P95 = {p95:.1f}h")

# Gamma fit — if we don't know if it's Exp, fit Gamma and see if k≈1
shape_g, loc_g, scale_g = gamma.fit(times, floc=0)
print(f"Gamma MLE: k = {shape_g:.3f}, scale = {scale_g:.2f}")
# If k ≈ 1, Exponential is a reasonable simpler model.
python · Log-normal — fitting Kartify order values
import numpy as np
from scipy.stats import lognorm

# Simulate Kartify order values — Log-normal with mu=6.58, sigma=1.37
np.random.seed(42)
orders = np.random.lognormal(mean=6.58, sigma=1.37, size=10_000)

print(f"Sample mean:   ₹{orders.mean():,.0f}")
print(f"Sample median: ₹{np.median(orders):,.0f}")
print(f"Mean / Median: {orders.mean() / np.median(orders):.2f}x (heavy-tail signal if > 1.5)")

# Simple MLE: take logs, fit Normal
log_orders = np.log(orders)
mu_hat    = log_orders.mean()
sigma_hat = log_orders.std(ddof=0)
print(f"MLE: μ̂ = {mu_hat:.3f}, σ̂ = {sigma_hat:.3f}")

# High-value segment: P(order > ₹10,000)
p_high = 1 - lognorm.cdf(10000, s=sigma_hat, scale=np.exp(mu_hat))
print(f"P(order > ₹10k) = {p_high:.3f} (approximately {p_high*100:.1f}% of orders)")
python · Weibull — customer lifetime / time-to-churn
import numpy as np
from scipy.stats import weibull_min
from scipy.special import gamma as gam_fn

# Simulate Kartify customer lifetimes — Weibull with k=0.82, lambda=180
np.random.seed(42)
k_true, lam_true = 0.82, 180
lifetimes = weibull_min.rvs(c=k_true, scale=lam_true, size=20_000)

# Fit Weibull
k_hat, loc_hat, lam_hat = weibull_min.fit(lifetimes, floc=0)
print(f"MLE: k̂ = {k_hat:.3f} (true {k_true})")
print(f"     λ̂ = {lam_hat:.1f} (true {lam_true})")

# Interpretation: k < 1 → decreasing hazard (infant mortality) → onboarding matters
print(f"Shape interpretation: k = {k_hat:.2f} — decreasing hazard (new-user churn front-loaded)")

# Mean lifetime: λ * Γ(1 + 1/k)
mean_life = lam_hat * gam_fn(1 + 1/k_hat)
print(f"Mean lifetime: {mean_life:.0f} days")

# Hazard rate at t=30 (month 1) vs t=365 (year 1)
h = lambda t: (k_hat / lam_hat) * (t / lam_hat) ** (k_hat - 1)
print(f"Hazard at 30d: {h(30):.5f}, at 365d: {h(365):.5f}  → new users at higher risk")
