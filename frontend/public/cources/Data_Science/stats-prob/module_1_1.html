// Section 1

Why Data Type Is the First Question You Must Ask

Before you compute a single mean, run a single t-test, or train a single model — you must ask: what kind of variable is this? The answer determines which statistical operations are legal, which visualizations are appropriate, and which ML models make sense.

⚡ Core Intuition

Imagine Kartify's analyst asks: "What's the average product category of orders this week?" That question is meaningless — not because categories are complex, but because "Ethnic Wear", "Sportswear", "Western" don't have a numerical relationship. You can't average them. Knowing data type tells you exactly which arithmetic is permitted and which produces nonsense.

This is not just academic. In real ML pipelines, confusing categorical data for numerical data — like encoding Kartify's 12 product categories as 1, 2, 3... 12 and then computing their mean — is one of the most common sources of silent model errors. The model trains, produces numbers, and is completely wrong in a way that's hard to detect.

🛍️ Kartify Orders Dataset
Real Column Examples
order_id — looks numeric but is NOMINAL (just a label, averaging is nonsense). customer_rating (1–5 stars) — ORDINAL (ordered but gaps aren't equal). price_inr — RATIO (true zero, doubling makes sense). delivery_days — RATIO (3 days is truly half of 6 days).
⚠️ The Encoding Trap
How Kartify's Rec Model Broke
A junior engineer encoded categories as integers: Ethnic Wear=1, Western=2, Sportswear=3, Kids=4... The linear model learned that "Sportswear is between Western and Kids." Orders from overlap zones got bizarre recommendations. The fix: one-hot encoding.
🏥 Healthcare Comparison
Same Principle, Higher Stakes
Patient ID (nominal), Pain level 1–10 (ordinal), Temperature °C (interval), Weight kg (ratio). Using the wrong summary for any of these gives wrong conclusions — and in medicine, wrong conclusions cost lives.
✅ The Rule to Remember
Always Check Before Touching
Nominal → use mode, count, chi-square. Ordinal → use median, rank tests. Interval/Ratio → use mean, SD, t-tests. Wrong operation on wrong scale = garbage output that looks legitimate.

The Four Measurement Scales

Stanley Stevens (1946) proposed four measurement scales ordered by statistical power. Each level inherits all properties of those below it, and adds one more capability.

The Stevens Measurement Hierarchy Each level adds one new capability →

↑ Hover over each level to see Kartify examples

Scale 1 · Lowest Power
Nominal
Categories with no order, no meaningful numerical difference. Labels only. You can count frequencies but never compute "distance" between categories.
📦 Kartify examples: product_category (Ethnic/Western/Kids), city, payment_method, return_reason, order_id
  • Only valid operation: counting (mode, frequency)
  • Cannot compute mean, median, or differences
  • ML encoding: One-hot encoding (never integer labels)
Scale 2
Ordinal
Categories with a meaningful order, but the gaps between ranks are NOT necessarily equal. "4 stars is better than 3 stars" — but the gap may not equal 3→2.
⭐ Kartify examples: customer_rating (1–5 stars), delivery_satisfaction (Poor/OK/Good/Excellent), size (XS/S/M/L/XL)
  • Valid: median, percentiles, Spearman correlation
  • Cannot compute mean (though commonly done — with caution)
  • ML encoding: Label encoding (preserving order) is OK
Scale 3
Interval
Ordered with equal intervals — differences are meaningful, but there's no true zero. So ratios are invalid.
📅 Kartify examples: order_date (year 2022 is not "twice" year 2011), temperature in warehouse (0°C ≠ no heat)
  • Valid: mean, SD, Pearson correlation, t-tests
  • Differences meaningful: "2 years later" is valid
  • Ratios NOT valid: "2022 is twice 2011" is nonsense
Scale 4 · Highest Power
Ratio
Equal intervals AND a true absolute zero. Zero means "none of this thing." All arithmetic is valid and meaningful.
💰 Kartify examples: price_inr, delivery_days, items_in_cart, gmv, discount_percent, return_count
  • All operations valid: mean, SD, ratios, geometric mean
  • "₹2000 is twice ₹1000" — valid statement
  • "3 days delivery is 3× faster than 9 days" — valid
⚠️ Most Common Confusion — Interval vs Ratio

The zero point is what matters. Temperature in Celsius is interval: 0°C is not "no temperature", it's the freezing point of water — an arbitrary human choice. That's why "30°C is twice as hot as 15°C" is wrong (temperatures can't be doubled). But Kartify's price in rupees is ratio: ₹0 really means no price, so "₹600 is twice ₹300" is perfectly valid. Ask yourself: does zero truly mean "none of this thing exists?"

Discrete vs Continuous Variables

This is a second, independent classification that cuts across the scale hierarchy. It tells you which probability distributions and density functions you'll use in Track 3.

Discrete
📦 Countable, Isolated Values
Takes isolated, countable values — typically integers. Kartify examples: items_in_cart (1, 2, 3... never 2.7 items), return_count, number_of_photos_per_listing, complaints_this_week. You can list the possible values.
Continuous
📈 Any Value in a Range
Can take any value in a range — infinite possibilities between any two points. Kartify examples: price_inr (₹199.50 is possible), delivery_time_hours (3.25 hours), discount_percentage (12.7% off). The value is limited only by measurement precision.
💡 Why This Matters for Track 3 (Probability)

Discrete → Probability Mass Function: P(X = 3 items in cart) is a real number.
Continuous → Probability Density Function: P(price = exactly ₹499.00) = 0. We must ask P(₹490 ≤ price ≤ ₹510) and integrate.
This distinction drives everything in probability theory. Always note which type you're working with.

Python: Detecting Data Types in Pandas

In practice, you identify data types by inspecting the DataFrame. Pandas uses its own type system which maps imperfectly onto the Stevens scale. Know the mapping — it's the first thing you should run on any new dataset at Kartify.

Python — Kartify Orders: dtype Inspection & Conversion 
import pandas as pd
import numpy as np

# Kartify orders dataset (simplified)
data = {
    'order_id':        ['KTF-1001', 'KTF-1002', 'KTF-1003', 'KTF-1004'],
    'category':        ['Ethnic Wear', 'Western', 'Sportswear', 'Ethnic Wear'],
    'customer_rating': [5, 3, 4, 2],        # ORDINAL — 1 to 5 stars
    'price_inr':       [1299, 499, 899, 2199], # RATIO   — true zero exists
    'delivery_days':   [3, 2, 5, 1],           # RATIO   — 0 days = instant
    'order_date':      ['2024-01-15', '2024-01-16', '2024-01-17', '2024-01-18'],
    'size':            ['S', 'L', 'M', 'XL'],     # ORDINAL — ordered sizes
}
df = pd.DataFrame(data)

# Step 1: See what pandas THINKS the types are (often wrong!)
print(df.dtypes)
# order_id          object  → nominal (treat as category)
# category          object  → nominal (pandas doesn't know it's categorical)
# customer_rating   int64   → ordinal (pandas thinks it's numeric — it's not!)
# price_inr         int64   → ratio   (correctly numeric)
# delivery_days     int64   → ratio   (correctly numeric)

# Step 2: Correct the types
df['category'] = df['category'].astype('category')   # nominal
df['order_date'] = pd.to_datetime(df['order_date'])     # interval (datetime)

# Step 3: Ordinal with correct order — CRITICAL for correct comparisons
size_order = pd.CategoricalDtype(
    categories=['XS', 'S', 'M', 'L', 'XL', 'XXL'],
    ordered=True
)
df['size'] = df['size'].astype(size_order)

# Step 4: Verify — now df['size'] supports comparisons
print(df['size'] > 'M')   # True for L and XL — works correctly!

# Step 5: One-hot encode nominal for ML (NEVER integer-encode categories)
df_ml = pd.get_dummies(df[['category', 'price_inr', 'delivery_days']],
                        columns=['category'], drop_first=True)
print(df_ml.columns.tolist())

Structured vs Unstructured Data

The Stevens scales cover structured data — values in rows and columns. But a huge portion of Kartify's data doesn't fit a table.

📊 Structured
Tabular — rows × columns
The Stevens scale applies here. Every column has a clear type. Examples: orders table, customer profiles, product catalog with prices and ratings. Pandas, SQL, sklearn work directly on this.
🖼️ Unstructured
Images, Text, Audio, Video
Kartify unstructured data: product photos (for visual search), customer reviews in Hindi & English (for sentiment analysis), return_reason free text ("zipper broke after 2 washes"). Requires NLP/CV before statistical analysis.
🕸️ Semi-Structured
JSON, XML, Logs
Has some structure but not tabular. Kartify's clickstream data (user scrolled → hovered → added to cart → exited), API logs, recommendation engine outputs. Requires parsing before analysis.
⚡ Why It Matters
70% of real-world data is unstructured
The majority of Kartify's signal lives in photos and reviews, not just transaction tables. Modern ML (BERT, ResNet, multimodal models) learns from all of it — but the statistical foundations you're building here apply everywhere once it's processed.

Module 1.1 — What You've Mastered
  • Four measurement scales: Nominal (labels) → Ordinal (ordered) → Interval (equal gaps) → Ratio (true zero)
  • Each scale inherits all operations of scales below it, plus one more
  • Nominal: only mode/count. Ordinal: add median. Interval: add mean/SD. Ratio: add geometric mean, CV, ratios
  • Kartify's price_inr is ratio (₹0 = free, doubling valid). customer_rating is ordinal (gaps unequal). city is nominal.
  • Integer-encoding nominal categories for ML is wrong — creates false ordering. Use one-hot encoding.
  • Discrete = countable isolated values (items_in_cart). Continuous = any value in range (discount_pct)
  • Structured (tables) vs Unstructured (reviews, photos) vs Semi-structured (JSON logs)
  • Pandas: .astype('category') for nominal, pd.CategoricalDtype(ordered=True) for ordinal, pd.to_datetime() for dates
