Track 5 · Regression & Relationships

Logistic Regression —
Binary Outcomes Done Right

Linear regression for probabilities? The math says no — predictions can exceed 1 or fall below 0, and noise isn't Normal when outcomes are 0/1. Logistic regression solves both problems with the logit link: $\log(p/(1-p)) = \mathbf X \boldsymbol\beta$. Coefficients become log-odds. No closed form — MLE via gradient descent or IRLS. Evaluation via confusion matrices, ROC curves, AUC, and precision-recall. The statistical foundation underneath every binary classifier you'll ever use.

⚡ Kartify — When the Answer Is Yes or No
Week 7. Priya's product team has a new class of questions. "Will this user convert during this session?" (yes/no). "Will this order be returned?" (yes/no). "Will this churning customer come back if we send a coupon?" (yes/no).

These are classification problems. The outcome is binary — 0 or 1, not a continuous number. Linear regression would, in principle, try: fit a line through the 0/1 values, predict a "score," and maybe threshold. But this fails hard:
  • Predictions can be $-0.3$ or $1.7$ — what does a "negative 30% probability" even mean?
  • Residuals aren't Normal. For a 0/1 outcome, an observation is either above or below the line — but never symmetrically. OLS inference breaks.
  • Variance isn't constant. $\mathrm{Var}(Y \mid p) = p(1-p)$ — larger near $p = 0.5$, smaller near 0 or 1. Classical heteroscedasticity.
Logistic regression fixes all three. Model the log-odds $\log(p/(1-p))$ as a linear function of predictors. The log-odds can be any real number; the sigmoid transform brings it back to a probability in $(0, 1)$. Errors follow Bernoulli, not Normal — and MLE handles them correctly.

Module 5.3 is the most important transition module in Track 5. Every classical ML classifier (logistic, neural networks for binary outcomes, SVMs with probabilistic output) builds on these ideas. Mastering logistic regression — the link function, the likelihood, odds-ratio interpretation, and the full evaluation toolkit — makes every downstream classifier intelligible instead of mysterious.

Running example. Kartify's session-level dataset: 5,000 user sessions with features (time on site, pages viewed, prior orders, mobile flag) and a binary "converted" outcome. We'll fit a logistic model, interpret coefficients as odds ratios, build decision boundaries, and evaluate via confusion matrix, ROC/AUC, and precision-recall.
// Section 1 · Why Linear Fails

Why Linear Regression Fails for Binary Outcomes — Three Reasons

Before we build logistic regression, let's see concretely why linear regression is the wrong tool for binary outcomes.

Linear regression on binary data — what goes wrong
Kartify session time (minutes) vs converted (0/1)
data (0 or 1)linear fitout-of-range predictions
Problem 1
Predictions escape $[0, 1]$
For sufficiently small or large $X$, $\hat Y = \hat\beta_0 + \hat\beta_1 X$ can be negative or greater than 1. But probabilities must live in $[0, 1]$. A linear function of $X$ cannot respect this constraint.
Problem 2
Non-Normal, heteroscedastic errors
$Y \in \{0, 1\}$ makes residuals $Y - \hat Y$ take only two values at each $X$ — far from Normal. Also: $\mathrm{Var}(Y \mid p) = p(1-p)$ — maximal at $p = 0.5$, vanishing near 0 or 1. OLS SEs and $t$-tests become invalid.
Problem 3
Wrong likelihood
OLS's "minimize squared errors" is MLE under Normal noise. For binary data, the right likelihood is Bernoulli — not Normal. Using OLS picks the wrong loss function.
What we need instead
Three design requirements for a good binary-outcome model:
  1. Outputs in $[0, 1]$. We need a link function that maps $\mathbf X \boldsymbol\beta \in \mathbb R$ to $p \in [0, 1]$.
  2. Correct likelihood. Use Bernoulli: $P(Y_i = 1) = p_i$, $P(Y_i = 0) = 1 - p_i$.
  3. MLE-based fitting. Maximize $\sum [Y_i \log p_i + (1 - Y_i) \log(1 - p_i)]$ — the Bernoulli log-likelihood.
Logistic regression is the construction that satisfies all three.
// Section 2 · The Logit Link

The Logit Link — Mapping $(0, 1)$ to $\mathbb R$

We want: a function that takes $p \in (0, 1)$ and returns a real number, which can then be linear in $\mathbf X$. The logit is the answer.

The logit function and its inverse (sigmoid / logistic)
$$\text{logit}(p) = \log\!\left(\frac{p}{1 - p}\right) \in \mathbb R$$
$$\sigma(z) = \frac{1}{1 + e^{-z}} = \frac{e^z}{1 + e^z} \in (0, 1)$$

These are inverses: $\sigma(\text{logit}(p)) = p$ and $\text{logit}(\sigma(z)) = z$. The ratio $p/(1-p)$ is called the odds. The logit is log-odds.

The sigmoid $\sigma(z)$ — the shape that makes logistic regression work
Maps any real $z$ into a probability. Steepest at $z = 0$ (probability 0.5).
sigmoid $\sigma(\beta_0 + \beta_1 X)$$p = 0.5$ threshold
Logistic regression — three equivalent forms
$$\text{logit}(p_i) = \log\!\left(\frac{p_i}{1 - p_i}\right) = \beta_0 + \beta_1 X_{i1} + \ldots + \beta_p X_{ip}$$
$$p_i = \sigma(\mathbf X_i^T \boldsymbol\beta) = \frac{1}{1 + e^{-\mathbf X_i^T \boldsymbol\beta}}$$
$$Y_i \mid \mathbf X_i \sim \text{Bernoulli}(p_i)$$
⚡ Why the logit, specifically?

There are other functions mapping $(0, 1) \to \mathbb R$ — e.g., $\Phi^{-1}(p)$ (probit), $\log(-\log(1-p))$ (complementary log-log). All are link functions in generalized linear model (GLM) terminology. Three reasons logit dominates:

  1. Interpretability. Coefficients are log-odds ratios — a clean multiplicative interpretation (Section 5).
  2. Canonical link for Bernoulli. In GLM theory, each exponential-family distribution has a "natural" link. For Bernoulli, it's the logit. This gives clean MLE equations.
  3. Numerical stability. Sigmoid is differentiable and smooth — easy for gradient descent.

// Section 3 · MLE

Fitting Logistic Regression — MLE with No Closed Form

Linear regression had a closed-form OLS solution. Logistic regression does not — we have to maximize the likelihood numerically.

Bernoulli log-likelihood
$$\ell(\boldsymbol\beta) = \sum_{i=1}^n \left[Y_i \log p_i + (1 - Y_i) \log(1 - p_i)\right]$$
$$p_i = \sigma(\mathbf X_i^T \boldsymbol\beta)$$
Gradient of the log-likelihood
1
Let $z_i = \mathbf X_i^T \boldsymbol\beta$ so $p_i = \sigma(z_i)$. Note: $\sigma'(z) = \sigma(z)(1 - \sigma(z))$ — a key identity.
2
For a single observation: $\frac{\partial}{\partial \beta_j}[Y_i \log p_i + (1 - Y_i)\log(1 - p_i)]$.
3
Using chain rule: $= \left[\frac{Y_i}{p_i} - \frac{1 - Y_i}{1 - p_i}\right] \cdot p_i(1 - p_i) \cdot X_{ij}$.
4
Simplify the bracket: $= \left[Y_i(1 - p_i) - (1 - Y_i)p_i\right] X_{ij} = (Y_i - p_i) X_{ij}$.
5
$\boxed{\nabla_{\boldsymbol\beta} \ell = \mathbf X^T (\mathbf Y - \mathbf p)}$ — sum of residual-weighted predictors, where $\mathbf p$ is the vector of fitted probabilities.
Comparing OLS and logistic gradients — same shape, different residuals
OLS gradient: $\mathbf X^T(\mathbf Y - \mathbf X\boldsymbol\beta)$ — residuals are actual minus predicted.
Logistic gradient: $\mathbf X^T(\mathbf Y - \mathbf p)$ — residuals are actual binary outcome minus predicted probability.

The form is identical — residuals dotted with predictors. The difference is that in logistic, the "predicted" is a probability through the sigmoid nonlinearity. This means the first-order condition $\mathbf X^T(\mathbf Y - \mathbf p) = \mathbf 0$ doesn't give a closed form — $\mathbf p$ depends on $\boldsymbol\beta$ nonlinearly. We solve iteratively.

Newton-Raphson / IRLS — the standard fitting algorithm

Iteratively Reweighted Least Squares (IRLS)
$$\boldsymbol\beta^{(t+1)} = \boldsymbol\beta^{(t)} + (\mathbf X^T \mathbf W^{(t)} \mathbf X)^{-1} \mathbf X^T (\mathbf Y - \mathbf p^{(t)})$$
$$\mathbf W^{(t)} = \text{diag}(p_i^{(t)}(1 - p_i^{(t)}))$$
Convergence
Quadratic (Newton)
Typically 5–20 iterations for convergence. The log-likelihood is strictly concave (Hessian is negative semi-definite), so a unique global maximum exists when data is not separable.
Interpretation
Weighted OLS at each step
Each iteration is a weighted OLS regression on a "working response." The weights $p_i(1 - p_i)$ downweight observations where the prediction is very confident (near 0 or 1). Observations near $p = 0.5$ get the most weight.
Alternative — gradient descent
For very large $n$
SGD (stochastic gradient descent) scales to millions of observations. Slower convergence (linear vs quadratic), but no need to invert a matrix. The standard choice for deep learning, also available via sklearn's SGDClassifier.
Separation problem
When MLE doesn't exist
If a predictor perfectly separates $Y = 0$ from $Y = 1$, MLE diverges: $\hat\beta_j \to \pm \infty$. Fix: add regularization (L2 ridge or L1 LASSO — Section 8). Real data rarely has perfect separation, but it's common in small samples.

// Section 5 · Odds Ratios

Odds Ratios — How to Actually Interpret Coefficients

Logistic coefficients are in log-odds units. Humans don't think in log-odds. We need to translate.

From coefficient to odds ratio
$$\text{Odds ratio} = e^{\beta_j}$$
$$\text{Interpretation: a one-unit increase in } X_j \text{ multiplies the odds of } Y = 1 \text{ by } e^{\beta_j}$$
Why odds ratio = $e^{\beta_j}$ — derivation
1
Baseline odds: $\text{odds}(X_j = x) = p/(1-p) = e^{\beta_0 + \ldots + \beta_j x + \ldots}$.
2
Odds with one-unit increase: $\text{odds}(X_j = x + 1) = e^{\beta_0 + \ldots + \beta_j(x+1) + \ldots} = e^{\beta_j} \cdot e^{\beta_0 + \ldots + \beta_j x + \ldots}$.
3
Ratio: $\text{odds}(X_j = x + 1) / \text{odds}(X_j = x) = e^{\beta_j}$. This is the odds ratio. $\blacksquare$
Kartify · interpreting each coefficient as an odds ratio
time_on_site: $\hat\beta = 0.18$. Odds ratio $= e^{0.18} = 1.197$. Each additional minute on site multiplies the odds of conversion by 1.20 — i.e., 20% higher odds per minute. Over 10 minutes: $1.20^{10} = 6.19$ — more than 6× the odds.
pages_viewed: $\hat\beta = 0.34$. Odds ratio $= e^{0.34} = 1.405$. Each additional page increases conversion odds by 40.5%.
prior_orders: $\hat\beta = 0.52$. Odds ratio $= e^{0.52} = 1.682$. Each prior order increases conversion odds by 68% — a strong signal. Repeat customers convert much more.
mobile: $\hat\beta = -0.28$. Odds ratio $= e^{-0.28} = 0.756$. Being on mobile (vs desktop) multiplies conversion odds by 0.76 — i.e., reduces odds by 24%.
Business insight. Priya's dashboard now reads: "prior orders is the biggest driver of conversion odds (68% lift per order). Mobile users convert 24% less often than desktop. Engagement (time, pages) matters but with smaller per-unit effects."
⚠ The odds ratio is NOT the probability ratio

"20% higher odds" does NOT mean "20% higher probability." These are different things:

  • Odds: $p / (1 - p)$. At $p = 0.5$: odds = 1. At $p = 0.75$: odds = 3.
  • Probability: $p$ itself.
At $p = 0.05$ (rare event), 20% higher odds ≈ 20% higher probability. But at $p = 0.5$, 20% higher odds (new odds = 1.2) means $p = 1.2/2.2 = 0.545$ — only 4.5 percentage-point lift, not 20. Always think carefully about whether "odds" or "probability" is what the stakeholder is asking about.

// Section 6 · Decision Boundary

Decision Boundary — From Probability to Class

Logistic regression outputs a probability $\hat p$. For classification, we threshold: predict $\hat Y = 1$ if $\hat p \ge c$, else $\hat Y = 0$. The default threshold is $c = 0.5$.

Decision boundary at threshold $c = 0.5$
$$\hat p = 0.5 \;\;\Leftrightarrow\;\; \mathbf X^T \boldsymbol\beta = 0$$

At $c = 0.5$, the decision boundary in predictor space is the hyperplane $\mathbf X^T \boldsymbol\beta = 0$ — a linear boundary. This is why logistic regression is called a linear classifier: decision boundaries are straight lines (in 2D), planes (3D), or hyperplanes (higher dimensions).

Decision boundary in 2D feature space
Kartify: time_on_site vs pages_viewed. Adjust threshold to see how the boundary moves.
Y = 0 (no convert)Y = 1 (convert)decision boundary
Why threshold $c = 0.5$ is not always right
The $c = 0.5$ default assumes equal cost of false positives and false negatives. This rarely matches business reality:
  • Fraud detection. A missed fraud costs ₹50K; a false alarm costs 5 minutes of analyst review. Lower $c$ (e.g., 0.1) to catch more frauds, tolerating more false positives.
  • Marketing to churners. A false alarm (email to someone who wasn't churning) costs ₹0.01; a missed churner costs ₹5,000 lifetime value. Lower $c$ aggressively.
  • Medical screening. Missing a disease is far worse than a false positive (leads to follow-up test). Lower $c$ heavily.
Choosing $c$ is a business decision, informed by the confusion matrix, ROC curve, and domain-specific cost functions. Always tune.

⚠ Accuracy trap — class imbalance

Kartify's conversion rate is 8.2%. A classifier that always predicts "no convert" gets 91.8% accuracy — sounds great, but is useless. For imbalanced classes, accuracy is a bad metric. Use precision-recall or ROC/AUC. Or: upsample the minority class, downsample the majority, or use class weights.

ROC curve — threshold-free evaluation

The ROC (Receiver Operating Characteristic) curve plots TPR vs FPR as the threshold $c$ varies from 1 to 0. Each threshold gives one $(FPR, TPR)$ point.

⚡ The magical AUC interpretation

AUC has a clean probabilistic interpretation: AUC = $P(\hat p_{\text{pos}} > \hat p_{\text{neg}})$ — the probability that a randomly chosen positive instance is ranked higher than a randomly chosen negative instance. AUC = 0.8 means: if you pick one converter and one non-converter at random, there's an 80% chance the model assigns higher probability to the converter. This is threshold-free — AUC measures ranking quality, not calibration.

Precision-Recall curve — for imbalanced data

When positives are rare (Kartify's 8.2% convert rate), ROC can look over-optimistic because even a bad classifier has many true negatives. The precision-recall curve plots precision vs recall as the threshold varies — a more honest view for imbalanced data.

Baseline
P-R: horizontal at base rate
A random classifier's P-R curve is a flat line at precision = base rate (0.082 for Kartify). Any improvement shows as a curve above this baseline.
Average Precision (AP)
Area under P-R curve
Equivalent to AUC but for P-R. Reports how well the classifier ranks positives at high recall — the regime that matters most for imbalanced problems.
When to report which
Balanced → ROC/AUC. Imbalanced → PR/AP.
With 50/50 class balance: ROC/AUC. With 1% minority class: PR curve is the honest picture. Kartify's 8.2% positive rate → report both, with PR as the primary.
Not threshold-free
Operating point matters
Neither ROC nor PR alone picks a threshold. They show the possibilities. The final threshold comes from cost-benefit analysis — or from tuning F1, F$\beta$, or a domain-specific metric.
// Section 8 · Extensions

Multinomial Logistic + Regularization — Beyond Binary

Multinomial logistic regression — $K > 2$ classes

For $K$ classes (e.g., order categories: Electronics, Fashion, Home, Sports), extend the binary logistic via the softmax:

Multinomial (softmax) regression
$$P(Y_i = k \mid \mathbf X_i) = \frac{e^{\mathbf X_i^T \boldsymbol\beta_k}}{\sum_{j=1}^K e^{\mathbf X_i^T \boldsymbol\beta_j}}$$

Each class $k$ gets its own coefficient vector $\boldsymbol\beta_k$. For identifiability, fix one class's $\boldsymbol\beta$ to zero (the reference class). The binary case is $K = 2$ with the reference class as the "0" outcome.

L1 and L2 regularization

When predictors are many or correlated, regularize the logistic MLE by adding a penalty:

Ridge (L2) and LASSO (L1) logistic regression
$$\hat{\boldsymbol\beta}_{\text{ridge}} = \arg\max_{\boldsymbol\beta} \left[\ell(\boldsymbol\beta) - \lambda \sum_j \beta_j^2\right]$$
$$\hat{\boldsymbol\beta}_{\text{LASSO}} = \arg\max_{\boldsymbol\beta} \left[\ell(\boldsymbol\beta) - \lambda \sum_j |\beta_j|\right]$$
L2 (Ridge)
Shrinks coefficients smoothly
Penalty is squared — $\beta_j \to 0$ smoothly as $\lambda$ grows but never exactly zero. Reduces multicollinearity, stabilizes coefficients. Fixes the separation problem (MLE diverges) — with L2, solution is always finite.
L1 (LASSO)
Selects features
Penalty is absolute value — creates a "corner" at zero that drives some $\hat\beta_j$ exactly to zero. Effectively performs automatic feature selection. Useful when many predictors are likely noise.
Elastic Net
Combines L1 + L2
$\lambda_1 \sum |\beta_j| + \lambda_2 \sum \beta_j^2$. LASSO-style selection + ridge-style stability with correlated predictors. Default in many modern pipelines.
Choosing $\lambda$
Cross-validation
Not derivable analytically — tune via $k$-fold CV. sklearn's LogisticRegressionCV does this in one call. Log-scale grid typically 10 values spanning $10^{-3}$ to $10^3$.
// Section 9 · Python

Python — sklearn, statsmodels, and the Full Workflow

python · fit logistic regression — sklearn for ML, statsmodels for inference
import numpy as np
import pandas as pd
from sklearn.linear_model import LogisticRegression
import statsmodels.api as sm

np.random.seed(42)
n = 5000

# Generate Kartify session data
time_on_site = np.random.exponential(8, n)        # minutes
pages_viewed = np.random.poisson(4, n)
prior_orders = np.random.poisson(1.5, n)
mobile = np.random.binomial(1, 0.6, n)

logit = -4.2 + 0.18*time_on_site + 0.34*pages_viewed + 0.52*prior_orders - 0.28*mobile
p = 1 / (1 + np.exp(-logit))
converted = np.random.binomial(1, p)

print(f"Conversion rate: {converted.mean():.3f}")

# ─────── sklearn (prediction-focused) ───────
X = np.column_stack([time_on_site, pages_viewed, prior_orders, mobile])
clf = LogisticRegression(penalty=None, max_iter=1000).fit(X, converted)
print(f"sklearn coef: {clf.coef_[0].round(3)}")
print(f"sklearn intercept: {clf.intercept_[0]:.3f}")

# ─────── statsmodels (full inference) ───────
X_sm = sm.add_constant(X)
result = sm.Logit(converted, X_sm).fit(disp=False)
print(result.summary())

# Odds ratios with 95% CI
params = result.params
conf = result.conf_int()
odds_ratios = pd.DataFrame({
    "OR": np.exp(params),
    "OR_lower": np.exp(conf[:, 0]),
    "OR_upper": np.exp(conf[:, 1])
}, index=["const", "time", "pages", "prior", "mobile"])
print(odds_ratios.round(3))
python · confusion matrix, precision, recall, F1
from sklearn.metrics import confusion_matrix, classification_report, accuracy_score
from sklearn.model_selection import train_test_split

# Train/test split
X_train, X_test, y_train, y_test = train_test_split(X, converted, test_size=0.3, random_state=42)
clf = LogisticRegression(max_iter=1000).fit(X_train, y_train)

# Predict on test set
y_pred = clf.predict(X_test)           # hard labels at c=0.5
y_proba = clf.predict_proba(X_test)[:, 1]  # probabilities

# Confusion matrix
cm = confusion_matrix(y_test, y_pred)
print("Confusion matrix (rows=actual, cols=predicted):")
print(cm)

# TN, FP, FN, TP for binary case
tn, fp, fn, tp = cm.ravel()
print(f"TN = {tn}, FP = {fp}, FN = {fn}, TP = {tp}")

# Metrics
print("\nClassification report:")
print(classification_report(y_test, y_pred))

# Manual computation
precision = tp / (tp + fp)
recall = tp / (tp + fn)
specificity = tn / (tn + fp)
f1 = 2 * precision * recall / (precision + recall)
print(f"Precision: {precision:.3f}, Recall: {recall:.3f}, Specificity: {specificity:.3f}, F1: {f1:.3f}")
python · ROC curve, AUC, and precision-recall curve
import numpy as np
from sklearn.metrics import roc_curve, roc_auc_score, precision_recall_curve, average_precision_score
import matplotlib.pyplot as plt

# Using y_test, y_proba from previous block

fig, ax = plt.subplots(1, 2, figsize=(12, 5))

# ROC curve
fpr, tpr, thresholds = roc_curve(y_test, y_proba)
auc = roc_auc_score(y_test, y_proba)
ax[0].plot(fpr, tpr, linewidth=2, label=f"AUC = {auc:.3f}")
ax[0].plot([0, 1], [0, 1], "k--", alpha=0.4, label="random")
ax[0].set_xlabel("False Positive Rate")
ax[0].set_ylabel("True Positive Rate")
ax[0].set_title("ROC Curve")
ax[0].legend()

# Precision-Recall curve
prec, rec, thresh_pr = precision_recall_curve(y_test, y_proba)
ap = average_precision_score(y_test, y_proba)
base_rate = y_test.mean()
ax[1].plot(rec, prec, linewidth=2, label=f"AP = {ap:.3f}")
ax[1].axhline(base_rate, ls="--", alpha=0.4, label=f"baseline = {base_rate:.2f}")
ax[1].set_xlabel("Recall")
ax[1].set_ylabel("Precision")
ax[1].set_title("Precision-Recall Curve")
ax[1].legend()

plt.tight_layout(); plt.show()

# Find optimal threshold by maximizing F1
f1_scores = 2 * prec * rec / (prec + rec + 1e-9)
optimal_idx = np.argmax(f1_scores)
optimal_threshold = thresh_pr[optimal_idx] if optimal_idx < len(thresh_pr) else 0.5
print(f"Optimal F1 threshold: {optimal_threshold:.3f}")
print(f"  (default 0.5 may not be optimal for imbalanced data)")

AOnly defined for positive $z$
BMaps any $z \in \mathbb R$ to a probability in $(0, 1)$. Monotonically increasing. $\sigma(0) = 0.5$ (the decision boundary at default threshold). $\sigma'(z) = \sigma(z)(1-\sigma(z))$ — a self-referential derivative that simplifies backprop.
CSymmetric around 0.5 on the y-axis
DAlways linear
Q 04 / 10
Why is there no closed-form MLE for logistic regression?
AThe likelihood is not differentiable
BThe first-order condition $\mathbf X^T (\mathbf Y - \mathbf p) = \mathbf 0$ depends on $\boldsymbol\beta$ nonlinearly through $\mathbf p = \sigma(\mathbf X \boldsymbol\beta)$. Can't rearrange to $\hat{\boldsymbol\beta} = \ldots$. Solve iteratively via Newton-Raphson / IRLS / gradient descent.
CMLE is impossible for non-Normal data
DThe log-likelihood has multiple maxima

DAccuracy is always the right metric
