What Is EDA — and Why It Comes First

EDA is the first thing you do with any new dataset, before modelling, before hypothesis testing, before any ML. Its goal is to understand the data's structure, quality, distributions, and relationships. Skipping EDA and jumping to modelling is how you get models trained on 40% missing values, duplicated rows, and the wrong variable types.

⚡ The EDA Mindset

EDA is detective work. You arrive at a crime scene (dataset) with no prior knowledge. You collect evidence systematically. You form hypotheses. You test them visually. You update your understanding. You never start with conclusions — you let the data reveal them.

Phase 4
Outlier Detection
Box plots, IQR fences, z-scores. Flag suspicious values. Kartify: order_id = 9999999 appears 347 times — clearly a test/dummy ID that must be filtered.
Phase 5
Relationships
Scatter plots, correlation matrix, pair plots. Which variables move together? Kartify: discount_pct and return_rate show moderate positive correlation — higher discounts → more returns.
Phase 6
Segment Analysis
Group by key dimensions: category, city, time. Do distributions change across segments? Kartify: delivery_days median is 2 in Mumbai, 6 in Tier-2 cities — huge gap.

Python — End-to-End Kartify EDA Template

Python · Kartify Orders: Complete EDA Pipeline
import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
import seaborn as sns

# ── Phase 1: Load & First Look ─────────────────────
df = pd.read_csv('kartify_orders.csv')
print(df.shape)              # (200000, 34)
print(df.dtypes)            # check inferred types
print(df.describe())        # numeric summaries
print(df.describe(include='object'))  # categorical summaries

# ── Phase 2: Missing Values ────────────────────────
missing = df.isna().sum().sort_values(ascending=False)
print(missing[missing > 0])  # only show columns with missing
missing_pct = (missing / len(df)) * 100
print(missing_pct[missing_pct > 5])  # columns with >5% missing

# ── Phase 3: Distributions ────────────────────────
numeric_cols = df.select_dtypes(include=np.number).columns
df[numeric_cols].hist(figsize=(15,10), bins=40)
plt.tight_layout()

# Category value counts
for col in ['category', 'city', 'payment_method']:
    print(df[col].value_counts().head(10))

# ── Phase 4: Outliers ─────────────────────────────
for col in ['price_inr', 'delivery_days', 'discount_pct']:
    Q1, Q3 = df[col].quantile([0.25,0.75])
    IQR = Q3 - Q1
    outliers = df[(df[col] < Q1-1.5*IQR) | (df[col] > Q3+1.5*IQR)]
    print(f"{col}: {len(outliers)} outliers ({len(outliers)/len(df)*100:.1f}%)")

# ── Phase 5: Relationships ─────────────────────────
corr = df[numeric_cols].corr()
sns.heatmap(corr, annot=True, fmt='.2f', cmap='coolwarm')
plt.title('Kartify Numeric Correlation Matrix')

# ── Phase 6: Segment Analysis ──────────────────────
print(df.groupby('city')['delivery_days'].describe().round(1))
print(df.groupby('category')['return_rate'].agg(['mean','median','std']))

The EDA Checklist

✅ Data Shape
Always run first
df.shape. Expected rows and columns? Any obvious truncation? Duplicated rows? df.duplicated().sum() on Kartify's data found 1,247 duplicate order_ids.
✅ Type Check
Types match reality?
Does pandas infer the right types? order_date as object (string) instead of datetime is common. customer_rating as float64 instead of ordered category.
✅ Missing Patterns
Random vs systematic
Is data missing completely at random (MCAR)? Or only missing for certain customer segments (MAR)? Or systematically tied to the value itself (MNAR)? Each needs different treatment.
✅ Distribution Shape
Skew, modes, spikes
Any unexpected spikes? (test orders at ₹1). Any impossible values? (delivery_days = −3, discount_pct = 150%). Any bimodal patterns? (two customer segments).
✅ Outliers
Real or errors?
Not all outliers are errors. A ₹49,999 luxury order is real. A ₹49,999 saree might be a data entry error. Context matters — investigate each flagged outlier.
✅ Correlations
Surprising relationships
Any unexpected strong correlations? (might reveal data leakage in ML context). Any expected correlations that are missing? (might indicate a data quality issue).

Anika's Day-One EDA Walkthrough

Anika runs the 7-phase EDA pipeline on Kartify's 200K order dataset. Here's exactly what she finds — and the decisions she makes at each phase.

Phase 1–3 · Load, Shape & Type Audit
Load: df = pd.read_csv('kartify_orders.csv') → 200,000 rows × 34 columns. Immediate check: df.shape, df.dtypes, df.head(3).
Shape issues found: order_date loaded as object (string) instead of datetime64. customer_rating loaded as float64 instead of ordered category. Fix both before any analysis.
Duplicate check: df.duplicated().sum() → 1,247 duplicate order_id rows — 0.6% of data. Drop them. These would have inflated GMV calculations by ≈₹8.4L.
→ Decision: fix dtypes and drop duplicates before Phase 4. Never skip this — downstream aggregations would be silently wrong.
Phase 4 · Missing Value Audit
Command: df.isnull().sum().sort_values(ascending=False)
Result: return_reason: 141,000 missing (70.5%) — expected, non-returned orders have no return reason. delivery_days: 3,200 missing (1.6%) — orders still in transit. price_inr: 0 missing — good.
Missing pattern type: return_reason is MNAR (missing not at random — tied to whether the order was returned). Imputation would be wrong. Keep as NaN, use a boolean was_returned flag instead.
→ Decision: return_reason stays NaN for non-returns. delivery_days NaNs filtered out when computing delivery statistics — don't impute with mean.
Phase 5–6 · Univariate & Bivariate Insight
price_inr distribution: Mean = ₹2,340 · Median = ₹680 · Skewness = +2.8 (heavily right-skewed). A histogram confirms: 80% of orders under ₹1,000, long tail to ₹45,000. Always use median for price summaries.
customer_rating: Mode = 4 (most common) · Mean = 3.6 · 22% of orders have rating 1 or 2. Category breakdown: Electronics returns have mean rating 2.9 — significantly worse than Apparel (4.1).
Bivariate finding: df.groupby('category')['return_rate'].mean() → Electronics 31%, Apparel 18%, Footwear 24%. Electronics return rate is 72% higher than Apparel — a critical business signal to investigate further.
→ EDA output: 3 high-priority flags raised in a one-page summary for Friday's presentation. Data is now clean, typed correctly, and understood well enough to begin modelling.
