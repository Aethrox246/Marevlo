⚡ Kartify — The Final Checklist Before Production
Week 9. Priya's regression model is ready to ship — to the dashboards consumed by the CMO daily, to the routing rules that decide which user gets which experience. Before deploying, Arjun runs the diagnostic checklist. Every previous Track 5 module touched on diagnostics; this module assembles them.

The discipline isn't optional. A model with great-looking summary statistics ($R^2 = 0.78$, all $t$-stats significant) can be silently wrong in ways that destroy downstream decisions: predictions biased in the regions that matter most, confidence intervals that under-cover by 50%, A/B test results based on assumed Normality of metrics that actually have heavy tails. The diagnostic toolkit catches these.

Five questions every model must answer.
(1) Is the functional form right? (residuals vs fitted)
(2) Are the residuals approximately Normal? (Q-Q plot)
(3) Is the variance constant? (scale-location plot, Breusch-Pagan)
(4) Are any individual observations dominating the fit? (leverage, Cook's D)
(5) Does the model generalize? (cross-validation, hold-out evaluation)

Plus distribution-level checks ($\chi^2$ goodness-of-fit, KS test) for when the question is "does my data follow this assumed distribution?" — important when the model relies on distributional assumptions about errors or the data itself.

Why visual diagnostics outperform formal tests
There's a temptation to rely on $p$-values: Shapiro-Wilk for normality, Breusch-Pagan for heteroscedasticity, Durbin-Watson for autocorrelation. But formal tests have a hidden problem: power scales with $n$. With $n = 100{,}000$, every test rejects every assumption — even the tiniest deviation from Normal becomes "statistically significant," even though the model is fine for practical purposes.

Visual diagnostics (Q-Q plots, residual plots) are scale-invariant. A Q-Q plot with $n = 100$ and $n = 100{,}000$ both clearly show whether residuals are approximately Normal — formal tests are uninformative in the second case. Modern practice: visual first, formal tests as supporting evidence. When the visual looks fine but the formal test rejects, trust the visual (you have lots of data). When the visual looks bad but the formal test doesn't reject, trust the visual (you don't have enough data to detect the problem statistically).

// Section 3 · Q-Q Plots

Q-Q Plots — Visual Test for Normality

Q-Q plot construction
$$\text{Plot } (\Phi^{-1}((i - 0.5)/n), \; e_{(i)}) \text{ for } i = 1, \ldots, n$$

Sort residuals as $e_{(1)} \le e_{(2)} \le \ldots \le e_{(n)}$. Plot each against the corresponding theoretical quantile of $N(0, 1)$. If residuals are Normal, the points fall close to a straight line.

Q-Q plot patterns — five characteristic shapes
See what Normal vs heavy-tailed vs skewed vs bimodal vs outlier-contaminated all look like
empirical quantilesreference line ($y = x$)

⚡ The CLT rescue — when Normality matters less than you think

OLS coefficients are linear combinations of $Y_i$. By the Central Limit Theorem, sums of independent random variables are approximately Normal — so $\hat{\boldsymbol\beta}$ is approximately Normal even when residuals aren't, as long as $n$ is reasonable (typically $n \ge 30$). This means: moderate non-Normality in residuals does NOT invalidate $t$-tests on coefficients. CLT does the heavy lifting. What matters more in large samples is heteroscedasticity (which the CLT does NOT fix) and influential observations (which can dominate even in large samples).

// Section 4 · χ² Goodness of Fit

$\chi^2$ Goodness-of-Fit — For Categorical Distributions

Module 4.5 introduced the $\chi^2$ test for independence. Goodness-of-fit answers a different question: does the data come from a particular distribution?

$\chi^2$ goodness-of-fit test
$$\chi^2 = \sum_{i=1}^k \frac{(O_i - E_i)^2}{E_i} \;\;\sim\;\; \chi^2_{k - 1 - m}$$

$O_i$ = observed counts in $k$ bins; $E_i$ = expected counts under the hypothesized distribution; $m$ = number of estimated parameters (subtract from df). For a fully specified distribution: $m = 0$, df $= k - 1$. Estimating $\mu, \sigma$ for Normal: $m = 2$, df $= k - 3$.

Kartify · do daily orders follow a Poisson distribution?
Setup. 200 days of order counts. Hypothesis: $X \sim \text{Poisson}(\hat\lambda)$ where $\hat\lambda = \bar X = 487$.
Bin the data. Group counts into bins (each $E_i \ge 5$): $[400, 425), [425, 450), \ldots, [575, 600)$. 8 bins.
Expected counts. For each bin $i$: $E_i = 200 \cdot P(\text{Poisson}(487) \in \text{bin } i)$.
$\chi^2$ statistic. Sum of $(O_i - E_i)^2/E_i$. Suppose $\chi^2 = 17.3$.
df. $k - 1 - m = 8 - 1 - 1 = 6$ (one parameter $\lambda$ estimated).
$p$-value. $P(\chi^2_6 > 17.3) = 0.0084$. Reject Poisson at $\alpha = 0.05$.
Conclusion. Daily order counts are NOT Poisson — likely overdispersed (variance $>$ mean). Switch to Negative Binomial for downstream modeling. This affects assumptions about confidence intervals and prediction intervals.
// Section 5 · Kolmogorov-Smirnov

Kolmogorov-Smirnov Test — For Continuous Distributions

KS test statistic
$$D_n = \sup_{x} |F_n(x) - F_0(x)|$$

$F_n(x)$ is the empirical CDF (jumps by $1/n$ at each data point). $F_0(x)$ is the hypothesized CDF. KS measures the maximum vertical gap between them.

One-sample KS
Test data against a fully specified $F_0$
"Does this data come from $N(0, 1)$?" Need fully specified parameters — estimating from the data invalidates the null distribution (Lilliefors variant adjusts for this).
Two-sample KS
Test if two samples have same distribution
"Do session times today and yesterday come from the same distribution?" Compares two empirical CDFs; non-parametric, distribution-free.
Strengths
Sensitive to any deviation
Detects shifts in mean, variance, shape — anything that moves the CDF. No bins needed (continuous).
Weaknesses
Less powerful for tail differences
Maximum gap is usually in the body of the distribution. For tail-specific issues, Anderson-Darling (weighted toward tails) is more powerful.
// Section 6 · CV as Diagnostic

Cross-Validation as Model Checking — Beyond In-Sample $R^2$

Module 5.5 introduced CV for prediction error. Here it returns as a model-validity diagnostic.

Train vs CV gap
$R^2_{\text{train}} \gg R^2_{\text{CV}}$ → overfitting
Training $R^2 = 0.85$ but CV $R^2 = 0.42$ means the model memorized the training data. Reduce model complexity, regularize, or get more data.
CV stability across folds
High CV variance → unstable model
If 5-fold CV gives scores [0.75, 0.45, 0.82, 0.51, 0.78], the model is highly fold-dependent. Could indicate sensitivity to outliers, data heterogeneity, or insufficient training data.
Learning curves
Performance vs training size
Plot CV score vs training fraction (10%, 20%, ..., 90%). Plateau = enough data. Still rising = more data would help. Gap between train and CV curves at large $n$ = irreducible model bias.
Holdout validation set
For final model selection
Even CV scores are inflated if you tune hyperparameters on them. Keep a separate holdout set, never touched during tuning, for final unbiased performance estimation.
// Section 7 · PPC Preview

Posterior Predictive Checks — A Preview of Bayesian Diagnostics

The frequentist diagnostics above ask "do residuals look right?" Bayesian inference (Track 6) introduces a more powerful generalization: posterior predictive checks (PPC). The idea: generate fake datasets from your fitted model and compare them to the real data.

Posterior predictive distribution
$$p(y^{\text{rep}} \mid y) = \int p(y^{\text{rep}} \mid \theta) \, p(\theta \mid y) \, d\theta$$
PPC procedure
1
Fit the Bayesian model. Sample $\theta^{(s)}$ from the posterior $p(\theta \mid y)$, $s = 1, \ldots, S$.
2
For each $\theta^{(s)}$: simulate a fake dataset $y^{\text{rep}, (s)}$ from $p(y \mid \theta^{(s)})$.
3
Compare summary statistics of $y^{\text{rep}, (s)}$ (mean, variance, max, P-90, # zeros, ...) to the same statistics of the real $y$.
4
If real $y$'s statistics fall in the typical range of the replicated datasets, the model fits. If they don't (e.g., real data has more zeros than any simulated dataset), the model is mis-specified.
⚡ The PPC bridge to Bayesian inference

PPC is one of the most powerful diagnostic tools in modern statistics — it works for any model where you can sample from the posterior, including hierarchical models, mixture models, and complex nonlinear models where classical residual plots break down. The frequentist analog is a simulated parametric bootstrap: refit the model many times on bootstrap samples, simulate from each, compare to real data. Track 6 covers PPC in depth as part of the Bayesian workflow.

// Section 8 · When Models Fail

When a Model Fails — Three Paths Forward

Diagnostics flagged a problem. Now what? Three strategies, ordered from least to most invasive:

Strategy 1 — Transform variables
Often fixes the easiest issues
Log-transform $Y$: fixes right-skew and heteroscedasticity (when variance grows with mean). Square-root: for count data with mild overdispersion. Box-Cox: data-driven optimal power transformation. Center / standardize $X$: improves interpretability and conditioning.
Strategy 2 — Robust methods
Keep the model, change the inference
Robust SEs (HC3, HAC): for heteroscedasticity / autocorrelation. Robust regression (M-estimators, Huber, Tukey biweight): for outliers. Quantile regression: for non-Normal errors with median or quantile focus.
Strategy 3 — Change the model
When the problem is structural
Generalized linear models (GLM): Poisson for counts, Negative Binomial for overdispersed counts, Gamma for positive continuous. Generalized additive models (GAM): non-linear smoothers per predictor. Mixed-effects models: hierarchical / clustered data. Tree-based models or neural nets: high-interaction non-linear structure.
Don't forget
Sometimes the fix is more data
A model that fails CV with 200 observations may pass with 2000. Sometimes the right answer is "we need more data" rather than "we need a fancier model." Learning curves (Section 6) tell you when more data would help.
Kartify · final diagnostic checklist applied
Model. conversions ~ ad_spend + sessions + weekend + promo + mobile (200 days).
Q1 (residuals vs fitted). Slight curvature — log-transformed sessions; cleared.
Q2 (Q-Q plot). Mild S-shape (heavier tails than Normal). Switched to robust HC3 SEs; coefficients unchanged, $t$-stats slightly more conservative.

Verdict. Model approved for production. The diagnostic process — identify problem → transform / robustify → re-check — is itself the value. The final $R^2$ of 0.71 isn't the headline; the path of careful checks is what makes Priya confident the inference is trustworthy.

python · the four-panel diagnostic plot
import numpy as np
import matplotlib.pyplot as plt
import statsmodels.api as sm
from scipy import stats

np.random.seed(42)
n = 200
X = np.random.uniform(5, 25, n)
y = -3 + 5*X + np.random.normal(0, 8, n)
X_design = sm.add_constant(X)
m = sm.OLS(y, X_design).fit()

resid = m.resid
fitted = m.fittedvalues
std_resid = m.get_influence().resid_studentized_internal

fig, ax = plt.subplots(2, 2, figsize=(12, 9))

# Panel 1: Residuals vs Fitted — linearity, homoscedasticity
ax[0, 0].scatter(fitted, resid, alpha=0.6, s=20)
ax[0, 0].axhline(0, color="red", ls="--", alpha=0.7)
# Add LOWESS smoother to see any trend
from statsmodels.nonparametric.smoothers_lowess import lowess
sm_curve = lowess(resid, fitted, frac=0.3)
ax[0, 0].plot(sm_curve[:, 0], sm_curve[:, 1], color="orange", lw=1.5)
ax[0, 0].set_title("Residuals vs Fitted")
ax[0, 0].set_xlabel("Fitted ŷ"); ax[0, 0].set_ylabel("Residual")

# Panel 2: Q-Q plot — normality of residuals
sm.qqplot(resid, line="45", fit=True, ax=ax[0, 1])
ax[0, 1].set_title("Normal Q-Q")

# Panel 3: Scale-Location — homoscedasticity
ax[1, 0].scatter(fitted, np.sqrt(np.abs(std_resid)), alpha=0.6, s=20)
sm_scale = lowess(np.sqrt(np.abs(std_resid)), fitted, frac=0.3)
ax[1, 0].plot(sm_scale[:, 0], sm_scale[:, 1], color="orange", lw=1.5)
ax[1, 0].set_title("Scale-Location")
ax[1, 0].set_xlabel("Fitted ŷ"); ax[1, 0].set_ylabel("√|Std Resid|")

# Panel 4: Cook's distance — influential observations
influence = m.get_influence()
cooks = influence.cooks_distance[0]
ax[1, 1].stem(range(n), cooks, basefmt=" ")
ax[1, 1].axhline(4/n, color="red", ls="--", label=f"4/n = {4/n:.3f}")
ax[1, 1].set_title("Cook's Distance")
ax[1, 1].legend()

plt.tight_layout(); plt.show()

# Formal test backups (use sparingly — visual is primary)
print(f"Shapiro-Wilk p: {stats.shapiro(resid).pvalue:.4f}")
from statsmodels.stats.diagnostic import het_breuschpagan
print(f"Breusch-Pagan p: {het_breuschpagan(resid, X_design)[1]:.4f}")
python · χ² goodness of fit and KS test
import numpy as np
from scipy import stats

np.random.seed(42)

# ─── χ² Goodness-of-fit: are daily orders Poisson? ───
daily_orders = np.random.negative_binomial(20, 0.04, 200)  # truly NB, not Poisson
lambda_hat = daily_orders.mean()
print(f"Sample mean = {lambda_hat:.1f}, sample var = {daily_orders.var():.1f}")
# If Poisson: var should ≈ mean. If they differ greatly → not Poisson.

# Bin and compare to Poisson(λ̂)
bins = np.linspace(daily_orders.min(), daily_orders.max() + 1, 10)
observed, _ = np.histogram(daily_orders, bins=bins)
expected_probs = stats.poisson.cdf(bins[1:] - 1, lambda_hat) - stats.poisson.cdf(bins[:-1] - 1, lambda_hat)
expected = expected_probs * len(daily_orders)
# Make sure all expected ≥ 5 (Cochran's rule)
mask = expected >= 5
chi2, p = stats.chisquare(observed[mask], f_exp=expected[mask] * observed[mask].sum() / expected[mask].sum(),
                              ddof=1)
print(f"χ² GOF for Poisson: χ² = {chi2:.2f}, p = {p:.4f}")
# Reject → not Poisson; data is overdispersed (var >> mean). Use Negative Binomial.

# ─── KS test: do residuals come from Normal(0, σ̂)? ───
resid = np.random.normal(0, 2, 100)  # synthetic Normal residuals
ks_stat, ks_p = stats.kstest(resid, "norm", args=(0, resid.std(ddof=1)))
print(f"KS test (one-sample): D = {ks_stat:.3f}, p = {ks_p:.3f}")
# Note: estimating params from data invalidates standard p-value. Use Lilliefors test for that.

# ─── Two-sample KS: do today's orders match yesterday's? ───
today = np.random.lognormal(7.3, 1.0, 500)
yesterday = np.random.lognormal(7.4, 1.0, 500)
ks_stat2, ks_p2 = stats.ks_2samp(today, yesterday)
print(f"KS test (two-sample): D = {ks_stat2:.3f}, p = {ks_p2:.3f}")
python · learning curve and CV stability check
import numpy as np
import matplotlib.pyplot as plt
from sklearn.linear_model import LinearRegression
from sklearn.model_selection import learning_curve, cross_val_score, KFold
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

np.random.seed(42)
n = 2000
X = np.random.normal(0, 1, (n, 5))
y = X @ np.array([1.0, 0.5, -0.3, 0.1, 0]) + np.random.normal(0, 1, n)

pipe = Pipeline([("scaler", StandardScaler()), ("reg", LinearRegression())])

# Learning curve
sizes, train_scores, val_scores = learning_curve(
    pipe, X, y, train_sizes=np.linspace(0.1, 1.0, 10),
    cv=5, scoring="r2", n_jobs=-1
)

plt.figure(figsize=(8, 5))
plt.plot(sizes, train_scores.mean(axis=1), "o-", label="Train R²")
plt.plot(sizes, val_scores.mean(axis=1), "o-", label="CV R²")
plt.fill_between(sizes, val_scores.mean(axis=1) - val_scores.std(axis=1),
                 val_scores.mean(axis=1) + val_scores.std(axis=1), alpha=0.2)
plt.xlabel("Training size"); plt.ylabel("R²")
plt.title("Learning Curve"); plt.legend(); plt.show()

# CV stability check
cv_scores = cross_val_score(pipe, X, y, cv=KFold(n_splits=10, shuffle=True, random_state=42),
                            scoring="r2")
print(f"10-fold CV R²: mean = {cv_scores.mean():.3f}, std = {cv_scores.std(ddof=1):.3f}")
print(f"Range across folds: [{cv_scores.min():.3f}, {cv_scores.max():.3f}]")
# If std is large or range is wide → unstable model
