Random Variables —
Bridge from Experiment to Number

Track 2 treated distributions as given. Track 3 flips the view: distributions are what you estimate from data. Every PMF, every PDF, every CDF you'll encounter in real work starts life as an assumed shape with unknown parameters. This track builds the language; Tracks 4 and 5 will populate the parameters.

⚡ Kartify — The Week the Distribution Got Real
Monday, week 3. Arjun opens the Kartify warehouse dashboard: a histogram of last month's delivery times, 100,000 orders. The shape is obvious — right-skewed, peaked near 18 hours, tail out to 96. He types into Slack: "Looks Exponential."

Priya replies: "Looks Exponential. But what's the rate? And how sure are you? And if we truncate at 72h — does it stay Exponential? And if it doesn't fit — what do you use?"

That's the week's work. In Track 2, we wrote $T \sim \text{Exp}(1/18)$ and computed. In Track 3, $T$'s distribution is what the data tells us. Before we can estimate anything (Track 4) or test any claim about Delhi or fraud (Track 5), we need one more pass over random variables — this time with the mindset that every PMF, PDF, and CDF on the page is an estimator's target. We'll also meet the quantile function, which turns CDFs into percentiles (the language product managers actually speak), and the inverse-CDF method — the algorithm every random number generator uses under the hood.
// Section 1

Random Variable, Re-examined

Track 2 defined a random variable as a function $X : S \to \mathbb{R}$. That's still true. What shifts in Track 3 is the epistemic stance:

Track 2 view
Model-given
"$T \sim \text{Exp}(\lambda = 1/18)$." We are told the distribution and compute consequences. Probabilities, expectations, tail events — all derived from an assumed model.
Track 3 view
Data-estimated
"$T$ has some unknown distribution $F$. We have 100,000 samples $t_1, \ldots, t_n$. Estimate $F$." The true $F$ is never fully known — only approximated through data and assumptions.
Empirical object
The empirical CDF $\hat{F}_n$
$\hat{F}_n(x) = \frac{1}{n} \sum_{i=1}^{n} \mathbb{1}[t_i \le x]$ — fraction of observations $\le x$. The simplest nonparametric estimator of $F$. Converges to the true $F$ by the Glivenko-Cantelli theorem.
Parametric model
Shape + unknown parameters
"Assume $T \sim \text{Exp}(\lambda)$; $\lambda$ is unknown." Now the question is which $\lambda$ best matches data. Track 4 answers this (MLE, Bayes). Track 3 gets the vocabulary right.
The core mental switch for Track 3
Every time you see a distribution written $X \sim F(\theta)$ — think two thoughts: (1) the shape $F$ is an assumption, drawn from a library (Exponential, Normal, Beta, ...), and (2) the parameters $\theta$ are unknown real-world quantities that data will help us estimate. A good statistician argues about both: "Is it really Exponential? And if so, what's the rate — and how uncertain is that estimate?" These are separate questions, and Track 3 isolates the vocabulary you need for each.

You met this in Track 2. Here we sharpen it with a practical diagnostic: how do I know which I'm looking at from raw data?

⚠ The trap — "looks continuous" isn't continuous

Order value in rupees looks continuous at a glance, but is actually discrete (increments of ₹0.01 or whole rupees). Delivery time in minutes rounded to whole minutes? Discrete. The rule of thumb: if your data provider rounded or quantized the measurement, treat it as discrete for exact calculations but continuous for approximations. Gaussian approximations to rupee distributions work fine even though rupees are technically discrete — the quantization is much finer than the variation.

PMF — The Discrete Object of Interest

Probability Mass Function
$$p_X(k) = P(X = k), \qquad p_X(k) \ge 0, \qquad \sum_{k \in \text{supp}(X)} p_X(k) = 1$$

The PMF as an estimation target — Kartify daily return count

Let $X$ = number of returns Kartify receives on a random day. $X$ is discrete (non-negative integer). The PMF is $p_X(k) = P(X = k)$, a function over $\{0, 1, 2, \ldots\}$. Two ways to get at it:

Empirical PMF from data — the nonparametric approach
1
Collect $n$ days of data. Observe $x_1, x_2, \ldots, x_n$.
2
Empirical PMF: $\hat{p}_X(k) = \dfrac{1}{n} \sum_{i=1}^n \mathbb{1}[x_i = k]$ — count the fraction of days with exactly $k$ returns.
3
As $n \to \infty$, $\hat{p}_X(k) \to p_X(k)$ by the Law of Large Numbers (Module 3.7).
Parametric PMF — assume a shape
1
Assume $X \sim \text{Poisson}(\lambda)$ for some unknown $\lambda$.
2
Now $p_X(k) = \lambda^k e^{-\lambda} / k!$ — a function of $\lambda$, not a free object.
3
Estimating the distribution reduces to estimating $\lambda$. Much easier than estimating a free PMF — one parameter vs infinitely many $p_X(k)$ values.
The bias-variance trade-off of parametric vs nonparametric
Empirical PMF is unbiased but has high variance for rare values (if $k = 23$ only appeared twice, $\hat{p}_X(23) = 2/n$ is noisy). Parametric Poisson estimate is biased (the true distribution may not be exactly Poisson) but has low variance (one parameter). This is the defining trade-off of statistical modeling. Reject the false choice; most real work uses the parametric estimate as a baseline and checks residuals against the empirical shape.

PDF — The Continuous Object of Interest

Probability Density Function
$$P(a \le X \le b) = \int_a^b f_X(x)\, dx, \qquad f_X(x) \ge 0, \qquad \int_{-\infty}^\infty f_X(x)\, dx = 1$$
⚠ Track 2 recap — density is not probability

$f_X(x)$ is a rate of probability accumulation. $P(X = x) = 0$ for any $x$; only intervals have positive probability. A PDF value can exceed 1 (density of Uniform$[0, 0.1]$ is 10). When in doubt, ask: "can I integrate this?" If yes, it's a density; if not, it's already a probability.

Kartify delivery time — parametric PDF estimation in practice

From histogram to PDF — the standard workflow
Step 1. Look. Plot a histogram of 100,000 delivery times (bin width 1 hour). Shape is right-skewed, peaked near zero, decaying tail.
Step 2. Hypothesize. The right-skew + monotone decay suggests Exponential. Alternative shapes: Gamma (more flexible), Log-Normal (heavier tail), Weibull.
Step 3. Estimate. If Exp$(\lambda)$: $\hat{\lambda} = 1 / \bar{t}$ (MLE — Track 4). Sample mean $\bar{t} = 18.3$, so $\hat{\lambda} = 0.0547$.
Step 4. Validate. Overlay $f_T(t) = \hat{\lambda} e^{-\hat{\lambda} t}$ on the histogram. Gaps in the fit (e.g., a bump around 24h from "next-day delivery" orders) indicate model inadequacy.
Conclusion. No single PDF fits Kartify delivery times perfectly — real data usually is a mixture. In production, a two-component mixture (fast and slow logistics lanes) often works. For planning calculations, a single Exp($\hat{\lambda}$) is the pragmatic approximation.

CDF — The Unified Object

The Cumulative Distribution Function works for every random variable — discrete, continuous, mixed. It's the lingua franca of probability distributions.

CDF · the universal definition
$$F_X(x) = P(X \le x), \qquad F_X : \mathbb{R} \to [0, 1]$$
PropertyStatementWhy it holds
Non-decreasing$a \le b \Rightarrow F_X(a) \le F_X(b)$$\{X \le a\} \subseteq \{X \le b\}$; probability is monotone
Limits$F_X(-\infty) = 0$, $F_X(+\infty) = 1$Kolmogorov A2 (normalization)
Right-continuous$\lim_{x \to a^+} F_X(x) = F_X(a)$Events $\{X \le a\}$ are closed from the right
Interval probability$P(a < X \le b) = F_X(b) - F_X(a)$Additivity on disjoint sets
Atoms (discrete jumps)$P(X = a) = F_X(a) - F_X(a^-)$Right-continuity + jump size = point mass

Why CDF is the universal object

⚡ Three reasons CDFs win in practice

1. Always well-defined. A mixed discrete-continuous distribution has no PMF or PDF, but it has a CDF. Example: an insurance claim is often "0 with probability 0.95, else continuous positive amount" — mixed.

2. Percentiles fall out. "95th percentile delivery time" is just $F^{-1}(0.95)$ — the quantile function (next section).

3. Empirical CDF converges. $\hat{F}_n(x) \to F(x)$ uniformly in $x$ (Glivenko-Cantelli theorem). No such uniform convergence exists for empirical PMFs / PDFs without smoothing.

Kartify · CDF of daily returns (Poisson model)
Model: $X \sim \text{Poisson}(\lambda = 8)$.
CDF at 10: $F_X(10) = \sum_{k=0}^{10} 8^k e^{-8} / k! \approx 0.816$. About 82% of days have ≤ 10 returns.
Interval probability: $P(5 \le X \le 10) = F_X(10) - F_X(4) \approx 0.816 - 0.100 = 0.716$.
Atom: $P(X = 8) = F_X(8) - F_X(7) \approx 0.593 - 0.453 = 0.140$ — the jump size at $k = 8$.
Key insight. The CDF encodes everything — the PMF is recovered as jump sizes, the interval probabilities as differences. In a single function, all probabilistic information.

The Quantile Function — CDFs Run Backwards

The CDF maps $x \mapsto P(X \le x)$ — a value to a probability. The quantile function is the inverse: it maps a probability $u \in [0, 1]$ to the $x$ such that $F(x) = u$. The language of percentiles.

Quantile function (generalised inverse CDF)
$$Q_X(u) = F_X^{-1}(u) = \inf \{ x : F_X(x) \ge u \}, \qquad u \in [0, 1]$$

The $\inf$ definition handles two edge cases: (1) discrete distributions where $F_X$ jumps and there's no $x$ with $F_X(x) = u$ exactly, and (2) flat stretches of $F_X$ where multiple $x$ satisfy $F_X(x) = u$. Taking the infimum picks the leftmost such $x$ — giving a well-defined function for any distribution.

Kartify — percentile planning with the quantile function

Kartify · SLA planning — what hour delivers 95% of orders?
Model: delivery time $T \sim \text{Exp}(\lambda = 1/18)$.
CDF: $F_T(t) = 1 - e^{-t/18}$.
Invert: solve $1 - e^{-t/18} = 0.95$, giving $t = -18 \ln(0.05) \approx 53.9$ hours.
Therefore: $Q_T(0.95) = 53.9$ — to hit a "95% of orders delivered within X hours" promise, Kartify needs $X \ge 54$h.
Business translation. The quantile function is the language executives and customers speak. "90th percentile load time," "99th percentile tail latency," "5th percentile bottom users" — all quantile function values. Whenever a KPI says "at the P$k$" — that's $Q(k/100)$.
Median
$Q(0.5)$
Kartify delivery median $= -18 \ln 0.5 \approx 12.5$ hours. Half of orders arrive within 12.5h. The median is the 50th percentile.
Quartiles
$Q(0.25), Q(0.75)$
Kartify order value Q1 = ₹450, Q3 = ₹2,100. The middle 50% of orders span this range — the interquartile range (IQR), a robust alternative to variance.
Tail percentiles
$Q(0.95), Q(0.99)$
P95 latency, P99 checkout time, P99.9 fraud score. The language of SLAs and alerting thresholds. Every observability dashboard runs on these numbers.
Confidence intervals
$[Q(0.025), Q(0.975)]$
The 95% central region — 2.5% in each tail. Bayesian credible intervals; empirical percentile-based confidence intervals. The backbone of statistical reporting.

The Inverse-CDF Method — How Every Simulator Actually Works

Here's a genuinely beautiful theorem that every data scientist should know: you can generate samples from any distribution using only uniform random numbers.

Inverse-CDF (Probability Integral Transform) theorem
$$U \sim \text{Uniform}(0, 1) \;\;\Rightarrow\;\; F^{-1}(U) \sim F$$
Proof — three lines
1
Let $X = F^{-1}(U)$. We want to show that $X$ has CDF $F$ — i.e., $P(X \le x) = F(x)$.
2
$P(X \le x) = P(F^{-1}(U) \le x) = P(U \le F(x))$ — since $F$ is non-decreasing, applying $F$ to both sides preserves the inequality.
3
$P(U \le F(x)) = F(x)$ — because $U$ is Uniform$(0,1)$, so $P(U \le u) = u$ for $u \in [0, 1]$. $\blacksquare$
Why this theorem is astonishing in practice
Every RNG in every language produces Uniform$(0, 1)$ bits. To sample from Exponential: draw $U$, compute $-\ln(1 - U) / \lambda$. To sample from any distribution whose CDF you can invert: one line of code. Even when $F^{-1}$ has no closed form, numerical inversion via binary search on $F$ works. Everything downstream — Monte Carlo, bootstrap, MCMC starting points, simulation-based inference — rests on this single identity.
Kartify · generating Exponential delivery times from Uniforms
Target: samples from Exp$(\lambda)$ with $\lambda = 1/18$.
CDF: $F(t) = 1 - e^{-\lambda t}$.
Inverse: solve $u = 1 - e^{-\lambda t}$ for $t$: $t = -\ln(1 - u) / \lambda$.
Algorithm: (1) draw $U \sim \text{Uniform}(0,1)$; (2) return $T = -\ln(1 - U) / \lambda$.
Validate: 10,000 samples should have $\bar{t} \approx 18$ and histogram matching the Exponential PDF. Both hold by the theorem.

Python — PMF, PDF, CDF, Quantile, Inverse-CDF Sampling

python · empirical vs theoretical PMF for Kartify daily returns
import numpy as np
from scipy.stats import poisson

# "Ground truth": Kartify daily returns ~ Poisson(8)
np.random.seed(42)
lam_true = 8
n = 500                            # 500 days of observations
samples = np.random.poisson(lam_true, n)

# Empirical PMF — just count fractions
k_range = np.arange(0, 20)
emp_pmf = np.array([(samples == k).mean() for k in k_range])

# Theoretical PMF — from parametric model
theor_pmf = poisson.pmf(k_range, mu=lam_true)

# Largest discrepancy
max_gap = np.abs(emp_pmf - theor_pmf).max()
print(f"Max |empirical − theoretical| PMF gap (n={n}): {max_gap:.4f}")

# As n grows, gap shrinks at rate 1/sqrt(n) (Law of Large Numbers)
for n_try in [100, 1000, 10000, 100000]:
    s = np.random.poisson(lam_true, n_try)
    ep = np.array([(s == k).mean() for k in k_range])
    print(f"  n={n_try:>6}  max gap = {np.abs(ep - theor_pmf).max():.5f}")
python · empirical CDF and quantile function — Kartify delivery times
import numpy as np
from scipy.stats import expon

# Simulate 100,000 Kartify delivery times ~ Exp(1/18)
np.random.seed(42)
mean_hr = 18
times = np.random.exponential(scale=mean_hr, size=100_000)

# Empirical CDF — step function on sorted data
def empirical_cdf(data, x):
    data_sorted = np.sort(data)
    return np.searchsorted(data_sorted, x, side="right") / len(data)

# Theoretical CDF
theor_cdf = lambda x: 1 - np.exp(-x / mean_hr)

for t in [6, 18, 30, 54]:
    print(f"t={t:3d}: emp CDF={empirical_cdf(times, t):.4f}, theor={theor_cdf(t):.4f}")

# Quantile function — invert the CDF
for p in [0.5, 0.9, 0.95, 0.99]:
    emp_q     = np.quantile(times, p)         # empirical
    theor_q   = expon.ppf(p, scale=mean_hr)     # theoretical (ppf = percent point function)
    print(f"P{int(p*100):3d}: emp={emp_q:6.2f}h  theor={theor_q:6.2f}h")
# P95 theoretical: -18 * ln(0.05) = 53.90 hours — the SLA planning number.
python · inverse-CDF method — generate any distribution from uniforms
import numpy as np

# Generate 100,000 Exp(1/18) samples using ONLY Uniform(0,1)
np.random.seed(42)
mean_hr = 18
lam = 1 / mean_hr

# The inverse-CDF transform in one line:
U = np.random.uniform(0, 1, size=100_000)
T = -np.log(1 - U) / lam          # F^{-1}(u) = -ln(1-u)/lambda for Exponential

print(f"Mean (should be ≈18):    {T.mean():.3f}")
print(f"Std  (should be ≈18):    {T.std():.3f}")
print(f"P95  (should be ≈53.9):  {np.quantile(T, 0.95):.2f}")

# Same recipe works for ANY distribution whose CDF can be inverted.
# This is literally how np.random.exponential is implemented under the hood.
