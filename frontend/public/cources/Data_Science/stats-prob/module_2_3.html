& Distributions

Events give you TRUE/FALSE. Random variables give you numbers. This is the bridge from "did it rain?" to "how much rain?" — and it's the foundation on which every ML model, every risk calculation, and every Kartify dashboard metric sits.

⚡ Kartify — Three Questions Priya Cannot Answer With Events Alone
Wednesday morning standup. The Bayes fraud fight from yesterday is settled — flags go to manual review, not auto-block. Priya opens her notebook with three new questions from different product owners:

Q1 (Ops): "In a batch of 3,000 orders, how many returns should I staff the warehouse for?" She cannot answer this with $P(\text{return})$ alone — she needs a number between 0 and 3,000.

Q2 (Logistics): "How long until the next delivery is late?" Not "will it be late" — a duration, in hours.

// Section 1

What Is a Random Variable?

Events partition the sample space; random variables assign numbers to outcomes. Formally:

Definition — Random Variable (Evans & Rosenthal §2.1)
$$X : S \to \mathbb{R}$$
$S$
sample space (all outcomes)
$X(\omega)$
a real number assigned to outcome $\omega$
$\{X \le x\}$
the event $\{\omega : X(\omega) \le x\} \subseteq S$

A random variable is a function from outcomes to real numbers. That's it. The "randomness" lives in the outcome $\omega$; $X$ just tags it with a number. Once you see this, every distribution formula stops being mysterious.

Three Kartify random variables — concretely

$X$ — Discrete
Number of returns in 3,000 orders
$X : S \to \{0, 1, 2, \ldots, 3000\}$. Counts. Priya's staffing question. Takes integer values only. This is the setup for the Binomial distribution (Module 2.4).
$T$ — Continuous
Time until next late delivery (hours)
$T : S \to [0, \infty)$. A real positive number. Can be 2.3h, 14.7h, 0.08h. Continuous — infinitely many possible values. Setup for the Exponential distribution (Module 2.5).
$R$ — Continuous
Tomorrow's revenue (₹)
$R : S \to [0, \infty)$. Sum of many small contributions from individual orders. By CLT (Module 4.2) $R$ is approximately Normal — the most important continuous distribution in all of statistics.
$K$ — Discrete
Customer's star rating
$K : S \to \{1, 2, 3, 4, 5\}$. Finite, ordered, discrete. Simple but not a "named" distribution — Kartify would model $K$ empirically from historical data (categorical distribution).
Why the "function" definition matters
Thinking of $X$ as a function makes transformations obvious. Want revenue in USD instead of ₹? That's $R/83$ — another random variable, same underlying outcome. Want squared deviation from mean? That's $(X - \mu)^2$ — another random variable. Every manipulation you do on $X$ produces a new random variable with its own distribution. Transforming random variables is the entire job of feature engineering in ML.

Discrete Random Variables & the PMF

A random variable is discrete if it takes values in a countable set — integers, labels, finite enumerations. The Probability Mass Function (PMF) tells us how probability is distributed across those values.

Probability Mass Function
$$p_X(x) = P(X = x), \qquad \sum_{x \in \text{support}(X)} p_X(x) = 1, \qquad p_X(x) \ge 0$$

Two requirements, both inherited from Kolmogorov: non-negativity (A1) and normalization (A2). The PMF is a complete description of a discrete random variable — know $p_X$ and you know everything.

Kartify PMF — returns in a batch of 5

Consider a small batch of 5 orders, each with $P(\text{return}) = 0.08$. Let $X$ = number of returns in the batch. $X \in \{0, 1, 2, 3, 4, 5\}$. Using independence (each order independent of others) and counting:

Deriving the PMF cell by cell
1
$p_X(0) = P(\text{all kept}) = 0.92^5 = 0.659$ Independence: each kept = 0.92, five in a row.
2
$p_X(1) = \binom{5}{1} \cdot 0.08 \cdot 0.92^4 = 5 \cdot 0.08 \cdot 0.7164 = 0.287$ Five ways to choose which of the 5 orders is the one that returned.
3
$p_X(2) = \binom{5}{2} \cdot 0.08^2 \cdot 0.92^3 = 10 \cdot 0.0064 \cdot 0.7787 = 0.0498$
4
$p_X(3) = \binom{5}{3} \cdot 0.08^3 \cdot 0.92^2 = 10 \cdot 0.000512 \cdot 0.8464 = 0.00433$
5
$p_X(4) = \binom{5}{4} \cdot 0.08^4 \cdot 0.92 = 5 \cdot 0.0000410 \cdot 0.92 = 0.000188$
6
$p_X(5) = 0.08^5 = 3.28 \times 10^{-6}$
7
Check: $\sum p_X(x) = 0.659 + 0.287 + 0.0498 + 0.00433 + 0.000188 + 0.00000328 \approx 1.000$ ✓ Normalization holds — this is a valid PMF.
How to think about a PMF
A PMF is a mass placed on each possible value — like pebbles of different weights on integers. Total mass always equals 1. Business interpretation: 66% of 5-order batches have zero returns; 29% have exactly one. Priya staffing for the 99th percentile needs $P(X \ge 3) = 0.00433 + 0.000188 + 0.00000328 \approx 0.0045$ — very rare. PMF tells her that.
Interactive PMF — returns in a batch
Binomial($n$, $p$)
$p_X(x)$ — probability massexpected value $np$

Cumulative Distribution Function (CDF)

The PMF answers "$P(X = x)$?" The CDF answers "$P(X \le x)$?" — cumulative probability up to and including $x$. It's the tool for answering threshold questions: "what's the probability of at most 10 returns?"

Cumulative Distribution Function
$$F_X(x) = P(X \le x) = \sum_{k \le x} p_X(k) \quad \text{(discrete)}$$

Key properties — these hold for every CDF, discrete or continuous:

P1
Non-decreasing
$a \le b \Rightarrow F_X(a) \le F_X(b)$
Cumulative can only grow as threshold rises. Derivable from monotonicity.
P2
Limits
$\lim_{x\to -\infty} F_X = 0$, $\lim_{x\to\infty} F_X = 1$
Sample-space normalization pushes CDF to 0 at the bottom, 1 at the top.
P3
Right-continuous
$\lim_{x \to a^+} F_X(x) = F_X(a)$
Jumps up at discrete mass points; continuous from the right.
P4
Interval probability
$P(a < X \le b) = F_X(b) - F_X(a)$
The single most-used identity in applied probability. Every "between $a$ and $b$" question is a CDF subtraction.
Kartify · CDF — at most 2 returns in batch of 5
Using PMF values from above:
$F_X(0) = p_X(0) = 0.659$
$F_X(1) = p_X(0) + p_X(1) = 0.659 + 0.287 = 0.946$
$F_X(2) = F_X(1) + p_X(2) = 0.946 + 0.0498 = 0.9958$
Answer. $P(X \le 2) = 99.58\%$. Equivalently, $P(X \ge 3) = 1 - 0.9958 = 0.42\%$. If Priya ships 5-order batches, needing to handle 3+ returns in one batch happens less than 1 in 200 batches.
Why CDF is the real workhorse
PMF tells you probability at a point. CDF tells you probability up to a threshold — which is almost always what the business question actually needs. "Will more than 400 orders be returned?" is $1 - F_X(400)$. "Will revenue fall between ₹10 lakh and ₹12 lakh?" is $F_X(12L) - F_X(10L)$. Almost every business question about a random variable is a CDF computation in disguise.

Continuous Random Variables & the PDF

For continuous random variables — like delivery time, order value, customer age — every exact value has probability zero. $P(T = 3.14159\ldots) = 0$. You cannot have a PMF. Instead, probability lives in densities.

Probability Density Function (PDF)
$$P(a \le X \le b) = \int_a^b f_X(x)\, dx, \qquad f_X(x) \ge 0, \qquad \int_{-\infty}^{\infty} f_X(x)\, dx = 1$$
⚠ $f_X(x)$ is not a probability

A PDF value can exceed 1 (!). For example, a Uniform distribution on $[0, 0.1]$ has $f_X(x) = 10$ for $x \in [0, 0.1]$. That's fine — densities are probabilities per unit length. Only when you integrate over an interval do you get a real probability in $[0, 1]$. This single confusion trips up 90% of beginners.

CDF for continuous — integrate the PDF
1
$F_X(x) = P(X \le x) = \int_{-\infty}^x f_X(t)\, dt$ CDF is the cumulative integral of the density.
2
By the Fundamental Theorem of Calculus: $f_X(x) = \dfrac{d}{dx} F_X(x)$ PDF is the derivative of the CDF — wherever $F_X$ is differentiable.
3
Corollary: $P(a \le X \le b) = F_X(b) - F_X(a)$ Same interval formula as discrete — CDF subtraction is universal.
4
Continuous special case: $P(X = a) = 0$ for any $a$, so $P(a \le X \le b) = P(a < X < b)$. Endpoints don't matter.

Kartify — delivery time as a continuous RV

Delivery time modeled as Exponential(rate $\lambda$)
Setup. Let $T$ = delivery time in hours. From historical Kartify data, the mean delivery time is 18h, so rate $\lambda = 1/18$ per hour.
PDF. $f_T(t) = \lambda e^{-\lambda t} = \dfrac{1}{18} e^{-t/18}$ for $t \ge 0$.
CDF. $F_T(t) = 1 - e^{-t/18}$ for $t \ge 0$.
Q: $P(T > 24)$ — probability delivery takes over 24 hours?
Math. $P(T > 24) = 1 - F_T(24) = e^{-24/18} = e^{-1.333} \approx 0.264$
Answer. 26.4% of deliveries take more than 24 hours. If Kartify's SLA promises "delivery within 24h," one in four orders will breach it. That's the number Rohan needs to negotiate SLA improvements with the logistics partner.

Support, Transformations & New Random Variables

The support of $X$ is the set of values $X$ actually takes with positive probability (or positive density). Beyond support, $p_X$ or $f_X$ is zero.

Finite support
Star rating $K$
$\text{supp}(K) = \{1,2,3,4,5\}$. $p_K(6) = 0$ — not a valid rating.
Countable support
Return count $X$
$\text{supp}(X) = \{0, 1, 2, \ldots\}$ (or $\{0, \ldots, n\}$ for Binomial). $p_X(-1) = 0$.
Continuous support
Delivery time $T$
$\text{supp}(T) = [0, \infty)$. $f_T(-2) = 0$ — negative delivery makes no sense.
Bounded support
Return-rate estimate $\hat p$
$\text{supp}(\hat p) = [0, 1]$. Kartify's daily return rate estimates live here — Beta distribution (Module 2.5).

Transformation of a random variable

If $Y = g(X)$ for some function $g$, then $Y$ is itself a random variable. Its distribution is derived from $X$'s.

Change of Variables — continuous, monotone $g$
$$f_Y(y) = f_X(g^{-1}(y)) \cdot \left|\frac{d\, g^{-1}(y)}{dy}\right|$$

The $|dg^{-1}/dy|$ term is the Jacobian — it accounts for how the transformation stretches or compresses probability density. This formula is the backbone of normalizing flows and many generative models.

Kartify · revenue in USD vs ₹
Setup. Let $R$ = daily revenue in ₹, with some PDF $f_R$. Let $Y = R/83$ (USD conversion). We want $f_Y$.
Transform. $g(r) = r/83$; $g^{-1}(y) = 83y$; $dg^{-1}/dy = 83$.
Apply formula. $f_Y(y) = f_R(83y) \cdot 83$
Sanity check. If $R$ has mean ₹10,00,000, then $Y$ has mean $10{,}00{,}000/83 \approx 12{,}048$ USD. The Jacobian factor of 83 correctly normalizes: density in USD is ~83× the density in ₹ at corresponding values, because 1 USD spans 83 ₹.
Why every ML engineer ends up memorizing this
Transformations are everywhere: log-transform for skewed data, z-score standardization, softmax, sigmoid. Every one of these maps one random variable to another, and the Jacobian tracks how probability density stretches. Normalizing flows are literally stacks of invertible transformations with Jacobians accumulating. Variational autoencoders use the same machinery. Master change-of-variables once, and half of modern generative modeling becomes bookkeeping.

Expectation & Variance — First Moments

A PMF or PDF is complete information about a random variable — but usually we want summary numbers. The two most important: expected value (where the distribution is centered) and variance (how spread out it is). Module 2.7 treats these in depth; here we introduce the essentials.

Expected Value
$$E[X] = \sum_{x} x \cdot p_X(x) \quad \text{(discrete)} \qquad\qquad E[X] = \int_{-\infty}^{\infty} x \cdot f_X(x)\, dx \quad \text{(continuous)}$$
Variance — and Standard Deviation
$$\mathrm{Var}(X) = E\big[(X - E[X])^2\big] = E[X^2] - (E[X])^2, \quad \sigma_X = \sqrt{\mathrm{Var}(X)}$$
Kartify · expected returns in a batch of 5
Using PMF from Section 2:
$E[X] = 0(0.659) + 1(0.287) + 2(0.0498) + 3(0.00433) + 4(0.000188) + 5(0.00000328)$
$= 0 + 0.287 + 0.0996 + 0.01299 + 0.000752 + 0.0000164 \approx 0.400$
Answer. $E[X] = 0.400$ returns per 5-order batch. Equivalently, $0.400/5 = 0.08$ return rate per order — exactly $p$. This is the Binomial shortcut: $E[X] = np$ (proved in 2.7). The long PMF summation matches the one-line formula.
The bridge to the rest of Track 2
PMF/PDF/CDF are the shape of a random variable. Expectation and variance are its summary. Modules 2.4 and 2.5 introduce the named distributions (Binomial, Normal, Exponential, ...) — for each one, the closed-form PMF/PDF, CDF, mean, and variance. Module 2.6 joins random variables. Python — PMFs, PDFs, CDFs in Code

python · discrete PMF and CDF for Kartify batch returns
from scipy.stats import binom
import numpy as np

n, p = 5, 0.08                     # batch size, return rate
X_values = np.arange(0, n+1)

# PMF — P(X = k) for k=0..5
pmf = binom.pmf(X_values, n, p)
for k, pk in zip(X_values, pmf):
    print(f"P(X = {k}) = {pk:.5f}")
# Sum check — must equal 1
print(f"Sum of PMF: {pmf.sum():.6f}")   # 1.000000

# CDF — P(X ≤ k)
cdf = binom.cdf(X_values, n, p)
print(f"P(X ≤ 2) = {binom.cdf(2, n, p):.4f}")   # 0.9958
print(f"P(X ≥ 3) = {1 - binom.cdf(2, n, p):.4f}")   # 0.0042

# Expected value and variance — two ways
E_from_pmf = (X_values * pmf).sum()             # definition
E_closed   = n * p                               # binomial shortcut
print(f"E[X] = {E_from_pmf:.4f}  (= np = {E_closed})")
python · continuous PDF, CDF, and inverse-CDF for delivery time
from scipy.stats import expon

mean_hr = 18                              # mean delivery time in hours
lam = 1 / mean_hr                         # rate parameter

# scipy.expon is parameterized by scale=1/lambda (= mean)
T = expon(scale=mean_hr)

print(f"f_T(18)  density = {T.pdf(18):.5f}")       # density at t=18h
print(f"F_T(24)  = P(T ≤ 24)  = {T.cdf(24):.4f}")   # 0.7364
print(f"P(T > 24) SLA breach = {1 - T.cdf(24):.4f}")   # 0.2636

# Inverse CDF — 95th percentile delivery time
t95 = T.ppf(0.95)
print(f"95% of deliveries arrive within {t95:.1f} hours")   # 53.9 h

# Why this matters: Kartify's SLA should be "within 54 hours" to hit 95% on-time
python · transformation — from ₹ revenue to USD
import numpy as np
from scipy.stats import norm

# Suppose daily revenue R (in ₹ lakh) is approximately Normal
mu_inr, sig_inr = 45, 8                   # ₹45 lakh ± ₹8 lakh daily
R = norm(loc=mu_inr, scale=sig_inr)

# Convert to USD: Y = R * 100000 / 83   (lakh → USD, 1 USD = ₹83)
# Linear transform of Normal is Normal: Y ~ N(mu*k, sigma^2 * k^2)
k = 100000 / 83
mu_usd = mu_inr * k
sig_usd = sig_inr * abs(k)
Y = norm(loc=mu_usd, scale=sig_usd)

print(f"Daily revenue: ₹{mu_inr} lakh = ${mu_usd:,.0f}")
print(f"P(revenue > ₹50 lakh) = {1 - R.cdf(50):.3f}")
print(f"Equivalently, P(Y > ${50*k:,.0f}) = {1 - Y.cdf(50*k):.3f}")
# Same probability. Transformations preserve event probabilities — just rescale axes.
