Key Discrete
Distributions

Six shapes that cover 95% of count-and-classify problems. For each: the PMF, the mean and variance, the situation that generates it, and the method-of-moments estimator that Track 4 will formalize. Think of this module as both a reference and a preview of inference.

⚡ Kartify — The Inventory Audit
Tuesday morning. Kartify Warehouse 4 is doing a quality audit. They have 1,200 units of the new Bluetooth earbuds in stock. QA samples 50 units without replacement to inspect for defects. They find 4 defective. Leadership wants: "What's our true defect rate, and how confident are we?"

This is not Binomial — Binomial assumes independent trials, but sampling without replacement changes the urn after each pick. The correct model is Hypergeometric, and ignoring the distinction costs you accurate confidence intervals when the sample is a non-trivial fraction of the population.

Module 3.2 walks through the six discrete distributions you'll actually meet at Kartify-scale companies. Each with (a) the generating story, (b) the PMF, (c) mean and variance, (d) how to estimate its parameter from observed data — the preview of MLE that Track 4 will complete. We build these in order of increasing complexity: Bernoulli → Binomial → Geometric → Negative Binomial → Poisson → Hypergeometric. At the end, the decision table: reading a business question and picking the right distribution.

The Six-Way Decision — Situation → Distribution

SituationDistributionNatural Kartify scenario
Single trial, two outcomesBernoulli($p$)Is this one order fraud? (yes/no)
$n$ fixed independent trials, count successesBinomial($n, p$)Out of 3,000 orders, how many returns?
Wait until first successGeometric($p$)How many orders before next fraud?
Wait until $r$-th successNegBin($r, p$)Emails to send for 100 redemptions?
Count events in a fixed intervalPoisson($\lambda$)Support tickets per hour
Sample without replacement from a finite poolHypergeom$(N, K, n)$Defects found in a 50-item audit from 1,200 units
The three diagnostic questions for any count problem
(1) Binary or count? If binary → Bernoulli family. If count of events → Poisson family.
(2) Fixed sample size, or waiting for a condition? Fixed → Binomial. Waiting → Geometric (1 success) or NegBin ($r$ successes).
(3) Independent trials, or sampling without replacement from a finite pool? Independent → Binomial. Finite pool → Hypergeometric. The difference matters when sample is a large fraction of the population.
// Section 2

Bernoulli — One Trial, Two Outcomes

Bernoulli$(p)$ · PMF, mean, variance
$$p_X(x) = p^x (1-p)^{1-x} \text{ for } x \in \{0, 1\}, \quad E[X] = p, \quad \mathrm{Var}(X) = p(1-p)$$
Kartify · the per-order fraud indicator
Setup. $X_i = 1$ if order $i$ is fraud, else $0$. Base rate $p$ — unknown, must be estimated from history.
Estimation (preview of Track 4). Given $n$ orders with $s$ fraud, $\hat{p} = s/n$. This is both the MLE and the method-of-moments estimator — they agree for Bernoulli.
Uncertainty. $\mathrm{Var}(\hat{p}) = p(1-p)/n$, so $\mathrm{SE}(\hat{p}) = \sqrt{p(1-p)/n}$. For $n = 10{,}000$ orders, $p = 0.01$: $\mathrm{SE} = 0.00099$ — ±0.1%.
ML translation. Every binary classifier outputs $P(Y = 1 \mid X)$ — a conditional Bernoulli probability. Logistic regression: $P(Y = 1 \mid X) = \sigma(w^T X + b)$. Training fits $w, b$ to match observed $X_i$s — Bernoulli MLE under the hood.
// Section 3

Binomial — Sum of i.i.d. Bernoullis

Binomial$(n, p)$ · PMF, mean, variance
$$p_X(k) = \binom{n}{k} p^k (1-p)^{n-k}, \quad E[X] = np, \quad \mathrm{Var}(X) = np(1-p)$$
Why Binomial is Bernoulli's big sibling — the identity
1
Given $n$ i.i.d. Bernoulli$(p)$: $X_1, \ldots, X_n$. Each outputs $\{0, 1\}$.
2
Let $X = X_1 + X_2 + \ldots + X_n$ — the total number of successes.
3
By linearity: $E[X] = np$. By independence: $\mathrm{Var}(X) = np(1-p)$.
4
The PMF $\binom{n}{k} p^k (1-p)^{n-k}$ counts the $\binom{n}{k}$ orderings that give exactly $k$ successes, each with probability $p^k(1-p)^{n-k}$.

Kartify — the Delhi return-spike formalized

Parameter estimation for a Binomial
Observed. 420 returns out of 3,000 Delhi orders.
Naïve estimate of $p$. $\hat{p} = 420 / 3000 = 0.140$.
Null model. Historical $p = 0.08$. Under that, $\mathrm{Var}(X) = 3000 \times 0.08 \times 0.92 = 220.8$, $\sigma = 14.86$.
Z-score of observed. $(420 - 240) / 14.86 = 12.1\sigma$.
Preview of Track 5: the tail probability $P(X \ge 420 \mid p = 0.08) \approx 6.4 \times 10^{-38}$ rejects the null at any imaginable significance level. The Delhi rate is not 0.08; it has changed.
◆ The Binomial-Normal approximation — when you can use it

When $n$ is large and $p$ isn't too close to 0 or 1, Binomial$(n, p) \approx$ Normal$(np, np(1-p))$ (by CLT, Module 3.8). Rule of thumb: $np \ge 10$ AND $n(1-p) \ge 10$. For the Delhi case: $np = 240$, $n(1-p) = 2760$ — both well past the threshold, so the Normal approximation works. Kartify's p-value can be computed via either the exact Binomial tail or a Normal Z-score; they agree to many decimals in this regime.

// Section 4

Geometric — Wait Until the First Success

Geometric$(p)$ · trial form ($k \ge 1$)
$$p_X(k) = (1-p)^{k-1} p, \quad E[X] = \frac{1}{p}, \quad \mathrm{Var}(X) = \frac{1 - p}{p^2}$$
⚠ Two Geometric conventions — check which your library uses

Trial form (used above): $X$ = the trial on which the first success occurs; $X \in \{1, 2, 3, \ldots\}$; $E[X] = 1/p$.

Failures form: $X$ = failures before the first success; $X \in \{0, 1, 2, \ldots\}$; $E[X] = (1 - p)/p$.

scipy.stats.geom and np.random.geometric both use the trial form. Wikipedia varies. Always check.

Kartify · estimating the fraud rate from inter-fraud spacing
Setup. Kartify observes spacings between fraud events: 87, 134, 76, 201, 95, 142 orders (6 samples).
Method of moments. $E[X] = 1/p \Rightarrow \hat{p} = 1 / \bar{X}$. Sample mean is $(87+134+76+201+95+142)/6 = 122.5$. So $\hat{p} \approx 0.00816$ — ~0.82%.
Comparison. The base rate of 1% would give $E[X] = 100$; we observed $\bar{X} = 122.5$, suggesting slightly lower fraud than expected. One of Track 4's jobs will be to quantify whether this 0.82% is meaningfully below 1%.
Memoryless. Geometric is the only discrete distribution that's memoryless: $P(X > s + t \mid X > s) = P(X > t)$. Knowing you've had no fraud in the last 100 orders doesn't change the probability for the next 100. This is why "we're due for a fraud" is always wrong.
// Section 5

Negative Binomial — Wait Until the $r$-th Success

NegBin$(r, p)$ · number of failures before $r$-th success
$$p_X(k) = \binom{k + r - 1}{k} p^r (1 - p)^k, \quad k \in \{0, 1, 2, \ldots\}$$
$$E[X] = \frac{r (1 - p)}{p}, \quad \mathrm{Var}(X) = \frac{r (1 - p)}{p^2}$$
Kartify · emails to hit 100 coupon redemptions
Setup. Redemption rate per email $p = 0.12$. Goal: $r = 100$ redemptions.
Expected failures: $E[X] = 100 \cdot 0.88 / 0.12 \approx 733$.
Total emails expected: $733 + 100 = 833$.
Standard deviation: $\sigma = \sqrt{100 \cdot 0.88 / 0.12^2} \approx 78$.
Planning. Budget for ~950 emails (95th percentile $\approx 833 + 1.96 \cdot 78 = 986$) to comfortably hit the target.
⚡ Why NegBin is also THE regression model for overdispersed counts

Poisson has variance = mean. Real-world count data often has variance > mean — "overdispersion." NegBin (reparameterized by mean $\mu$ and dispersion $r$) has $\mathrm{Var} = \mu + \mu^2/r$. As $r \to \infty$: $\mathrm{Var} \to \mu$ (recovers Poisson). As $r \to 0$: $\mathrm{Var}$ grows quadratically. Negative Binomial regression is the go-to for modeling overdispersed counts — support-ticket arrival, sales per SKU, vehicle collisions. Kartify weekly support tickets: mean 84, variance 287 → $r \approx 36$.

Poisson — Events at a Rate

Poisson$(\lambda)$
$$p_X(k) = \frac{\lambda^k e^{-\lambda}}{k!}, \quad E[X] = \lambda, \quad \mathrm{Var}(X) = \lambda$$
Poisson as the limit of Binomial — the key result
1
Consider Binomial$(n, p)$ with $n \to \infty$, $p \to 0$, but $np \to \lambda$ (constant).
2
$\binom{n}{k} p^k (1 - p)^{n-k} = \frac{n!}{k!(n-k)!} \left(\frac{\lambda}{n}\right)^k \left(1 - \frac{\lambda}{n}\right)^{n-k}$.
3
As $n \to \infty$: $\frac{n!}{n^k (n-k)!} \to 1$; $\left(1 - \frac{\lambda}{n}\right)^n \to e^{-\lambda}$; $\left(1 - \frac{\lambda}{n}\right)^{-k} \to 1$.
4
Combining: $\to \frac{\lambda^k e^{-\lambda}}{k!}$. $\blacksquare$ Poisson is Binomial in the "many opportunities, rare success" regime.
Kartify · estimating Poisson rate from historical data
Setup. Kartify observed hourly support-ticket counts over 168 hours (one week). Total tickets: 2,016.
Estimate $\hat{\lambda}$. Sample mean $= 2016 / 168 = 12.0$ tickets/hour.
Variance check. If Poisson, variance should also be 12. Observed sample variance: 16.8. Ratio $16.8 / 12 = 1.4$ — evidence of mild overdispersion.
Interpretation. Pure Poisson is a reasonable first approximation; for precise tail probability estimates (like "prob of 20+ tickets"), consider Negative Binomial to account for the extra variance. This is the standard diagnostic move.
// Section 7

Hypergeometric — Sampling Without Replacement

The model you need when the sample is a non-trivial fraction of the population and units are drawn without replacement. Binomial assumes each trial is independent (equivalent to sampling with replacement from an infinite pool). When you're inspecting 50 units out of 1,200 — 4.2% of the warehouse — Binomial overestimates variance because it ignores that removing one defective unit changes the probability for the next draw.

Hypergeometric$(N, K, n)$ · PMF, mean, variance
$$p_X(k) = \frac{\binom{K}{k} \binom{N - K}{n - k}}{\binom{N}{n}}, \quad k \in \{\max(0, n - N + K), \ldots, \min(n, K)\}$$
$$E[X] = n \cdot \frac{K}{N}, \quad \mathrm{Var}(X) = n \cdot \frac{K}{N} \cdot \frac{N - K}{N} \cdot \frac{N - n}{N - 1}$$
$N$
Population size
$K$
Successes in population
$n$
Sample size (drawn without replacement)
$k$
Successes observed in the sample
The finite-population correction factor
Note the $\frac{N - n}{N - 1}$ factor in the variance — this is the finite-population correction. When $n$ is small relative to $N$, this factor is near 1, and Hypergeometric variance matches Binomial. When $n$ approaches $N$ (sampling most of the population), variance shrinks toward zero — you're almost certain about $k$ because you've seen almost everyone. This is the statistical mechanism behind why auditing more of the pool gives tighter confidence intervals.

Kartify — the warehouse audit, correctly modeled

Earbud warehouse audit — Hypergeometric vs Binomial
Setup. $N = 1{,}200$ units. Inspect $n = 50$. Unknown true defect count $K$. Observed $k = 4$ defects.
Naïve Binomial estimate. $\hat{p} = 4/50 = 0.08$. $\mathrm{Var}_{\text{bin}}(\hat{p}) = 0.08 \times 0.92 / 50 = 0.001472$, so $\mathrm{SE} \approx 0.0384$.
Correct Hypergeometric estimate. Same $\hat{p} = 0.08$, but variance is corrected: $\mathrm{Var}_{\text{hyp}} = \mathrm{Var}_{\text{bin}} \times \frac{N - n}{N - 1} = 0.001472 \times \frac{1150}{1199} = 0.001412$. $\mathrm{SE} \approx 0.0376$.
95% CI. Binomial: $[0.08 - 1.96(0.0384), 0.08 + 1.96(0.0384)] = [0.0047, 0.155]$. Hypergeometric: $[0.0064, 0.154]$.
Takeaway. For a 4.2% sample fraction, the correction is modest (~2% tighter CI). For a 20% sample, the correction is meaningful. Always apply the finite-population correction when sample fraction exceeds ~5%.

Python — All Six in Code

python · Bernoulli / Binomial — fraud, returns, Delhi analysis
from scipy.stats import bernoulli, binom
import numpy as np

# Bernoulli — per-order fraud indicator
p_fraud = 0.01
X = bernoulli(p_fraud)
print(f"P(fraud)   = {X.pmf(1)}, Var = {X.var():.5f}")

# Binomial — Delhi return-spike exact p-value
Y = binom(n=3000, p=0.08)
print(f"E[Y] = {Y.mean()}, σ = {Y.std():.2f}")

# Z-score of observed 420 under null
z = (420 - Y.mean()) / Y.std()
p_value = 1 - Y.cdf(419)
print(f"Z = {z:.2f}σ, p-value = {p_value:.3e}")

# Parameter estimation: if you observed 420/3000, the MLE of p is 0.140
p_hat = 420 / 3000
se_p  = np.sqrt(p_hat * (1 - p_hat) / 3000)
print(f"p_hat = {p_hat:.3f} ± {1.96 * se_p:.4f} (95% CI)")
python · Geometric / Negative Binomial — fraud spacing, campaign planning
from scipy.stats import geom, nbinom
import numpy as np

# Geometric — estimate fraud rate from inter-fraud spacings
spacings = np.array([87, 134, 76, 201, 95, 142])
p_hat_geom = 1 / spacings.mean()     # method-of-moments estimator
print(f"Fraud rate estimate = {p_hat_geom:.4f} ≈ {p_hat_geom*100:.2f}%")

# Negative Binomial — emails until 100 redemptions
NB = nbinom(n=100, p=0.12)    # failures before r-th success
print(f"Expected failures: {NB.mean():.0f}, total emails: {NB.mean() + 100:.0f}")
print(f"95th percentile: {NB.ppf(0.95) + 100:.0f} emails")
python · Hypergeometric — the warehouse audit, correctly modeled
from scipy.stats import hypergeom, binom
import numpy as np

# Kartify warehouse audit: N=1200 units, n=50 inspected, true defect rate unknown
N = 1200         # population
n = 50           # sample size
K_true = 96      # hypothetical true defects (8% rate)

# Probability of observing exactly 4 defects in the sample
H = hypergeom(M=N, n=K_true, N=n)     # scipy reverses conventions — careful
print(f"Hypergeom mean: {H.mean():.2f}, var: {H.var():.3f}")

# Binomial approximation (assumes infinite population)
B = binom(n=n, p=K_true/N)
print(f"Binomial   mean: {B.mean():.2f}, var: {B.var():.3f}")

# Finite-population correction factor
fpc = (N - n) / (N - 1)
print(f"FPC factor: {fpc:.4f}  →  hypergeom var = binom var × FPC ≈ {B.var() * fpc:.3f}")

# Confidence interval for the defect rate
p_hat = 4 / n
se_bin = np.sqrt(p_hat * (1 - p_hat) / n)
se_hyp = se_bin * np.sqrt(fpc)
print(f"95% CI (Binom):   [{p_hat - 1.96*se_bin:.4f}, {p_hat + 1.96*se_bin:.4f}]")
print(f"95% CI (Hypgeo):  [{p_hat - 1.96*se_hyp:.4f}, {p_hat + 1.96*se_hyp:.4f}]")
