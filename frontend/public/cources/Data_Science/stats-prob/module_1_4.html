Moments — The Mathematical DNA of a Distribution

Every distribution can be completely described by a set of numbers called moments. Think of them as the coordinates of a distribution in shape-space. You already know the first two. The next two — skewness and kurtosis — are what this module is about.

⚡ Core Intuition

The 1st moment (mean) tells you where the distribution lives on the number line. The 2nd moment (variance) tells you how spread out it is. The 3rd moment (skewness) tells you which direction it's lopsided. The 4th moment (kurtosis) tells you how heavy the tails are. Four numbers, complete description.

Formally, the r-th central moment of a variable X is defined as:

// r-th Central Moment
μᵣ = E[(X − μ)ʳ] = (1/n) · Σ (xᵢ − μ)ʳ
// When r=1: always 0 (deviations cancel). r=2: variance. r=3: used for skewness. r=4: used for kurtosis.
⚠️ Common Misconception

Many students think "moment" is just a metaphor. It's not. The term comes directly from physics — the first moment of mass distribution around a pivot equals the center of mass. Statistics borrowed this framework exactly. The mathematics is identical.

Skewness — Measuring Asymmetry

Skewness measures how asymmetric a distribution is around its mean. A perfectly symmetric distribution (like the normal distribution) has skewness = 0. Real-world data almost never is.

// Fisher's Skewness (γ₁)
γ₁ = μ₃ / σ³ = [Σ(xᵢ − x̄)³/n] / [Σ(xᵢ − x̄)²/n]^(3/2)
// Standardised by σ³ so the result is unitless — comparable across datasets.

⚡ The Mean-Median-Mode Rule

For unimodal distributions: right-skewed → Mode < Median < Mean (mean gets pulled toward the long tail). Left-skewed → Mean < Median < Mode. This is how Priya's manager instantly spotted the problem: Kartify's price_inr had mean ₹2,400 and median ₹650 — mean is 3.7× median. Massive positive skew.

Worked Example · Kartify price_inr skewness
Data: Sample of 8 Kartify order prices (₹): 350, 450, 500, 550, 600, 700, 850, 12000
Mean: (350+450+500+550+600+700+850+12000) / 8 = 16000/8 = ₹2,000
Median: Middle two values = (550+600)/2 = ₹575
Observation: Mean (₹2,000) >> Median (₹575) — the ₹12,000 luxury item pulled the mean massively rightward
Direction: Mean > Median → right-skewed (positive γ₁)
γ₁ > 0: The ₹12,000 outlier creates a right tail — exactly what Priya's ML model was struggling with. The model saw a mean of ₹2,000 as "typical" when 87.5% of orders were below that.
// Section 3

Kurtosis — Weight of the Tails

Kurtosis measures how heavy the tails are relative to a normal distribution. High kurtosis means extreme values (outliers) occur more often than you'd expect. For Kartify's fraud detection team, this is critical — fraud events are extreme, and a high-kurtosis transaction dataset means frauds happen more often than a normal model would predict.

// Excess Kurtosis (κ — Kurt)
κ = μ₄/σ⁴ − 3
// The "−3" makes a normal distribution have excess kurtosis = 0. Most software reports excess kurtosis. Always check which one.
📊 Mesokurtic (κ ≈ 0)
Normal Distribution
Baseline. Tails are "normal weight." Most natural phenomena fall here. Kartify example: delivery_days for standard products — roughly normal, few extreme delays.
📊 Leptokurtic (κ > 0)
Heavy Tails
More extreme values than normal. Sharp peak, fat tails. Kartify example: Return rates by seller — most sellers normal, but occasional rogue sellers with 90%+ return rates.
📊 Platykurtic (κ < 0)
Light Tails
Fewer extreme values than normal. Flat peak, thin tails. Kartify example: Uniform discount_pct — evenly distributed 0%–50%, few extremes.
🚨 Why It Matters for ML
Model Assumptions
Linear regression, LDA, and many models assume normal features. High kurtosis means the model will systematically underestimate the frequency of extreme events — exactly what caused Priya's return prediction failure.
⚠️ The Kurtosis = "Peakedness" Myth

Textbooks often define kurtosis as measuring "peakedness." This is wrong. What kurtosis actually measures is tail weight — how often extreme values occur. A distribution can have high kurtosis with a flat peak if the tails are heavy. The visual peak is a side effect, not the definition.

Worked Example · Kartify delivery_days outlier analysis
Context: Kartify measures excess kurtosis of delivery_days across 10,000 orders
Result: scipy.stats.kurtosis(delivery_days) returns κ = +4.7
Interpretation: κ = +4.7 > 0 → leptokurtic — heavier tails than normal
Business meaning: Extreme delivery delays (15+ days) happen far more frequently than a normal distribution would predict. If Kartify's SLA model assumed normality, it would be underestimating breach risk significantly.
Action: Use non-parametric models or explicitly model the heavy tail with a distribution like the log-normal or Student's t. Do not assume normality for delivery_days.
// Section 4

Transformations — Fixing Skewed Data for ML

Most ML algorithms (linear regression, logistic regression, SVM, PCA) implicitly assume features are roughly normally distributed. When your data is heavily skewed, you transform it to reduce skewness before feeding it to the model. This is what Arjun did with Priya's price data.

Kartify — The One-Line Fix
Priya's data: price_inr with γ₁ = +3.2 (severely right-skewed). After np.log1p(price_inr), the transformed feature had γ₁ = +0.18 — nearly symmetric. The ML model trained on the log-transformed feature immediately found meaningful patterns in return prediction that the skewed raw data had been hiding.

⚡ Why log1p not log?

np.log(0) = −∞ (your pipeline crashes). np.log1p(x) = log(x+1), so log1p(0) = log(1) = 0. Kartify's data has orders starting at ₹0 (gifted items, free samples). Always use log1p when your data can contain zeros — which in e-commerce is almost always.

Worked Example · Log Transform on Kartify price_inr
Raw data: price_inr values: 299, 450, 650, 850, 1200, 2500, 5999, 44999
Raw stats: Mean = ₹7,118, Median = ₹1,025, γ₁ = +2.9 (heavily right-skewed)
After log1p: Values become: 5.70, 6.11, 6.48, 6.75, 7.09, 7.83, 8.70, 10.71
Transformed stats: Mean = 7.42, Median = 7.26, γ₁ = +0.2 — nearly symmetric
The log transform compressed the 150× price range (₹299 to ₹44,999) into a 1.9× range (5.70 to 10.71). The ML model can now find linear patterns in price that were invisible in the raw data.
⚠️ Never Transform Without Checking First

A common mistake: apply log transform blindly to every numeric column. Symmetric data doesn't need transformation — applying log to it will introduce left-skew. Always compute skewness (|γ₁| > 0.5 is a signal to consider transformation) before deciding. Transforming well-behaved features can hurt model performance.

💡 The AHA Moment

The log transform doesn't lie to the model — it shows the model the same data in a different coordinate system. A ₹500 vs ₹600 item (₹100 difference) is very different from a ₹5,000 vs ₹5,100 item (₹100 difference but different context). Log captures that: log(500) vs log(600) is bigger gap than log(5000) vs log(5100). The transform encodes proportional thinking, which is how price actually works.

Normality Tests — Is Your Data Normal Enough?

Before applying transformations (or deciding you need to), test whether your data is significantly non-normal. Two common tests:

🧪 Shapiro-Wilk Test
Best for small samples (n < 2000)
scipy.stats.shapiro(x) → returns (W, p-value). H₀: data is normal. If p < 0.05, reject normality. Kartify use: Testing delivery_days for a specific city/product segment.
🧪 D'Agostino-Pearson Test
Best for large samples (n > 2000)
scipy.stats.normaltest(x) → combines skewness and kurtosis into one test. H₀: data is normal. Shapiro-Wilk loses power at n>2000 — use this for Kartify's full 200K order dataset.
📌 Key Insight — The CLT Safety Net

For large samples (n > 30–50), the Central Limit Theorem guarantees that sample means are approximately normally distributed, even if the underlying data is not. So normality tests matter most when: (1) you're modeling individual values (not means), (2) n is small, or (3) you're computing confidence intervals on individual predictions. Priya's ML model was predicting individual order returns — so the skewness in individual prices absolutely mattered.

Python — Shape Statistics on Kartify Data

Python · scipy.stats + pandas · Kartify Shape Analysis 
import pandas as pd
import numpy as np
from scipy import stats

# Load Kartify orders dataset
df = pd.read_csv('kartify_orders.csv')

# ── 1. SKEWNESS & KURTOSIS ──────────────────────────────
for col in ['price_inr', 'delivery_days', 'customer_rating', 'discount_pct']:
    sk = df[col].skew()          # pandas uses Fisher's definition
    ku = df[col].kurtosis()      # excess kurtosis (normal = 0)
    print(f"{col:20s}  skew={sk:+.2f}  kurt={ku:+.2f}")

# Output (approximate):
# price_inr             skew=+3.21  kurt=+14.7  → severely right-skewed
# delivery_days         skew=+0.87  kurt=+2.10  → moderate right-skew
# customer_rating       skew=-1.24  kurt=+1.83  → left-skewed (mostly 4-5★)
# discount_pct          skew=+0.12  kurt=-0.34  → roughly symmetric

# ── 2. NORMALITY TEST ──────────────────────────────────
stat, p = stats.normaltest(df['price_inr'])
print(f"Normality test: stat={stat:.2f}, p={p:.4f}")
if p < 0.05:
    print("Reject H₀: price_inr is significantly non-normal → transform it")

# ── 3. LOG TRANSFORM & COMPARE ────────────────────────
df['log_price'] = np.log1p(df['price_inr'])

print(f"\nBefore transform: skew = {df['price_inr'].skew():+.2f}")
print(f"After log1p:      skew = {df['log_price'].skew():+.2f}")

# ── 4. BOX-COX (finds optimal λ automatically) ────────
# Note: Box-Cox requires strictly positive values
transformed, lmbda = stats.boxcox(df['price_inr'] + 1)
print(f"\nBox-Cox optimal λ = {lmbda:.3f}")
# λ≈0 → log transform was correct
# λ≈0.5 → sqrt transform would be better
# λ≈1 → data already approximately normal

# ── 5. SQRT TRANSFORM (for moderate skew) ─────────────
df['sqrt_delivery'] = np.sqrt(df['delivery_days'])
print(f"\ndelivery_days skew: {df['delivery_days'].skew():+.2f} → {df['sqrt_delivery'].skew():+.2f}")

Module 1.4 — What You Now Know
  • Statistical moments are the mathematical DNA of distributions: 1st=mean, 2nd=variance, 3rd→skewness, 4th→kurtosis
  • Skewness (γ₁) measures asymmetry: positive = right tail (Kartify prices, GMV), negative = left tail (customer ratings)
  • For right-skewed distributions: Mode < Median < Mean — the mean gets pulled toward the outliers
  • Kurtosis measures tail weight, not peakedness — high kurtosis = extreme events more common than normal model predicts
  • Most ML models assume normality — heavily skewed features degrade model performance in predictable, fixable ways
  • Use log1p for strong right skew (price, GMV), sqrt for moderate right skew (counts, delivery days), Box-Cox to auto-select
  • Always use log1p not log in production — zero-value data crashes log silently or loudly
  • Shapiro-Wilk for n < 2000, D'Agostino-Pearson for larger samples — both test H₀: data is normal, p < 0.05 rejects it
  • Box-Cox λ=0 is log, λ=0.5 is sqrt, λ=1 is no transform — it finds the optimal λ for your specific data
  • Priya's fix: one log1p line took her ML recall on returns from 12% to 71% — shape matters more than hyperparameter tuning
