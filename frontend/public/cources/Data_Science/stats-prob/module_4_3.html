Hypothesis Testing —
The Complete Framework

From data to decision. The null-hypothesis framework: formulate $H_0$ and $H_1$, pick a test statistic, compute the $p$-value, decide with a pre-specified $\alpha$. Then understand what else is hidden in the decision: Type I vs Type II errors, statistical power, sample-size economics, and the CI–test duality that collapses two apparently separate tools into one.

Module 4.3 $H_0$/$H_1$ · Test stat · $p$-value · Type I/II · Power · CI duality Kartify: is the campaign lift real? Wasserman Ch. 10 · Casella & Berger Ch. 8
⚡ Kartify — Wednesday's Decision Meeting
Wednesday. Growth team walks in: "Campaign converts at 4.08%, baseline was 3.5%, a 16% relative lift. We should roll this out nationally and increase the ad budget by ₹15 crore." The CFO looks at Priya. She has to answer one question: is 4.08% statistically different from 3.5%, or could this just be noise?

This is the central question of inference: given noisy data, is the observed effect real or is it plausibly attributable to random fluctuation? A 16% relative lift looks impressive, but with a finite sample, any point estimate has sampling variability. To decide, we formalize a claim (the null hypothesis $H_0$: $\theta = 0.035$), compute a test statistic that measures how far the data is from this claim, translate into a $p$-value (probability of data this extreme under $H_0$), and compare against a pre-specified threshold $\alpha$.

Two errors are possible. Type I (false positive, $\alpha$): we reject a true null. Rolling out a campaign that isn't actually better. Costs ₹15 cr of wasted ad spend. Type II (false negative, $\beta$): we fail to reject a false null. Missing a real winning campaign. Costs lost revenue. These errors trade off against each other. Power $= 1 - \beta$ is our ability to detect real effects. Module 4.3 walks through the full framework, ends with the CI–test duality (they're the same reasoning), and closes with a power analysis showing what Kartify's sample size can actually detect.

The Hypothesis-Testing Framework — Six Steps

NHST — the standard recipe
$$\text{(1) Specify } H_0, H_1 \;\; (2) \text{ Choose } \alpha \;\; (3) \text{ Compute test stat } T \;\; (4) \text{ Determine } p\text{-value} \;\; (5) \text{ Compare } p \text{ vs } \alpha \;\; (6) \text{ Decide}$$
1. Hypotheses
$H_0$: status quo. $H_1$: what you want to detect.
Kartify: $H_0$: $\theta = 0.035$ (baseline holds). $H_1$: $\theta > 0.035$ (one-sided — we only care about increase) or $\theta \ne 0.035$ (two-sided). Choose before seeing the data.
2. Significance level $\alpha$
Tolerance for Type I error
Convention: $\alpha = 0.05$ for most applied work, $\alpha = 0.01$ for strict contexts. In physics: $5\sigma$ ($\alpha \approx 3 \cdot 10^{-7}$). Kartify: $\alpha = 0.05$.
3. Test statistic $T$
A number summarizing how far data is from $H_0$
Kartify: $Z = (\hat p - p_0)/\mathrm{SE}$, with SE under $H_0$. $Z$'s sampling distribution is standard Normal if $H_0$ is true and $n$ is large enough. Value: 3.37.
4. $p$-value
$P(\text{test stat as extreme or more} \mid H_0)$
One-sided: $p = P(Z \ge 3.37 \mid H_0) = 0.00038$. Small $p$ = data is unusual under $H_0$. Misinterpretation warning: $p \ne P(H_0 \text{ true})$.
Kartify · the full campaign-lift test, step by step
Step 1. $H_0: \theta = 0.035$ (baseline). $H_1: \theta > 0.035$ (we want to detect an improvement). One-sided test — we don't care about a decrease in conversion; we want to know if the campaign raises it.
Step 2. $\alpha = 0.05$. Willing to accept a 5% chance of falsely rolling out a non-improving campaign.
Step 3. Under $H_0$, $\hat p$ is approximately $N(0.035, \; 0.035 \cdot 0.965 / 12000) = N(0.035, \; 2.815 \cdot 10^{-6})$. SE under $H_0 = 0.00168$. Test statistic $Z = (0.04075 - 0.035)/0.00168 = 3.42$.
Step 4. $p = P(Z \ge 3.42) = 1 - \Phi(3.42) = 0.00031$.
Step 5. $p = 0.00031 \ll \alpha = 0.05$. Reject $H_0$.
Decision. The data is highly inconsistent with "true conversion rate is 3.5%" — evidence supports that the campaign raises it. Combined with the magnitude (+0.58 percentage points), Priya recommends rolling out. This is the complete argument that pairs with the Module 4.2 CI excluding 3.5%.

Type I & Type II Errors — The Two Ways to Be Wrong

$H_0$ true (campaign doesn't help)$H_0$ false (campaign helps)
Fail to reject $H_0$✓ Correct (pr = $1 - \alpha$)✗ Type II error (pr = $\beta$)
Reject $H_0$✗ Type I error (pr = $\alpha$)✓ Correct — "Power" (pr = $1 - \beta$)
Type I
False positive, rate $\alpha$
Kartify: we claim the campaign works when it actually doesn't. Cost: ₹15 cr of wasted ad spend, brand risk. $\alpha = 0.05$ sets this risk deliberately.
Type II
False negative, rate $\beta$
Kartify: we kill the campaign when it actually would have worked. Cost: lost upside, poor decisions. $\beta$ depends on true effect size; determined by test design.
Power
$1 - \beta$
Probability of correctly detecting a real effect. Desired: ≥ 80% (or higher for high-stakes decisions). Primary lever on power: sample size.
Trade-off
$\alpha$ and $\beta$ fight each other
Lower $\alpha$ (stricter) → higher $\beta$ (miss more real effects) for fixed $n$. Escaping this trade-off requires more data.
The meta-choice: whose mistake is more expensive?
$\alpha = 0.05$ is convention, not a moral law. For stakes where Type I is catastrophic (new drug approval, safety regulation) use $\alpha = 0.01$ or stricter. For stakes where Type II is catastrophic (cancer screening, early fraud detection) accept a higher $\alpha$ but lower $\beta$ by collecting more data. The choice of $\alpha$ is a business decision about asymmetry of errors — not a statistical one. Kartify's $\alpha = 0.05$ implicitly says "I'd rather risk a 5% chance of a wasted campaign than run a bigger test."

The $p$-value — What It Is, What It Isn't

$p$-value · formal definition
$$p\text{-value} = P\!\left(T \ge t_{\text{obs}} \mid H_0\right)$$

Probability of observing a test statistic at least as extreme as what we saw, assuming $H_0$ is true. Small $p$ = the data is surprising under $H_0$ = evidence against $H_0$.

⚠ What the $p$-value is NOT

All of these are wrong and commonly stated:

  • NOT $P(H_0 \text{ true} \mid \text{data})$. That's the Bayesian posterior probability, requires a prior.
  • NOT $P(\text{data} \mid H_0 \text{ true})$. It's $P(\text{data at least this extreme} \mid H_0)$ — the tail, not the point.
  • NOT a measure of effect size. Tiny $p$ can come from large $n$ with trivial effect size. Always report effect size alongside $p$.
  • NOT the probability your result is due to chance. It's the probability of the data pattern given chance. Different quantity.
$p$ decision rule
Reject $H_0$ if $p < \alpha$
Operationally: small $p$ → the null is implausible given data. Kartify $p = 0.00031 < 0.05$ → reject.
One-sided vs two-sided
Direction matters
Two-sided: $p = 2 P(Z \ge |z_{\text{obs}}|)$. One-sided is half. Use one-sided only when you have a pre-specified direction of interest (rare in practice; default to two-sided).
Continuous $p$
$p = 0.049$ vs $p = 0.051$
Binary "significant/not" thinking hides information. ASA 2016 statement: report $p$ as a continuous evidence measure, not a yes/no. "$p = 0.08$" is weak-moderate evidence; "$p = 0.0001$" is strong.
$p$-hacking
Searching for significance
Running 20 tests and reporting the one with $p < 0.05$ guarantees false positives — Type I rate is 64% under the null, not 5%. Module 4.8 covers corrections (Bonferroni, FDR). Always register hypotheses before analysis.

CI–Test Duality — Two Views, One Truth

The duality theorem
$$\theta_0 \notin \text{CI}_{1-\alpha} \;\;\Leftrightarrow\;\; \text{Two-sided test at level } \alpha \text{ rejects } H_0: \theta = \theta_0$$
Collapsing two apparently separate tools
CIs and hypothesis tests appear to answer different questions: CIs say "where does $\theta$ plausibly live?" and tests say "is $\theta$ consistent with a specific value?" The duality theorem shows they're the same mathematical machinery, expressed differently. Given a CI, you can test any null by checking whether the null value lies inside. Given a test (for any null), you can build a CI by collecting all null values that would not be rejected. Same evidence, two presentations.
Kartify · the duality in action
Module 4.2 Wald 95% CI. $[0.0372, 0.0443]$.
Module 4.3 test. $H_0: \theta = 0.035$ rejected at $\alpha = 0.05$ (two-sided) since $0.035 \notin [0.0372, 0.0443]$.
Alternative null. Is $H_0: \theta = 0.040$ rejected? $0.040 \in [0.0372, 0.0443]$ — fail to reject. Data is consistent with $\theta = 0.04$ at 95%.
Alternative null. Is $H_0: \theta = 0.042$ rejected? $0.042 \in [0.0372, 0.0443]$ — fail to reject. Also consistent.
Takeaway. Kartify can report the CI or individual test results — both encode the same information. Modern practice: always report the CI. It shows what values are consistent with the data, not just a binary reject/fail-to-reject.
// Section 5

Statistical Power — What Can Your Sample Actually Detect?

Power — the probability of detecting a real effect of size $\delta$
$$1 - \beta = P\!\left(\text{reject } H_0 \mid H_1 \text{ true, with effect size } \delta\right)$$
Power calculation for Kartify's test
1
Under $H_0: p_0 = 0.035$, reject if $\hat p > p_0 + z_{1-\alpha} \cdot \mathrm{SE}_0 = 0.035 + 1.645 \cdot 0.00168 = 0.03776$.
2
Under $H_1$ with true $p_1 = 0.040$: $\hat p \sim N(0.040, 0.040 \cdot 0.96/12000) = N(0.040, 0.001790^2)$.
3
Power $= P(\hat p > 0.03776 \mid p_1 = 0.040) = P(Z > (0.03776 - 0.040)/0.00179) = P(Z > -1.25) = 0.894$.
4
With $n = 12{,}000$, Kartify has 89% power to detect a lift from 3.5% to 4.0%. If true lift is only to 3.7% (a "small" lift), power drops to 52%.
Power depends on
$n$, effect size $\delta$, $\alpha$, variance $\sigma^2$
Larger $n$ → more power. Larger $\delta$ → more power. Stricter $\alpha$ → less power. Higher variance → less power. These are the four levers.
Common target
80% or 90% power
A study with 50% power is a coin flip even under the alternative — weak evidence whatever the outcome. Design for $\ge 80\%$; strong studies aim for 90%+.
Minimum detectable effect
MDE — design target
The smallest effect size your study can reliably detect. Compute MDE given your $n$ and desired power. If MDE > smallest business-meaningful effect → study is underpowered, redesign.
Post-hoc power
Don't use it
Computing "observed power" using the observed effect size is circular and uninformative (always correlated with $p$-value). Power analysis is a pre-experiment design tool, not post-hoc justification.
// Section 6

Common Mistakes — The Landmines Around NHST

⚠ Significance vs magnitude

With huge $n$, any trivial effect becomes "statistically significant." Kartify with $n = 10^8$ would detect a 0.0001% lift at $p < 10^{-6}$. But 0.0001% lift is not business-meaningful. Always report effect size alongside $p$. Cohen's $d$ for continuous data; absolute and relative differences for proportions.

⚠ "Accept $H_0$" vs "fail to reject"

If $p > \alpha$, we fail to reject $H_0$. We do NOT "accept" or "prove" it. Absence of evidence ≠ evidence of absence. With low power, we can easily fail to reject a null that is actually false. Reporting "no significant difference" without showing power or CI is weak practice.

⚠ Multiple testing

Running $k$ independent tests at $\alpha = 0.05$ each: probability of at least one false positive under all-nulls-true is $1 - 0.95^k$. For $k = 20$, that's 64%. Module 4.8 covers Bonferroni, Holm, BH-FDR. Pre-register hypotheses. Declare families of tests.

⚠ Peeking during the experiment

If you run $n=1000$, check the $p$-value, and stop if significant, you inflate Type I error. Sequential testing with proper stopping rules (alpha-spending, SPRT, group sequential) is its own methodology. Don't sneak peeks.

Python — From Hypothesis to Decision

python · one-proportion Z test — Kartify campaign lift
import numpy as np
from scipy.stats import norm
from statsmodels.stats.proportion import proportions_ztest

# Kartify data
n, k = 12000, 489
p_hat = k / n
p0 = 0.035         # null — baseline conversion rate

# One-sided test: H0 p = 0.035 vs H1 p > 0.035
# Use SE under H0 (not p_hat)
se_H0 = np.sqrt(p0 * (1 - p0) / n)
z_stat = (p_hat - p0) / se_H0
p_value_one_sided = 1 - norm.cdf(z_stat)
print(f"Z statistic:     {z_stat:.2f}")
print(f"One-sided p:     {p_value_one_sided:.5f}")
print(f"Two-sided p:     {2 * (1 - norm.cdf(abs(z_stat))):.5f}")

# statsmodels one-liner (gives two-sided by default)
z, p = proportions_ztest(count=k, nobs=n, value=p0, alternative="larger")
print(f"statsmodels:     Z = {z:.2f}, p = {p:.5f}")

# Decision
alpha = 0.05
if p < alpha:
    print(f"\nReject H0 at α={alpha}. Evidence that conversion rate > {p0}.")
else:
    print(f"\nFail to reject H0.")
python · power analysis — what can Kartify detect?
import numpy as np
from scipy.stats import norm
from statsmodels.stats.power import NormalIndPower

# Scenario: Kartify n=12000, alpha=0.05, baseline p0=0.035
n, alpha, p0 = 12000, 0.05, 0.035
se_H0 = np.sqrt(p0 * (1 - p0) / n)
critical_val = p0 + norm.ppf(1 - alpha) * se_H0
print(f"Reject H0 if p̂ > {critical_val:.5f}")

# Power at various true p_1 values
print(f"\n{'True p':>8} {'Lift':>6} {'Power':>8}")
for p1 in [0.036, 0.037, 0.038, 0.040, 0.042, 0.045]:
    se_H1 = np.sqrt(p1 * (1 - p1) / n)
    power = 1 - norm.cdf((critical_val - p1) / se_H1)
    lift = (p1 - p0) / p0
    print(f"  {p1:.3f} {lift*100:5.1f}% {power:8.3f}")

# Sample size for 80% power to detect a 10% relative lift (3.5% → 3.85%)
effect = (0.0385 - 0.035) / np.sqrt(0.035 * (1 - 0.035))
# Cohen's h style effect size; illustrative
print(f"\nFor 80% power to detect 10% relative lift, rough n ~ {int((norm.ppf(0.95) + norm.ppf(0.8))**2 / effect**2):,}")
python · CI-test duality demonstration
import numpy as np
from scipy.stats import norm

# Kartify data
n, k = 12000, 489
p_hat = k / n
se = np.sqrt(p_hat * (1 - p_hat) / n)
z_crit = norm.ppf(0.975)
ci = (p_hat - z_crit * se, p_hat + z_crit * se)
print(f"95% Wald CI: [{ci[0]:.5f}, {ci[1]:.5f}]")

# Duality: test H0: p = p0 for various p0. Reject iff p0 outside CI.
print(f"\n{'Null p0':>9} {'In CI?':>7} {'Test Z':>8} {'Two-sided p':>11} {'Reject at 5%?':>13}")
for p0 in [0.030, 0.035, 0.038, 0.040, 0.045, 0.050]:
    in_ci = ci[0] <= p0 <= ci[1]
    se_p0 = np.sqrt(p0 * (1 - p0) / n)
    z = (p_hat - p0) / se_p0
    p_val = 2 * (1 - norm.cdf(abs(z)))
    reject = p_val < 0.05
    print(f"  {p0:.4f} {str(in_ci):>7} {z:>8.2f} {p_val:>11.5f} {str(reject):>13}")

# Notice: "in CI" is the complement of "reject". The duality is exact.
