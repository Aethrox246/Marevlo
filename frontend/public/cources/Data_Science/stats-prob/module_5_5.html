Resampling Methods —
Bootstrap & Cross-Validation

When closed-form formulas don't exist — medians, ratios, AUC, custom KPIs — simulate. The bootstrap is the most powerful non-parametric technique in modern statistics: treat your sample as a stand-in for the population, resample it, and watch your statistic vary. Cross-validation is its evaluation cousin: estimate out-of-sample error directly. Permutation tests give exact non-parametric $p$-values. After this module, you can build inference for any statistic without a single distributional assumption.

⚡ Kartify — Three Questions Without Closed-Form Answers
Week 8 continued. Arjun's models are fit; now the operations team has follow-up questions:

Question 1. "What's the 95% CI on the median order value?" — Standard $z$-tests give CIs for the mean; medians have no clean closed-form CI.
Question 2. "Our recommendation engine has AUC = 0.83 on test data. What's the uncertainty in that AUC?" — AUC isn't a sample mean; no neat SE formula.
Question 3. "Does our new model actually predict better, or are we just lucky on this test set?" — How do we estimate true out-of-sample error?

None of these have analytic solutions. They share a common need: quantify uncertainty in something complicated. The bootstrap, cross-validation, and permutation tests are the three modern tools for exactly this.

The bootstrap (Efron, 1979) is one of the most cited statistical methods of the 20th century. The idea is almost embarrassing in its simplicity: if your sample is a good representation of the population, resampling from your sample (with replacement) mimics drawing fresh samples from the population. Every resample gives a slightly different statistic. The spread of those statistics estimates the sampling distribution — without ever knowing the true distribution.

Cross-validation answers a different question: not "what's the SE of my statistic" but "how would my model perform on data it's never seen?" K-fold CV partitions the data, holds out folds, fits on the rest, evaluates on the held-out fold. The average across folds estimates true out-of-sample error.

Permutation tests give exact non-parametric $p$-values for any test statistic — Module 4.7 introduced them; here we deepen them.

Running examples. Kartify's order-value distribution (heavy-tailed, no closed-form median CI), the recommendation-engine AUC (no closed-form SE), and a model-comparison question (cross-validation as the answer).
// Section 1 · The Bootstrap Principle

The Bootstrap Principle — "Sample Is the Population"

The plug-in principle
$$\theta = T(F) \;\;\text{(target — function of true distribution } F)$$
$$\hat\theta = T(\hat F_n) \;\;\text{(estimate — same function of empirical distribution)}$$

If $\theta$ is some function of the population distribution $F$ — say the mean, median, ratio of variances, or AUC — we estimate it by applying the same function to the empirical distribution $\hat F_n$ (which puts mass $1/n$ on each observation).

The bootstrap as a "what if" experiment
Frequentist inference asks: "if I drew many fresh samples from $F$, how would $\hat\theta$ vary?" Without knowing $F$, this question seems unanswerable.

Bootstrap's solution: pretend $\hat F_n$ is $F$, and draw many fresh samples from $\hat F_n$. Each "fresh sample" is a resample (with replacement) from your original data. Each gives a new $\hat\theta^*$. The empirical distribution of $\{\hat\theta^*_b\}_{b=1}^B$ approximates the sampling distribution of $\hat\theta$.

Why this works: by the Glivenko-Cantelli theorem, $\hat F_n \to F$ uniformly as $n \to \infty$. So drawing from $\hat F_n$ (bootstrap) approximates drawing from $F$ (the actual but unknown sampling distribution).
The bootstrap algorithm
$$\text{For } b = 1, \ldots, B: \;\; X^{*b}_1, \ldots, X^{*b}_n \stackrel{\text{iid}}{\sim} \hat F_n, \;\; \hat\theta^{*b} = T(X^{*b}_1, \ldots, X^{*b}_n)$$
$$\widehat{\mathrm{SE}}_{\text{boot}}(\hat\theta) = \sqrt{\frac{1}{B-1}\sum_{b=1}^B (\hat\theta^{*b} - \bar{\hat\theta^*})^2}$$
$B$ — number of bootstrap samples
Typically 1,000–10,000
Larger $B$ reduces Monte Carlo error. $B = 1000$ for SE; $B = 10{,}000$+ for percentile CIs (need extreme quantiles). Cost is linear in $B$.
Resample WITH replacement
Same size $n$ as original
Each bootstrap sample has the same size as the original (so SE scales with $n$ correctly). Some original observations appear twice, others zero times. Without replacement gives the original sample every time — useless.
Works for nearly any statistic
Mean, median, correlation, AUC, ...
As long as $T(F)$ is a "smooth" function of $F$ (regularity condition). Doesn't require Normality, doesn't require known SE formulas, doesn't require sufficient statistics.
Doesn't fix bias from bad data
Garbage in → garbage out
Bootstrap is faithful to your original sample. If your sample is biased (selection bias, non-representative), the bootstrap reproduces that bias. Bootstrap quantifies sampling uncertainty, NOT data quality.
The bootstrap in action — sampling distribution of the median
Heavy-tailed Kartify order values; no closed-form CI for the median. Run bootstrap to get one.

// Section 2 · Bootstrap CIs

Bootstrap Confidence Intervals — Three Methods

Three common ways to turn the bootstrap distribution $\{\hat\theta^*_b\}$ into a CI. Each has trade-offs.

Method 1 — Percentile (simplest, most common)
$$\text{CI}_{1-\alpha}^{\text{pct}} = \left[\hat\theta^*_{(\alpha/2)},\; \hat\theta^*_{(1 - \alpha/2)}\right]$$

Just take the empirical $\alpha/2$ and $1 - \alpha/2$ quantiles of the bootstrap distribution. For 95% CI: 2.5th and 97.5th percentiles. Robust, intuitive, but biased when the bootstrap distribution is skewed.

Method 2 — Pivotal / basic (centered around $\hat\theta$)
$$\text{CI}_{1-\alpha}^{\text{piv}} = \left[2\hat\theta - \hat\theta^*_{(1 - \alpha/2)},\; 2\hat\theta - \hat\theta^*_{(\alpha/2)}\right]$$

Uses the bootstrap distribution of $\hat\theta^* - \hat\theta$ as a pivot. Often more accurate than percentile when bias is present, but can give pathological intervals (wrong sign of skew correction) in some cases.

Method 3 — BCa (Bias-Corrected and Accelerated)
$$\text{Adjusted quantiles: } \alpha_1 = \Phi\!\left(\hat z_0 + \frac{\hat z_0 + z_{\alpha/2}}{1 - \hat a(\hat z_0 + z_{\alpha/2})}\right), \quad \alpha_2 = \Phi\!\left(\hat z_0 + \frac{\hat z_0 + z_{1-\alpha/2}}{1 - \hat a(\hat z_0 + z_{1-\alpha/2})}\right)$$
$$\text{CI}_{1-\alpha}^{\text{BCa}} = \left[\hat\theta^*_{(\alpha_1)},\; \hat\theta^*_{(\alpha_2)}\right]$$

Two corrections: bias correction $\hat z_0$ (fraction of bootstrap samples below $\hat\theta$) and acceleration $\hat a$ (jackknife-based skewness estimate). BCa is the gold standard — second-order accurate (error $O(1/n)$ vs $O(1/\sqrt n)$ for percentile). Default in modern bootstrap packages.

Kartify · 95% CI for the median order value
Data. $n = 5{,}000$ orders. Sample median $= ₹1{,}450$.
Bootstrap. $B = 5{,}000$ resamples. Bootstrap medians range from ₹1,380 to ₹1,520.
Percentile CI. $[\hat\theta^*_{(0.025)}, \hat\theta^*_{(0.975)}] = [1{,}412,\; 1{,}488]$.
BCa CI. $\hat z_0 = -0.04$ (slight bias), $\hat a = 0.018$ (mild skew). Adjusted: $[1{,}408,\; 1{,}484]$.
Conclusion. Median order value is in [₹1,408, ₹1,484] with 95% confidence. No formula was needed — just resample and read off quantiles. The percentile and BCa intervals are close because the median's bootstrap distribution is nearly symmetric here. For more skewed statistics (e.g., tail quantiles), BCa would differ more from percentile.
// Section 3 · Beyond Means and Medians

Bootstrap for Anything — Complex Statistics, Ratios, Model Outputs

Bootstrap shines when the statistic of interest has no analytic SE formula. Three Kartify examples:

Ratio of medians
Premium median / Standard median
"Premium orders are how many times larger than standard?" No closed-form SE for a ratio of medians. Bootstrap each tier separately, compute the ratio, repeat $B$ times. Done.
AUC of a classifier
CI for model AUC = 0.83
Resample (X, y) pairs from the test set with replacement, recompute AUC. Repeat $B$ times. Percentile or BCa CI on the bootstrapped AUCs gives uncertainty quantification — without distributional assumptions about the model.
Custom business KPI
Conversion rate × average order value
Composite KPIs like LTV, CAC payback, expected revenue per visitor — all functions of multiple statistics. Bootstrap the joint distribution by resampling rows; recompute the KPI. CI is an afterthought.
Regression coefficients
Bootstrap when assumptions fail
When OLS errors aren't Normal, or under heteroscedasticity, classical SEs are wrong. Cluster bootstrap (resample whole observation rows including X and y) gives valid SEs without assuming homoscedasticity or Normality.
// Section 4 · Jackknife

The Jackknife — Bootstrap's Older, Cheaper Cousin

Predates the bootstrap (Quenouille, 1949). Instead of resampling $B$ times, just leave one observation out at a time and recompute the statistic.

Jackknife estimates
$$\hat\theta_{(-i)} = T(X_1, \ldots, X_{i-1}, X_{i+1}, \ldots, X_n) \quad (i = 1, \ldots, n)$$
$$\widehat{\mathrm{SE}}_{\text{jack}}(\hat\theta) = \sqrt{\frac{n-1}{n} \sum_{i=1}^n (\hat\theta_{(-i)} - \bar{\hat\theta_{(-\cdot)}})^2}$$
MethodComputationStrengthWeakness
Bootstrap$B$ resamples ($B$ = 1k–10k)Works for almost any statisticRandom — needs many resamples
Jackknife$n$ leave-one-out fitsDeterministic, no random seedFails for non-smooth statistics (e.g., median)
⚡ When jackknife fails — non-smooth statistics

Jackknife requires the statistic to be a "smooth" function of the data — small changes in data give small changes in $\hat\theta$. The median fails this test: removing one of $n$ data points around the middle can jump the median by a discrete amount. Jackknife SE for the median is wildly inaccurate. Bootstrap, on the other hand, handles the median fine — by averaging over many resamples, it recovers the true variability. Rule of thumb: use bootstrap unless you specifically need jackknife's properties (deterministic, fast).

// Section 5 · Cross-Validation

Cross-Validation — Estimating Out-of-Sample Error

Bootstrap quantifies uncertainty in a statistic. Cross-validation answers a different question: how would my model perform on data it has never seen? The two most common variants:

$k$-fold cross-validation
$$\widehat{\text{Err}}^{\text{CV}} = \frac{1}{k} \sum_{j=1}^k L\!\left(y_{\text{fold } j}, \hat f^{(-j)}(X_{\text{fold } j})\right)$$
$k$-fold CV procedure
1
Randomly split data into $k$ disjoint folds of approximately equal size.
2
For $j = 1, \ldots, k$: train model on data excluding fold $j$. Predict on fold $j$. Record loss.
3
Average the $k$ loss values. This is $\widehat{\text{Err}}^{\text{CV}}$ — an estimate of true out-of-sample error.
4
Standard choices: $k = 5$ or $k = 10$ (bias-variance trade-off). Leave-one-out CV is $k = n$.
$k = 5$ or $k = 10$
The standard choice
Each fold is 10–20% of data. Reasonable bias-variance balance. Smaller $k$: faster, but training set is smaller (more pessimistic estimate). Larger $k$: slower, less bias but more variance.
Leave-one-out (LOOCV)
$k = n$
$n$ models fit, each on $n-1$ observations. Nearly unbiased but high variance — successive folds are highly correlated. For OLS, LOOCV has a closed-form shortcut via the hat matrix; for other models, very slow.
Stratified CV
For imbalanced classes
When $Y$ is binary with rare positives (Kartify's 8.2% conversion), random folds can leave a fold with zero positives. Stratify each fold to have the same class ratio. Default in sklearn.model_selection.StratifiedKFold.
Time-series CV
Sequential folds
For temporal data, randomly shuffling violates causality (predicts past from future). Use rolling-origin or expanding-window splits instead. Folds are sequential: train on past, validate on future.
⚠ The biggest CV mistake — leakage

Any preprocessing that uses the held-out fold's data invalidates CV. Examples:

  • Standardizing features using mean/std of the full dataset before splitting. The hold-out fold influences scaling. Fix: fit scaler on training fold only, apply to test.
  • Feature selection on the full dataset. Selecting the "top 10 features by correlation with $y$" using all data inflates CV-estimated performance. Fix: do feature selection inside each fold.
  • Hyperparameter tuning on the test set. If you tune via CV and then report the same CV score, the score is overly optimistic. Fix: nested CV (outer fold for evaluation, inner fold for tuning).
Python's Pipeline and cross_val_score handle these correctly — use them religiously.

// Section 6 · Bagging

Bagging — Bootstrap Aggregation for Variance Reduction

Bagging (Breiman, 1996) uses the bootstrap not for inference but for prediction. Fit one model per bootstrap sample; aggregate predictions.

Bagging algorithm
$$\hat f_{\text{bag}}(x) = \frac{1}{B} \sum_{b=1}^B \hat f^{*b}(x)$$

Each $\hat f^{*b}$ is fit on a bootstrap sample $X^{*b}$. The aggregate prediction is the average (regression) or majority vote (classification).

Why bagging works
Variance reduction
If individual predictors have variance $\sigma^2$ and pairwise correlation $\rho$, the average of $B$ has variance $\rho \sigma^2 + (1-\rho)\sigma^2/B \to \rho\sigma^2$. Lower correlation between bootstrap fits → bigger variance reduction.
When bagging helps most
High-variance, low-bias models
Decision trees, kNN, complex neural nets. These have high variance — small data perturbations move predictions a lot. Bagging absorbs this.
When bagging doesn't help
Stable models (linear regression, regularized fits)
Linear models change little with small data perturbations — already low-variance. Bagging adds compute without much gain.
Random Forest
Bagging + random feature subsetting
Bagged decision trees + a random subset of features at each split. The feature randomness decorrelates trees further, amplifying variance reduction. Modern default for tabular data.
// Section 7 · Permutation Tests

Permutation Tests — Exact Non-Parametric Significance

Module 4.7 introduced permutation tests; here we deepen them. The idea: under $H_0$ (no group difference), the labels are exchangeable — every relabeling of the data is equally likely. Random relabelings build the exact null distribution of any test statistic.

Permutation test for a two-sample comparison
$$T_{\text{obs}} = T(X_A, X_B), \quad p\text{-value} = \frac{1 + \#\{T_{\pi}^{(b)} \ge T_{\text{obs}}\}}{1 + B}$$
Exact validity
No asymptotic approximations
Type I error rate is exactly $\alpha$ (up to discretization) under exchangeability. No CLT, no $\chi^2$ approximation needed. Works for $n = 10$ as well as $n = 10^6$.
Works for ANY statistic
Mean, median, AUC, Gini, custom KPI
The permutation test doesn't care what $T$ is — just that exchangeability holds under $H_0$. Compare medians, ratios of variances, area under custom curves — all permutation-testable.
Exchangeability assumption
Critical to verify
Under $H_0$, $(X_1, \ldots, X_n)$ should be exchangeable. Violated by: time series with autocorrelation, paired data treated as independent, hierarchical structure ignored. Use cluster permutation (Section 9 of Module 4.7) when needed.
Compute cost
$B \cdot$ statistic-time
$B = 10{,}000$ permutations is standard. For complex statistics, this can be slow — but scipy's permutation_test (since 1.8) is well-optimized. Under tight budgets, $B = 1{,}000$ usually gives reliable rough $p$-values.
// Section 8 · When to Use What

Bootstrap vs CV vs Permutation — Three Tools, Three Goals

ToolGoalOutputTypical use
BootstrapQuantify uncertainty in a statisticSE, CI"What's the CI for this AUC, median, ratio?"
Cross-validationEstimate out-of-sample prediction errorLoss estimate (RMSE, accuracy, AUC)"How well will my model perform on new data?"
Permutation testTest a hypothesis about distribution equality$p$-value"Are these two groups really different?"
All three under one umbrella — "simulate to substitute analytics"
Each method replaces an analytical calculation with simulation:
  • Bootstrap: replaces "derive sampling distribution from $F$" with "resample from $\hat F_n$."
  • CV: replaces "derive expected test loss" with "average loss across held-out folds."
  • Permutation: replaces "derive null distribution of $T$" with "compute $T$ under random label shuffles."
Together, they form the modern non-parametric inferential toolkit. Modern statistical practice — especially in ML, A/B testing, and data science — relies on these tools as much as on classical $z$/$t$/$\chi^2$ tests.
// Section 9 · Python

Python — Bootstrap, CV, and Permutation in Practice

python · bootstrap CI for the median (manual + scipy)
import numpy as np
from scipy.stats import bootstrap

np.random.seed(42)
n = 5000

# Kartify order values — heavy-tailed log-normal
order_values = np.random.lognormal(7.3, 1.0, n)
print(f"Sample median: ₹{np.median(order_values):,.0f}")

# ─── Manual bootstrap ───
B = 5000
boot_medians = np.empty(B)
for b in range(B):
    sample_b = np.random.choice(order_values, size=n, replace=True)
    boot_medians[b] = np.median(sample_b)

# Percentile CI
ci_pct = np.percentile(boot_medians, [2.5, 97.5])
print(f"Manual percentile CI: [₹{ci_pct[0]:,.0f}, ₹{ci_pct[1]:,.0f}]")

# Bootstrap SE
boot_se = boot_medians.std(ddof=1)
print(f"Bootstrap SE: ₹{boot_se:,.1f}")

# ─── scipy bootstrap with BCa ───
res = bootstrap(
    (order_values,),
    np.median,
    confidence_level=0.95,
    n_resamples=5000,
    method="BCa",
    random_state=42
)
print(f"BCa CI: [₹{res.confidence_interval.low:,.0f}, ₹{res.confidence_interval.high:,.0f}]")
print(f"BCa SE: ₹{res.standard_error:,.1f}")
python · bootstrap for AUC of a classifier
import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import roc_auc_score
from sklearn.model_selection import train_test_split

np.random.seed(42)
# Synthetic Kartify-like data
n = 3000
X = np.random.normal(0, 1, (n, 5))
logit = -1 + X @ np.array([0.8, 0.5, -0.3, 0.1, 0])
y = np.random.binomial(1, 1 / (1 + np.exp(-logit)))

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=42)
clf = LogisticRegression(max_iter=1000).fit(X_train, y_train)
proba_test = clf.predict_proba(X_test)[:, 1]

auc_obs = roc_auc_score(y_test, proba_test)
print(f"Observed AUC: {auc_obs:.3f}")

# Bootstrap CI for AUC
B = 2000
boot_aucs = []
n_test = len(y_test)
for b in range(B):
    idx = np.random.choice(n_test, n_test, replace=True)
    # Skip resamples with no positives or no negatives (AUC undefined)
    if len(np.unique(y_test[idx])) < 2:
        continue
    boot_aucs.append(roc_auc_score(y_test[idx], proba_test[idx]))

boot_aucs = np.array(boot_aucs)
ci = np.percentile(boot_aucs, [2.5, 97.5])
print(f"Bootstrap 95% CI for AUC: [{ci[0]:.3f}, {ci[1]:.3f}]")
print(f"Bootstrap SE: {boot_aucs.std(ddof=1):.4f}")
python · k-fold CV with proper preprocessing pipeline
import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import Pipeline
from sklearn.model_selection import StratifiedKFold, cross_val_score, TimeSeriesSplit

np.random.seed(42)
n = 2000
X = np.random.normal(0, 1, (n, 10))
y = np.random.binomial(1, 1/(1+np.exp(-(0.8*X[:, 0] + 0.5*X[:, 1] - 2))))
print(f"Class balance: {y.mean():.3f}")

# Pipeline ensures scaler is fit per-fold (no leakage)
pipe = Pipeline([
    ("scaler", StandardScaler()),
    ("clf", LogisticRegression(max_iter=1000))
])

# Stratified k-fold for imbalanced binary classification
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
scores = cross_val_score(pipe, X, y, cv=cv, scoring="roc_auc")
print(f"5-fold CV AUC: {scores.mean():.3f} ± {scores.std(ddof=1):.3f}")

# For time-series data: never randomize folds — use TimeSeriesSplit
tscv = TimeSeriesSplit(n_splits=5)
ts_scores = cross_val_score(pipe, X, y, cv=tscv, scoring="roc_auc")
print(f"Time-series CV AUC: {ts_scores.mean():.3f} ± {ts_scores.std(ddof=1):.3f}")
# Note: TS-CV folds are sequential (train: past; test: future). No shuffling.
python · permutation test — beyond Module 4.7
import numpy as np
from scipy.stats import permutation_test

np.random.seed(42)

# Kartify: do Premium and Standard tiers have different median order values?
standard = np.random.lognormal(7.1, 1.2, 200)
premium = np.random.lognormal(8.2, 1.3, 150)

# Test statistic: difference in medians (no closed-form analytic test exists!)
def median_diff(x, y, axis):
    return np.median(x, axis=axis) - np.median(y, axis=axis)

result = permutation_test(
    (premium, standard),
    median_diff,
    n_resamples=9999,
    alternative="greater",
    random_state=42
)
print(f"Observed median difference: ₹{result.statistic:,.0f}")
print(f"Permutation p-value: {result.pvalue:.5f}")

# For arbitrary statistics — permutation test is the only general option
def ratio_of_iqr(x, y, axis):
    iqr_x = np.percentile(x, 75, axis=axis) - np.percentile(x, 25, axis=axis)
    iqr_y = np.percentile(y, 75, axis=axis) - np.percentile(y, 25, axis=axis)
    return iqr_x / iqr_y

result2 = permutation_test(
    (premium, standard), ratio_of_iqr,
    n_resamples=9999, alternative="two-sided", random_state=42
)
print(f"\nRatio of IQRs: {result2.statistic:.3f}, p = {result2.pvalue:.4f}")
